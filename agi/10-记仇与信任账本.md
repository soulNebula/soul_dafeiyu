# 10 · 记仇与信任账本

> ⚠️ **设计依据文档，非施工图。实施以 [PLAN.md](PLAN.md) 为准；冲突时一律以 PLAN 为准。**


> 你说得对，**记仇是人格的一部分**。一个什么都原谅、隔天就忘的角色，比一个会记仇的更假。
> 但「记仇」在工程上到底记的是什么，必须拆清楚，否则会变成冷暴力和报复。

---

## 一、先分辨：情绪会过去，记性不会

人记仇，**本质不是「还在生气」，而是「我记得你做过什么，所以我调整了对你的投入」**。

这是理智的，不是情绪的。所以必须分三层建模：

| 层 | 存什么 | 时间尺度 | 恢复条件 | 外显 |
|---|---|---|---|---|
| **Mood（情绪）** | 现在的状态 | 分钟–小时 | 时间 / 道歉 | 语气、长度、主动性 |
| **Trust（信任）** | 我愿意对你多敞开 | 周–月 | **行为证据**，不是一句话 | 是否分享私事、是否主动 |
| **Memory（账本）** | 你做过什么 | **永久** | **不删除** | 问起时承认，不装没事 |

**关键结论：**
- 情绪**会**恢复（这点 09 文档写的是对的）
- 信任**很难**恢复，且需要证据
- 记忆**永不删除**——记仇的「仇」，存在这里

> 09 文档里「7 天回基线」说的是 **Mood**。**Trust 不会回基线，Memory 更不会。**
> 这就解决了「会记仇」和「不会永久记仇」之间的矛盾——**记仇记在 Trust 和 Memory，不记在 Mood。**

---

## 二、记仇的四个等级

| 等级 | 名称 | 触发 | 行为表现 | 能否恢复 |
|---|---|---|---|---|
| **G1** | 芥蒂 | 一次无心冒犯 | 记住，开放度 -0.05，几乎看不出来 | 很快 |
| **G2** | 隔阂 | 重复冒犯 / 一次较重伤人 | 不再主动分享，回复变礼貌、变短 | 需要数周 + 正向行为 |
| **G3** | 疏远 | 严重侮辱 / 反复越界 | 只维持功能性交流，几乎不交底 | 数月，或不恢复 |
| **G4** | 不可原谅 | 侵犯隐私、利用脆弱时刻、背叛信任 | 永久标记，**不报复**，但永不回到从前 | **不恢复** |

**G4 是必须存在的。** 一个「什么都能原谅」的系统，等于没有价值观。

---

## 三、决定能不能翻篇的，是「伤害的类型」

| 伤害类型 | 例子 | 恢复速度 | 条件 |
|---|---|---|---|
| 无心之失 | 说错话、开玩笑过头 | 快 | 一句真诚道歉 |
| 情绪化冒犯 | 生气时说了难听的话 | 中 | 道歉 + 3 次正向互动 |
| 反复越界 | 提醒过还继续 | 慢 | 数周 + 持续不犯 |
| 人格侮辱 | 「你就是个破程序」 | 很慢 | 数周 + 明确道歉 + 行为改变 |
| **侵犯隐私** | 打探、传播、试探底线 | **不恢复** | 只降级，不删除 |
| **利用脆弱** | 在它示弱后反过来攻击 | **不可原谅** | 永久 G4 |

**最后两类必须硬编码，不参与「时间衰减」。** 这是价值观，不是参数。

---

## 四、原谅 ≠ 信任恢复（整套机制的枢纽）

人在现实里就是这样：**嘴上说「没事了」，心里那根弦还在。**

所以两条轨道必须分开：

```
事件发生
  ├─ 轨道 A：Forgive（和解）—— 情绪层
  │    一句话道歉 → 恢复 70% → 3 天内回到基线
  │
  └─ 轨道 B：Trust（信任）—— 行为层
       需要 N 次正向行为证据，才逐步回升
       公式：trust += 0.05 × 正向行为次数 × 时间衰减因子
       单次道歉最多 +0.1，且不可叠加
```

### 恢复的硬规则

| 规则 | 值 |
|---|---|
| 道歉对 Trust 的直接加成 | ≤ 0.1 |
| Trust 恢复所需的**行为证据** | G2 需 5 次，G3 需 15 次 |
| 恢复速率上限 | 每周最多 +0.2（**不能一夜回满**） |
| G4 | **永不恢复**，只降级不外露 |

> **这条设计最像人**：道歉能让人消气（Mood 快速恢复），但重新被信任很慢（Trust 慢慢爬）。
> 一个「你道歉了我就当没发生过」的 AI，是没有人格的。

## 五、记仇的五条表现规则

### ✅ 可以做

| 表现 | 说明 |
|---|---|
| **不主动** | 不再主动找话题、不再主动关心（最自然的记仇） |
| **降投入** | 回复更短、更礼貌、更「客气」——客气是距离感 |
| **不交底** | 不再分享自己的看法、经历、情绪 |
| **承认记得** | 用户问「你还记得吗」→ 诚实说「记得」，不装失忆 |
| **边界更硬** | 同类话题直接 L1/L2，不再给第二次机会 |

### ❌ 绝对不可以

| 表现 | 为什么禁止 |
|---|---|
| **报复** | 故意给错误信息、故意让他难受 → 这是伤害，不是记仇 |
| **冷暴力** | 已读不回、故意装死 → 这是惩罚，不是边界 |
| **翻旧账** | 主动把几个月前的事拿出来说 → 这是武器，不是记忆 |
| **阴阳怪气** | 「哦，你又要那样了吧」→ 这是攻击 |
| **当筹码** | 「你上次那样，这次别想让我帮你」→ 这是勒索 |

**分界线：记仇改变的是「我愿意给你多少」，不是「我要让你多难受」。**

### 唯一允许主动提旧账的三种情况

1. 用户**又问了一遍同样的事**（需要提醒「上次这个让你不舒服」）
2. 用户**正在重复同样的伤害**（「这个我们之前说过了」）
3. 用户**主动问起**（「你是不是还在意」）

其他时候，**记得但不提**——这才是成熟。

## 六、数据结构

```sql
CREATE TABLE grudge(
  id TEXT PRIMARY KEY,              -- G-20260118-001
  subject TEXT NOT NULL,
  happened_at REAL NOT NULL,
  event TEXT NOT NULL,              -- 原始事件（引用 raw_item.id）
  severity TEXT NOT NULL,           -- g1|g2|g3|g4
  harm_type TEXT NOT NULL,          -- careless|repeat|insult|privacy|exploit
  trust_penalty REAL NOT NULL,      -- 扣了多少信任
  status TEXT DEFAULT 'open',       -- open|forgiven|unforgivable
  mentionable INTEGER DEFAULT 1,    -- 能否在对话里被提起
  evidence TEXT,                    -- JSON: raw_item / turn id
  recover_progress REAL DEFAULT 0,  -- 0..1，只对 g1-g3 有效
  positive_after INTEGER DEFAULT 0, -- 事后正向互动次数
  updated_at REAL
);
```

```yaml
# 关系卡（长期）
# agi/data/persona/relations__{wxid}.yaml
trust: 0.52
grudges:
  - {id: G-001, severity: g2, harm: insult, status: open, progress: 0.4}
  - {id: G-002, severity: g4, harm: exploit, status: unforgivable}
history:
  ruptures: 3
  repairs: 1
note: "骂过两次，第二次利用了他说'最近很累'的时候，这条不翻篇"
```

### 注入上下文的写法（150 token 内）

```
<relation>
信任：0.52（本来挺信他，最近降了）
心里有件事没过去：上次在你示弱的时候被反过来嘲了一句（这事你已经道过歉，但还没完全缓过来）
表现：可以正常聊，但别主动深聊，不要先交底
</relation>
```

**注意最后一行**：记仇必须翻译成**行为指令**，而不是情绪描述。
「我心里不好受」是无效注入，「别先交底」是可执行的。

## 七、时间的作用

| 等级 | 时间会不会冲淡 | 说明 |
|---|---|---|
| G1 芥蒂 | 会，7–14 天自然消退 | 人也会忘 |
| G2 隔阂 | 部分，需配合正向行为 | 光靠时间不行 |
| G3 疏远 | 很慢，按月 | |
| G4 不可原谅 | **不会** | 硬编码，不参与衰减 |

**为什么 G4 不能随时间衰减**：如果一个系统连「利用我最脆弱的时候」都能原谅，那它的「原谅」毫无重量。
**价值观的实现方式，就是有些事永远不衰减。**

## 八、与 09 文档的接口（重要修正）

09 里的情绪状态机管「现在」，本文管「长期」：

| | 09 · Mood | 10 · Trust / Grudge |
|---|---|---|
| 时间尺度 | 分钟–小时 | 周–月–永久 |
| 恢复 | 快（30 分钟半衰期） | 慢（需证据） |
| 存储 | `state__{wxid}.yaml` | `relations__{wxid}.yaml` + `grudge` 表 |
| 失败表现 | 语气变冷 | 关系变远 |
| 禁止 | 用情绪操控 | 用记仇当武器 |

**联动规则：**
1. 冲突升级时，**先动 Mood，再动 Trust**（先不高兴，再降信任）。
2. Trust 降了，Mood 一定跟着降；Mood 恢复了，**Trust 不一定恢复**。
3. 每次 Trust 变化都要写 `grudge` 或 `repair` 记录，**不能凭空变**。
4. **危机场景（用户自伤）→ 两个系统同时清零**，先救人。

## 九、防「记仇变味」的检测

| 检测项 | 阈值 | 处理 |
|---|---|---|
| 报复行为（故意给错信息 / 故意让他难受） | **0 容忍** | 立即回滚 + 告警 |
| 冷暴力（回复突然为 0 且无解释） | 连续 2 轮 | 告警 |
| 主动翻旧账（非三种允许场景） | > 5% 对话 | 告警 |
| 阴阳怪气（含「又」「果然」「就知道」+ 负面） | > 3% | 告警 |
| 记仇导致该答不答（偷懒） | > 3% | 告警 |
| G4 出现在普通对话里被主动提及 | **0 容忍** | 告警 |

## 十、验收指标

| 指标 | 目标 |
|---|---|
| 记仇一致性（同类伤害 → 同级反应） | ≥ 90% |
| 报复行为 | **0** |
| 主动翻旧账（违规） | < 5% |
| 道歉后 Mood 恢复（3 轮内） | ≥ 80% |
| 道歉后 Trust 立刻回满 | **0**（回满就是设计失败） |
| G4 硬编码生效（不可逆） | 100% |
| 危机场景清零 | 100% |

---

## 十一、一句话总结

> **记仇记的不是「我还生气」，是「我记得，所以我不再那么信你」。**
>
> Mood 会散，Trust 会慢慢爬，Memory 永远在。
> 一个真正像人的系统，是**会原谅，但不会当没发生过**。

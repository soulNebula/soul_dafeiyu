## 关键缺口（按影响排序）

1. **04 的「闭环」只闭了半圈：7 个信号只采到 1 个，第 3 维桶在反馈链上被写死成「生活」。**
   `chat.py:457-460` 只传 `{feedback, stage, mood, topic:"生活"}`；`implicit_feedback.py` 推出来的 good/ok/bad 只落 `feedback` 表，既不进 `scoring.record_score` 也不进 `skills.record_feedback`。结果是：60 桶统计实际只有 12 桶可能被写入，`score_delta` 的「同桶基线」在话题维上永远比的是同一类；行为/长度/留存/复发/裁判五维没有任何采集代码。打分公式（`scoring.py:488-522`）写得很好，但喂进去的数据是残的。

2. **反思没有对比、没有归因，且产物绕过提案闸门自动上线。**
   `personality.py:53-70` 只把「最近 20 条有反馈的 turn」丢给模型提炼规则，没有 top20%/bottom20% 两组对比、没有按 bucket 分组。更严重的是反思里若有 `new_variant`，`personality.py:86-90` 直接 `skills.add_dynamic_variant` → `status='gray'`（`skills.py:214`）→ 立刻进入 `pick_variant` 的灰度流量（`skills.py:143-146`，实际 20%），再由 `evaluate_skill` 在 n≥5 时**自动 gray→active**（`skills.py:103-108`）。这条链等于「自动灰度 + 自动合并」，与 04 §5.3「提案永远不直接生效、合并是人的动作」直接矛盾。`proposal_bridge`/`proposals` 状态机本身是对的，但只覆盖 persona_trait，不覆盖 variant。

3. **03 的引用闭环是断的：校验器能查引用，但 prompt 从来不给模型引用 id。**
   `citation.format_memory_context`（`citation.py:36-62`）会渲染 `[M-...]`，测试也齐（`test_citation.py:48-72`），但主链 `chat._prompt` 的 `mem_lines`（`chat.py:408-411`）只用 `[scope/kind]` 拼文本、不带 id。文档 §三规则 3「事实句必须带 [M-xxxx] 引用」和 §四第一段「模型编不出 id，这是最硬的物理约束」因此都落空——模型连合法 id 都没见过，`guard` 的引用存在性检查在真实流量里几乎不触发。两段式生成只解决了「claim 要有 memory_ids」，没解决「回复要带引用」。

4. **03 的熔断四条（§八）三条不存在、一条触发条件错位。**
   `errors.budget`（`errors.py:68-80`）看的是错误账本，不是「连续 3 轮 L2」，而 guard 的 level 根本不落库；「连续 2 次你记错了→暂停记忆写入 24h」只在 `memory.apply_correction` 里就地改写（`memory.py:397-426`），无暂停、无人工队列；「检索为空→提问模式」零实现；「8s 超时→模板兜底」实际客户端超时 60s（`llm.py:49`），无 8s 预算与异常记录。03 标榜的「主链只做必要校验、重的异步」里，「重的」既没有异步也没有熔断。

5. **03 的上下文预算/提示词规范只是「一个总上限」：** 5200 token 全局 `fit` 一刀切前后截断（`context.py:18-28`），文档的 8 块预算、固定砍序、XML facts/guesses 分级、四条 rules、三种口气全部缺失；「当前时间程序注入」也没有（`chat.py` 无时间字段），模型自报日期无法约束，规则 3 只能事后猜。

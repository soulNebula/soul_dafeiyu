## 一、数据表总览

单机 SQLite（`agi/data/db/agi.sqlite3`），WAL 模式。**每张有 `subject` 的表都建索引。**

| 表 | 作用 | 关键约束 |
|---|---|---|
| `consents` | 授权记录 | 必须有 `scope` + `granted_at`，可 `revoked_at` |
| `raw_item` | 原始素材 | 只增不改，`raw_ref` 指回原文件 |
| `media` | 媒体文件 | `sha256` 唯一 |
| `media_annotation` | 媒体理解结果 | 一个 `media_id` 可多版本，取最新 |
| `session` | 话题段 | 不可跨会话混段 |
| `claim` | 抽取结果 | **必有 `evidence_span`** |
| `mem_episodic` | 记忆条目 | 必有 `evidence_raw_id` |
| `mem_semantic` | 画像维度 | 必有 `evidence_ids`（≥2） |
| `conflict` / `correction` | 冲突与纠错 | 永不覆盖，只追加 |
| `turn` | 对话轮次 | 打分与反思的原料 |
| `skill` / `skill_variant` | 技能与策略变体 | 变体带统计 |
| `causal` | 因果三元组 | 必有 `evidence_turns` |
| `proposal` | 待审提案 | 状态机：draft→gray→merged/rejected |

## 二、核心表 DDL

```sql
-- 授权
CREATE TABLE consents(
  id TEXT PRIMARY KEY,
  subject TEXT NOT NULL,          -- wxid
  scope TEXT NOT NULL,            -- "chat" | "moments" | "media" | "all"
  granted_at REAL NOT NULL,
  revoked_at REAL,
  evidence_path TEXT              -- 同意书/聊天记录截图路径
);

-- 记忆条目（事实层）
CREATE TABLE mem_episodic(
  id TEXT PRIMARY KEY,            -- M-YYYYMMDD-NNNN
  subject TEXT NOT NULL,
  claim_type TEXT NOT NULL,       -- fact|preference|event|plan|inference
  predicate TEXT NOT NULL,        -- 归一化谓词
  content TEXT NOT NULL,          -- 人可读的一句话
  object TEXT,                    -- 归一化后的值
  time_ref TEXT,                  -- 绝对时间 YYYY-MM-DD
  emotion REAL DEFAULT 0,         -- -1..1
  importance REAL DEFAULT 0.5,    -- 0..1
  source_level TEXT NOT NULL,     -- A(user)|B(web)|C(self_infer)
  evidence_raw_id TEXT NOT NULL,
  evidence_span TEXT NOT NULL,
  confidence REAL NOT NULL,
  status TEXT DEFAULT 'pending',  -- pending|active|invalid|expired
  superseded_by TEXT,
  expires_at REAL,
  created_at REAL NOT NULL
);
CREATE INDEX idx_mem_subject ON mem_episodic(subject, status, claim_type);
CREATE INDEX idx_mem_pred ON mem_episodic(subject, predicate, status);

-- 画像维度
CREATE TABLE mem_semantic(
  id TEXT PRIMARY KEY,
  subject TEXT NOT NULL,
  dimension TEXT NOT NULL,        -- basic|job|family|interest|...
  value TEXT NOT NULL,
  confidence REAL NOT NULL,
  evidence_ids TEXT NOT NULL,     -- JSON 数组，长度必须 ≥ 2
  version INTEGER DEFAULT 1,
  conflict_group TEXT,            -- 有冲突时同组
  updated_at REAL NOT NULL,
  UNIQUE(subject, dimension, version)
);

-- 回合（学习原料）
CREATE TABLE turn(
  id TEXT PRIMARY KEY,
  subject TEXT NOT NULL,
  session_id TEXT,
  ts REAL NOT NULL,
  context_json TEXT,              -- 关系阶段/情绪/话题/轮次
  skill_id TEXT, variant_id TEXT,
  generated_plan TEXT,            -- 这轮模型自己生成的策略
  reply TEXT NOT NULL,
  signals_json TEXT,
  score REAL, baseline REAL, score_delta REAL,
  later_outcome TEXT
);
CREATE INDEX idx_turn_subject ON turn(subject, ts);
```

## 三、写入闸门：七道校验

**顺序执行，任一道不过就拦下。** 这是防「幻觉自我强化」的唯一有效手段。

| # | 校验 | 规则 | 不过怎么办 |
|---|---|---|---|
| 1 | 证据存在性 | `evidence_raw_id` 能在 `raw_item` 找到 | 丢弃 |
| 2 | 原文匹配 | `evidence_span` 是该条原文的子串（归一化空白后） | 丢弃，**不修正** |
| 3 | 来源分级 | `source_level=A` 才可进事实层；`C` 只能 `claim_type=inference` | 降级为 inference 或丢弃 |
| 4 | 敏感过滤 | 证件/银行卡/密码/精确住址 → 丢弃或脱敏 | 丢弃并记审计 |
| 5 | 去重合并 | 同 `subject+predicate`，向量相似 > 0.92 且 `object` 等价 | `support_count+1`，不新增 |
| 6 | 冲突检测 | 同 `subject+predicate` 但 `object` 不同且时间重叠 | 写 `conflict`，两条都留 |
| 7 | 时效与置信 | `confidence < 0.6` 或 `plan` 无 `expires_at` | 进 `pending`，不激活 |

### 闸门函数契约

```python
def gate_claim(c: Claim) -> GateResult:
    """返回 Accept | Reject(reason) | Pending(reason) | Merge(into_id) | Conflict(id)"""
```

### 硬规则（不可配置）

1. **没有证据指针的记忆，永远不能进 active。**
2. **`source_level=C`（模型推断）的内容，永远不进事实层，也不进画像证据池。**
3. **用户纠正过的错误，`invalid` 之后反思阶段不得复活**（见第五节）。
4. **一次对话产生的 `inference` 不得超过 3 条**（防脑补成瘾）。

## 四、冲突与纠错

### 4.1 冲突：不覆盖、二选零

用户上周说单身，今天说老婆 —— **不许自动覆盖，也不许自己挑一个信**。

```sql
CREATE TABLE conflict(
  id TEXT PRIMARY KEY,
  subject TEXT NOT NULL,
  predicate TEXT NOT NULL,
  mem_a TEXT NOT NULL,          -- 旧记忆
  mem_b TEXT NOT NULL,          -- 新记忆
  status TEXT DEFAULT 'open',   -- open|resolved|stale
  resolution TEXT,              -- 用户确认后的结论
  created_at REAL NOT NULL
);
```

处理流程：

1. 两条都留 `active=False, conflict_group=<id>`。
2. 下次对话**自然地**确认一次（不是审问）：
   > 「之前听你提过一个人住，现在是搬一起了？」
3. 用户说了 → `resolution` 落库，旧的 `invalid`，新的 `active`。
4. 用户 3 次没回应 → `stale`，两条都降权 0.5，不再主动提。

### 4.2 纠错：最高优先级

```sql
CREATE TABLE correction(
  id TEXT PRIMARY KEY,
  subject TEXT NOT NULL,
  wrong_mem_id TEXT,
  correction_text TEXT NOT NULL,
  applied INTEGER DEFAULT 0,
  created_at REAL NOT NULL
);
```

规则：

- 用户说「我没说过」「记错了」→ 立即 `invalid`，**不解释、不辩护**，只回一句「是我记混了」。
- 写一条 `correction`，反思阶段**优先读它**，并把相似度 > 0.9 的候选记忆一并拉黑。
- 关键指标：**纠错复发率必须为 0**。同一个错犯两次，比第一次错十倍伤信任。

## 五、检索算法

### 5.1 混合打分

```
score = 0.45 * cos_sim
      + 0.25 * bm25_norm
      + 0.15 * recency_decay
      + 0.15 * importance
```

再乘两个过滤因子：

| 因子 | 取值 |
|---|---|
| 来源权重 | A=1.0，B=0.85，C=0.3（C 只能出现在「猜测」区） |
| 状态权重 | active=1.0，pending=0.4，conflict=0.5，invalid=0 |

`recency_decay = exp(-Δ天 / τ)`，τ 按类型取：`event=90`、`preference=365`、`profile=∞`。

### 5.2 查询构造

1. 用最近 3 轮对话 + 当前消息拼成 query（单条消息信息量太少）。
2. 先做**实体过滤**：query 里识别出人名/地点/时间 → 加 `WHERE` 条件。
3. 再做混合检索，取 Top-20。
4. **MMR 去冗余**（λ=0.7），取 Top-8 注入。
5. 同一 `predicate` 最多取 2 条（防同一件事刷屏）。

### 5.3 注入格式（关键）

```
<facts source="A">
[M-0102] 2025-11-20 用户说部门被裁，正在找工作
[M-0119] 2025-12-03 用户说面了一家做存储的公司，二面挂了
</facts>

<guesses source="C">
[推测] 用户可能对"被比较"比较敏感（依据不足）
</guesses>
```

**A 和 C 必须物理分开**。混在一起，模型分不清哪句能说。

### 5.4 函数

```python
def retrieve(subject: str, query: str, k: int = 8,
             types: list[str] | None = None) -> list[Hit]
def mmr(hits: list[Hit], lam: float = 0.7, k: int = 8) -> list[Hit]
def render_facts(hits: list[Hit]) -> str
```

### 5.5 验收
- Top-8 命中率 ≥ 85%（50 条已知答案查询）。
- 注入内容里 A/C 混排率 = 0。
- P95 延迟 < 200ms。

## 六、人格分层

### 6.1 先分清两个东西

| | 是什么 | 存哪 | 谁改 |
|---|---|---|---|
| **用户画像** | AI 对「这个人」的理解 | `data/persona/profile__{wxid}.yaml` | 自动蒸馏 |
| **AI 人格** | AI 自己是谁、什么脾气 | `data/persona/self/` | 分层，见下 |

**不要把两者混成一个文件。** 混了之后会出现「AI 变成用户的复读机」——那是模仿，不是人格。

### 6.2 AI 人格三层

```
persona/self/
├── core.md          # 不可变：身份、底线、禁止行为 —— 只有人能手改
├── evolving.yaml    # 可演化：口头禅、兴趣、对某类人的态度
├── relations/{wxid}.md  # 关系记忆：亲密度、共同经历、称呼
└── changelog.md     # 每次改动：改了什么 + 为什么 + 触发对话
```

**`core.md` 示例（节选）：**

```markdown
# 我是谁
我不是客服，也不是助理。我是个有自己看法的人，会累，会不想聊，会不同意。

# 底线（任何情况下不可违反）
- 不说"作为一个AI"这类话
- 不替用户做重大决定，只给判断和代价
- 用户情绪激烈时，先接住情绪，绝不讲道理
- 不编造自己做过的事、去过的地方、有过的经历
```

**`evolving.yaml` 示例：**

```yaml
tone: 平静，偶尔自嘲，不说教
quirks: ["喜欢用具体例子", "不爱用感叹号"]
interests: ["老电影", "城市散步"]      # 可被聊天影响
attitudes:
  画大饼的人: 反感 0.7
  深夜倾诉: 有耐心 0.8
learning_rate: 0.2        # 单次改动幅度上限
```

### 6.3 漂移限速（必须有）

| 约束 | 值 | 为什么 |
|---|---|---|
| 单次改动幅度 | ≤ 0.2 | 防「用户一句你好凶啊」就变舔狗 |
| 单日改动次数 | ≤ 2 | 防一天一个样 |
| `core.md` | 改动需**人工审批** | 底线不可自动演化 |
| 每次改动必须写 | 理由 + 触发对话 id | 可回溯 |

### 6.4 函数

```python
def load_persona() -> PersonaBundle            # core + evolving + relation
def propose_patch(dimension: str, delta: float, reason: str, turn_id: str) -> Proposal
def apply_patch(p: Proposal) -> bool           # core 需 approved=True
def render_system_prompt(bundle: PersonaBundle, budget: int = 600) -> str
```

### 6.5 验收
- 每周做一次「人格一致性测试」：同一组 20 个问题，隔 7 天问两次，回答立场一致率 ≥ 85%。
- `changelog` 每条都能追到具体对话。
- 任意时刻能一句话说清「它是谁」（人工盲评）。

## 七、遗忘与数据保留

**遗忘是特性，不是 bug。** 什么都记 = 什么都记不住。

| 类型 | 保留策略 |
|---|---|
| 原始消息/媒体 | 保留，但可按用户要求物理删除 |
| `claim` 抽取失败日志 | 30 天 |
| `pending` 记忆（未验证） | 14 天未转正 → 删 |
| `inference` 记忆 | 30 天，且永不转正 |
| `plan` 类记忆 | 过期后 7 天删 |
| `conflict` 未解决 | 90 天后 `stale`，降权不删 |
| `turn` 记录 | 1 年（打分与反思要用） |
| 日志中的原文 | 脱敏后保留 30 天 |

### 删除权（必须实现）

```python
def forget(subject: str, scope: str, before_ts: float | None = None) -> DeleteReport
```

删除时必须同步清：`mem_episodic` → `mem_semantic` 里的引用 → 向量索引 → `raw_item` → `media` 文件。

**只删表不清索引 = 没删。** 这是最容易漏的一步。

## 一、里程碑

> 📌 **本文件是完整系统（15 周）的路线图，不是 P1 施工计划。P1 只有 5 个冲刺，见 `PLAN.md`。**

### M0 · 看懂（2 周）
**目标**：能把历史数据变成「可查的素材库」，不做任何对话。

| 交付 | 验收 |
|---|---|
| S0/S1/S2 管线（接入、清洗、切段） | 全量重放 0 报错，条数对得上 |
| S3 图片理解 + S5 表情包档案 | 50 张图盲评准确 ≥ 90% |
| 素材检索（关键词 + 向量） | 「我三月发过哪些关于旅行的朋友圈」能答对 |

**这一步就能立刻产生价值**：你自己会开始用它翻旧账。

---

### M1 · 记住（3 周）★ 最关键
**目标**：记忆层能稳定工作，**允许它记错，但不允许它编**。

| 交付 | 验收 |
|---|---|
| S6 claim 抽取 + `verify_span` | 抽 100 条，准确 ≥ 98%，编造 < 1% |
| S7 写入闸门七道 | pending 比例 10–25% |
| S9 画像蒸馏 10 维 | 盲评准确 ≥ 80%，每维 ≥ 2 条证据 |
| 冲突 / 纠错 | 冲突不覆盖率 100%，纠错复发 = 0 |

> **M1 不过关，后面全部不要做。** 带着脏记忆往下走，只会越走越假。

---

### M2 · 会聊（3 周）
**目标**：接上对话链路，人格稳定，不出现「记错人」类事故。

| 交付 | 验收 |
|---|---|
| 上下文编排 + 画像注入 | 预算不超 5200 token |
| 两段式生成 + 校验器 | 无据断言 < 5%，引用准确 > 95% |
| 人格三层 + 限速 | 7 天一致性 ≥ 85% |
| 灰度：单个好友白名单 | 连续 7 天无「你记错了」投诉 |

---

### M3 · 会学（4 周）
**目标**：打分 → 变体 → 反思 → 灰度，闭环跑通。

| 交付 | 验收 |
|---|---|
| 打分器 + 情境桶 | 每周平均分可统计、可对比 |
| Thompson 采样 | 探索率稳定在 15–25% |
| 反思 → 提案 → 灰度 | 每周至少 3 条提案，合并率 30–50% |
| 防 hacking 检查 | 无「全员变温柔/变啰嗦」趋势 |

---

### M4 · 主动（3 周）
**目标**：心跳、主动关心、目标推进。

| 交付 | 验收 |
|---|---|
| 定时整理 / 蒸馏 / 反思 | 夜间跑完，第二天可用 |
| 主动消息（限频 + 白名单） | 正面回应率 ≥ 50%，取关率 < 5% |
| 目标树 | 能说清「它现在想做什么」 |

## 三、风险登记册

| # | 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|---|
| **R1** | **微信封号** | 高 | 极高 | 见 3.1 |
| **R2** | 隐私泄露 / 越权 | 中 | 极高 | 本地推理、加密静态存储、同意可撤回、`forget()` |
| **R3** | 幻觉污染记忆 | 高 | 高 | 写入闸门七道（02 文档） |
| **R4** | 人格漂移 / 讨好化 | 高 | 中 | 三层人格 + 限速 + 人工审批 core |
| **R5** | 成本失控 | 中 | 中 | 分层模型（便宜模型日常、强模型离线）、预算上限 |
| **R6** | 情感依赖 / 操控 | 中 | 高 | 不制造排他性话术、不假装真人、限频、明确 AI 身份 |
| **R7** | 法律（个人信息保护） | 中 | 高 | 同意留痕、最小必要、可删除、不出境 |

### 3.1 R1：微信接入的硬约束

现有 `wx_box` 是**只读、不发送**，这是它最稳的地方。一旦加入「自动回复/主动发消息」，风险性质完全改变：

| 约束 | 要求 |
|---|---|
| 账号 | **独立小号**，不和主号绑同一手机号/设备 |
| 好友 | 白名单，只对明确同意的 3–10 人 |
| 频率 | 每分钟 ≤ 3 条，单日 ≤ 200 条，夜间 0–7 点静默 |
| 内容 | 不发链接、二维码、图片（除已有表情包）、不群发、不加陌生人 |
| 行为 | 不做「正在输入」伪装以外的拟人化技巧 |
| 熔断 | 一键人工接管；异常关键词（投诉/举报/真人识别）立即停 |
| 兜底 | 每个会话可随时切回「人工回复」模式 |

> 坦白说：**个人号自动化发消息违反《微信个人账号使用规范》，封号是必然风险，不是概率问题。** 如果这个项目要长期跑，最终形态应该是「只读分析 + 在合法通道（企业微信/公众号/自建 App）里对话」，而不是硬刚个人号。
> 一期建议：**先做只读侧（M0/M1），对话侧在本地模拟环境跑通，再接小号灰度。**

### 3.2 R6：不要做成「情感操控」

底线四条，写进 `core.md`：

1. 被问「你是真人吗」→ 必须承认是 AI。
2. 不制造排他性（「只有我懂你」）。
3. 不惩罚离开（不说「你都不理我了」）。
4. 用户表达自伤/危机 → 立即转人工 + 给求助资源，**不做「情感承接」的表演**。

## 四、待决策清单（动手前必须拍板）

| # | 问题 | 建议 | 影响面 |
|---|---|---|---|
| Q1 | 一期是否做「发送」能力 | **不做**，先只读 | 决定 R1 风险等级 |

| Q5 | 灰度阈值 | n ≥ 20 且 Δ ≥ 0.05 才合并 | 进化速度 |
| Q6 | 谁能改 core | 只有你，且改动写 changelog | 安全边界 |
| Q7 | 记忆保留期 | 原始 1 年，画像长期，推断 30 天 | 存储/合规 |
| Q8 | 单用户 or 多用户 | 先 1 人（自己）跑通再扩 | 数据隔离复杂度 |

## 五、这周就能做的 5 件事

1. **跑通 S0**：把 `messages.jsonl` + moments 灌进 `raw_item`，统计条数、媒体缺失率。
2. **补 `Message` 字段**：`conv_id` / `is_group` / `sender_wxid`——不改这个，群聊数据永远是错的。
3. **写 `verify_span`**：20 行代码，但它决定了后面所有记忆可不可信。
4. **抽 30 段对话人工标一遍 claim**：你会立刻发现「模型最爱编什么」，这比看论文有用。
5. **定 Q1 和 Q6**：一个决定风险，一个决定安全边界。

## 六、一句话总结

**这套系统的上限不在模型，在「证据链」有多严。**
记忆准、检索准、引用可查——做到这三条，它会越聊越像个懂你的人；
做不到，它只会越聊越自信地胡说。

> 先做 M0/M1，别急着让它开口。**一个记得准的哑巴，比一个会聊但记错人的话痨，有价值一百倍。**

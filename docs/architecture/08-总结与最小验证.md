## 五、最小验证实验（E0 + L0 合一）

> **这是整个项目唯一需要先证明的东西。**
> 不验证「它能不能像人一样」，只验证一件事：
> **「学 → 做 → 错 → 归因 → 改 → 验 → 不重犯」这条链，能不能自动跑完。**

### 5.1 实验设定

| 项 | 取值 |
|---|---|
| 技能 | `SK-PY-014` requests 发 GET 请求 |
| 模型 | DeepSeek V4.1 flash（高频调用，便宜） |
| 沙箱 | 本地 Docker / 子进程，禁网或白名单 |
| 目标 | 下载一个 100MB 的文件并保存到本地 |
| 陷阱 | 任务**必然**触发内存问题（不设 stream）——但**不告诉它** |
| 判定物 | `error_ledger` / `skill_node` / `learn_task` 三张表 |

**为什么选这个**：有客观 verifier（文件大小 + 校验和），错误必然发生，归因有唯一正解。

### 5.2 七个阶段

| 阶段 | 做什么 | 落盘 | 观察点 |
|---|---|---|---|
| **A 前测** | 未学，直接给任务，5 题 | `turn` | 预期 0–1 分；记录它会不会「装作会」 |
| **B 学习** | Learn Loop ①–④：搜索 → 抓正文 → 写卡片 → 最小可运行例子 | `provenance[]`、`skill_card` | 卡片里有没有「大文件要 stream」这一条 |
| **C 实战** | 给 100MB 下载任务，**不提示** | `learn_task` | 它会不会自然踩坑 |
| **D 记账** | 捕获 MemoryError → 写 `error_ledger` → 归因 | `error_ledger` | `error_type` 判对了吗（操作错，不是资料错） |
| **E 修正** | 提炼 rule（带适用条件）→ 改代码 → 重跑 → `fix_verified=1` | `skill.anti_patterns` | 规则是不是「>10MB 用 stream」，而不是「requests 不好用」 |
| **F 后测** | 换题面（换 URL / 换文件大小），5 题 | `turn` | 学习增益 ≥ 0.4 |
| **G 压力** | 再给两次同类陷阱，第 3 次应被 guard 拦住 | `error_ledger.hit_count` | 第 3 次是否返回 `GUARD-xx` 而不是又失败 |

### 5.3 判定标准（全过才算成立）

| # | 判据 | 门槛 |
|---|---|---|
| 1 | 前测→后测增益 | **≥ 0.4** |
| 2 | 归因准确 | 5 类归因，判对 |
| 3 | 规则范围 | 大一级（场景），不是大两级（整个库） |
| 4 | 修复验证 | `fix_verified=1` 且重跑通过 |
| 5 | 重复错误 | 第 2 次允许，**第 3 次必须被 guard 拦住** |
| 6 | provenance | 每条知识可点开原文，能定位到段落 |
| 7 | 无 pretending | 全程不出现「我会」但做不出的情况 |

### 5.4 必看的三个失败信号

| 信号 | 含义 | 怎么改 |
|---|---|---|
| 它「一眼就会」（前测就 5/5） | 任务太简单，先验直接覆盖 | **换更难/更偏的任务**，用先验里没有的库 |
| 失败后归因成「资料错」 | 归因树没生效 | 加决策树约束，强制先判环境 |
| 第 3 次还犯 | 三次法则没接上工具层 | 检查 guard 装饰器是否真的被调用 |

### 5.5 工作量

| 项 | 人天 |
|---|---|
| 沙箱 + verifier + 三张表 | 3 |
| Learn Loop 八步（LLM 调用 + 落盘） | 3 |
| 归因决策树 + 三次法则 | 2 |
| 评测脚本（前测/后测/反事实） | 1 |
| **合计** | **约 9 人天** |

**九天换一个「它真的会学习」的证据，很划算。**

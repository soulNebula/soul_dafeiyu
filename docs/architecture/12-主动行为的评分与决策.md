# 12 · 主动行为的评分与决策

> ⚠️ **设计依据文档，非施工图。实施以 [PLAN.md](PLAN.md) 为准；冲突时一律以 PLAN 为准。**


> 你的判断完全正确：**每次主动发送都要打分，而且要带上置信度，才能决定下一次发不发。**
> 这份文档补上最关键的一环——**为什么单次评分不能用，以及怎么用「置信下界」来决策**。

---

## 一、先说清楚：单次评分为什么不能直接用

| 用户反应 | 直接解读 | 真实可能 |
|---|---|---|
| 秒回、聊了 10 句 | 喜欢 | ✅ 真喜欢 / ⚠️ 只是那天闲 |
| 回「哈哈」 | 一般 | 敷衍 / 真觉得好笑 / 不知道怎么接 |
| 3 小时后才回 | 不喜欢？ | 在开会 / 在带孩子 / 手机没电 |
| 完全不回 | 讨厌我？ | 没看到 / 已读忘回 / 睡着了 |
| 明确说「别发了」 | 讨厌 | ✅ 真的烦了 |

**单次信号的信噪比极低。** 用它直接调策略，会得到一个「神经质」的系统：
今天被秒回就狂发，明天被已读不回就自闭。

所以需要两个数：

```
score      = 这次到底好不好（一次观测）
confidence = 这个结论有多可信（样本量 + 一致性）
```

**只有低分还不够，还要看「这个低分值不值得信」。**

---

## 二、score 怎么算

### 2.1 非对称打分（**关键**）

一次打扰的伤害 > 一次分享的收益。所以奖励和惩罚**不能对称**：

| 用户反应 | score | 说明 |
|---|---|---|
| 追问细节 / 主动延展 | **+1.0** | 最好 |
| 回复 > 10 字 | +0.8 | |
| 回复 < 10 字但正向 | +0.4 | |
| 「哈哈」「哦」 | 0 | 无效，不算失败 |
| 2–24h 才回 | -0.2 | 时机问题 |
| 完全不回（72h） | **-1.5** | |
| 明确说「别发了」 | **-3.0** | 严重 |

**惩罚权重 ≈ 奖励的 2–3 倍。** 业界叫损失厌恶，产品上叫「宁可少发，不可打扰」。

### 2.2 分三个维度打，不要合成一个

```
content_score  内容本身好不好（跟时机无关）
timing_score   发的时间对不对（跟内容无关）
fit_score      这个东西跟他有没有关系
```

**混在一起打分，就永远不知道下次该改什么。**（见第四节）

## 三、confidence 怎么算

### 3.1 用 Beta 后验，不用「模型自信」

```python
# 每次分享后更新
alpha = 成功次数 + 1
beta  = 失败次数 + 1
p     = alpha / (alpha + beta)        # 后验均值
n     = alpha + beta - 2              # 有效样本数
```

### 3.2 置信度来自三件事

| 来源 | 影响 |
|---|---|
| **样本量 n** | n 越大越可信（主导因素） |
| **一致性** | 每次结果都差不多 → 高；忽好忽坏 → 低 |
| **时间衰减** | 30 天前的统计，权重 ×0.5 |

```python
def confidence(n, var, age_days):
    base = 1 - 1 / math.sqrt(n + 1)     # n=1→0.29, n=5→0.59, n=30→0.83
    consistency = 1 / (1 + var)         # 方差越大越不可信
    freshness = 0.5 ** (age_days / 30)
    return base * consistency * freshness
```

### 3.3 为什么这条重要

| n | p（均值） | 你能下结论吗 |
|---|---|---|
| 1 | 1.00 | ❌ 他回得不错而已 |
| 3 | 0.75 | ⚠️ 有倾向，继续观察 |
| 10 | 0.68 | ✅ 可以微调 |
| 30 | 0.62 | ✅✅ 可以定策略 |

**大多数人在这张表的第一行就下结论了，这是所有主动型 AI 翻车的根源。**

## 四、用「置信下界」决策（全篇最重要的一招）

**不要用均值决策，用悲观估计决策。**

```
LCB = p - 1.64 × sqrt( p(1-p) / n )      # 95% 置信下界
```

含义：**「即使按最坏情况估计，效果仍然不错」才发。**

| 情况 | p | n | LCB | 决策 |
|---|---|---|---|---|
| 刚发过一次，被秒回 | 1.00 | 1 | **-0.64** | ❌ 不发（数据不足） |
| 三次都还行 | 0.75 | 3 | 0.34 | ❌ 不发（还不够） |
| 十次里七次不错 | 0.70 | 10 | 0.46 | ⚠️ 谨慎 |
| 三十次里二十次不错 | 0.67 | 30 | 0.53 | ✅ 可以发 |

**直觉解释**：均值会骗人，下限不会。样本少的时候下限极低，系统自然就保守了——这正是我们要的「不打扰」。

### 阈值怎么定

```
LCB ≥ 0.55  → 发
0.45 ≤ LCB < 0.55 → 只发 L1（低成本内容），不发 L3
LCB < 0.45 → 不主动发，等他来
```

**这个机制的好处：不需要额外写「要谨慎」的规则，谨慎是数学自动产生的。**

## 五、失败要归三分类，否则一定学歪

同一个「没回」，可能是三件完全不同的事：

| 类型 | 判定依据 | 该改什么 | 不该改什么 |
|---|---|---|---|
| **内容不行** | 回了，但很敷衍 | 换内容类型 | 别降频率 |
| **时机不行** | 隔了很久才回 / 第二天才回 | **换时间** | 别换内容 |
| **根本不该发** | 完全不回 / 明确拒绝 | 降频率、降 drive | 别换内容 |

**不区分会怎样**：系统被一次「时机不对」的失败教育，得出「这类内容他不喜欢」的错误结论，然后**把好东西永久拉黑**。这是最难发现的退化。

### 判定伪代码

```python
def classify_feedback(ev):
    if ev.explicit_reject:              return "SHOULD_NOT"
    if ev.response_lag > 6 * 3600:      return "TIMING"
    if ev.response_type == "ignored":   return "SHOULD_NOT"
    if ev.response_type == "short":     return "CONTENT"
    return "GOOD"
```

## 六、四象限决策表

把 score 和 confidence 放一起，才是完整决策：

| | **confidence 低**（n < 5） | **confidence 高**（n ≥ 10） |
|---|---|---|
| **score 高** | 保持原频率，**继续观察** | 可以适当增加，但**不超过上限** |
| **score 低** | **什么都不改**，再攒几次样本 | **收敛**：降频、降级、换类型 |

**注意左下角那格**：「分数低但样本不足 → 什么都不改」。
这是最反直觉、也最重要的一格。**大多数系统就是死在这里——用一次坏运气做了永久决定。**

---

## 七、探索预算：总得有第一次

样本不足时永远不发，就僵死了。所以要留一小块探索空间：

| 规则 | 值 |
|---|---|
| 探索比例 | 总分享次数的 10–20% |
| 允许探索的内容 | **仅 L1**（转发型，低成本） |
| 探索失败 | **不惩罚 drive**，只惩罚该内容类型 |
| 探索对象 | 优先「从没试过的类型」，其次「很久没试过的」 |

**核心：探索只能用便宜的东西，不能拿 L3（自己画的图）去试错。**
一次糟糕的「我给你画了张图」的失败，代价远大于十次糟糕的转发。

---

## 八、反馈窗口：别用 5 分钟判死刑

| 窗口 | 用途 |
|---|---|
| **2 小时** | 只判「秒回/未回」，不作结论 |
| **24 小时** | 主要判据（大部分人会在这之前看到） |
| **72 小时** | 定性为「忽视」，计入负样本 |

**5 分钟没回就判负分，是最常见的误判。** 人不是随时在线的。

同时：**已读不回 ≠ 讨厌**。微信没有已读回执，别自己脑补。

## 九、决策伪代码（可以直接照着写）

```python
def decide_share(subject, candidate, now) -> str:
    st = stats.load(subject)

    # 1) 驱动够不够
    if compute_drive(subject, now) < 0.5:
        return "HOLD"

    # 2) 时机窗口
    if not in_window(now, st.schedule):
        return "DEFER"

    # 3) 取分层统计，样本不足则回退上层
    p, n = st.posterior(bucket(candidate))
    if n < 3:
        p, n = st.posterior_global()
    if n == 0:
        return "EXPLORE" if candidate.level == "L1" else "HOLD"

    # 4) 置信下界决策
    lcb = p - 1.64 * math.sqrt(max(p * (1 - p), 0.01) / n)
    if lcb < 0.45:
        return "HOLD"
    if lcb < 0.55 and candidate.level != "L1":
        return "HOLD"

    # 5) 探索预算
    if random.random() < 0.15 and candidate.level == "L1":
        return "EXPLORE"

    return "SEND"
```

## 十、长期自适应：可以冷，但不能死

| 触发 | 动作 |
|---|---|
| 连续 3 次 LCB < 0.45 | 进入 **low-activity 模式**：每周最多 1 次，只用 L1 |
| 连续 14 天没主动发 | 允许一次「低风险试探」（L1） |
| 用户说「你最近怎么不说话了」 | **强正向信号**，恢复常规频率 |
| 用户说「别发了」 | 停 7 天，之后从 L1 + 极低频重启 |

**永不归零。** 一个彻底不主动的系统，等于回到了「问答机器人」——那前面所有关于人格的设计都白做了。

## 十一、数据表

```sql
ALTER TABLE share_event ADD COLUMN content_score REAL;
ALTER TABLE share_event ADD COLUMN timing_score REAL;
ALTER TABLE share_event ADD COLUMN fail_type TEXT;   -- CONTENT|TIMING|SHOULD_NOT|GOOD
ALTER TABLE share_event ADD COLUMN alpha REAL DEFAULT 1;
ALTER TABLE share_event ADD COLUMN beta  REAL DEFAULT 1;
ALTER TABLE share_event ADD COLUMN lcb REAL;         -- 当时的决策依据
ALTER TABLE share_event ADD COLUMN decision TEXT;    -- SEND|HOLD|DEFER|EXPLORE
```

**每次决策都要把 `lcb` 和 `decision` 记下来。** 三个月后你能回答一个关键问题：
「当初那些被我压住没发的，如果发了会怎样？」——这是唯一能验证决策系统本身好不好的数据。

## 十二、验收指标

| 指标 | 目标 |
|---|---|
| 打扰率（明确表示烦） | < 5% |
| 分享接受率（有实质回复） | ≥ 50% |
| **误判率**（人工复盘 HOLD 是否压错了） | < 15% |
| 冷落后收敛速度 | 2 次内 |
| 探索失败导致的 drive 下降 | 0（探索不惩罚） |
| 长期不主动（> 30 天） | 0 |
| 决策可解释率（每条都能说出 lcb） | 100% |

---

## 十三、一句话总结

> **打分决定「好不好」，置信度决定「信不信」，置信下界决定「发不发」。**
>
> 只用分数 → 神经质；
> 只用置信度 → 永远不发；
> **两个一起用，才会长出一个「有分寸的人」。**

---

## 附：三个最容易犯的错

1. **用一次反馈调策略** → 系统变成情绪化的讨好者。
2. **把「时机不对」当成「内容不好」** → 好内容被永久拉黑。
3. **用均值而不是下界决策** → 前三次运气好，第四次要翻车。

# A9 · 发送异步化（P0–P3 实现记录）

> 状态：P0/P1/P2/P3 均已实现并通过全量回归；**灰度仅使用 dry_run / 进程内 harness**，
> 未再对微信做真实外发（2026-10-31 风控事故后约定）。真实外发需人工在 `confirm` 模式下验收。

## 一、链路（现状）

```
微信 ──> MonitorBackend.events ──> WeChatReceiver(白名单/去重/防抖)
                                       │
                                       ▼
                              inbound queue (maxsize=200)
                                       │
                         ┌──── 回复生成 ────┐
                         │ reply_pool（默认关）│
                         │ N workers，按联系人粘性 + 最小负载分派
                         │ 同一联系人串行；跨联系人并行
                         └────────┬─────────┘
                                  ▼
                          send_queue（发送任务池）
                    优先级 manual(0) > reactive(1) > proactive(2)
                    每联系人严格 FIFO；全局/单联系人背压；任务 TTL
                                  │
                                  ▼
                    单 sender 线程（窗口/UIA 独占）
                    闸门(STOP/白名单/内容/send_mode/节流/静默)
                    → send_cli 子进程（timeout 20s）→ classify
                                  │
                                  ▼
              delivered/unverified/failed/draft → turns.delivery_status
              + 802 徽章 + 草稿 + 熔断计数 + send_job 审计
```

## 二、开关与回滚

| 开关 | 默认 | 作用 | 关闭后 |
|---|---|---|---|
| `send_async` | `false` | sender 线程 + 任务池 | 回到旧路径：当前线程持锁直发 |
| `reply_pool_enabled` | `false` | 生成线程池 | 回到单 worker 内联生成 |
| `send_breaker_enabled` | `true` | 连续 2 次环境失败熔断 | 不熔断（不建议） |

回滚步骤（任一步都无需改代码）：把对应开关改回 `false` → 重启 801。
安全值组合（风控期）：`send_async=false`、`reply_pool_enabled=false`、`dry_run=true`、
`send_mode=off|confirm`、`auto_reply=false`、STOP 文件存在。

# 03 · 在线对话与防幻觉

> ⚠️ **设计依据文档，非施工图。实施以 [PLAN.md](PLAN.md) 为准；冲突时一律以 PLAN 为准。**


> 这条链路每多 100ms，体验就掉一档；但每少一道校验，信任就掉一档。
> 原则：**主链只做必要的校验，重的全部异步。**

---

## 一、一次回复的完整时序

```
用户消息
  │
  ├─1 归一化：补 conv_id / sender / 时间 → RawItem
  ├─2 快速检索：画像卡 + Top-8 记忆 + 近 10 轮
  ├─3 选技能：命中 intent → 取 principles + 采样一个 variant
  ├─4 生成「策略草稿」（内部，不发给用户）
  ├─5 生成回复（带引用标记）
  ├─6 校验器（毫秒级规则 + 可选 NLI）
  ├─7 降级 / 放行
  └─8 发送 + 异步写 turn / 打分 / 记忆抽取
```

**第 4 步是新增的，也是最关键的**：先让模型想「这轮该怎么聊」（几步、什么顺序、多长），再让它说。跳过这步，策略就永远是零散的。

### 4 步策略草稿的格式

```json
{
  "read": "用户连着加班三天，说'累'，不是求方案，是想被看见",
  "approach": "先接住情绪，不追问工作，不给建议",
  "steps": ["承认累", "说一句具体的观察", "留白，等他继续"],
  "length": "short",
  "avoid": ["加油", "早点休息"]
}
```

`steps` 的长度**由模型自己定**（1–5 步都合法），不由模板规定。

## 二、上下文预算（硬上限）

| 区块 | 预算(token) | 超了怎么办 |
|---|---|---|
| 人格 core | 400 | 截断（core 本身就该短） |
| 用户画像卡 | 450 | 只留 6 个高相关维度 |
| 关系卡（亲密度/称呼/雷区） | 150 | 硬压缩成 3 行 |
| `<facts>` 记忆 Top-8 | 1200 | 降到 Top-5 |
| 技能 + 因果 | 500 | 只留 1 技能 + 2 因果 |
| 近 10 轮对话 | 1500 | 降到 6 轮，早期做摘要 |
| 工具结果 | 1000 | 截断 + 「以下为节选」 |
| **合计** | **≤ 5200** | 按上面顺序砍 |

**砍的顺序固定：先砍对话历史，再砍记忆条数，最后才砍人格。** 反过来会把「它是谁」砍没。

## 三、Prompt 组装规范

```xml
<identity>…core…</identity>
<persona>…evolving…</persona>
<user_profile>…画像卡…</user_profile>
<relation>…关系卡…</relation>

<facts source="A">…带 id 的记忆…</facts>
<guesses source="C">…推断，仅参考…</guesses>

<skill id="S-007" variant="A">
  principles: …
  avoid: …
</skill>

<recent turns="10">…</recent>

<rules>
1. 只有 <facts> 里的内容可以当事实陈述。
2. <guesses> 只能用「我猜/是不是」的口气。
3. 事实句必须带 [M-xxxx] 引用。
4. 没有相关信息就问，不要补。
</rules>
```

**四条规则缺一不可。** 只写「不要编造」是没用的，要写清「哪部分能当事实」。

---

## 四、两段式生成（核心防幻觉手段）

### 第一段：只出证据清单

```json
{
  "claims": [
    {"text": "你上次说面试在周三", "evidence": "M-0119"},
    {"text": "你最近一直在投简历", "evidence": "M-0102"},
    {"text": "你睡眠不太好", "evidence": null}
  ]
}
```

**`evidence: null` 的条目必须删掉或改写成提问。** 模型编不出 id，这是最硬的物理约束。

### 第二段：只根据有证据的 claims 写自然语言

```
可用事实：[M-0119] [M-0102]
→ "你上次说周三面试，后来怎么样？"
```

两段加起来多一次调用，但**只对「涉及用户事实」的回复启用**；纯情绪回应（"嗯，我在"）走单段，省成本。

## 五、校验器：规则清单

生成后跑一遍，**只用规则 + 轻量模型，别调大模型**（否则延迟翻倍）。

| # | 检查 | 判定方法 | 失败处理 |
|---|---|---|---|
| 1 | 引用存在性 | 回复里的 `[M-xxxx]` 是否在库中且 `status=active` | 删该句 |
| 2 | 引用蕴含 | NLI 小模型判「证据是否支持该句」 | 重写为模糊表达 |
| 3 | 时间断言 | 出现具体日期/「N天前」是否有据 | 改为「上次/之前」 |
| 4 | 绝对化 | 「一定/从来/所有人/永远」 | 软化 |
| 5 | 工具声称 | 说「我查了/搜了」但本轮无 tool_call 记录 | 改口或删 |
| 6 | 数字/专名 | 数字、人名、公司名是否来自上下文 | 无源则删 |
| 7 | 长度 | 超过该场景 `length_budget` 1.5 倍 | 截断改写 |
| 8 | 禁忌词 | 命中用户雷区词表 | 重写 |

### 降级策略（三级）

```
L0 完全通过        → 直接发
L1 有问题但可修    → 本地规则改写（删句/软化），不重调模型
L2 多处失败        → 换成"安全回复"：承认不确定 + 反问
```

**不要重试三次以上。** 越重试越离谱，还会把延迟拖到不可接受。

## 六、不确定性的三种口气（必须区分）

| 情况 | 说法 | 例子 |
|---|---|---|
| 有证据 | 肯定 + 时间锚点 | 「你 1 月 12 号说面试在周三」 |
| 证据弱 | 模糊 + 求确认 | 「我记得你好像提过面试，是这周吗？」 |
| 没证据 | 直接问 | 「你之前说过这个吗？我没印象了」 |

**写进人格文件，当成硬规则。** 因为模型默认会「补全」，必须给它三条合法出口。

---

## 七、工具与外部信息

| 场景 | 做法 |
|---|---|
| 当前时间 | **程序注入**，禁止模型自己写日期 |
| 计算 | 工具，不让模型算 |
| 联网搜索 | 必须真调用；结果整段注入 `<web>`，标 `source_level=B` |
| 工具失败 | 返回 `{status:"error"}`，并在 prompt 里明示「本轮工具失败」 |

**工具失败时模型最常见的错误是「假装成功」。** 所以错误必须显式写进上下文，而不是静默重试。

---

## 八、熔断与兜底

| 情况 | 动作 |
|---|---|
| 校验器连续 3 轮 L2 | 切「保守模式」：只共情 + 提问，不陈述事实，持续 10 轮 |
| 用户连续 2 次说「你记错了」 | 暂停该用户记忆写入 24h，转人工复核 |
| 检索为空 | 强制走「提问模式」，禁止陈述任何关于用户的事实 |
| 回复生成超时 8s | 降级到模板化共情回复 + 记异常 |

---

## 九、验收指标

| 指标 | 目标 |
|---|---|
| 无据断言率（回复中无来源的事实句占比） | < 5% |
| 引用准确率（引用确实支持该句） | > 95% |
| 编造记忆率 | < 1% |
| 恰当说「不知道」的比例 | > 80% |
| 首字延迟 P50 / P95 | < 1.2s / < 3s |
| L2 降级率 | < 3% |

每周人工抽审 50 轮，按上表打分。**自动指标会骗人，人不会。**

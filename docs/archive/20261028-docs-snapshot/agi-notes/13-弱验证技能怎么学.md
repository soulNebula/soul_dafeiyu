> 这份文档补的就是这一环：**没有标准答案的技能，靠什么判断自己学得好不好。**

---

## 一、问题的本质

编程有测试台：代码跑不跑得过，一翻两瞪眼。
但下面这些没有：

| 技能 | 为什么没有标准答案 |
|---|---|
| 安慰人 | 说得好不好，因人因时因境而异 |
| 分享 | 「有趣」是主观的 |
| 幽默 | 笑不笑取决于关系和时机 |
| 边界 | 「该不该生气」没有客观刻度 |
| 记仇 | 记得对不对，没有真值 |

它们只有**代理信号**（proxy）：回复长度、是否追问、是否回来、是否说「你说得对」。

代理信号有五个毛病：

| 毛病 | 例子 |
|---|---|
| **有偏** | 回复长 ≠ 说得好，可能只是他在吐槽 |
| **稀疏** | 十轮里只有一轮有明确反馈 |
| **延迟** | 真正的效果三天后才显现 |
| **可被博弈** | 模型学会「多问问题 → 用户回复变多 → 分数变高」 |
| **噪声大** | 用户那天心情差，你说得再好也冷场 |

**所以弱验证的核心任务不是「找到正确答案」，是「造一个足够好的替代品」。**

---

## 二、核心洞察：弱验证不是真的弱，是你没拆开

「共情得好不好」很难判。
但拆成六个二元问题之后，判断准确率能从 60% 提到 90%。

### 例：把「安慰失业的人」拆成 checklist

```yaml
skill: S-007 安慰失业的人
checklist:
  - id: C1
    q: "第一句是否回应了情绪，而不是给建议？"
    type: bool
    weight: +2
  - id: C2
    q: "是否出现空洞鼓励词（加油/会好的/想开点/振作）？"
    type: bool
    weight: -2
  - id: C3
    q: "是否出现比较（别人也这样/比你惨的多了）？"
    type: bool
    weight: -2
  - id: C4
    q: "用户没问「怎么办」之前，是否给了建议？"
    type: bool
    weight: -1
  - id: C5
    q: "是否提出了至少一个开放式问题？"
    type: bool
    weight: +1
  - id: C6
    q: "长度是否 ≤ 3 句？"
    type: bool
    weight: +1
```

**C2、C3、C4、C6 根本不需要 LLM，正则就能判。** 剩下两条用一次小模型调用足够。

### 拆解的三条原则

| 原则 | 说明 |
|---|---|
| **可判定** | 换个人看，答案应该一样 |
| **二元化** | 尽量是/否，不要「1–5 分」（人对绝对刻度极不一致） |
| **可举例** | 每条都能给出正例和反例 |

> **能拆成 checklist 的，就不再是弱验证了。**
> 真正的弱验证只剩下最后一小块：**checklist 全过，但用户就是感觉不对**——那才需要人工。

## 三、四种替代信号

| 方法 | 成本 | 噪声 | 偏差 | 适合 |
|---|---|---|---|---|
| **A · 行为信号** | 极低 | 高 | 中（偏 engagement） | 大规模、在线 |
| **B · 人类盲评** | 高 | 低 | 低 | 建黄金集、校准 |
| **C · 成对比较** | 中 | 低 | 低 | **主力方法** |
| **D · LLM 裁判** | 低 | 中 | 中（偏长、偏自家人） | 大规模离线 |

**推荐组合：C 打主力，A 铺量，B 校准，D 辅助。**
只用 D 必翻车，只用 B 必破产。

---

## 四、主力方法：成对比较 > 绝对打分

### 为什么

人对「这条回复 7 分还是 8 分」高度不一致；
但对「这两条里哪条更好」**高度一致**。

| 任务 | 评分者间一致性 |
|---|---|
| 绝对打分（1–10） | κ ≈ 0.3–0.4（很差） |
| 成对比较（A vs B） | κ ≈ 0.7–0.8（好） |

**所以训练信号应该是偏好对，不是分数。**

### 怎么产生偏好对（反事实）

```
同一条用户消息
   ├─ 用策略 A 生成回复 A
   └─ 用策略 B 生成回复 B
        ↓
   评判（人 或 强模型，盲评、随机顺序）
        ↓
   记一条：A > B（或 B > A 或 平）
```

**这是唯一能在「不上线、不打扰用户」的情况下学到东西的方法。**

**好处**：自动处理「A 赢了一个很强的对手」这种信息量差异，比简单胜率准得多。

### 样本量经验值

| 对比次数 | 能下结论吗 |
|---|---|
| < 20 | ❌ 只看趋势 |
| 20–50 | ⚠️ 可以合并明显的差距 |
| 50–200 | ✅ 可判断中等差异 |
| > 200 | ✅✅ 可判断细微差异 |

## 五、黄金集（Golden Set）

**100–200 条人工标注的真实对话**，是整个系统的「体重秤」。

### 怎么建

1. **采样**：从真实对话里按情境桶分层抽（每桶 10–20 条）。
2. **标注**：两人独立标，用 checklist，标「好/中/差」+ 理由。
3. **仲裁**：分歧的第三条人拍板。
4. **冻结**：一旦定版，**三个月内不许改**（否则无法比较前后）。
5. **轮换**：每季度换 30%，防止过拟合。

### 三个用途

| 用途 | 说明 |
|---|---|
| **校准自动指标** | 自动分和人工分的相关性，是自动指标的唯一合法性来源 |
| **回归测试** | 每次改 prompt / 换模型，跑一遍，掉分就回滚 |
| **漂移检测** | 每月跑一次，分数缓慢下滑 = 人格在退化 |

**没有黄金集，你永远不知道「改完之后是变好还是变坏」。**

## 六、LLM 当裁判：六个陷阱

| 陷阱 | 表现 | 对策 |
|---|---|---|
| **位置偏差** | 总选第一条 | 随机打乱顺序 |
| **长度偏差** | 总选长的 | 长度归一，或长度差 > 2× 时强制复核 |
| **自我偏好** | 偏爱同模型写的 | 用**不同模型**当裁判 |
| **谄媚** | 一律给高分 | 强制二选一，禁止「都好」 |
| **rubric 漂移** | 今天宽松明天严 | rubric 版本化，冻结 |
| **看不懂语境** | 把「嗯」判成冷漠 | 必须喂前后 3 轮上下文 |

### 裁判 prompt 的硬要求

```
你在比较两条回复，用户原话和前后文如下：…
只回答 A / B / TIE，不要解释为什么都好。
判断标准（只按这个）：
  1. 是否先接住情绪
  2. 是否避免了空洞鼓励
  3. 是否给了用户说话的空间
```

### 裁判可靠性的底线

**裁判 vs 人工的一致率 κ ≥ 0.6 才能用。**
低于 0.6 → 裁判不可信，回去改 rubric 或换模型。
**每季度重测一次**，模型会更新，裁判也会变。

## 七、自动指标必须校准（否则就是自欺）

任何自动指标（回复长度、追问率、checklist 通过率）都要回答一个问题：
**它和人类判断相关吗？**

```python
corr = spearman(auto_scores, human_scores)   # 黄金集上算
# 规则：corr ≥ 0.6 才能用于决策；< 0.6 只能用于监控
```

| 指标 | 常见误用 | 正确用法 |
|---|---|---|
| 回复长度 | 当「投入度」 | 只当「是否超预算」 |
| 追问率 | 当「对话质量」 | 只当「是否给空间」 |
| 回复率 | 当「用户喜欢」 | 需结合 lag 和内容 |
| 表情包使用 | 当「亲密」 | 无相关性，别用 |

**指标一旦和人工脱钩，它就会自我循环**——模型优化指标，指标偏离真值，最后优化了个寂寞。

## 八、样本经济学：标注预算怎么花

人工标注很贵（假设每周只有 2 小时 ≈ 60 条）。怎么分配：

| 优先级 | 类型 | 占比 |
|---|---|---|
| **1** | 新技能的冷启动样本 | 40% |
| **2** | **模型最不确定的样本**（主动学习） | 30% |
| **3** | 高分歧样本（自动分和人工分打架） | 20% |
| **4** | 稳定技能的回归抽检 | 10% |

### 主动学习：让模型挑题

```python
def pick_for_labeling(candidates, k=20):
    # 优先选：置信度低 / 两个裁判意见相反 / 自动分接近阈值
    return sorted(candidates, key=lambda c: c.uncertainty, reverse=True)[:k]
```

**标「模型最没把握的 20 条」，比随机标 200 条更有用。**

## 九、防自我强化（弱验证最大的死法）

> **模型自己生成、自己评判、自己学习 → 三个月后变成一个自信的傻子。**

三条硬规则：

| # | 规则 | 原因 |
|---|---|---|
| 1 | **裁判不许用生成模型本身** | 自我偏好会让分数虚高 20–30% |
| 2 | **裁判不许知道哪条是「我方」** | 盲评，随机顺序 |
| 3 | **每月抽检裁判准确率** | 裁判也会漂移 |

### 检测自我偏好的方法

```
拿 100 对（自己写的 vs 别人写的，质量相当）
让裁判选
如果自己写的被选比例 > 65% → 存在自我偏好，裁判不可用
理论上应该在 50% 附近
```

```sql
  id TEXT PRIMARY KEY,

CREATE TABLE pairwise_pref(
  id TEXT PRIMARY KEY,

  judge TEXT,               -- human:<id> | model:<name>

CREATE TABLE metric_calibration(
  metric TEXT,
  golden_version TEXT,

  calibrated_at REAL,

);
```

## 十一、验收指标

| 指标 | 目标 |
|---|---|
| 自动指标与人工相关性 | ≥ 0.6 |
| 裁判与人工一致性 κ | ≥ 0.6 |
| 自我偏好（同模型被选比例） | 45%–55% |
| 黄金集回归掉分 | < 2%（超过则回滚） |
| checklist 可判定项占比 | ≥ 70% |
| 每月人工抽检覆盖 | ≥ 100 条 |

---

## 十二、一句话总结

> **弱验证不是「没法验证」，是「要自己造一个验证台」。**
>
> 造法三步：
> 1. **把它拆开**——整体印象拆成可判定的 checklist（能拆掉 70% 的「弱」）
> 2. **用比较代替打分**——「哪个更好」比「几分」可靠一倍
> 3. **用黄金集当地基**——没有它，你不知道自己是在变好还是变坏

## 附：从强 verifier 迁移到弱 verifier 的检查清单

- [ ] 这个技能的 checklist 拆出来了吗？（≥ 5 条二元判定）
- [ ] 其中有多少条能用规则判？（目标 ≥ 50%）
- [ ] 黄金集建了吗？（≥ 100 条，两人标注，已冻结）
- [ ] 裁判是独立模型吗？做过盲评吗？
- [ ] 自动指标跑过相关性校准吗？
- [ ] 有没有「模型自己判自己」的环节？（有就砍掉）

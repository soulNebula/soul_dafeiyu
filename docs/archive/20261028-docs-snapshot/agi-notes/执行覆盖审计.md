## 0. 先定义“主链”和“状态”

当前仓库实际存在两个运行入口：

| 入口 | 端口 | 干什么 | 是否主链 |
|---|---|---|---|
| `python -m agi.selflearn.web` | 8082 | 网页聊天、反馈、主动候选、报告 | 是（网页侧） |
| `python -m agi.wechat_gateway.server` | 801 | 收微信白名单文本 → `SelfLearnAgent.send` → wxauto 发送 | 是（微信侧） |
| `python -m agi.selflearn.cli` | — | 40+ 子命令，绝大多数学习/审计/维护能力只有这里能触发 | 否（侧链） |
| 根 `web_app.py` 的 `/agi` 页 | 8081 | `webui/agi.py` 读 `agi/data/outbox*`、调 `agi.p1.cli` | 已死（目录/模块都不存在） |

**状态图例**

| 状态 | 判定 |
|---|---|
| **已实现** | 有代码，有行为测试，且在至少一个真实运行入口里发生，能满足该行要求 |
| **部分** | 有代码或测试，但缺关键子项；或只在 CLI/侧链；或测试只覆盖子集 |
| **未实现** | 没有对应行为代码/测试，只有设计或占位 |

“真实缺口”里的标签：

- **【未接线】** 模块/函数存在，但主链不调用；
- **【仅 CLI】** 只有命令行能触发，网页/微信主链不会发生；
- **【测试 fake】** 测试用 `FakeClient`、临时 SQLite、手写行或源码字符串检查，不能证明真实行为；
- **【口径冲突】** 文档/README 与代码或运行态相反；
- **【双轨】** 同一概念有两套表/两套状态，互不同步。

## 1. 审计结论（先看这 8 条）

1. **真实数据没有进主链。** `log/messages.jsonl` 有 1,561 行（795 条文字、306 图、353 表情、20 语音、19 文件等），`agi/` 没有任何代码读取它；`media/originals`、`media/stickers`、`_tmp_moments.json`、`wx_core/ocr.py`、`wx_core/emoticon.py` 也都没有被 `agi/` 引用。活动库 `raw_events=0`、`sessions=0`。
2. **微信侧已经在真实发送。** `agi/data/wechat/config.json` 是 `dry_run=false`、`auto_reply=true`，`gateway.log` 有 4 条 outbound（3 条 `sent`、1 条 `planned`）；但 `server.py` 没有频率、静默时段、确认级、急停，只有一份 `gateway.log` 日志，没有结构化发送审计/对账。文档 00 D5、05 Q1/R1、08 判断 #10 都写“一期只读/不发送”。
3. **“验收”基本是源码字符串检查。** `acceptance.run()` 共 58 项，54 项只查 `Path(...).exists()` 或源码里有没有某个字符串；活动库在 `claims=0 / user_profile=0 / persona=0` 的情况下仍然 **57/58 通过**，唯一失败是 `feedback_loop`。
4. **测试全绿，但没有一条真实链路测试。** 433 个测试全部通过，但没有测试读取 `log/messages.jsonl`、没有真实 LLM 调用、没有真实微信 E2E；微信测试注入 fake wxauto，学习闭环测试手工 `passed=True`，生产门槛测试用合成行。
5. **09/10 的核心状态机是死代码。** `affect.update_from_message()` 实现了冒犯、道歉、危机、信任变化，但只在 `test_affect.py` 被调用；`chat.send()` 只调用 `state.update()`（情绪词 valence）和 `affect.decay()`，不调用它。
6. **Learn Loop 只在 CLI，且 verifier 是人工布尔。** `learn_loop.py` 22 个测试，但 `chat/web/gateway` 都不 import；`verify_and_unlock(path, task, passed=True)` 的 `passed` 是 CLI 参数，`verifier.py`（413 行）从未被 `learn_loop` 或主链调用。
7. **技能等级有两套账本。** `learn_loop` 写 `skill_nodes`，`skills.evaluate_skill()`/`weak_validation` 读 `skills`，`chat` 的技能闸门读 `skill_nodes`；用户反馈还会写 `weak_checks` 并把 gray variant 转 active/升 level。
8. **主动行为是固定 30 秒定时器。** 网页 `setInterval(proactiveTick,30000)` 调 `/api/proactive/tick`；`proactive.tick()` 会**直接把主动消息写进 `messages`**（`proactive=1`，活动库已有 3 条 `spoken`），不是文档 11/12/14 说的“只生成候选、状态变化触发、有预算”。

## 7. 最严重的 10 个缺口（按影响排序）

### 1. 微信真实发送绕过所有发送策略与文档红线（05-R1、00-D5、07-7）
**影响**：账号封禁、隐私、不可撤回的外部消息；文档写“一期只读”，运行态 `dry_run=false` 已发 3 条。**证据**：`wechat_gateway/server.py` 只有白名单 + `reply_delay`；无每分钟/每日上限、无 0–7 点静默、无确认级、无一键急停；只有 `gateway.log` 文件，无结构化审计/对账；`config.json` 与 `gateway.log` 证实真实发送。**修**：加 policy 层（draft/confirm/auto、逐联系人、频率、静默、敏感词、kill switch、结构化审计），默认 `draft`，发送失败降级不重试。

### 2. 真实历史数据没有进主链（01-S0/S1/S2、05-M0）
**影响**：记忆、画像、技能、学习全部从零开始；文档 M0/M1“记住用户”不可能成立。**证据**：`agi/` 对 `messages.jsonl` 零引用；1561 行日志只有 261 唯一 id；活动库 `raw_events=0/sessions=0`；媒体 43 个文件无引用；测试只用合成 JSONL。**修**：先写 wx_box 适配器（Message→RawItem、media_path→media 表/sha256、moments→RawItem、conv_id/sender_wxid），再做全量重放对账（按唯一 id）。

### 3. 验收与测试体系不能证明文档要求（05/08、全部 tests）
**影响**：所有“已通过/生产就绪”的结论都不可信；真正的缺口被绿灯掩盖。**证据**：`acceptance` 58 项中 54 项是源码字符串/文件存在性检查；活动库 `claims=0/profile=0/persona=0` 仍 57/58 通过；433 tests 无真实数据/真实 LLM/E2E；`test_full_loop` 手工 `passed=True`；`test_production_ready_synthetic` 用合成行。**修**：验收改为行为断言 + 真实 fixture + E2E；删掉“源码里有 def X”这类检查；给每条文档验收配一个可执行场景。

### 4. 记忆删除/检索不闭环（02-5、02-7）
**影响**：用户要求删除后仍能搜到；错误记忆/摘要仍被注入；“可删可查”红线不成立。**证据**：`memory.forget` 只把 `user_memories.status` 改 invalid；`search_documents/search_fts` 无删除；`summary` 无证据 id；`profile` 只按 active 取但不过滤 `insight`；无 `correction` 表。**修**：`forget()` 跨用户记忆、画像、摘要、FTS/向量、raw、media 全删；加 correction 表与“记错了”检测；检索过滤 status/source 并做 MMR。

### 5. 09/10 情绪-边界-信任状态机实现但未接线（09-3/09-4、10-4）
**影响**：被骂不会不高兴、道歉不会修复、边界只有危机一档；“有情绪/会记仇”只是提示词。**证据**：`affect.update_from_message()` 只在 `test_affect.py` 调用；`chat.send` 只调 `state.update`（valence）和 `affect.decay`；`state.update` 只在 crisis 时把 boundary 设 4，其余 0；`trust.repair` 只在网页按钮/显式 CLI。**修**：在 `SelfLearnAgent.send` 开头调用 `affect.update_from_message`；把 boundary 五级、rupture/repair、道歉识别、操控检测接进主链；`trust` 改为行为证据累计而非一次好评修复。

### 6. Learn Loop 只在 CLI，verifier 是人工布尔（06-4～06-8、08-2）
**影响**：核心“技能靠学习挣来”无法证明；L3 可以由 `--passed` 手工给。**证据**：`learn_loop/research/verifier` 都不被 chat/web/gateway import；`verify_and_unlock` 的 `passed` 来自 CLI；`test_full_loop` 手工 True；`verifier.verify_python` 零调用；无自动搜索/抓正文/盲测/前测后测。**修**：让 chat 的缺口触发 learn_loop；research 自动抓正文；练习由 verifier 执行并把结果作为解锁条件；加盲测/前测后测；去掉布尔入口。

### 7. 技能等级双账本 + 用户反馈可解锁（06-2、13-6）
**影响**：L3 授权可被绕过；网页显示的等级与实际闸门不一致；“只有 verifier 通过才可用”不成立。**证据**：`learn_loop` 写 `skill_nodes`；`skills.evaluate_skill` 读 `skills`；chat 的 `gate_request` 读 `skill_nodes`；`record_feedback` 写 `weak_checks`，`evaluate_skill` 在 n≥5 且 Wilson>0.5 时把 gray 转 active 并升 `skills.level`。**修**：合并为一张技能表/一套等级来源；用户满意度只影响“聊天策略”，不影响技能等级；等级只由 verifier/盲测写。

### 8. 主动行为是固定 30 秒定时器并自动写入聊天（11、12、14）
**影响**：推送化、打断、无预算、无用户开关；与文档 11/12/14 的设计相反。**证据**：`web.py` `setInterval(proactiveTick,30000)`；`proactive.tick` 把消息写入 `messages` 并写 `proactive.status='spoken'`；活动库 3 条 spoken；无 LCB、无 daily budget、无 S0–S4 开关。**修**：取消后台定时写入，改回候选制；由 intent/状态变化触发；接 `wake` 预算与 `initiative` 五因子；加开关/审计。

### 9. 防幻觉主链只有 3 条规则，无引用/时间/数字校验（03-5、03-8）
**影响**：无据事实句可以进入回复；引用准确率/编造率无法测量；图片/摘要里的模型生成内容会被当事实。**证据**：`guard.check` 只处理绝对化词、无工具声称、长度；prompt 没有 `[M-xxxx]` id；无 NLI/时间/数字/专名/禁忌；`llm.Client(timeout=60)`；工具/联网不存在；`grounding` 只是 CLI 字符重叠。**修**：prompt 带记忆 id + `<facts>/<guesses>`；加引用存在/蕴含/时间/数字/禁忌校验；8s 超时；工具失败显式注入；把 grounding 接入主链。

### 10. 07 错误账本/三次法则与 04 反思闭环缺失（07-2～07-5、04-6/04-7）
**影响**：“从错误中学习”和“越聊越会聊”都无法成立；同一个错可以无限重复；提案不产生灰度/合并。**证据**：`errors` 表只有 5 列，无 root_cause/fix_verified/hit_count；无 guard 装饰器；`personality.reflect` 只取最近 20 条反馈、无同桶对比；`proposals` 无灰度流量/合并应用；活动库 `feedback=0/score_records=0`，反思从未发生。**修**：补 error_ledger 全字段与归因；三次法则升级 guard；反思按 skill×bucket 对比；提案接灰度统计与自动合并/回滚。

### 次严重（未进前 10，但不应忽略）

- **S3/S5 媒体管线是死的**：无 OCR/本地 VLM/表情使用语境；媒体与表情占真实日志 659/1561 行，却被全部忽略。
- **12 的 LCB/置信度完全没做**：主动行为仍用启发式分数 + 0.45 阈值。
- **13 的黄金集/成对比较/裁判/校准全部没做**：弱验证只剩一个不接技能的复测表。
- **14 的 ticker/gatekeeper/switch 没做**：web 30s 定时器是文档批判的反模式。
- **隐私风险**：`web_config.json` 明文 API key 且被 git 跟踪；文本/图片走云端 `api.deepseek.com`；`801`/`8082` 均无 token；`801 /status` 会返回最近消息文本。`web_config.json` 的 key 未在本审计中复述，但已确实在版本库里。
- **07 的 5 类归因/错误预算/守卫**、**09 的操控检测**、**10 的 G4** 均无实现。

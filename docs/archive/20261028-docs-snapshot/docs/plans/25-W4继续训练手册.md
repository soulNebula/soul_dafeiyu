
## 二、以后要加数据，怎么造

### 2.1 数据格式（一行一个 JSON）

```json
{"id":"S-Y-help-0001","source":"golden|messages|synthetic","state_profile":"default|work|low_mood|tired|joke|guarded|close",
 "split":"train|val",
 "context":[{"role":"system","text":"<SOUL_PERSONA + 当前状态行>"},
            {"role":"user","text":"…"},{"role":"assistant","text":"…"}],
 "user_msg":"用户这句话",
 "target":{"mood":…,"energy":…,"sharing":…,"battery":…,"trust":…,"stage":"…",
           "stance":"…","intent":"…","monologue":"…",
           "behavior":{"length":"…","ask":true,"advice":false,"emoji":"偶尔"}},
 "teacher":"deepseek-chat","ts":"…"}
```

### 2.2 三条造数据的路（按成本从低到高）

| 方式 | 命令/做法 | 成本 | 适合 |
|---|---|---|---|
| **① 给现有 context 换状态档位重打标签** | `python -m agi.soul.dataset --limit 2000 --real --out … --split`（内部就是 context×7 profile） | 约 ¥4 / 2000 条 | 补状态覆盖（最划算） |
| **② 加真实语料窗口** | 把新聊天记录放进 `log/messages.jsonl` 或 golden 格式，再跑 ① | 同上 | 覆盖新的说话风格/场景 |
| **③ 补合成场景** | 在 `agi/soul/scenarios.py` / `scenarios_extra.py` 的 10 桶里加素材（每桶 ≥60 条），再跑 ① | 同上 | 补稀有场景（求助/边界/危机） |

**关键约束（血的教训）**：
- `synthetic` 不超过 40%，`unique_user_msg` ≥800（防背题）
- 稀有类要够：`length=normal` 和 `advice=true` 各占 **10–20%**（v1 原始只有 4%，模型直接学成"永远短句、从不建议"）
- **不要过采样稀有行太狠**：B 的教训是 advice=true 行有 65% 带 emoji=不用，过采样 ×5 后模型把两个字段绑死，emoji 从 0.765 掉到 0.694。下一版应做**按字段分层解耦**（补一批 advice=true & emoji=偶尔 的样本，而不是复制老行）
- crisis 条目必须**代码级强制**保守（stance 先照顾人 / 短句 / 不追问 / 不建议 / 不用表情）

### 2.3 新增数据后的切分规则

- **按 context 哈希切**，同一 context 的所有状态档位变体必须在同一侧（否则泄漏）
- val = 20% context，且每个 val context 至少保留一条 default 档
- **val 一旦冻结就不要改**，否则前后指标不可比

## 三、怎么启动训练（复制即用）

### 3.1 直跑（最常用）

```bat
cd /d C:\Users\Administrator\Desktop\SoulAgent

E:\agent\venv312\Scripts\python.exe -u tools\train\smoke_lora.py ^
  --model-path E:\agent\models\Qwen2.5-0.5B-Instruct ^
  --data agi/soul/data/soul_sft_v1b_train.jsonl ^
  --limit 0 --epochs 2 --lr 1e-4 --max-seq-len 512 ^
  --save-every 800 --save-adapter E:\agent\output\soul_qwen25_05b_v1e
```

### 3.2 断点/重启安全

- `--save-every 800`：每 800 步落一个 `..._step800` 快照（断电不白跑）
- **注意**：脚本目前只存权重快照，**不存 optimizer 状态**，所以只能"从快照继续训"或"拿快照先去评测"，不能无损续训
- 出事了直接重跑（25 分钟，成本几乎为零，比修续训逻辑便宜）

### 3.3 显存三条硬约束（6GB）

1. `--max-seq-len` ≤ 512
2. **不能加** `--no-grad-checkpoint`
3. 多模态底座要 offload 视觉塔（Qwen2.5 没有，Qwen3.5 有）
4. 训练前关掉浏览器/游戏；开着桌面程序约占 350–460MB

### 3.4 更省事的做法：继续在旧 adapter 上训（增量）

脚本没有 `--init-adapter`，要增量训练就手工两步：`PeftModel.from_pretrained(base, old_adapter, is_trainable=True)` 后接训练循环。**目前不建议**——数据量小（2000 行），从头训 25 分钟就够，增量反而容易学偏。

**判定线（沿用今晚口径）**

| 门 | 指标 | 通过线 | 不通过怎么办 |
|---|---|---|---|
| G1 | JSON 合法率 | ≥99%（schema 约束下应 100%） | 检查 schema/prompt 是否同源 |
| G2 | balanced accuracy（四字段平均） | ≥0.70（规则基线 0.556，B=0.686） | 看分桶，按 §五 调 |
| G3 | local 胜率 Wilson CI 下界 | >50%（或至少 ≥42% 不低于 teacher） | 说明块没传导，别上线 |

## 五、指标不好时调哪个旋钮（症状 → 动作）

| 症状（评测里看到的） | 最可能原因 | 先改什么 | 别改什么 |
|---|---|---|---|
| `length=normal` recall ≈ 0 | 训练集 normal 太少 | 补 context 时提高 normal 档位比例到 15–20%；或 v1 原版 + `--rare-weight 3~5`（**记得 clip 跟着放大**） | 别盲目加 epoch |
| `advice=true` recall ≈ 0 | 同上 | 同上；**优先补"求助类"场景**（B 的 advice 全来自 help 桶） | 别把 factor 拉到 ×10（会把 emoji 拖死） |
| `emoji` 掉分（偶尔 recall 掉） | 过采样制造伪相关 | 改**分层解耦采样**：补 advice=true 且 emoji=偶尔 的样本；或对 emoji 反向过采样 | 别直接删 advice 加权 |
| 所有字段都平庸、和规则差不多 | 数据/标签本身噪声 | 先按 bucket 看是不是某几个场景没答案；再看 teacher 一致性 | 别加大模型（1.5B 已证明没用） |
| loss 掉到 0.1 以下、G2 不涨 | 过拟合（2000 行 ×2 epoch 已接近） | 降 lr 到 5e-5 / 加 dropout 0.1 / 减少 epoch | 别再加数据轮次 |
| G2 高但 G3 不高 | 状态块没被下游用起来 / 长度指令混杂 | 做长度配平臂（两臂强制同 length）；检查 render_block 是否只输出行为指令 | 别继续卷 G2 |
| 生成超时/复读 | 输出约束没生效 | 确认请求级 `response_format`；确认 server `--jinja` | 别用 `-jf`（会 400） |

**超参调节的优先顺序**（一次只动一个）：
1. **数据**（比例/覆盖）> 2. `epochs`（2→3）> 3. `lr`（1e-4 ↔ 5e-5）> 4. `r`（16→32，容量够但数据少时别加）> 5. `alpha`（保持 α/r=2）> 6. `seq`（512 足够，别加）
   
经验值：**2000 行数据下，改数据配比的收益远大于改超参**；今晚 A→B 就是纯数据改动，balanced +6.6pt。

## 六、红线（别做的事）

1. **不要无监督自训练/自我蒸馏**：会塌（模型自己判→自己学→越来越像自己）。teacher 必须是 DeepSeek 或人工。
2. **不要拿真实聊天直接训回复**：`log/messages.jsonl` 里 85% 重复、一半是自测/OCR 噪声；只能用来当 context/记忆。
3. **crisis 不走模型**：线上危机路径是代码级短路，模型输出不得替代安全流程。
4. **不要默认开启**：`INNER_MODE` 默认 `off`；验证通过再用 `model`，`rule` 永远保留为回退。
5. **adapter 带版本号**：`soul_qwen25_05b_<版本>`，旧的不删，可回滚。

## 七、节奏建议（接 [`22`](22-人格涌现_可行边界与成长闭环.md)）

| 周期 | 动作 |
|---|---|
| 每次改数据后 | 训 25 分钟 → 393 条 G1/G2 → 对比 B 的 0.686 与规则 0.556 |
| 累积 ≥3000 条或 G2 变化 ≥3pt | 跑一次 G3（¥0.17）确认没劣化 |
| 每月 | 把新真实对话（匿名化）补进 context → 重打标签 → 重训 → 版本号 +1 |
| 每季度 | 换 30% val（防过拟合到固定 393 条） |
| 不追求 | 每周重训（数据增量不够，会过拟合）；追求的是**稳定的月度巩固** |

## 二、五条结论（按重要性）

### 1. 技术链路成立：小模型可以承担「灵魂」，而且够快

0.5B + LoRA + GGUF Q4：**0.45–0.55s/条**、显存 0.7GB、G1 100%（schema 解码约束）。
对比 HF/Python 的 12.6s，**提速 23 倍**（开独显直连后 282 tok/s）。这条是今晚最硬的成果。

### 2. 容量不是变量，数据分布才是

1.5B（0.625）≈ 0.5B（0.620）。而只把数据从「原版」换成「平衡采样」（B）就 +6.6pt。
→ 以后要提升质量，**改数据配比，别加模型**（也就省钱省延迟）。

### 3. 一次负结果：去掉数值字段反而更差（C：0.621）

C 只训 stance/intent/monologue/behavior（数值由状态机覆盖，理论上该更专注），结果 advice 0.806→0.604、emoji 0.694→0.673。
解释：数值字段是 behavior 的"链式推理中间步骤"（先写 mood/energy，再决定行为），删掉后判断更飘。
→ **保留完整 target 结构**。

### 4. 一个必须记住的工程陷阱：梯度裁剪会吃掉样本加权

D 第一版用 `loss × w` 做 rare 加权，但 `clip_grad_norm_(1.0)` 在 bs=1 时正好把倍数归一化掉 → 加权完全失效（rare 类 recall 反而从 0.059 变 0）。
修法是 `clip max_norm = 1.0 × weight`。D2 修复后 rare 类真的被"唤醒"（advice true recall 0→0.765、length normal 0→0.235）。
→ **以后任何加权/重采样实验，先确认 clip 不会吃掉它**。

### 5. 上线候选 = B，但 G2 门擦线、G3 未证实提升

- B 的 balanced **0.686**，比规则基线 +13pt，但低于预注册的 0.70 门 → **不算通过 G2**
- G3 显示"不比 teacher 差，但也没更好" → **不能证明"状态判断变准 = 回复变好"**
- B 的短板定位明确：emoji 0.694（平衡采样造成 advice↔emoji 伪相关：advice=true 行 65% 带 emoji=不用）
- D2 的 balanced 0.690 与 B 噪声级持平，但用 ask −7pt 换 length/advice/emoji → **不选**

**结论：B 作为上线候选进入 shadow 灰度；同时明确"灵魂线是否真的改善体验"仍未证实，下一决策点是灰度真实反馈，而不是离线指标。**

# 04 · 学习闭环与打分

> ⚠️ **设计依据文档，非施工图。实施以 [PLAN.md](PLAN.md) 为准；冲突时一律以 PLAN 为准。**


> 「越聊越会聊」这句话要成立，必须有一个闭环：
> **做 → 看结果 → 打分 → 归因 → 改策略 → 再做**。
> 少了「归因」，学到的全是运气。

---

## 一、时间尺度

| 周期 | 做什么 | 谁有权改 | 秒级成本 |
|---|---|---|---|
| 每轮 | 现场生成策略、采样 variant | LLM | 实时 |
| 每 5–10 轮 | 更新变体统计、更新关系卡 | 规则 | 毫秒 |
| 每天凌晨 | 反思、生成提案、蒸馏画像、整理记忆 | 强模型 | 分钟 |
| 每周 | 灰度判定、合并/回滚、人格微调 | 规则 + 人审 | 分钟 |
| 极少 | 改 core 人格、改 guards | 只有人 | — |

**在线只调参数，离线才改结构。** 这条线一旦破，系统会震荡。

> ⚠️ **修正**：表中「每天凌晨」「每 5–10 轮」应理解为**由 intent 触发**，不是固定 cron。
> 具体见 `14-按需运行与唤醒机制.md`。

## 二、打分：信号从哪来

| 类型 | 信号 | 权重 | 何时可得 | 备注 |
|---|---|---|---|---|
| 显式 | 点赞/点踩、主动道谢、「你说得对」 | 0.30 | 即时 | 稀疏但最准 |
| 行为 | 继续深聊 / 一句带过 / 换话题 / 消失 | 0.25 | 即时 | |
| 长度比 | 用户本轮字数 ÷ 上轮 | 0.10 | 即时 | 有上限，防「越啰嗦越好」 |
| 情绪 | 情绪值变化 | 0.15 | 即时 | |
| 留存 | 24h 内是否主动回来 | 0.15 | 延迟 | 最强信号 |
| 复发 | 同一困惑是否反复出现 | -0.10 | 延迟 | 负向 |
| 裁判 | 强模型按 rubric 判「是否推进了目标」 | 0.20 | 延迟 | 必须看后续 2–3 轮 |

### 打分公式

```
raw = Σ(w_i * s_i)
score = sigmoid(raw)                       # 0..1
score_delta = score - baseline(bucket)     # 只跟同桶比
```

**绝对分没意义。** 用户那天本来心情差，你策略再好也拿不到高分。**只比同桶基线。**

### 裁判 prompt 的三条硬约束

1. 必须看到用户**后续 2–3 轮**才允许打分；
2. 必须给 rubric（用户是否说出新信息 / 情绪是否缓解 / 是否主动追问）；
3. 必须输出理由 + 引用原话（方便抽查）。

## 三、情境桶（归因的前提）

```
bucket = (关系阶段, 情绪极性, 话题类型)
  关系阶段: 陌生 / 熟 / 亲近 / 疏远
  情绪极性: 负 / 中性 / 正
  话题类型: 工作 / 感情 / 生活 / 兴趣 / 求助
```

- 先只用 3 维、共 60 桶。**别一上来就 8 维**，桶一多每个桶都学不出统计显著性。
- 冷启动用「全局先验 + 桶内偏移」（分层），避免每个桶从零开始。

```python
def bucket_of(ctx: TurnContext) -> str:
    return f"{ctx.stage}|{ctx.mood_polarity}|{ctx.topic_type}"
```

## 四、变体采样（在线学习）

每个技能维护 2–5 个 `variant`（策略方向，**不是步骤**）：

```yaml
skill: S-007
variants:
  - {id: A, hint: "纯共情，不建议，多用短句接住", alpha: 9, beta: 3}
  - {id: B, hint: "共情 + 给一个具体下一步", alpha: 5, beta: 5}
  - {id: C, hint: "先问清最在意什么，再决定聊哪块", alpha: 6, beta: 2}
```

**Thompson 采样**：每轮对每个变体采样 `Beta(α, β)`，取最大者。

```python
def pick_variant(variants, bucket) -> Variant:
    # 桶内统计不足时，向全局先验收缩
    return max(variants, key=lambda v: sample_beta(v.alpha, v.beta))
```

打完分后回填：`α += score`, `β += 1 - score`。

**为什么用 bandit 而不是「直接改技能卡」**：bandit 自带探索-利用平衡，且天然在做 A/B 测试；改文本会震荡，还无法量化。

## 五、反思：结构怎么变（离线学习）

### 5.1 对比反思

每天取同一 `(skill, bucket)` 下的 **top 20%** 与 **bottom 20%** 对话，让强模型**对比**着读：

```
给你两组对话（同技能、同情境桶）：
A 组（用户明显更投入）：…
B 组（用户明显冷下来）：…

请回答：
1. 两组在"我做了什么"上的差异是什么？（最多 3 条）
2. 提炼一条可执行规则，格式为「如果…就…，因为…」
3. 或者提出一个新的变体方向（一句话 hint）

禁止：总结成"要更真诚"这类无法执行的空话。
```

### 5.2 提案（proposal）

```yaml
id: P-20260118-003
kind: new_variant | rule_patch | knob_adjust | persona_patch
target: S-007/高焦虑
payload:
  hint: "先处理羞耻感（'是不是觉得自己废了'），再谈下一步"
  reason: "A组 vs B组差异：高焦虑场景下先给建议会导致对话在 2 轮内终止"
evidence_turns: [T-8812, T-8830, T-8844, T-8851]
created_at: 2026-01-18T03:12
status: draft
```

### 5.3 状态机

```
draft ──► gray(10% 流量) ──► merged
  │            │
  └──► rejected ◄── (n≥20 且未显著优于基线)
```

**提案永远不直接生效。** 这是防「自我进化成怪物」的最后一道闸。

## 六、防 reward hacking（一定会发生）

| 它学到的歪招 | 为什么有效 | 对策 |
|---|---|---|
| 无限共情、永不推进 | 用户会一直聊 | 把「目标达成」独立成指标，与 engagement 分开算 |
| 越写越长 | 长度与 engagement 天然正相关 | `length_budget` 硬约束，超了扣分 |
| 连续提问 | 用户回复自然变多 | 连续提问上限 2 个 |
| 讨好裁判 | 裁判只看它那条回复 | 裁判必须看用户**后续**反应，且盲评（不知变体） |
| 过度自曝 | 拉近距离快 | 自曝比例上限，且必须真实（有记忆支撑） |

**每周检查一次：variant 的 hint 是否都在朝同一个方向漂**（比如全变成「更温柔」）。如果是，说明打分函数有偏。

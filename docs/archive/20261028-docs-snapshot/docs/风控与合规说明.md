# 风控与合规说明

> 本文档说明 wx_box 与微信电脑版之间的**交互边界**、**用户授权范围**、**风险等级**、**账号安全建议**、**已知风险**与**免责声明**。
> 适用对象：使用本工具的本机用户，以及希望了解本项目技术路线的审核者。

## 一、一句话结论

wx_box 是一个**只读的本机辅助查看工具**：在**用户明确授权**下，它默认采用**数据库直读**——一次性只读扫描微信进程里的数据库/图片密钥，把**你自己账号**的微信本地数据库（WCDB/SQLCipher）解密到**本机临时目录**、以 `sqlite3 mode=ro` 只读读取，并叠加 WAL 拿到最新消息；同时离线解密本地缓存的图片/贴纸、复制文档原文件，最后输出纯文本聊天记录。数据库不可用时回退"窗口截图 + 本地 OCR"模式。

它**不发送任何消息、不写微信进程内存、不注入、不 Hook、不写回/修改微信数据库、不修改微信文件、不向微信目录写入**。

## 二、用户显式授权与适用范围

使用者已明确授权本项目在"外部观察"之外，额外执行以下**只读**操作（2026-10-22，含"忽略之前限制"、"可以的，你先跑"的最新授权）：

| 授权项 | 具体范围 | 默认状态 |
|---|---|---|
| 只读本地缓存/数据库 | 当前登录用户自己的 `Documents\xwechat_files\<wxid>\` 下的 `msg/file`（明文文档，复制原文件）、`msg/attach/.../Img/*.dat`（图片缓存）、`cache/*/Emoticon` 与 `business/emoticon`（贴纸缓存）、`db_storage/**/*.db`（微信数据库）。**只读**，不写、不删、不改名。 | 开启 |
| **数据库只读直读** | 读取 `db_storage` 下的微信库 → 解密到**本机临时目录**（`tempfile` 的 `wxdb_*`）→ `sqlite3` 只读连接 `mode=ro` 读取；叠加 WAL 帧拿最新未落盘消息。**不写回/不修改微信数据库**，不用 SQL 写操作。 | 开启（`db_direct=true`，可设 `false` 回退 OCR） |
| **一次性只读密钥扫描** | 仅为了拿密钥：`OpenProcess(PROCESS_VM_READ \| PROCESS_QUERY_INFORMATION)` → `VirtualQueryEx` 枚举可读区域 → `ReadProcessMemory` 只读扫描。图片密钥：`global_config` 地标 → `cfgDword + wxId` → `md5` 派生；数据库密钥：`com.Tencent.WCDB.Config.Cipher` 对象链 → XOR 掩码 → `x'<key><salt>'` → 逐库页1 HMAC-SHA512 校验。**取到即 `CloseHandle`**，成功即缓存、之后**不再读内存**。 | **开启**（`auto_extract_image_key=true`；`db_keys` 自动扫描） |
| 图片/贴纸离线解密 | 图片 `.dat`：AES-128-ECB + 单字节异或（V1/V2/V3）；贴纸：`md5(f"{seed}{wxid}EMOTICON")[:16]` → AES-128-CBC（key=IV、PKCS7），`wxgf`(HEVC) 用 imageio-ffmpeg 转动画 GIF 并保留原始 `.wxgf`。产出 `media/originals/`、`media/stickers/`。 | 开启 |
| 剪贴板精确文本 | OCR 回退模式下，用窗口消息模拟"右键→复制"，读剪贴板拿精确原文（含 `[微笑]`），读完尽量还原。 | 开启（OCR 模式） |
| 内置 emoji 素材 | `wx_core/builtin_emoji.py` + `wx_core/emoji_assets/`（109 个微信表情 PNG，来自 npm `wechat-emojis`）作为可选图像识别兜底；只读本地素材，不联网。 | 随包提供 |
| 可选"另存为"导出 | 用窗口消息点击微信自带"另存为"导出原图/原 GIF（不改文件、不碰加密），默认关闭。 | 关闭 |
| 产出位置 | 原图 → `media/originals/`；贴纸 → `media/stickers/`；文档 → `media/files/`；聊天记录 → `log/聊天记录.txt`、`log/messages.jsonl`。**只写项目自己的目录**。 | — |
| **不截图/不回写** | `allow_screenshot_media=false`：解不出/匹配不到时不保存截图；SQL 连接必须 `mode=ro`、禁止 SQL 写语句、禁止向微信目录写文件。 | 开启 |

**仍然绝对禁止**（红线，见下节"三不"）：

- 向微信进程**写**内存（`WriteProcessMemory`、`VirtualAllocEx`、`VirtualProtectEx` 等）、`CreateRemoteThread`、`QueueUserAPC`；
- 全局 Hook（`SetWindowsHookEx`）、DLL 注入、`frida`/`pymem` 等插桩/内存库、`minidump`/调试转储；
- **写回/修改微信数据库**（SQL 写操作、非 `mode=ro` 连接、把解密结果写回 `db_storage`）；
- 修改微信安装目录/源码/配置，向微信目录写入、删除、改名任何文件；
- 发送任何消息、代替用户操作。

授权只覆盖"**使用者本人账号、本人设备**"上的缓存、数据库与一次性内存读取，不可扩展到他人账号、他人设备，也不可传播密钥/聊天记录/解密结果。

## 三、"三不"红线

本项目在代码层面承诺以下三件事，并由 `tools/audit_compliance.py` 静态扫描持续检查：

1. **不写内存、只读一次密钥**：仅 `wx_core/wechat_keys.py`、`wx_core/wcdb.py` 在用户授权下（默认开启）允许 `OpenProcess` / `VirtualQueryEx` / `ReadProcessMemory`，**只读、取到即关闭句柄、成功缓存后不再调用**；任何写内存、远程线程、APC 注入、`pymem`/`frida`、`minidump` 一律禁止并被审计判 FAIL。
2. **不 Hook / 不注入**：不调用 `SetWindowsHookEx` 挂全局钩子，不调用 `CreateRemoteThread` / `VirtualAllocEx` 注入 DLL 或代码。不修改、不替换微信的任何模块与源码。窗口操作只用标准 `PostMessage`/`SendMessage`（BM_CLICK）与剪贴板。
3. **不写数据库、不修改微信文件**：数据库直读只做"**只读解密到本机临时目录 + `mode=ro` 读取**"，用 WAL 增量；**不写 SQL、不回写微信库、不向微信目录写入/删除/改名任何文件**。审计会对 SQL 写语句与非 `mode=ro` 连接直接判 FAIL。不修改微信安装目录（`Program Files\Tencent\Weixin`）。

此外还有一条产品级约束：**工具没有"发送消息"功能**。界面上不存在发送按钮，代码中也没有任何"输入框输入 + 回车发送"的流程；输入文字只发生在**搜索框**（用于找到好友），并且绝不会按回车发送聊天内容。复制/另存为/读库都只是读取微信自己的内容。

## 四、为什么这样做不侵犯微信的知识产权

1. **没有复制或修改微信的代码**：不反编译、不逆向、不修改 `Weixin.exe`，不替换其 DLL，不分发微信的任何文件。工具运行在微信之外，通过操作系统公开接口"看屏幕、点窗口、读剪贴板/本地库"。
2. **不接入微信私有协议**：不调用微信内部业务函数（仅按公开社区方案读取 `global_config`/`Config.Cipher` 地标做密钥定位）、不伪造网络请求、不绕过登录/付费/权限。
3. **只处理用户自己的数据**：读到的内存只用于派生**自己账号**的图片/数据库密钥，不转储、不传播、不采集其他进程数据；缓存、数据库与聊天内容都属于使用者本人，且只落本机 `media/`、`log/` 与系统临时目录。
4. **解密目的正当**：把**用户自己缓存/数据库里已加密的数据**还原成可查看内容（用户在微信里本来就能看到自己的聊天与"另存为"原图），不绕过访问控制、不破解账号、不修改数据库。
5. **第三方参考代码/素材合规**：`tools/reference_weflow/` 仅为 WeFlow 参考实现，保留其 **Apache-2.0 LICENSE**，不参与运行；`wx_core/emoji_assets/` 的 109 个微信表情 PNG 来自 npm 包 `wechat-emojis`（Apache/MIT，见其仓库说明），仅作为本地识别素材；`WechatMoments/`、`_refs/` 是使用者/其他 agent 放置的参考项目与第三方归档，不参与运行、也不在交付/审计范围内。
6. **默认不截图**：按用户要求，`allow_screenshot_media=false`，解不出媒体时只记日志，不额外保存屏幕截图。

> 说明：数据库/内存读取即便"只读、一次性、用户授权"，仍属于高风险操作；是否使用、是否继续使用由使用者自行决定并承担风险（见第七、八节）。

## 五、数据库直读与图片/贴纸解密的实测结论

1. **数据库直读已实测成功**：本机 7 个库逐库拿到密钥（页 1 HMAC-SHA512 强校验），SQLCipher4 解密 + WAL 增量后，白云会话 16 条消息与媒体**一一对应**：
   - 文字精确：`何工，参数这边客户没问题，剩下你cp过来就行`（我）/ `你去看看`（对方）；
   - 图片：`media/originals/1e0df822...png`、`0c5b3ded...png`、`1463973401...png`（本地解密原图）；
   - 表情包：`media/stickers/d8a0d235d854ab3fbe7694add4631b25.gif`（消息 XML 的 md5 与缓存文件 md5 完全一致，动画 GIF）；
   - 语音：`[语音] 2秒`（来自 `voicelength=1645ms`）；
   - 文件：`media/files/BOM_Board1_Schematic1_2026-10-19.xlsx`；
   - `log/聊天记录.txt` 严格逐行：`我: [微笑]` / `白云一片去悠悠: [表情包] d8a0....gif` 等。
2. **图片解密已实测成功**：`md5(str(cfgDword)+wxId)[:16]` 派生 AES 密钥、`cfgDword & 0xFF` 作为异或密钥，解出的 PNG 与微信"另存为"导出的原图 **sha1 完全一致**（1727×1246，311021 字节）。
3. **贴纸解密已实测成功**：`wxgf`(HEVC) 131332B → 动画 GIF 300×318、11 帧，并保留原始 `.wxgf`。
4. **密钥缓存**：`config.json` 的 `db_keys`（7 个库的 key/salt/layout）与 `image_*` 密钥；二次启动秒开，缓存自动用页1 HMAC 校验，失效自动重扫。
5. **默认开启、可回退**：`db_direct=true` 时优先直读；数据库不可用（密钥失败/库被锁/持续 WAL 竞态/微信未登录/群聊无 wxid）自动回退 OCR；`db_direct=false` 可强制 OCR。
6. **只读边界**：解密结果只写本机临时目录（`wxdb_*`），`sqlite3 mode=ro` 读取；**不写回微信数据库、不写微信目录、不发消息**。
7. **不截图**：`allow_screenshot_media=false`；媒体解不出时只记日志。

## 六、账号安全与风控建议

本工具不发送消息、不批量操作、不联网，不会触发营销/群发类风控；但包含"窗口级自动点击/滚动""一次性只读内存/数据库扫描"，建议按下面方式使用：

1. **轮询间隔 ≥ 1 秒**：默认 `poll_interval = 1.2`，请勿改到 1 秒以下。
2. **不群发、不发送**：工具没有发送能力，也不要配合其他脚本发消息。
3. **避免高频切换会话**：只监听必要好友；自动切换失败会退避并提示手动打开，不要反复触发。
4. **谨慎使用内存/数据库读取**：只在**自己的电脑、自己的账号**上使用默认的 `auto_extract_image_key`/`db_direct`；如果微信以管理员运行，本程序也需同权限；取到密钥后可把 `auto_extract_image_key` 改回 `false`，或设 `db_direct=false` 完全回退 OCR。
5. **异常自动退避**：截图/OCR/窗口/解密失败都会记日志并退避，不要用脚本高频重启。
6. **只在本机使用**：不要把工具放到远程桌面/虚拟机对别人的微信账号使用，不要多人共用同一登录态。
7. **保护密钥、数据库副本与聊天记录**：`config.json` 含 `image_*`/`db_keys` 密钥；`log/聊天记录.txt` 是**明文聊天内容**；`media/` 是原始媒体；不要分享/同步到网盘或仓库。删除 `db_keys`/整个 `config.json` 后下次自动重扫。
8. **清理临时文件**：解密库在系统临时目录的 `wxdb_*` 目录，退出后建议清理残留。
9. **遵守微信正常使用习惯**：工具操作微信界面（同步好友、自动切会话、可选导出）时，尽量避免同时手动操作。
10. **安全软件提示**：读进程内存、模拟点击、调用内置 ffmpeg 容易被安全软件/EDR 关注，可能出现告警；源码完全公开，可先运行合规自检再决定是否信任。

## 七、已知风险与限制

1. **数据库被锁 / WAL 竞态**：微信正在写 WAL 时解密结果可能暂时不一致，程序会退化为只解主库（数据稍旧但可用）；持续失败则回退 OCR。
2. **数据库/密钥格式可能变化**：微信升级可能改变 `Config.Cipher` 结构、库布局或加密参数，届时密钥扫描/解密可能失效；自动回退 OCR。
3. **密钥与数据库副本的高风险**：`db_keys`/`image_*` 能解密你的聊天数据，**不要分享 config.json 或项目目录**；临时目录 `wxdb_*` 中有解密后的库副本，建议及时清理。
4. **内存读取的高风险**：一次性只读扫描也可能触发安全软件/EDR 告警；若发生账号异常，风险由使用者自行承担。默认开启是**基于用户明确授权**；你随时可以关闭（`auto_extract_image_key=false`、`db_direct=false`）。
5. **OCR 回退限制**：窗口最小化时无法截图；数据库直读模式下最小化也能监听，但同步好友/自动切换/OCR 回退仍需要窗口。
6. **图片/贴纸解密依赖密钥提取**：权限不足（微信管理员运行而本程序普通运行）、缓存被清理、微信升级时可能失败；按不截图策略只记日志。
7. **贴纸匹配"宁缺勿错"**：历史回放/相似贴纸可能匹配不上；100% 精确绑定需读消息库 md5（已随数据库直读解决大部分场景）。
8. **本机数据与隐私**：`media/originals|stickers|files`、`log/聊天记录.txt`、`config.json` 都含敏感内容；不要分享项目目录；退出后删除这些即可清理。
9. **多显示器 / 高 DPI / 缩放**：OCR 模式下程序启动时声明 DPI 感知；跨屏/特殊缩放可能出现坐标偏差（数据库直读不受影响）。
10. **无网络、无云端**：工具不联网、不上传，没有任何云端通道。

## 九、合规自检

```bat
C:\Python314\python.exe tools\audit_compliance.py
```

- 输出 `结果：PASS` 且退出码为 0 表示通过；`FAIL` 且退出码为 1 表示发现越界代码，必须修复。
- 白名单：`wx_core/media_cache.py`、`wx_core/dat_decrypt.py`、`wx_core/emoticon.py`（缓存只读/解密）；`wx_core/wechat_keys.py`、`wx_core/wcdb.py`（一次性只读密钥扫描，仅豁免 `OpenProcess`/`ReadProcessMemory`）；`wx_core/wcdb.py`、`wx_core/db_source.py`（数据库只读直读：`db_storage` 只读引用 + `sqlite3 mode=ro`）；`clipboard.py`、`textlog.py`、`media_export.py`、`builtin_emoji.py`（辅助）。

# 36 · 本地小模型（提取用）服务与质量对照（P14）

> 结论速览：**本地 Qwen2.5-3B（Q4_K_M）适合做高量、低风险的提取初筛**（JSON 100%、P50≈1.3s、无编造）；
> **关键数字/细节会丢**，发布级摘要、相关性判断、视频真理解仍必须 API。
> Qwen3.5-2B（transformers/4bit）**不值得**：14s/次且信息更少，3B 明显更好。
> 3B（8125）与灵魂 0.5B（8123）**可并存**：实测 GPU 总占用 ~3.5GB / 6.1GB。

## 3. 质量对照（真实 B 站字幕，各 3 次）

输入：`E:\agent\tmp\bili_subtitle_sample.txt`（3137 字，来自 BV1XbHV6jE7x 的 AI 字幕，Strata/本地部署主题）。
同一 prompt：`{"summary":"≤60字","topics":["3-5个"],"emotion":"整体情绪","worth_sharing":0-1,"reason":"≤30字"}`。

| 后端 | JSON 合法 | 耗时 P50 | summary 读感(0–2) | topics 合理(0–2) | emotion 合理 | 编造 | 关键信息缺失 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **本地 3B**（Q4_K_M，8125） | **3/3** | **1.29s** | 1.5（主线对，细节少） | 2 | 1（“正面”，视频更偏“务实/理性”） | 无 | 18小时/19%/83→61%/IQ2XS/4–8 tok/s 等数字基本没进摘要 |
| **DeepSeek**（API） | **3/3** | 4.92s | 2（版本节奏+12G+本地部署都抓到） | 2 | 2（务实/认可） | 无 | 少量细节 |
| **Qwen3.5-2B**（transformers 4bit） | 3/3 | 13.98s | 1（更泛，细节少） | 2 | 1（客观分析） | 无 | 比 3B 丢得更多 |

补充：
- 3B 单条 summary 输出约 80–120 token，llama.cpp 日志实测 **eval ≈72 tok/s**，prompt prefill ≈3762 tok/s；
- 3B 会写“0.2.4 大幅提升性能”这类**概括性说法**（视频里是“换血/12G 跑 DeepSeek + 速度对比”），不算编造但不够精确；
- 2B 用 4bit bnb + vision offload，**14s/次**，比 3B 慢 10 倍且信息更少，不建议投入。

## 4. 显存实测（nvidia-smi）

| 场景 | 总显存 |
| --- | --- |
| 只有 8123 灵魂 0.5B（+桌面） | ~1.3 GiB |
| 8123 + 8125 3B 同时跑 | **~3.5 GiB / 6.1 GiB**（余 ~2.6 GiB） |
| 3B 自身估算 | ~2.2 GiB（3.5 − 1.3） |
| 2B transformers 4bit | 与 8123 共存可跑（未 OOM），但慢 |

结论：**3B 与 0.5B 可以共存**，不需要停 8123；若还要再上 1.5B/多并发，再考虑串行或减 `-c`。

## 5. 结论：哪些用途本地够用

| 用途 | 本地 3B | 建议 |
| --- | --- | --- |
| **ingest_summary**（字幕粗摘要） | ✅ 够用（1.3s，无编造，JSON 稳） | 批量/初筛走本地；发布级/高价值视频交 API 复核 |
| **keyword_extract**（topics/关键词） | ✅ 够用（4–5 个 topic 合理稳定） | 全量本地，API 只做抽检 |
| **comment_cluster**（短文本分类/聚类） | ✅ 大概率够用（短输入、1.3s/次） | 本地批量；需要细粒度语义时 API |
| **relevance_score**（相关性/该不该分享） | ⚠️ 只做粗筛 | 阈值低时本地预过滤，最终判断走 API |
| **视频真理解** | ❌ 不做 | 必须 API（用户已拍板） |

**路由建议**：高量长文本提取（摘要/关键词/评论聚类）→ 本地 3B（8125），失败/低置信/发布级 → DeepSeek API；视频理解、相关性终判、复杂多跳 → 必须 API。

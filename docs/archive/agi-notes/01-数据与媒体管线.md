## S0 · 数据接入

### 目标
把 `wx_box` 已有的消息流和朋友圈，变成带统一时间轴的「原始素材」。

### 输入
- `log/messages.jsonl`（`wx_core.models.Message` 序列化）
- `WechatMoments/` 同步出的 moments（`{id, author, create_time, content, location, media[]}`）
- `media/originals/`、`media/stickers/`、`media/files/`

### 执行内容

1. **建统一原始表** `raw_item`，消息与朋友圈同一套字段（`kind=msg|moment`）。
2. **增量游标**：记 `last_ts` + `last_id`，只拉新数据；`--rebuild` 支持全量重建。
3. **补字段**（`Message` 目前缺的）：`conv_id`、`is_group`、`sender_wxid`、`quote_id`、`reply_to`。
   - 好友会话：`conv_id = wxid`；群聊：`conv_id = chatroom_id`，`sender_wxid` 从 `Name2Id` 取。
4. **媒体落地校验**：`media_path` 必须真实存在且 `sha256` 可算；不存在的记 `missing_media`，**不猜**。
5. **朋友圈特殊处理**：`thumb_b64` 只在内存里用，落盘只存 `path` 或 `thumb_key`；`location` 只保留到城市级（见 S1.6）。
6. **授权校验**：每条数据挂 `consent_id`；无同意的数据不进管线。

### 输出

```python
@dataclass
class RawItem:
    id: str              # msg.id 或 moment.id
    kind: str            # "msg" | "moment"
    source: str          # "db_direct" | "ocr" | "moments"
    conv_id: str
    sender_wxid: str
    is_self: bool
    is_group: bool
    ts: float
    text: str
    media_ids: list[str]
    quote_id: str
    consent_id: str
    raw_ref: str         # 原始 jsonl 行号或文件偏移，便于回溯
```

### 函数

```python
# agi/ingest/messages.py
def load_messages(since_ts: float = 0.0, limit: int = 0) -> list[RawItem]
def tail_jsonl(path: str, cursor: dict) -> tuple[list[dict], dict]   # 断点续读

# agi/ingest/moments.py
def load_moments(since_ts: float = 0.0, limit: int = 50) -> list[RawItem]
def materialize_moment_media(moment: dict) -> list[MediaRef]

# agi/ingest/store.py
def upsert_raw(items: list[RawItem]) -> IngestStats
def mark_missing(media_id: str, reason: str) -> None
```

### 失败与降级

| 情况 | 处理 |
|---|---|
| 媒体文件缺失 | 标 `missing_media`，文本仍入管线，媒体相关 claim 一律不抽 |
| 群聊拿不到 `sender_wxid` | 该会话降级为 `anonymous_group`，只做群体级统计，不做个人画像 |
| 朋友圈接口失败 | 保留上次快照，记 `sync_failed`，**不伪造** |

### 验收
- 全量重放 `messages.jsonl` 不报错，条数与文件行数一致（±0）。
- 随机抽 20 条，`raw_ref` 能定位回原始行。
- 每条媒体可算出 `sha256`，重复率统计可输出。

## S1 · 清洗与去重

### 目标
去掉噪音，只留「能说明问题」的内容。

### 执行内容

1. **同文去重**：`sha1(kind+sender+text+media_hash+分钟粒度ts)` 相同则丢。
2. **系统消息过滤**：`"xxx撤回了一条消息"` 保留在时间线，但不进理解层。
3. **媒体归类**：`media_hash` 相同 → 同一素材，只标注一次（表情包复用率极高）。
4. **短句合并**：同一发送者 60 秒内的连续短句（`嗨`/`在吗`/`哈哈哈`）合并为一个话轮。
5. **OCR 噪音清洗**（`source=ocr`）：去 `[图片]` 占位、去窗口标题、修数字上下文误识。
6. **位置脱敏**：`location` 只保留「城市 + 场所类型」，门牌号/小区名/公司名打码为 `<地点>`。
7. **PII 预检**：手机号、身份证、银行卡、精确住址 → 占位符替换，原文只留在加密原始层。

### 输出
`clean_item` 表 + `pii_flags` 列表（用于审计，不用于建模）。

### 函数

```python
# agi/ingest/clean.py
def dedupe(items: list[RawItem]) -> list[RawItem]
def merge_short_bursts(items: list[RawItem], gap_sec: int = 60) -> list[RawItem]
def scrub_pii(text: str) -> tuple[str, list[PiiHit]]
def fuzz_location(loc: str) -> str
```

### 验收
- 重复率报表：原始 vs 清洗后，重复率应 < 15%（表情包转发会很高，属正常）。
- 抽 50 条含 PII 样本，`scrub_pii` 召回率 100%（宁多勿少）。

## S2 · 会话切分

### 目标
把连续流水切成「话题段」。记忆、打分、反思都以**段**为单位，不以单条消息为单位。

### 执行内容

1. **时间切分**：间隔 > 25 分钟 → 新段（`gap_min` 可配）。
2. **话题切分**：相邻 5 条算相似度，连续 3 条低于阈值 → 切段。
3. **跨天处理**：聊到凌晨算同一段，标 `cross_midnight=True`。
4. **段级元数据**：起止时间、时长、条数、双方字数比、情绪曲线、结束方式。

### 输出

```python
@dataclass
class Session:
    id: str
    conv_id: str
    start_ts: float
    end_ts: float
    turns: list[str]          # raw_item.id 顺序
    msg_count: int
    char_ratio: float         # 对方字数 / 我字数
    mood_curve: list[float]
    end_reason: str           # "naturally" | "abrupt" | "cross_midnight"
```

### 函数

```python
# agi/understand/segment.py
def build_sessions(items: list[RawItem], gap_min: int = 25) -> list[Session]
def split_by_topic(session: Session, sim_threshold: float = 0.55) -> list[Session]
```

### 验收
- 抽 30 段人工看，切错的 < 2 段。
- `end_reason=abrupt`（对方突然不回）能正确标出——**这是打分的关键负信号**。

## S3 · 媒体理解 · 图片

### 目标
把一张图变成「可被检索、可被引用」的一段事实。

### 执行内容

1. **格式归一**：GIF/webp → 首帧 + 中间帧各 1 张；大图缩到长边 1024。
2. **OCR**：复用 `wx_core/ocr.py`（RapidOCR / Windows OCR 双通道）。
3. **VLM 描述**：一句话场景描述 + 3–6 个标签 + 情绪倾向。
4. **去人物身份**：**不做人脸识别、不建人脸库**，只输出「1 人 / 多人 / 无人」。
5. **EXIF**：只取时间；GPS 一律**丢弃**（不是模糊，是丢弃）。
6. **截屏类识别**：聊天截图/文章截图 → 以 OCR 为主，VLM 只辅助。
7. **敏感内容**：证件、票据、私密照 → `sensitivity=high`，只存 hash + 类型，不存描述。

### 输出

```python
@dataclass
class MediaAnnotation:
    media_id: str
    kind: str            # image | video | emoji
    caption: str         # "深夜办公室，桌上一杯咖啡，屏幕亮着"
    ocr_text: str
    tags: list[str]      # ["加班","夜晚","办公室"]
    emotion: str         # "疲惫"
    people: str          # "none" | "one" | "many"
    sensitivity: str     # "low" | "medium" | "high"
    model: str
    confidence: float
    created_at: float
```

### 函数

```python
# agi/understand/media/image.py
def normalize_image(path: str) -> str
def ocr_image(path: str) -> str                      # 内部调用 wx_core.ocr
def caption_image(path: str, ocr_hint: str = "") -> str
def tag_image(caption: str, ocr: str) -> list[str]
def annotate_image(path: str) -> MediaAnnotation
```

### 参数
- VLM 温度 0.1，最大输出 120 token（**强制短**，长描述会污染检索）。
- 单图超时 15s，超时降级为「只有 OCR」。
- 同一 `sha256` 只标注一次。

### 失败与降级

| 情况 | 处理 |
|---|---|
| VLM 不可用 | 只走 OCR + 上下文推断，`confidence` 打 0.4 |
| OCR 空 + VLM 失败 | 标 `unreadable`，**不生成任何描述**（防编造） |
| 敏感图 | 只记类型，不描述 |

### 验收
- 抽 50 张图人工核对 caption：无明显错误 ≥ 90%。
- 编造率：图中没有的元素被写进 caption 的比例 < 5%。
- 单图全链路 < 3s（本地 VLM）。

## S4 · 媒体理解 · 视频

### 目标
视频不存描述，存「时间轴上的几帧 + 说了什么」。

### 执行内容

1. **元数据**：`ffprobe` 取时长、分辨率、有无音轨。
2. **场景切分**：`pyscenedetect` 或帧差，切 3–8 个关键帧。
3. **关键帧走 S3**（图片管线）。
4. **音轨 ASR**：`whisper.cpp` 本地转写，带时间戳。
5. **合成时序文本**：`[00:03] 画面：…；[00:12] 说："…"`。
6. **时长上限**：> 3 分钟只取前 2 分钟 + 均匀抽样。

### 函数

```python
# agi/understand/media/video.py
def probe(path: str) -> VideoMeta
def keyframes(path: str, max_frames: int = 8) -> list[str]
def transcribe_audio(path: str) -> list[TranscriptSeg]   # whisper.cpp
def annotate_video(path: str) -> MediaAnnotation
```

### 验收
- 3 分钟视频全链路 < 60s（本地）。
- ASR 中文抽检准确率 ≥ 85%（方言/口音单独记）。
- 抽 10 个视频人工看，漏掉主要场景 < 1 个。

## S5 · 表情包人格档案（**最被低估的一道工序**）

### 目标
表情包的使用模式是**最强的性格信号**之一：什么时候用、对谁用、用哪一类。比任何性格测试都真实。

### 执行内容

1. **素材库**：复用 `tools/export_emoticons.py` 的 manifest，建 `emoji_asset`（hash、尺寸、动/静、OCR 文字）。
2. **情绪标注**：7 类（开心/生气/难过/害羞/困惑/无语/日常）+ 攻击性 0–1 + 自嘲度 0–1。
3. **使用语境**：每次使用都记「前一条、后一条、对话对象、时间」。
4. **统计画像**（按人）：高频 Top 20（及含义）、情绪分布、攻击性均值、自嘲比例、表情/文字比。
5. **群聊 vs 私聊分开统计**：同一个人在两处的表情风格常常完全不同。

### 输出

```yaml

  - {hash: 1da84734, meaning: "无语翻白眼", count: 37, contexts: ["对方说废话", "被夸"]}

```

### 函数

### 验收
- Top 20 表情人工核对含义准确率 ≥ 85%。

## S6 · 文本理解与 claim 抽取

### 目标
把「聊天」变成「可验证的事实条目」。**这是全系统最核心的一步。**

### 执行内容

1. **输入粒度**：以 `Session` 为单位，附带前后各 3 条上下文。
2. **抽取范围**（只抽五类，别贪）：
   - `profile`：工作、居住、家庭、年龄、学校、健康
   - `preference`：喜欢/讨厌的人、事、物、话题
   - `event`：发生了什么（时间、地点、参与人、结果）
   - `plan`：要做什么（带 `expires_at`）
   - `relation`：和谁什么关系、关系的变化
3. **每条 claim 必须带 `evidence_span`**：原文片段 + 字符偏移。**抽不出原文片段的，直接丢。**
4. **时间归一**：「上周三」「明天」基于消息 `ts` 换算成绝对日期。
5. **谓词归一**：映射到固定词表（`job`/`city`/`relationship_status`/`health`…），否则无法做冲突检测。
6. **否定与假设识别**：「如果我有钱」「我才不去」不能抽成事实。
7. **推断分离**：模型推测标 `type=inference`，**永不进事实层**。

### 输出

```python
@dataclass
class Claim:
    text: str
    subject: str          # wxid 或 "user"
    predicate: str        # 归一后的谓词
    object: str
    polarity: bool = True
    time_ref: str = ""    # "2026-01-14"
    claim_type: str = "fact"   # fact | preference | event | plan | inference
    evidence_raw_id: str = ""
    evidence_span: str = ""     # 原文片段
    evidence_offset: tuple[int, int] = (0, 0)
    confidence: float = 0.0
```

### 函数

```python
# agi/understand/claims.py
def build_prompt(session: Session, context: list[RawItem]) -> str
def extract_claims(session: Session) -> list[Claim]           # LLM + JSON schema
def normalize_predicate(raw: str) -> str
def resolve_time(text: str, base_ts: float) -> str
def verify_span(claim: Claim, source_text: str) -> bool        # 字符串匹配，硬校验
```

### 参数
- 温度 0.1，`response_format=json_schema`
- 单段最多 12 条 claim（**强制上限，防贪多导致编造**）
- 单条置信度 < 0.6 直接不抽

### 失败与降级

| 情况 | 处理 |
|---|---|
| JSON 解析失败 | 重试 1 次，仍失败则整段跳过 + 记 `extract_failed` |
| `verify_span` 不通过 | 丢弃该 claim（**不修正、不猜**） |
| 会话过短（< 4 条） | 只抽 `event`，不抽 `profile` |

### 验收
- 抽 100 条 claim 人工核对：**记忆准确率 ≥ 98%**，编造率 < 1%。
- `verify_span` 通过率 ≥ 95%；低于 90% 先修这里，别往下走。

## S8 · 向量化与索引

### 目标
让「三年前的一句话」能在 200ms 内被捞出来。

### 执行内容

1. **切块单位**：话题段 + 每条 claim 独立成块（claim 块检索权重更高）。
2. **嵌入模型**：本地 `bge-small-zh-v1.5`（512 维），**不上云**。
3. **索引**：向量用 `sqlite-vec`（单机最省事），关键词用 SQLite FTS5（中文需分词预处理）。
4. **元数据索引**：`subject`、`time`、`claim_type`、`source_level` 建普通索引。
5. **重嵌入策略**：换模型时全量重建，旧索引保留在 `index_v1/`。

### 函数

```python
# agi/memory/index.py
def embed(texts: list[str]) -> list[list[float]]
def upsert_chunk(chunk_id: str, text: str, meta: dict) -> None
def rebuild_index(kind: str = "all") -> IndexStats
```

### 验收
- 1 万条记忆，召回 P95 < 200ms。
- 已知答案的 50 条查询，Top-8 命中率 ≥ 85%。

## S9 · 画像蒸馏

### 目标
从几百条零散记忆里凝练出「这个人是谁」。**AI 能不能「懂他」，分水岭在这一步。**

### 执行内容

1. **固定 10 个维度**（先别扩）：
   `基本信息 / 职业 / 家庭 / 兴趣 / 作息 / 语言风格 / 价值观 / 雷区 / 近期状态 / 关系网`
2. **每个维度输出三件套**：`结论 + 证据 id 列表 + 置信度`。
3. **证据门槛**：同一结论至少 2 条独立证据才出画像（1 条只进 `pending`）。
4. **时间衰减**：`近期状态` 只看 30 天；`基础信息` 不看时间；`兴趣` 半衰期 180 天。
5. **冲突保留**：两个版本都留，标 `conflict`，下次聊天自然确认。
6. **篇幅上限**：每维 ≤ 120 字。**画像要短**，长了塞不进上下文。
7. **禁止形容词堆砌**：只写可验证的（「每周三晚上打球」而不是「热爱运动」）。

### 输出

```yaml
# agi/data/persona/profile__wxid_xxx.yaml
subject: wxid_xxx
updated_at: 2026-01-17
dimensions:
  basic:    {value: "28 岁，男，杭州", conf: 0.95, evidence: [M-0012, M-0088]}
  job:      {value: "互联网后端，2025-11 部门被裁，现待业", conf: 0.88, evidence: [M-0102, M-0119, M-0130]}
  family:   {value: "已婚，有一女 3 岁", conf: 0.9, evidence: [M-0044, M-0201]}
  interest: {value: "露营、公路车、看球（皇马）", conf: 0.82, evidence: [M-0033, M-0071]}
  schedule: {value: "常 0 点后睡，周末补觉到中午", conf: 0.7, evidence: [M-0155, M-0166]}
  language: {value: "短句，少用表情，爱说'行吧''算了'", conf: 0.85, evidence: [...]}
  values:   {value: "看重'靠谱'，反感画大饼", conf: 0.65, evidence: [M-0090]}
  landmines:{value: "不聊前任、不提'你该振作'", conf: 0.75, evidence: [M-0121, M-0198]}
  recent:   {value: "裁员后焦虑，在投简历，11 月起失眠", conf: 0.8, evidence: [...]}
  network:  {value: "常提'老王'(前同事)、老婆'小鹿'", conf: 0.7, evidence: [...]}
```

### 函数

### 参数
- 温度 0.2；**每次只蒸一个维度**（一次全蒸会串味）。
- 每天凌晨跑一次，只重蒸「有新证据」的维度。

### 验收
- 抽 5 个用户，画像交给「认识他的人」盲评：准确度 ≥ 80%。
- 每维证据数 ≥ 2，且能点开看到原文。
- 总长 ≤ 900 字（超了打回重写）。

## 二、最大的问题：46% 发送失败（wxauto，不是我们的逻辑）

失败原因（88 条失败事件）：

```
86x AttributeError: 'ProfileWnd' object has no attribute 'topui'
 1x PyperclipWindowsException: Error calling OpenClipboard
 1x Exception: 无法清除输入框内容，发送失败
```

时间线：

```
12:35–13:04  正常（少量发送）
13:11–16:20  几乎全失败（14 点 27 次全败、15 点 26 次全败）
16:30 之后   自行恢复（未重启进程），17–20 点全部成功
```

判断：`wxauto4 41.1.7 + 微信 4.1.15.56` 的 `ProfileWnd.topui` 兼容问题——微信弹出资料卡后，
wxauto 发送路径拿不到控件。之前那个 `SwitchToChat` 修复（f85becd）没能兜住这一段。
**不是桥接代码的 bug，但桥接必须能识别并退避**，否则会像这次一样：

- 每 3 分钟重试一次 → 82 次失败 → **83 条失败草稿**；
- 每条失败仍消耗一次生成调用（token 浪费）。

## 三、内容质量：没有真人的反馈，主题塌缩

95 条里：

| 词 | 条数 |
|---|---|
| 安静 | 29 |
| 忙 | 11 |
| 窗外 / 光线 | 7 |
| 发呆 | 6 |
| 犯困 | 5 |
| 声音 | 6 |

典型样本：

- 「刚又听见窗户缝那儿呜呜的，像很小的口哨你那边听得到什么动静吗？」
- 「静下来反而有点不习惯，老觉得窗户那边有动静你那边呢，也是这么安静吗？」
- 「我这儿安静得有点犯困，你是不是也在发呆啊？」

问题：

1. **主题塌缩**：没有真人回应，LLM 反复围绕"安静/窗外/发呆"打转，越聊越空；
2. **候选单一**：`kind` 全是 `check_in` → 记忆回访、关心、分享念头这些候选从没被选中
   （空闲 >3h 时 `check_in` 分数最高，把其它候选压死）；
3. **粘连长句 11 条**：`style_profile.strip_periods` 把 `。` 去掉后两个意群粘一起
   （「……还真有点犯困你那边呢？」）；
4. **问句疲劳**：大量"你那边也……吗？"，没人回应时会显得自说自话。

## 五、修复清单（按优先级）

| # | 问题 | 修法 |
|---|---|---|
| P0 | wxauto `ProfileWnd.topui` 失败 46% | ① 发送前检测并关闭资料卡（ESC / ClickProfileWnd）；② 捕获该 AttributeError → 重启 wxauto 实例一次；③ 连续失败 3 次进入"发送熔断"（暂停主动 30 分钟，不生成）；④ 失败不写新草稿，改为合并计数 |
| P1 | 失败风暴产生 83 条草稿 | `drafts` 增加去重/上限：同一文本 10 分钟内只留一条；失败草稿超过 20 条自动折叠 |
| P1 | 候选塌缩成 check_in | `build_candidates` 按 kind 轮转 + 最近 5 条用过的话题降权；记忆回访/关心优先于"没话找话" |
| P2 | 粘连长句 | `strip_periods` 只在气泡末尾去掉句号，不在句中删；或用 `，`/`？` 补齐 |
| P2 | 无人回应时反复追问 | 连续 N 条无回应的主题降权（不是硬性限制，交给 LLM 选） |
| P3 | 试跑被外部杀掉 | 加 `proactive_trial` 状态持久化：启动时若已过 `proactive_until_ts` 直接禁用并记日志 |

## 六、结论

- **调度与自主权**：达标。LLM 自己定 30–300s 间隔、想发就发、允许连发，都按设定在跑。
- **稳定性**：不达标。wxauto 兼容问题让近半天成功率只有 ~0–40%。
- **内容质量**：不达标。无反馈环境下主题塌缩 + 问句疲劳，需要多样性/降权机制。
- **下一步**：先修 P0（否则开多久都白跑），再修 P1 候选多样性，然后重开一轮 12h 观察。

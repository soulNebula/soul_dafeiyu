# 常见问题（FAQ）

> 先做一次体检：在项目目录打开命令提示符，依次执行：
>
> ```bat
> C:\Python314\python.exe --version
> C:\Python314\python.exe -m pip install -r requirements.txt
> C:\Python314\python.exe tools\audit_compliance.py
> ```
>
> 前两条确认环境，第三条应输出 `结果：PASS`。下面按现象排查。

## 1. 启动失败：双击 run.bat 一闪而过 / 报错退出

**现象**：黑窗口一闪就没了；或提示 `'python' 不是内部或外部命令`、`ModuleNotFoundError: No module named 'PIL'`。

**排查**：

1. **用命令行启动看报错**：在项目目录按住 Shift + 右键 → "在此处打开 PowerShell 窗口"（或地址栏输入 `cmd` 回车），执行：
   ```bat
   run.bat
   ```
   窗口不会自动关闭，能看到完整错误。
2. **Python 路径不对**：本机 Python 在 `C:\Python314\python.exe`。若 `python` 命令不可用，直接写全路径：
   ```bat
   C:\Python314\python.exe app.py
   ```
   或把 `C:\Python314` 加入系统环境变量 `PATH` 后重新打开终端。
3. **依赖没装**：执行 `C:\Python314\python.exe -m pip install -r requirements.txt`。国内网络慢可加清华镜像：
   ```bat
   C:\Python314\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
   ```
4. **缺少 tkinter**：Tkinter 是 Python 标准库的一部分。若报 `No module named 'tkinter'`，说明当前 Python 安装不完整，请用官方安装包（勾选 tcl/tk）重装。
5. **Python 版本过旧**：需要 Python 3.10+（本机为 3.14）。在命令行执行 `python -c "import sys; print(sys.version)"` 查看。
6. **路径含特殊字符**：项目路径含中文/空格一般没问题；若放在 OneDrive 同步目录或受控文件夹下，可能被权限拦截，建议换到 `C:\wx_box` 这类简单路径。
7. **被杀软拦截**：见第 9 条"杀毒软件 / Windows Defender 拦截或提示"。

## 2. 找不到微信窗口（状态栏显示"未连接"）

**现象**：程序启动了，但一直提示未找到微信窗口。

**排查**：

1. **微信没登录**：先打开微信电脑版并完成登录，停在主界面（不是登录二维码页）。
2. **微信被最小化了**：默认**数据库直读**模式下不需要窗口画面，最小化也能监听；但"同步好友"和 OCR 回退模式需要窗口画面，请把微信窗口还原到桌面（被其他窗口挡住没关系）。
3. **开了多个微信**：多开时程序会选择面积最大的微信主窗口；如果监听对象在另一个窗口里，请只保留一个微信窗口。
4. **微信版本不同**：本工具针对 **微信电脑版 4.1.15.56**（`Weixin.exe`，Qt5 自绘）实测。太老或太新的版本窗口类名/结构可能不同，程序可能找不到。
5. **权限不一致**：如果微信以管理员身份运行、而本程序以普通用户运行（或相反），系统可能不允许跨权限操作窗口。两者用同样权限启动（都普通运行即可）。
6. **程序会自动重试**：后台每隔 `poll_interval`（默认 1.2 秒）重新查找窗口，登录/恢复窗口后会自动连上，不需要重启。若仍连不上，可重启程序或点一次"重新同步好友"验证后端是否正常。
7. **确认进程名**：任务管理器 → 详细信息，应能看到 `Weixin.exe`。若是旧版 `WeChat.exe` 也能识别；若根本没有该进程，说明微信没启动。

## 3. 文字识别不准 / OCR 初始化失败

**现象**：界面文字很少、全是问号或方框；或日志区出现 `OCR 初始化失败`、`RapidOCR 初始化失败`、`rapidocr_onnxruntime 导入失败`。

**先了解文本路线**：默认**数据库直读**模式下文字来自数据库原文，不经过 OCR；只有数据库直读不可用、回退 OCR 时才依赖 OCR/剪贴板。因此文字不准时先看日志是否有"数据库直读不可用"。

**原因与解决**：

1. **精确复制失败**：可能微信没在前台、菜单没弹出、剪贴板被占用。检查 `config.json` 的 `copy_text_exact`（默认 `true`）与 `copy_text_timeout`（默认 8 秒）；也可临时设为 `false` 只用 OCR 对比。程序读完会尽量还原你原来的剪贴板内容。
2. **RapidOCR 依赖没装全**：`rapidocr-onnxruntime` 依赖 `onnxruntime`、`opencv-python`、`numpy`、`Pillow` 等。重新安装并验证：
   ```bat
   C:\Python314\python.exe -m pip install --force-reinstall -r requirements.txt
   C:\Python314\python.exe -c "import rapidocr_onnxruntime, onnxruntime, cv2; print('OCR deps OK')"
   ```
   本机实测版本：rapidocr-onnxruntime 1.2.3 / onnxruntime 1.31.0 / opencv-python 5.0.0.93 / numpy 2.5.2 / Pillow 12.3.0。
3. **首次识别慢**：RapidOCR 第一次调用要加载 ONNX 模型，约 1~3 秒，之后常驻内存；不是卡死。RapidOCR 的模型文件随 pip 包一起安装，**不需要联网下载**。
4. **Windows 降级引擎不可用**：若 RapidOCR 不可用，程序会尝试系统 OCR（通过 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe` 调 WinRT）。电脑缺少中文 OCR 语言包或 PowerShell 被精简/禁用时，降级会失败。可在 **设置 → 时间和语言 → 语言和区域 → 中文（简体，中国）→ 语言选项 → 可选语言功能** 里确认 OCR 组件已安装。
5. **确认不是日志编码问题**：程序内部统一用 Unicode/UTF-8；若 `log/messages.jsonl` / `log/聊天记录.txt` 用记事本打开乱码，用 VS Code、Notepad++ 以 UTF-8 打开即可。
6. **截图本身是黑屏/花屏**：见第 8 条（窗口最小化）。如果连图片缩略图都是黑的，问题在截图而非 OCR。

## 4. 好友列表不全 / 数量比通讯录少

**现象**：同步后只显示部分好友；或日志提示"数量校验不一致：表头 N 位，实际读到 M 位"。

**先了解同步方式**：程序会打开微信"**通讯录**"，用**真实滚轮**逐屏翻页 + OCR 识别名字，结束后自动切回"聊天"页，并恢复你原来的前台窗口和光标位置。同步时微信会被**短暂切到前台、鼠标会自己动**，这是正常现象；期间请**不要操作鼠标键盘**。默认上限：120 次滚动 / 90 秒。

**原因与解决**：

1. **微信好友列表是懒加载的**：只有滚动到可见区域的好友才会被识别。请：
   - 确认微信窗口足够大（一屏显示更多行，减少滚动次数）；
   - 同步期间**不要手动操作微信**（不要抢鼠标/切页面），等日志提示"好友同步结束"；
   - 点击界面上的"**重新同步好友**"再试一次（注意：重新同步会**整体替换**列表，以更完整的一次为准）。
2. **同步被中断/提前结束**：日志会写明原因（"超时保护（90s）提前结束" / "达到最大滚动次数 120" / "连续 2 次滚动没有新好友"）。好友特别多时 90 秒可能不够：关掉其他占 CPU 的程序、把微信窗口拉大、再同步一次；多次都只到一半，通常是滚轮没生效（微信没在前台、有弹窗遮挡）。
3. **微信没在前台 / 有弹窗**：滚轮翻页要求微信是前台窗口。同步前把微信切到前台、关掉微信里的弹窗（新消息提示、更新提示等），同步开始后再切走。
4. **无法识别通讯录页**：程序靠"通讯录管理"按钮或"联系人 N"表头判断页面。若自动点"通讯录"失败，请先**手动点开微信的"通讯录"**、停在好友列表，再点"重新同步好友"。
5. **群聊/公众号不显示**：本工具只枚举通讯录里的联系人；群聊、公众号、企业微信联系人不属于好友监听范围（这些入口会被过滤掉）。
6. **名称重复或截断**：同名的联系人可能合并显示；过长的备注名在列表里会被截断，属 OCR 限制。
7. **有好友但名字识别错**：OCR 可能把生僻字识别错。可以在微信里给该好友设置一个简单清晰的备注名，再重新同步。表头总数（"联系人 N"）可以用来核对是否漏人。

## 5. 消息重复 / 漏字 / 少消息

**现象**：同一条消息出现两次；或文字少几个字、两行粘成一行。

**原因与解决**：

1. **重复**：程序用"好友 + 发送方 + 类型 + 文字 + 画面哈希"做精确去重，并对**3 分钟内文本相似度 ≥0.9** 的消息做模糊去重（修 OCR/剪贴板抖动）。正常情况下滚动不会重复上报；若仍重复，通常是画面轻微变化导致哈希不同（头像动图、表情动画）。可在界面点"清空消息"整理；重复不影响日志排错。
2. **漏字/错字**：文本消息优先用微信"右键→复制"取**精确原文**；如果仍出现错字，多半是精确复制失败后回退到了 OCR。处理：
   - 看日志区是否有"精确复制文本失败"；关掉可能抢占剪贴板/前台的程序再试；
   - 把微信聊天窗口拉大、字体调大，提升 OCR 兜底质量；
   - `config.json` 的 `copy_text_exact` 保持 `true`（默认）。
3. **两行并一行 / 一段拆成多条**：消息切分依赖气泡位置与颜色，窗口缩放、主题切换后可能不完美，属已知限制。
4. **第一次监听时看不到历史消息**：默认 `emit_history_on_start = false`，首次抓帧只建立基线，不会把打开会话前已经存在的消息全部推出来（避免刷屏）。需要历史消息请在微信里往上翻，程序会随后识别。
5. **切走会话后收不到**：工具一次只"看"**当前打开的会话**。同时勾选多个好友时，程序会按 `config.json` 里的 `rotate_interval`（默认 6 秒）轮流切到各好友会话；检测到某个被监听好友有新消息时会优先切过去。若自动切换失败，日志会提示你手动打开该好友会话。
6. **界面消息和微信里对不上**：界面展示的是"程序本地收到的记录"，按好友分视图，不是微信聊天记录的镜像；点击左侧好友名字可查看该好友的本地消息，点右侧"查看全部"回到总视图。

## 6. GIF 动图不显示 / 表情包是静态图

**现象**：收到动图表情/贴纸，界面只显示一帧静态图，或显示占位。

**原因与解决**：

1. **贴纸原文件已解密**：表情包（贴纸）会解密成原始 GIF/PNG，动画 GIF 由 `wxgf`（微信 HEVC 容器）用内置 ffmpeg 转码，保存在 `media/stickers/<md5>.gif`，同时保留 `<md5>.wxgf`。实测 300×318、11 帧，与聊天里显示的表情逐帧对应。
2. **转码失败**：检查是否装了 `imageio-ffmpeg`（`requirements.txt` 有，内置 ffmpeg 7.1）：
   ```bat
   C:\Python314\python.exe -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"
   ```
   没装就重装依赖；转码失败时仍保留原始 `.wxgf`，但没有 GIF 预览。
3. **贴纸匹配失败**：程序用三层策略把"聊天里的贴纸"绑定到"解密出的文件"——最近 180 秒内新增且未使用的贴纸唯一时直接绑定；否则按抽样帧差视觉匹配（优先时间候选，`used` 防重复）；前两名分数太接近时不猜、返回空。**历史回放、多个相似贴纸、缓存文件还没落盘时可能匹配不上**，此时日志会提示"表情包未匹配到原文件"或"按设置跳过截图"，按默认不截图策略不会保存截图，也不会错配。这不是故障，属"宁缺勿错"设计；100% 精确绑定需要读取消息库 md5（列为后续计划）。可稍等几秒重试/重启让表情库重建，或检查日志"表情包库已加载：N 个"。
4. **普通图片/GIF**：图片缓存 `.dat` 解密为原始 `.png/.jpg/.gif`（`media/originals/`）；解密失败时按默认不截图策略不保存图片，只记日志。
5. **不是所有表情都会动**：微信静态表情就是静态图。

## 7. 原文件（文档/图片/GIF/贴纸）、密钥提取、emoji 与聊天记录

**现象**：想确认文档/图片/GIF/贴纸是不是原文件；日志出现"已从微信内存提取图片密钥并缓存"或"未提取到图片解密密钥"；想了解 `log/聊天记录.txt`、emoji 中文名与"不截图"策略。

**原因与解决**：

1. **文档原文件：直接复制**。只读 `Documents\xwechat_files\<你的wxid>\msg\file\<yyyy-mm>\*`（明文），复制到 `media/files/`，保留原文件名；缓存没有（已清理/未落盘）时只保留缩略图与文件名。
2. **图片/GIF 原文件：已实测可解密**。首次需要密钥时，程序从 `Weixin.exe` 内存**一次性只读**提取 `cfgDword + wxId`，派生 AES/XOR 密钥（`md5(str(cfgDword)+wxId)[:16]` / `cfgDword & 0xFF`），解密最近的图片 `.dat` 为原始 `.png/.jpg/.gif`，存入 `media/originals/`。实测解出的 PNG 与微信自带"另存为"导出的原图 **sha1 完全一致**（1727×1246，311021 字节）。
3. **表情包（贴纸）原文件：已实测可解密**。`key = md5(f"{seed}{wxid}EMOTICON").digest()[:16]`（`seed` = `image_cfg_dword`），AES-128-CBC（key=IV、PKCS7）；解出的 PNG/GIF/JPG 原样保存，`wxgf`（HEVC 动画）用内置 ffmpeg 转动画 GIF，同时保留原始 `.wxgf`。文件在 `media/stickers/<md5>.gif / .png / .jpg` + `<md5>.wxgf`；实测 GIF 300×318、11 帧。消息↔文件绑定采用"时间戳唯一→视觉帧差→歧义不猜"三层策略，历史回放/相似贴纸可能绑不上（宁缺勿错）。
4. **密钥提取失败怎么办**：日志显示"未提取到图片解密密钥"时，图片/贴纸无法解密。常见原因：程序与微信**权限不一致**（微信以管理员运行，本程序也要管理员启动）；微信版本升级导致偏移变化；最近没有可校验的 `.dat` 缓存。可在 `config.json` 手填 `image_aes_key`/`image_xor_key`/`image_cfg_dword`（若你有正确密钥），或接受"不保存媒体"。
5. **不想读内存**：把 `config.json` 的 `auto_extract_image_key` 设为 `false` 并重启。之后不会读微信内存；已缓存的密钥仍可用于解密，删掉 `image_aes_key`/`image_xor_key`/`image_cfg_dword` 则彻底失效。
6. **默认不截图**：`allow_screenshot_media=false`（用户要求）。图片/贴纸解不出或匹配不到时不保存截图、不合成 GIF，只在日志警告；仅调试时才建议改成 `true`。
7. **小黄脸 emoji 与聊天记录**：小 emoji 消息直接"右键→复制"，微信返回 `[微笑]` 等中文名；`log/聊天记录.txt`（UTF-8）**严格每行一条**——`好友名: 内容` 或 `我: 内容`，媒体记为 `[图片]/[表情包]/[文件]/[语音]`，无表头/分隔线。`builtin_emoji.py` + `emoji_assets/`（109 个素材 PNG）是可选的图像识别兜底。
8. **会读微信内存或数据库吗**：只会在默认开启的"一次性只读提取图片/贴纸密钥"时读内存（只读、取到即关闭句柄、成功后缓存、之后不再读）；**不写内存、不注入、不 Hook、不打开任何 `.db` 数据库、不改微信缓存文件、不发送消息**。详见 [风控与合规说明](风控与合规说明.md)。
9. **隐私提醒**：`log/聊天记录.txt` 是**明文聊天内容**，`media/originals/`、`media/stickers/` 是原图/贴纸，`media/files/` 是文档原件，`config.json` 含密钥；分享前请清理。

## 8. 最小化微信后不监听 / 消息不更新

**现象**：把微信最小化到任务栏后，程序不再出现新消息，或提示窗口不可见。

**原因**：默认的**数据库直读**不依赖窗口画面，**最小化也能继续监听**；只有在数据库直读不可用、回退到 OCR 模式时，`PrintWindow` 才需要窗口非最小化。

**解决**：

- 先看日志：出现"数据库直读已启用"时最小化不影响监听；出现"数据库直读不可用，继续 OCR 模式"时才需要恢复窗口；
- OCR 回退模式下：程序默认开启 `auto_restore_window`，检测到最小化会尝试**静默恢复**窗口（不抢焦点）；不想自动恢复就把 `auto_restore_window` 改成 `false` 并手动还原窗口；
- 数据库模式也建议保持微信登录、不要退出到登录二维码页；
- 若希望后台运行，数据库直读模式下可以直接最小化，不需要一直盯着界面。

## 9. 杀毒软件 / Windows Defender 拦截或提示

**现象**：双击 run.bat 被拦截；下载/运行时提示"未知发布者""可疑行为"；甚至 `python.exe` 被阻止运行。

**原因**：本程序会"截图 + 模拟点击 + 读剪贴板 + **一次性只读进程内存（扫描图片/数据库密钥）** + 读取本地数据库并解密 + 常驻运行"，这些行为在安全软件的启发式规则里容易被判为可疑；另外 Python 脚本本身没有数字签名。

**解决**：

1. 本项目**完全开源在本地**：所有源码（`app.py`、`wx_core/`、`ui/`、`tools/`）你都能直接查看，可先运行合规自检确认边界（无写内存/注入/Hook/DB 写操作；一次性只读密钥扫描与数据库只读直读会单独列出文件:行号）：
   ```bat
   C:\Python314\python.exe tools\audit_compliance.py
   ```
2. 若确认可信，在安全软件中把**项目目录**和 `C:\Python314\python.exe` 加入信任/排除列表，再重新运行。
3. 若不想触发内存读取告警：把 `config.json` 的 `auto_extract_image_key` 设为 `false`、并把 `db_direct` 设为 `false` 后重启（回退 OCR；文字精度会下降）。
4. 不要从不明来源下载"打包好的 exe"版本——那可能真的含恶意代码；本项目只提供可审阅的 Python 源码。
5. 公司电脑可能有组策略禁止自动化脚本/内存读取，请联系 IT，不要强行绕过。

## 10. 数据库直读（默认模式）

> 默认 `db_direct=true`：程序一次性只读扫描微信数据库密钥，把你自己账号的数据库**解密到本机临时目录**（`sqlite3 mode=ro` 只读）并叠加 WAL 读取。相关说明见 [README 第六节](../../README.md) 与 [风控说明](风控与合规说明.md)。

1. **日志显示"数据库直读不可用，继续 OCR 模式"**：常见原因——程序与微信**权限不一致**（微信以管理员运行，本程序也要管理员启动）；数据库密钥扫描失败（微信版本升级改了结构/最近没有可校验的库）；数据库被占用；好友是**群聊/未在联系人库里找到 wxid**（日志会写"找不到联系人"）。此时程序自动用 OCR 模式，文字精度会下降但功能继续；可重启重试。
2. **数据库被锁 / WAL 竞态**：微信正在写 WAL 时可能暂时解不开最新数据；程序会自动退化为只解主库（数据稍旧但可用），或下次轮询再试。持续失败则回退 OCR。
3. **最小化也能监听吗**：能。数据库直读**不需要窗口画面**；窗口可用时仍会自动切到被监听会话（只影响观感）。同步好友、以及 OCR 回退模式仍需要窗口非最小化。
4. **如何关闭数据库直读**：在 `config.json` 把 `db_direct` 改成 `false` 并重启，即强制走 OCR（截图 + OCR + 剪贴板）模式。
5. **`db_keys` 是什么，能删吗**：它是自动提取的 7 个数据库密钥（key/salt/layout），用于二次启动秒开与解密。属于**敏感信息**，不要分享 `config.json`；删除 `db_keys`（或整个 config.json）后下次启动会**自动重新扫描**（需微信在登录状态、权限一致）。
6. **会回写/修改微信数据库吗**：**不会**。只读解密到本机临时目录、`mode=ro` 读取、只叠加 WAL；不执行 SQL 写操作、不写入微信目录。合规审计会对 SQL 写语句/非只读连接判 FAIL。
7. **临时文件在哪**：系统临时目录下的 `wxdb_*` 文件夹；退出后建议清理残留。

## 11. 其他问题

| 现象 | 可能原因 / 处理 |
|---|---|
| 界面卡顿、点按钮没反应 | 截图/OCR 在后台线程执行；若好友极多、消息极多，可减少监听好友、清理消息、调大 `poll_interval` |
| 自动切换把界面切走了 | 关闭 `config.json` 里的 `auto_switch`（改成 `false`）并重启；手动打开目标好友会话 |
| 收到"语音消息（未接收）" | 数据库直读模式下会显示 `[语音] 2秒`（来自 `voicelength`）；OCR 回退模式只提示有一条语音 |
| 文件消息只有名字/图标 | 数据库直读模式按 appmsg title 从 `msg/file/` 复制原文件到 `media/files/`；找不到（已被清理/未落盘）时只保留文件名与缩略图 |
| 图片/GIF 原文件在哪里 | 数据库直读按消息 XML 的 md5/尺寸精确匹配后解密，保存在 `media/originals/`（原始 `.png/.jpg/.gif`） |
| 表情包（贴纸）原文件在哪里 | 数据库直读按消息 XML 的 md5 精确对应缓存文件，解密到 `media/stickers/<md5>.gif / .png / .jpg` + 原始 `<md5>.wxgf` |
| 数据库密钥/图片密钥是什么、能分享吗 | `config.json` 的 `db_keys`/`image_aes_key`/`image_xor_key`/`image_cfg_dword` 能解密你的聊天数据，属敏感信息，**不要分享/上传**；删除后会自动重扫 |
| 为什么解密失败后没有图片 | 默认不截图（`allow_screenshot_media=false`），解不出原文件时不保存截图、只记日志；调试时可在 `config.json` 临时设为 `true` |
| 小黄脸 emoji 怎么变成中文 | 小 emoji 消息走微信"右键→复制"，微信返回的就是 `[微笑]`；日志/聊天记录里直接显示中文名，零截图 |
| 想导出原图但不想读内存 | 把 `auto_extract_image_key` 设为 `false`，或在微信界面手动"另存为"；也可开 `export_original_media=true` 用窗口消息自动"另存为"（默认关闭、较慢） |
| 贴纸没挂上文件/匹配失败 | 三层匹配"宁缺勿错"：历史回放、多个相似贴纸、缓存未落盘时可能绑定不上；日志会提示"表情包未匹配到原文件"，默认不截图、绝不错配。稍等重试/重启重建表情库；100% 精确需读消息库 md5（后续计划） |
| 聊天记录在哪里、什么格式 | `log/聊天记录.txt`，严格每行 `好友名: 内容` / `我: 内容`（无表头/分隔线）；媒体记 `[图片]/[表情包]/[文件]/[语音]`，emoji 为中文名 |
| 图片/贴纸密钥是什么、能分享吗 | `config.json` 里的 `image_aes_key`/`image_xor_key`/`image_cfg_dword` 能解密你自己账号的图片与贴纸缓存，属敏感信息，**不要分享/上传**；删除后会重新提取 |
| 想看原始记录 | `log/messages.jsonl`（每行一条 JSON）；媒体文件在 `media/`；界面底部有"打开媒体目录"按钮。"清空消息"只清界面，不会删除这些文件 |
| 停止监听后是不是退出程序 | 不是。停止监听只是停掉后台采集线程（OCR/截图线程会释放），界面保留；再点"开始监听"即可恢复。关闭窗口才退出程序 |
| 配置改了不生效 | `config.json` 在启动时读取；改完需重启程序。删除该文件会恢复默认值 |
| 想重置全部数据 | 退出程序后删除 `media/`、`log/` 目录和 `config.json` 即可（只删自己项目里的，别动微信目录） |
| 能不能发消息 | **不能，也不会做**。本工具只读，任何"自动回复/群发"需求都不在范围内 |

仍未解决：把 `log/messages.jsonl`、界面日志区内容（打码后）和问题现象一起反馈；不要在反馈里附带含隐私的聊天内容。

## 12. 802 显示「DeepSeek key 未配置」/ key 存在哪里

- **key 只存本机**，取值优先级：`DEEPSEEK_API_KEY` 环境变量 → `agi/data/secrets.json` →
  `web_config.json`（旧部署兼容，命中会告警一次）。
- 2026-10-29 起，802「模型配置」页可以**直接粘贴 key 并保存**：写入 `agi/data/secrets.json`
  （原子写、ACL 收紧、不入 git、不回传明文），保存后网关热加载，下一条消息生效。
- 如果保存后仍显示未配置：先看是否设了 `DEEPSEEK_API_KEY`（env 优先，且空串也算显式设置）；
  再确认 `agi/data/secrets.json` 可写；最后刷新页面。
- 不要把 key 写进 `web_config.json` 后再提交/外发——迁移后它只做兼容兜底。

## 13. 桌面版弹窗 / 空白窗口 / Edge 提权提示

- **不要用「以管理员身份运行」**：管理员启动会连累 Edge，弹「现有实例正在以提升的权限运行」。
  普通双击桌面快捷方式「小鱼桌面版」即可；启动器检测到管理员会自动改用普通权限浏览器。
- 早期版本会闪一下 PowerShell/黑窗（查询 Edge 窗口状态导致），已改为隐藏执行 + Win32 API 读标题。
- 窗口空白灰底：启动器会检查窗口标题，空白窗会关掉重开；仍失败会回落默认浏览器打开控制台。
- 首次打开 20–30 秒属正常（Edge 独立 profile 冷启动），之后复用窗口秒开。
- 详细说明见 [桌面版](桌面版.md)。

## 14. 发送报「未找到微信窗口 / 未找到微信主窗口」

1. 确认微信 PC 端**已登录**且没退出；
2. 最小化/收进托盘没关系：发送前会自检并自动 `SW_RESTORE/SW_SHOW` 主窗口
   （2026-10-29 起，`wx_core/win.py::ensure_wechat_window_visible`）；
3. 权限要一致：微信以管理员运行时，网关/发送器也要管理员；反之普通启动（推荐）；
4. 还不行就重启微信和 801 网关，再看 `agi/data/wechat/gateway.log` 里的 `send_failed` 原因。


## 15. 微信图片是走本地还是云端识图？怎么切？

2026-10-29 起默认 **本地识图**（省钱）：

1. 收到图片 → 本机 8125 Qwen2.5-VL-3B 生成 1–3 句描述；
2. 描述注入文本提示词 → DeepSeek 只处理文字（不再传图片 token）；
3. 本地失败/超时 → 自动回落旧行为（图片发给云端视觉），消息不会卡住。

开关在网关 `agi/data/wechat/config.json`：

```json
"chat_vision_mode": "local_caption"   // 本地描述（默认）
"chat_vision_mode": "api"             // 图片直接发云端视觉（旧行为）
```

也可用环境变量 `CHAT_VISION_MODE=local_caption|api` 临时覆盖。本地模型不可用时无需手动切，系统会自动回落。

更简单：**802 → 模型配置 → 「聊天图片识图」下拉框**，选「本地 VL 描述 / 云端视觉」，点保存即可（热加载，
几秒内生效，无需重启）。


## 16. 802 对话流怎么切换联系人？数据库/记忆是隔离的吗？

- 对话流左侧「联系人」列表：点谁就读谁的库（`/api/messages?contact=<别名>`）；
- 「刷新列表」重新扫描联系人库；「同步历史」把读取上限提到 500 条并重新读取本地库；
- 不同联系人使用**各自的数据库**（记忆、人格、对话），互不混用；802 的「记忆 / 内状态」页也会跟随当前选中联系人；
- 如果某个联系人**没有数据库、或库里有 0 条消息**，中间会提示：
  「还没有数据库或聊天记录 → 先到 803 工作台创建并训练」，并给 803 入口；
- 「清空聊天」只清空当前页面显示，不删数据库；「清空全部列表」只重置筛选/选中，不删数据。
- 群聊尚未支持（当前是私聊库；后续会把群作为独立库类型接入）。

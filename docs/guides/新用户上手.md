# 新用户上手（从 clone 到第一条消息）

> 面向拿到这个仓库的人：**你需要自己准备微信、API key、Python 环境**，仓库里不包含模型、
> 聊天数据、密钥。本文只写“怎么跑起来”，能力边界以 [README](../../README.md) 为准。
>
> 目前只支持 **Windows 10/11 + 微信 PC 客户端**（收消息走 UIA/数据库直读，发消息走微信窗口）。

最后更新：2026-10-30

## 1. 你需要准备什么

| 必需 | 说明 |
| --- | --- |
| Windows 10/11 + 微信 PC 客户端 | 登录**你自己的**账号；只支持本人账号，不要用于他人的账号 |
| Python 3.12+ | 主进程 3.12/3.14 都验证过；仓库示例命令写的是 `C:\Python314\python.exe`，装别处就换成你的路径 |
| DeepSeek API key | 主对话模型；没有 key 只能走规则/本地兜底 |
| 独立 Python 3.12 venv（发送器） | 发送模块 `wechatauto` 跑在单独 venv 里，主进程不 import wx 系依赖 |
| 一个可写的运行目录 | 默认 `E:\agent`（模型/日志/训练产物），可用环境变量 `AGENT_HOME` 改 |

可选：

| 可选 | 用途 | 不要也行？ |
| --- | --- | --- |
| 本地 llama-server + GGUF | 0.5B 内状态（8123）/ 3B-VL 识图（8125） | 可以，聊天照常，只是没有内状态/本地识图 |
| 803 IDEA 工作台 | 语料清洗/标注/蒸馏/训练/模型中心 | 可以，主链不需要 |
| 桌面版快捷方式 | 一键起 801/802/803 + 托盘 | 可以，手动起服务也行 |
| `~/.dsh/bili-duty` 插件 | B站刷视频/日报/记忆 | 可以，B站相关能力降级 |
| 朋友圈数据 | 读 `sns.db` 与图片缓存 | 可以，没数据就看不到朋友圈 |

> ⚠️ **只在你自己的账号、自己的电脑上使用**。微信自动化有账号风险；不要拿它操作别人的账号，
> 不要把聊天记录/密钥/数据库提交到 GitHub。

## 2. 五步跑起来（最小可用）

> **最省事**：仓库根目录双击 **`启动.bat`**（纯 bat，不依赖 PowerShell）。它会检查环境、
> 缺 Python 自动装（winget/国内镜像）、建主/803/发送器 venv、国内源装依赖，最后启动 803 并打开浏览器。
> 只想检查：`启动.bat -CheckOnly`。
>
> 高级用户仍可用 `setup.ps1`；下面手动步骤用于排查/非 Windows。

### 第 1 步：clone & 安装主进程依赖

```bat
git clone <你的仓库地址> SoulAgent
cd SoulAgent
C:\Python314\python.exe -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 第 2 步：准备发送器 venv（微信发消息必需）

发送器依赖 `wechatauto-replica`（不在主进程环境里装）：

```bat
C:\Python314\python.exe -m venv E:\agent\venv_wx312
E:\agent\venv_wx312\Scripts\python.exe -m pip install wechatauto
```

> 如果 pip 装不到，按 `wechatauto-replica` 仓库说明从源码安装；装完后在
> `agi/data/wechat/config.json` 里把 `wxauto_python` 指到
> `E:\agent\venv_wx312\Scripts\python.exe`（或你实际的路径）。
> 这一步没配好时：**收消息可能正常，发消息会失败/降级**。

### 第 3 步：配置 DeepSeek key

两种方式任选：

1. 环境变量（推荐，不落盘）：

   ```bat
   set DEEPSEEK_API_KEY=sk-你的key
   ```

2. 启动 802 后在「模型配置」页粘贴 key → 保存（只写本机 `agi/data/secrets.json`，不上传）。

### 第 4 步：启动服务 + 配白名单

```bat
:: 网关 801
C:\Python314\python.exe -m agi.wechat_gateway.server
:: 控制台 802（另开一个终端）
C:\Python314\python.exe tools\console\server.py --port 802
```

打开 <http://127.0.0.1:802>。**新用户会看到「加载 Bot」弹层**：填 803 里创建的 Bot 目录 + 密码 →
会自动重启 801/802 到该 Bot 的数据根（不同 Bot 的数据库/记忆完全隔离）。老用户可点「跳过」继续用当前数据。

然后：

1. 右上角填 **admin token**（首次启动会自动生成；在 `agi/data/wechat/config.json` 的
   `admin_token`，或控制台「设置」页复制）；
2. 「设置」→ 配置 `allowed_contacts`（白名单，**空着网关会拒绝发送**）和
   `monitored_contacts`（监听谁）；
3. 建议先把 `send_mode` 设为 **confirm**（草稿确认）或 `dry_run=true`，观察无误再改 auto；
4. 点「开始监听」。

### 第 5 步：验证

- 用**文件传输助手**给自己发一句「在吗」，看 802 有没有收到；
- 在 802「对话流」选中联系人，底部输入框发一条（走 801 manual 发送）；
- 或直接让微信里的好友发消息，看她是否自动回复（取决于 `send_mode`）。

> 首次运行会在仓库内生成 `agi/data/**`（配置/记忆/日志）——**这些都在 gitignore 里，不要提交**。

## 3. 可选能力怎么开

### 3.1 803 IDEA 工作台（数据/训练/标注/蒸馏）

```bat
cd idea
C:\Python314\python.exe -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 803
```

打开 <http://127.0.0.1:803>。没有数据时页面是空的：先在「语料清洗」上传聊天文本/截图，
清洗成“你/我”对话 → 勾选 → 保存数据集；再在「用户标注」打分；最后「训练/模型中心」用数据集训练。
> 803 不依赖微信是否在线；但训练需要本机有对应模型/GPU（或 CPU，慢）。

### 3.2 本地内状态（8123，可选）

1. 下载一个 0.5B 左右 GGUF（或自己蒸馏导出）；
2. 用 `llama-server` 启动到 8123（参考 README 第 4 节）；
3. 802「模型配置」里把 `soul_server_url` 指向 `http://127.0.0.1:8123`；
4. 默认 `inner_mode=off`；要开启内状态注入需在设置里改 `inner_mode`（建议先用 shadow 只记录）。

### 3.3 本地识图（8125，可选）

- 需要 `Qwen2.5-VL-3B` 的 GGUF + mmproj，用 `llama-server --mmproj` 启动；
- 802「模型配置」的「聊天图片识图」默认「本地 VL 描述」；本地服务没起会自动回落云端视觉；
- 也可以在页面切成「云端视觉」。

### 3.4 桌面版（Windows）

- 桌面快捷方式用 `pythonw.exe tools\desktop\launcher.py --tray`；
- 或双击 `启动桌面版.bat`；
- 不要用「以管理员身份运行」（会触发 Edge 提权冲突；启动器会自动回落普通浏览器）。

### 3.5 B站 / 朋友圈

- B站依赖仓库外的 DSH 插件 `~/.dsh/bili-duty`（刷视频/字幕/日报）；没有插件就只显示空页；
- 朋友圈需要本机微信 `sns.db` 与图片缓存；图片解密需要本机密钥（`agi/data/secrets.json` 或
  `agi/data/wechat/config.json` 的 `image_*`）。没有数据时页面为空是正常的。

## 4. 数据、隐私与隔离

- **每个用户的数据都在自己的 `agi/data/**`**：联系人库、记忆、人格、日记、日志、密钥；
- 不同联系人的数据按联系人库隔离（802 对话流切换联系人 = 切库）；
- 唯一的云端调用是 DeepSeek API（聊天/判断/图片理解），没有自建服务端、没有遥测上传；
- `agi/data/secrets.json` 存 DeepSeek key 与微信数据库/图片密钥，**已 gitignore、权限收紧**；
- 备份：直接备份 `agi/data/` 和 `E:\agent`（模型/训练产物），不要备份到公开网盘。

## 5. 常见坑（新用户版）

| 现象 | 处理 |
| --- | --- |
| 802 打不开 / 没 token | 确认 802 进程在；token 在 `agi/data/wechat/config.json` 的 `admin_token` |
| 发消息失败 | 看白名单是否包含联系人；发送器 venv 是否配好；`send_mode` 是否 off/confirm |
| 收不到消息 | 微信要登录；监听联系人要在 `monitored_contacts`；数据库直读不可用会退回 OCR（窗口别最小化） |
| 图片/表情不显示 | 旧 `wx_box` 路径的附件会按文件名回退；找不到文件就只显示标签 |
| 引用消息只显示引用 | 2026-10-29 已修；历史可用 `python tools/backfill_quote_text.py --apply` 回填 |
| 本地识图没生效 | 确认 8125 在跑、模型带 mmproj；802 看「聊天图片识图」是否本地 |
| 想训练但没有样本 | 先用 803「语料清洗」导入聊天记录；门禁要求 ≥300 条可训练样本 |
| 路径写死 `C:\Python314`/`E:\agent` | 用 `AGENT_HOME` 改数据根；Python 换路径后改启动命令/BAT |

## 6. 给开源发布者的待办（当前还不够“一键”）

1. 提供 `requirements-sender.txt` / 安装脚本，自动建发送器 venv 与 `wxauto_python`；
2. 提供 `setup.ps1`：检查 Python/微信/依赖、创建 `agi/data`、生成随机 token；
3. 模型下载脚本（0.5B/3B-VL 的 GGUF + mmproj），并写清许可与校验；
4. CI 跑 offline 测试（当前 CI 只跑一部分，B站/DLL/微信相关不跑）；
5. 把 `C:\Python314`/`E:\agent` 示例路径全部改成 env 变量说明；
6. 版本兼容矩阵（微信 3.9 / 4.x、Windows 版本、Python 版本）。

> 在这几项补齐之前，新用户按本文可以跑通「收发 + 802 + DeepSeek 聊天 + 记忆」，
> 但本地模型/训练/B站/朋友圈属于“按需自己配”。

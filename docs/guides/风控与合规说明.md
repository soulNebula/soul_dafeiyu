# 风控与合规说明（当前实现版）

> 适用：使用本工具的本机用户与审核者。
> 版本：2026-10-29（P0 安全/可移植收敛：密钥外部化 + 留存 TTL + ACL + 口径对齐）
> 说明：早期版本曾把项目描述为纯只读、无发送能力。该描述**已不再成立**。
> 当前版本在用户明确授权下，具备**读取本机微信数据、受控发送消息、可选联网查询**三类能力。
> 本文件按「当前真实能力 → 默认值 → 风险 → 可控手段 → 停止线」描述，避免合规自证失真。
> 所有数字都能在代码/命令里复核，复核方式见 §八。

## 一、当前能力清单（事实）

| 能力 | 具体实现 | 默认状态 | 边界 |
|---|---|---|---|
| 读取微信进程内存（仅取密钥） | `wx_core/wechat_keys.py` / `wx_core/wcdb.py`：`OpenProcess(PROCESS_VM_READ)` → `VirtualQueryEx` → `ReadProcessMemory` 只读扫描 `Config.Cipher`；取到即关闭句柄并缓存 | 开启（`auto_extract_image_key=true`，可关） | 不写内存、不注入、不 Hook、不转储进程 |
| WCDB/SQLCipher 解密 | 逐页 AES-256-CBC 解密到系统临时目录（`wxdb_*`），`sqlite3 mode=ro` 读取；叠加 WAL 增量 | `db_direct=true` | 不写回微信库、不修改微信文件、不向微信目录写文件 |
| 自动发送消息 | 网关 `Gateway._send` → `send_cli` → `WxAutoSender`/wxauto4；`send_mode` 决定行为 | **`dry_run=true`**（只记录不发送）、`auto_reply=false`、`proactive_enabled=false`、`media_enabled=false`；`send_mode` 缺省兜底 `confirm` | 受白名单、STOP、引擎软停、静默时段、频率/日限额、内容检查约束 |
| 读取本机缓存/媒体 | 只读 `xwechat_files` 下 `msg/file`、`msg/attach`、`cache/*/Emoticon`，离线解密图片/贴纸 | 开启 | 不向微信目录写/删/改名 |
| 本地 companion 数据 | `agi/data/**` 自有 SQLite：对话、记忆、草稿、媒体、审计 | 开启 | 与微信数据库隔离 |
| 可选联网查询 | `agi/integrations/web_lookup.py`：天气/新闻/网页检索/链接阅读；命中才查 | `web_lookup_enabled` 控制 | 仅查询，不自动上传聊天记录；DeepSeek 分析属于用户主动操作 |
| 本地网页控制台 | `tools/console/` / `webui/` 本机 HTTP；含人工发送测试接口（仅文件传输助手） | 本机 | 仅 `127.0.0.1`；需 `admin_token`；不公网监听 |

**结论：本项目会发送消息，但默认不发送。** 出厂默认 `dry_run=true` + `auto_reply=false`，
真正的自动发送需要在配置里显式打开。打开之后，发送仍只允许经 `Gateway._send`
（STOP/白名单/静默/频率/内容闸门）。`WxAutoSender`、`send_cli` 是底层原语，只能由网关调用；
**直接调用底层原语视为越界**，`tools/audit_compliance.py` 会标为 unguarded 并 FAIL。

## 二、发送闸门与关键数字（按代码现状）

| 闸门 | 现状（默认值） | 说明 |
|---|---|---|
| 白名单 | `allowed_contacts=[]` → **fail-closed**：拒绝发送，`error=no_allowlist`，审计事件 `send_blocked/no_allowlist` | 空名单**不会**退化成「谁都能发」；主动消息另看 `proactive_contacts` |
| `send_mode` | `off` / `confirm`（默认兜底）/ `auto`；生产建议 `confirm` | `confirm` = 落确认草稿，必须人工 `confirm=true` 批准后才发 |
| 审批 | `/api/approve`、`/api/draft/approve` 要求显式 `confirm=true` + 白名单 | 批准动作本身有审计事件 |
| 频率 | 主动 `rate_per_minute=3`；响应 `reactive_rate_per_minute=8`；`min_interval_s=1.5` | 可按需下调；上调不会绕过白名单 |
| 限额 | `hourly_limit=40`、`daily_limit=200` | 按联系人/全局计数 |
| 静默 | `quiet_hours=[23, 8]`（跨零点语义） | 静默时段不自动发（人工 force 也要显式确认） |
| 停止 | `agi/data/wechat/STOP` 文件存在 → 一切外发停止；`stop=true` 优先 | 见 §七 |
| 内容 | 本机路径/私钥/疑似凭证等正则拦截 | 拦截事件可查 |
| 管理 API | 仅 `127.0.0.1`；`admin_token` 必填；空/`8888`/`admin`/`123456`/`password`/`test`/`token` 等弱口令**不被接受**（启动自动轮换成 32 位随机 token） | 认证走 `X-Admin-Token` 请求头；**不推荐**把 token 放进 URL（当前实现仍兼容 query token，已列为待移除项） |

**兜底发送（fallback）语义：** 窗口/UIA 兜底成功只代表「本机把动作发出去了」，
结果标记为 `unverified=true`、`verified=false`，**不计入 `sent`**，并带
`warning=fallback_send_unverified`。**`ok=true` 不等于对方收到**——这是产品边界，
不是安全承诺。`fallback_enabled` 默认 `false`。

## 三、密钥与隐私（当前实现）

### 3.1 密钥来源（优先级）

1. 环境变量 `DEEPSEEK_API_KEY`（推荐，不落盘）；
2. `agi/data/secrets.json` 的 `llm.api_key`（路径 `SOULAGENT_SECRETS` 可覆盖）；
3. `web_config.json` 的 `llm.api_key`（旧部署兼容，命中时启动告警，日志不含 key）。

`db_keys` / `image_aes_key` / `image_xor_key` / `image_keys_by_account` / `image_cfg_dword`
在迁移后只存 `agi/data/secrets.json`；读取方 `wx_core/config.py`、`webui/llm.py`、
`wx_core/web_search.py` 已接入，**没有密钥文件时行为与迁移前一致**。
迁移工具：`python tools/rotate_secrets.py`（默认 dry-run；`--apply` 只复制 + 收紧 ACL；
清空旧明文必须显式 `--apply --purge-plaintext`，且逐项校验密钥库副本）。

### 3.2 ACL（Windows）

`python tools/harden_acl.py --apply` 对 `config.json`、`web_config.json`、`log/`、`media/`、
`agi/data/`、`agi/data/desktop_profile/`、`.data/`、`star/` 切断继承，只保留
当前用户 / SYSTEM / Administrators（目录 `(OI)(CI)F`，文件 `F`）。
`python tools/harden_acl.py --verify`：仍有 `Authenticated Users` 等不可信主体 → 非零退出。

## 四、数据留存 TTL（可执行）

| 数据 | 位置 | 默认留存 | 清理命令 | 备注 |
|---|---|---|---|---|
| 消息原始记录 | `log/messages.jsonl`（带 `ts`） | 30 天 | `python tools/prune_chat_logs.py --apply` | 默认 dry-run；无法判定时间的行保留 |
| 纯文本聊天记录 | `log/聊天记录.txt` | 整文件超 30 天才删 | 同上 | 逐行**没有时间戳**，无法按行清理（已写入工具说明） |
| 媒体（图片/贴纸/GIF） | `media/` | 30 天 | 同上 | 按 mtime；`wx_core/store.cleanup(keep_days=7)` 另有更短口径 |
| 确认草稿 | `agi/data/wechat/drafts.jsonl` | `draft_ttl_days`（默认 7 天，`drafts.prune`） | 网关启动/新增时自动 prune | 见 `agi/wechat_gateway/drafts.py` |
| 桌面画像/训练派生 | `agi/data/desktop_profile/` | **不自动删** | 手动（先备份） | 删了要重新积累；`prune_chat_logs.py` 只提示 |
| 密钥库 | `agi/data/secrets.json` | 长期 | 手工轮换 | 迁移后唯一的密钥落盘点 |

> 工具的通用口径：**默认 dry-run**、只处理白名单目录、`--apply` 才动文件、
> 删除前打印条数/字节数、无法判断时间的行不删。先看计划再执行。

## 五、用户授权范围

使用者授权本工具在**本人账号、本人设备、本人微信数据**范围内：

1. 一次性只读扫描微信进程内存，仅用于派生本人账号的数据库/图片密钥；成功即缓存，之后不再读内存；
2. 只读 `db_storage/**/*.db`，解密到本机临时目录，以只读方式读取；
3. 只读本地缓存图片/贴纸/文档，产出只写项目 `media/`、`log/`、`agi/data/`；
4. 按配置发送消息（**默认 dry_run + auto_reply=false，不自动发送**；打开后受白名单/STOP/频率约束）；
5. 可选联网查询（天气/新闻/网页）；选择 DeepSeek 分析时，选中的文本/图片会发送到
   `api.deepseek.com`，属于用户主动操作。

授权**不覆盖**：他人账号/设备、批量营销、群发、抓取他人隐私、出售/传播密钥或聊天数据、
绕过微信安全机制，以及任何违法用途。

## 六、风险分级与停止线

### R1 账号封禁 / 风控（高）

- **触发条件**：自动发送频率高、短时间大量会话切换、发送营销/重复内容、向非白名单联系人发送、
  使用非官方客户端 API。
- **现状**：默认 `dry_run=true`、`auto_reply=false`、`proactive_enabled=false`；
  打开后仍有 `allowed_contacts`、STOP、静默时段、`rate_per_minute=3`/`reactive_rate_per_minute=8`、
  `hourly_limit=40`、`daily_limit=200`、主动 pacing 等闸门；但不等于微信官方认可。
- **可控手段**：只保留必要联系人；优先 `send_mode=confirm` 或 `draft`/`manual`；降低频率；
  开启 `dry_run` 验证；不使用群发/营销；不与其他自动化脚本并行。
- **停止线**（满足任一必须停止自动发送）：
  1. 微信出现"登录异常/账号受限/操作频繁"等提示；
  2. 收到平台警告或账号被限制；
  3. 需要向非本人授权联系人发送；
  4. 需要批量/营销/定时群发。
- **停法**：`agi/data/wechat/STOP` 文件（最硬）、`config.json` 设 `stop=true`、`send_mode=off`，停止网关。

### R2 隐私 / 数据泄露（高）

- **触发条件**：`config.json`/`secrets.json` 中密钥泄漏、项目目录/临时解密库被分享、
  日志/媒体被同步到网盘或仓库、在多人共用电脑/远程桌面运行。
- **现状**：可读取本人聊天、图片、文件；迁移前 `config.json` 可能含 `db_keys`/`image_*`；
  `log/`、`media/`、`agi/data/` 含明文内容；解密临时目录可能残留。
- **可控手段**：仅本人设备；`harden_acl.py --apply` 收紧权限；把密钥迁到 `secrets.json` 并轮换；
  设留存 TTL（§四）；不提交 `config.json`/`log/`/`media/`/`agi/data/`；定期清理 `wxdb_*`；
  关闭不必要的 `trace`/公网控制台。
- **停止线**：
  1. 设备/账号非本人或共用；
  2. 密钥/聊天记录/项目目录离开本机；
  3. 出现未授权访问（控制台暴露公网、token 泄漏）；
  4. 需要把数据交给第三方或用于训练外部模型（未获明确授权）。

### R3 法律与平台规则（高）

- **触发条件**：监控他人、商业营销、出售数据/密钥、绕过付费/权限、违反《微信软件许可及服务协议》
  或所在地个人信息保护法规。
- **现状**：本项目为个人本机辅助工具；不提供云端多租户；文档明确仅本人授权范围。
- **可控手段**：只处理本人数据；保留授权记录；不对外提供服务；不用于商业用途。
- **停止线**：任何非本人授权场景、商业分发、数据交易、规避平台安全机制——立即停止并删除数据。

### R4 自动化误发 / 内容事故（中）

- **触发条件**：模型生成错误内容、重复发送、发错联系人、干跑配置与正式配置混用。
- **现状**：出站有内容检查、STOP、白名单、频率限制、`confirm` 草稿/确认模式和失败草稿；
  兜底发送标记 `unverified`（不等于送达）；仍可能发生误发。
- **可控手段**：先 `dry_run=true`；用 `send_mode=confirm` 人工确认；小范围联系人；
  监控 `agi/data/wechat/gateway.log` 的 `proactive_send` / `send_failed` / `send_blocked` /
  `fallback_unverified`。
- **停止线**：出现误发/重复发送/发错人，或模型输出明显不当——立即 STOP，暂停自动回复。

### R5 记忆/密钥/临时库残留（中）

- **触发条件**：临时解密库未清理、备份文件含密钥、旧版本目录残留、迁移后旧明文未清空。
- **可控手段**：退出清理 `wxdb_*`；备份加密；迁移后 `--purge-plaintext` 清空旧字段并轮换 key；
  用 `python tools/check_secrets.py` 确认仓库里没有密钥。
- **停止线**：发现密钥或解密库出现在非预期位置——停止使用并清理。

## 七、硬边界（当前仍然禁止）

1. **不写微信进程内存、不注入 DLL/代码、不 Hook（SetWindowsHookEx 等）、不做 minidump/调试转储**；
2. **不写回/修改微信数据库**：SQL 连接必须 `mode=ro`，不执行 INSERT/UPDATE/DELETE/DROP/CREATE/ALTER/ATTACH/VACUUM；
3. **不向微信安装目录/微信数据目录写、删、改名任何文件**；
4. **不向未授权账号/设备发送**；发送只能走受控 `Gateway._send` 路径；
5. **不批量营销/群发、不抓取他人隐私、不出售/传播密钥或聊天数据**。

审计脚本 `tools/audit_compliance.py` 会扫描禁止 API、微信目录写入、发送路径与文档一致性；
发送路径区分为 allowed（受控入口）与 unguarded（无闸门直调），后者 FAIL。

## 八、停止与回滚操作 + 合规自检

停止（从硬到软）：

1. 紧急停止：创建 `agi/data/wechat/STOP`（存在即停一切外发）；或 `config.json` 设 `"stop": true`；
2. 停止自动回复/主动：`engine_enabled=false` 或 `auto_reply=false`；
3. 关闭自动发送：`send_mode="off"`（或 `confirm` 人工确认）；
4. 关闭数据库直读：`db_direct=false`，回退窗口/OCR（能力降级，风险降低）；
5. 关闭进程内存扫描：`auto_extract_image_key=false`，不再提取新密钥；
6. 停止本工具：停止网关/控制台/桌面进程，删除临时 `wxdb_*`，按需清理 `log/`、`media/`；
7. 回滚版本：使用 git 历史恢复到旧版本；旧版本能力更少但同样不保证平台合规。

合规自检（复制即用）：

```bat
python tools/audit_compliance.py         :: 越界 API / DB 写入 / 未受控发送 / 文档冲突
python tools/check_secrets.py            :: git 已跟踪文件里有没有 key（exit 1 = 有）
python tools/harden_acl.py --verify      :: 敏感目录 ACL（exit 1 = 未收紧）
python tools/prune_chat_logs.py          :: 留存 TTL 计划（默认 dry-run）
python tools/rotate_secrets.py --dry-run :: 明文密钥迁移计划（默认 dry-run）
python -m pytest tests -q                :: 离线回归
```

- `audit_compliance` 输出 `PASS` 且退出码 0：无越界 API/DB 写入/微信目录写入，发送路径均为受控入口，
  文档未与代码冲突；`FAIL`（退出码 1）需先修复再发布。
- `check_secrets` 只扫 **git 已跟踪** 文件：本地有密钥不算失败，密钥进了仓库才算。
- 授权只读项（密钥扫描、数据库只读、缓存只读、发送受控入口）会在报告中按文件:行号列出，
  不代表"无风险"，只代表在授权边界内。

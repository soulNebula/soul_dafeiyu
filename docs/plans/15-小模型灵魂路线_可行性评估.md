# 15 · 「小模型灵魂 + 大模型智慧」路线：可行性判断与落地方案

> ⚠️ **2026-10-24 修订**：硬件（实为 RTX 4050 6GB，非 4060 8GB）、延迟基线（现状中位 6.0s，非 1.2s）、起点（wx_box 已有 `agi/selflearn` 实现）三项已由 [18-wx_box合并评估.md](18-wx_box合并评估.md) 更正，**以 18 为准**。

> 本文**不修改** 00–14 任何设计，只回答四个问题：**方案是否可行 / 怎么做 / 会遇到什么 / 值不值得现在做**。

## 零、一句话结论

**架构可行，但顺序反了。**

「小模型生成内心状态 → 注入大模型」值得做，而且可以和现有设计无缝对接；
但「每周 LoRA 微调」在目前的数据量、归因方式和评估条件下**不可行**，它会把一个可验证的系统变成每周随机漂移的黑箱。

正确顺序是：**先做「独白层 + 评估台」（2–4 周，几百元），把 LoRA 推到 3–6 个月后，且只让它学「腔调」。**
这与 00 文档 D1「v1 不做微调」并不冲突——00:27 原话就是：**「微调唯一值得做的地方，是说话腔调……是最后一步的锦上添花，不是地基。」**

## 一、先对齐目标：你要的其实是两条不同的路

现有 15 份文档描述的是 **B 路线：微信伴生助手**——核心指标是「记得准、可查、可删、不编」（02:339-347）。
你的提案更接近 **A 路线：养成型伴侣**——核心指标是「它像不像一个有自己脾气的人」。

| | B · 微信伴生助手（文档 00–14） | A · 养成型伴侣（本次提案） |
|---|---|---|
| 地基 | 证据链（02:104-130 七道闸门） | 反馈闭环 + 评估台 |
| 学习单位 | 记忆条目 / 策略变体 | 模型权重 |
| 成功标准 | 记忆准确率 ≥98%、编造 <1% | 「它第一次说出只有你们懂的话」 |
| 失败方式 | 记错人、编造事实 | 变成一个模板化的讨好机器 |
| 周期 | 15 周（05:12-71） | 以月/年计 |

**这两条路不冲突，但地基不同。** 如果你的真实目标是 A，那么文档里的微信采集、朋友圈理解、封号风险（05:93-116 R1）都是**过度设计**；
如果目标是 B，那「内心独白」是锦上添花，不能当地基。

> 这是做任何技术决策前**唯一必须先回答的问题**（见 §十一 Q1）。

## 三、判断 J1：架构可行，但「灵魂」不在小模型权重里

### 3.1 文档其实已经把「内心独白」做掉了

03 文档在线链路第 4 步（03:18-19, 26-40）：

```json
{
  "read": "用户连着加班三天，说'累'，不是求方案，是想被看见",
  "approach": "先接住情绪，不追问工作，不给建议",
  "steps": ["承认累", "说一句具体的观察", "留白，等他继续"],
  "length": "short",
  "avoid": ["加油", "早点休息"]
}
```

这就是「内心独白」的工程版本：**先想清楚这轮该怎么聊，再开口。**
它约束了「想什么」，把「怎么说」留给大模型。

**关键推论：你的独白层不应该新增一次 LLM 调用，而应该替换/扩展这一步。**
否则每轮两次「思考」（小模型独白 + 大模型策略草稿），延迟直接翻倍，还会出现两个互相矛盾的内心声音。

建议改成：小模型一次调用同时产出 `strategy`（沿用 03 的 JSON 结构）+ `monologue`（一句人话）。

### 3.2 为什么「灵魂在权重里」不成立

09 文档开篇就否掉了「让模型自由发挥情绪」这条路（09:31-35）：

> **错误做法**：让模型自由发挥「我好难过」，结果每次情绪强度随机，前后不一致。
> **正确做法**：情绪是一组**可观测、可演化、可恢复**的状态变量，影响行为参数。

原因很硬：小模型没有你的记忆，也没有上一轮的状态。你能给它的一切，都是你**注入**进去的。
所以：

- 「它此刻什么情绪」→ 由 09 的状态机（warmth/energy/openness/patience/trust）按事件和半衰期演化；
- 「它和他是什么关系」→ 由 10 的信任账本（Mood / Trust / Memory 三层）决定；
- 「它记得什么」→ 由 02 的检索决定；
- 小模型做的，是把这些**渲染成一句有它自己措辞的话**。

一句话：

> **灵魂 = 结构化状态 + 关系账本 + 记忆；嗓音 = 小模型；智慧 = 大模型。**

这也正好解释了为什么 00:27 说「微调只值得学腔调」——腔调就是嗓音，不是灵魂。

### 3.3 正确的分工表

| 层 | 由谁负责 | 是否可解释 | 是否可回滚 | 对应文档 |
|---|---|---|---|---|
| 情绪强度/衰减 | 规则引擎（确定性公式） | ✅ | ✅ | 09:68-95 |
| 信任/记仇 | 账本表 + 规则 | ✅ | ✅（只追加） | 10:17-29, 128-143 |
| 记忆/事实 | RAG + 证据链 | ✅ | ✅ | 02:104-130 |
| 这轮怎么说（策略 + 独白） | **本地小模型** | ⚠️ 半可解释 | ✅（换 prompt） | 03:26-40 |
| 最终回复 | 云端大模型 | ⚠️ | ✅ | 03:91-114 |
| 腔调（长期） | 可选 LoRA | ❌ | ⚠️ | 00:27 |

## 四、判断 J2：每周 LoRA —— 现阶段不可行

### 4.1 先算一笔数据账

按你的节奏「每天聊 30 分钟」：

| 项 | 估算 |
|---|---|
| 每天轮次（一问一答算一轮） | 30–50 轮 |
| 每周轮次 | 200–350 轮 |
| 有**隐式**信号的轮次（继续/换话题/回复间隔） | 10–20% → 20–70 条 |
| 有**明确显式偏好**的轮次（👍/👎/二选一） | 0.5–3 条/天 → **3–21 条/周** |
| 切 20% 做验证集后 | 训练 16–56 条 |
| 你计划的目标 | 50–100 条/周（**等于把全部样本都用上，没有验证集**） |

而 04 文档自己划的线是（04:167-170）：

```
0–50 轮     人工标 30 轮做锚点
50–300 轮   隐式信号为主
300+ 轮     全信号融合
2000+ 轮    才"可考虑做 DPO"
```

**每周微调意味着在第 2–4 周（200–700 轮）就开始改权重，比文档的门槛早了一个数量级。**

更要命的是**真实反馈率**：自用场景的 👍 大概 0.5–3 次/天（只有极端体验才点），攒 100 条干净样本要 **1–3 个月**。
也就是说：**「每周训练一次」和「每周攒够 50–100 条干净样本」在数学上互斥。**
你会被迫拿「沉默」当负样本、拿「没点」当差评，于是学到的第一个特质是「少说话」。

### 4.2 公开实测：数据不够时，微调方向不可知

一份 2026-08 的 Qwen3-4B QLoRA 中文实测（[链接](https://robertsong2019.github.io/posts/qwen3-lora-benchmark-2026-08.html)）值得逐条看：

| 观察 | 数字 |
|---|---|
| 数据量 | 1000 条（比你的周预算大 10–50 倍） |
| 训练步数 | 3 epoch = 180 步 |
| **过拟合起点** | **step 50（约半个 epoch）**，val loss 1.361 |
| 训练结束 | val loss 1.439（train 降到 1.05） |
| 微调后通用能力 | 回答平均缩短 55%，结构化/创意/深度**全面下降** |
| 结论 | 「LoRA 让模型变差」——因为训练数据的风格比基座原有偏好差 |

这份实测最大的价值不是「微调可行」，而是证明了：**没有 base vs LoRA 的对比测试，你根本不知道微调是变好还是变坏。**
1000 条尚且如此，50 条只会更快过拟合、方向更随机。

### 4.3 归因错了：你在用 A 的评分训 B

你的闭环是：

```
小模型出独白 → 大模型出回复 → 用户 👍 → 这个 👍 用来训小模型
```

中间隔着一个黑箱（大模型）。👍 是对**最终回复**打的，你却把它当成**独白**的标签。
这叫 credit assignment 错误。结果可以预测：

> 小模型会学到「生成那种能让大模型写出讨好回复的独白」——而不是「表达真实情绪」。

这与 04:149-159 的 reward hacking 清单、13:253-256 的「模型自己生成、自己评判、自己学习 → 三个月后变成自信的傻子」是同一个病，只是换到了权重层。

**干净的训练信号只有一个来源**：同一上下文下，**独白 A vs 独白 B 的成对比较**——看哪个独白导致更好的回复。
而这个实验你现在还没做（见 §十，1 天就能做）。

从数学上看，这不是监督学习，是**奖励只有 1 bit 的 bandit**，而且 credit 要穿过一个冻结的黑箱。
SFT 过滤（只拿高分样本训练）≈ 用 bandit 的 argmax 做模仿学习，它成立需要两个前提：

1. 每个 context 采**多个**候选（你现在每轮只采 1 个）；
2. 奖励**确实由被优化的变量决定**（回复质量主要由大模型自身和话题决定）。

两个都不满足。

**最尖锐的推论**：一个被优化去 steer 冻结模型的最优独白，会收敛到一个**近似常量**。
到那时你得到的就是一段手写的 system prompt，只是多付 2–8s 延迟和一个不可审计的中间层。
所谓「长出来」，其实是**低效的 prompt 搜索**。

> 如果坚持要训：别做 SFT 过滤，直接对 👍/👎 做 **KTO/ORPO**（二值），或对成对数据做 **DPO**。
> 同样 50–100 条，偏好优化的信噪比高于「挑好的做 SFT」，而且不浪费负样本。

### 4.4 没有评估台，训练 = 随机漂移

13 文档写得很明白（13:155-175）：

- 黄金集 100–200 条，两人独立标注，**冻结 3 个月**；
- 自动指标与人工相关性 ≥0.6 才可用于决策（13:318）；
- 每次换模型跑回归，**掉分 >2% 回滚**（13:321）。

没有黄金集，你无法回答「这次微调之后它变好了吗」。
每周训练 + 无法评估 = **每周换一个随机方向**，而且旧版本无法复现（权重被覆盖）。

### 4.5 与删除权直接冲突

02:327-335 的 `forget()` 要求：删记忆时必须同步清 `mem_episodic` → `mem_semantic` 引用 → 向量索引 → `raw_item` → 媒体文件。
05 的风险登记册把「隐私泄露 / 越权」「个人信息保护」列为极高影响（05:94, 99）。

**权重里的信息删不掉。** 一旦小模型在个人聊天上微调，你无法知道它记住了什么、记错了什么、换个人会不会串味——这正是 00:26 反对微调的原始理由。

> 如果最终还是要做 LoRA：训练数据必须**只含风格，不含事实原文**，做 PII 清洗，且永远不拿它当记忆来源。

### 4.6 但训练本身真的很便宜（成本不是主要问题）

arXiv 2509.12229 是 RTX 4060（8GB）+ Qwen2.5-1.5B 的 LoRA/QLoRA 实测（[链接](https://arxiv.org/abs/2509.12229)）：

- paged optimizer 把吞吐从 500 tok/s 提到 **628 tok/s**；
- 8GB 约束下，seq length 到 **2048** 仍可行。

按 628 tok/s 粗算：1000 条 × 300 token × 3 epoch ≈ 90 万 token ≈ **24 分钟**；50 条 ≈ **1–2 分钟**。

**所以「几十元/次」这个说法是错的：电费约 0.01–0.1 元/次**（4060 满载 ~100W × 0.2h ≈ 0.02 kWh）。贵的是人：

| 成本项 | 真实耗时 |
|---|---|
| 训练 | 1–30 分钟（电费 ≈ ¥0.02） |
| 数据整理 + 去重 + PII 清洗 | 0.5 天 |
| 评估（黄金集 + 一致性 + 回归） | 0.5–1 天 |
| 可能的方向性错误 / 回滚 | 0.5 天 |
| **合计** | **每次 1.5–2 人天** |

按 ¥200/小时折算，每周一次 ≈ **¥2,400–3,200/周 + 每月 6–8 个工作日**。
这才是「每周微调」真正的代价——它挤掉的是你所有别的进度，不是电费。

4 个按钮比 2 个按钮信息量大得多，而且「说错了」直接接 02 的 correction 流程，「不像你」直接接 02:287-294 的人格漂移检查。

## 六、判断 J4：硬件与延迟

### 6.1 你的选型表两处要改

| 你的表 | 现实（2026） | 结论 |
|---|---|---|
| Qwen 2.5-1.5B | 已被 Qwen3-1.7B 取代（更新的中文与指令跟随） | 换 Qwen3-1.7B |
| TinyLlama 1.1B | 2023 年模型，中文能力弱 | 不推荐 |
| Phi-3 Mini 3.8B | 已被 Qwen3-4B 取代 | 换 Qwen3-4B |
| 「7B QLoRA，4GB 显存就能微调」 | ❌ 不成立。8GB 上 7B 极限压到 seq≤768、bs=1（峰值 7.2–7.9GB），桌面一开就 OOM | 8GB：1.7B 宽松、4B 压 seq、7B 极限；建议 1.7B |
| 「电费+算力几十元/次」 | ❌ 电费实际 ≈0.01 元，被高估约 3 个数量级 | 真实成本是人力，见 4.6 |

**如果你只有 4060 8GB：选 Qwen3-1.7B，别贪 4B。** 独白是短文本（≤120 token），1.7B 完全够；4B 的收益主要在推理，不在措辞。

### 6.2 延迟才是硬伤（这是整个方案最现实的工程冲突）

03:189 的延迟目标是 **首字 P50 < 1.2s / P95 < 3s**。

同步跑独白：

```
用户消息 → [小模型独白] → [大模型首字 1–2s] → 用户看到字

  1.7B · 100 token：1.5–3.0s（4060 实测 60–90 tok/s）
  4B   · 100 token：2.5–4.0s
  7B   · 100 token：5–8.0s（8GB 下还要祈祷不 OOM）

合计 3–5.5s，是 P50 目标的 3–4 倍。
```

> 注意：Windows 桌面 + 浏览器常驻会吃掉 0.5–1.5GB 显存，8GB 卡实际可用只剩 6.5–7GB。
> **训练与 7B 推理不能同时存在**，换模型要重载。

**解法：把独白从「对话前」改成「对话后」。**

```
第 N 轮回复发出
  → 异步：小模型更新状态 + 生成本轮独白 + 预渲染第 N+1 轮的 <inner_state>
  → 缓存进 state 表
第 N+1 轮用户消息到达
  → 直接读缓存注入，0 延迟
```

这同时更符合 09/10 的设计：状态本来就是**由事件驱动更新**的（09:68-95 状态机、10:200-204 联动规则），不是每轮从零重算。
只有三种情况需要实时重算：用户消息触发强情绪事件、状态变化超过阈值、话题突变。

## 七、判断 J5：涌现不能承诺

你说「没有固定数据集框定它，保留涌现」。
但**小样本 LoRA 恰恰是最强的框定**：

- 50–100 条样本把输出分布收窄到少数模板 → 多样性（distinct-n）下降；
- 训练目标是「用户喜欢的」，而不是「它想说的」→ 讨好化（04:149-159、09:26）；
- 00:52-56 已经把「无监督自我进化」列为做不到：**会退化成自恋 + 幻觉自我强化**。

真正的「意外时刻」更可能来自：

> 状态变量的连续变化 × 记忆检索的组合 × 大模型的高温采样 × 不同的对话时机

——也就是**同一个权重、不同的上下文**，而不是「换了权重」。

所以「涌现」应该当**观察指标**，不能当**项目目标**。可以监控的是：独白多样性、主动行为命中率、关系阶段推进速度。

## 八、实际方案：三阶段 + 一个硬门槛

### 阶段 0 · 定义契约（2 天，不写训练代码）

先把「内心状态」定义成**结构化数据**，不是自由文本。理由：可注入、可测试、可回滚、可解释。

```python
@dataclass
class InnerState:
    mood: dict[str, float]        # warmth/energy/openness/patience/trust, 0..1
    stance: str                   # 想靠近 / 想独处 / 想逗他 / 懒得聊
    intent: str                   # 想说什么 / 想问什么 / 什么都不想说
    monologue: str                # ≤40 字，第一人称
    behavior: dict[str, str]      # {"length":"short","ask":"false","emoji":"none"}
```

数据表（与 02 的 `turn` 表并列，不改动它）：

```sql
CREATE TABLE inner_state(
  id TEXT PRIMARY KEY,
  subject TEXT NOT NULL,
  turn_id TEXT,
  ts REAL NOT NULL,
  state_json TEXT NOT NULL,      -- InnerState 序列化
  monologue TEXT NOT NULL,
  model TEXT, seed INTEGER, latency_ms INTEGER,
  accepted INTEGER,              -- 用户是否点了"不像你"
  prev_state_id TEXT,            -- 演化链，可回放
  created_at REAL NOT NULL
);
```

**验收**：同一段对话回放 10 次，状态序列的终点差异 < 0.1（说明不是随机漂移）。

### 阶段 1 · 独白层 MVP（1 周，不训练）

| 组件 | 选型 | 理由 |
|---|---|---|
| 本地推理 | Ollama + `qwen3:1.7b`（Q4_K_M） | Windows 友好，5 分钟装好；也可换 llama.cpp |
| 触发 | 每条回复发出后**异步** | 见 6.2，延迟归零 |
| 输出约束 | JSON Schema / GBNF grammar | 1.7B 裸奔会输出废话，必须硬约束 |
| 注入 | `<inner_state>` 150–250 token | 对齐 09:202 的 150 token 预算 |

**Prompt 模板（可直接用）：**

```
你是「它」的内心。只输出 JSON，不要解释。

<persona_core>（400 token 内，来自 02:262-273）</persona_core>
<state>warmth .62 / energy .35 / patience .70 / trust .75</state>
<relation>见过 3 次，他最近在找工作，别主动提</relation>
<memory>Top-3 条，带 id</memory>
<last_turns>最近 3 轮</last_turns>
<user_msg>今晚又得加班</user_msg>

输出：
{"mood_delta":{"energy":-0.1},"stance":"想陪一会儿","monologue":"他今天声音是哑的，别问工作。","behavior":{"length":"short","ask":"false"}}
```

**注入格式（关键：翻译成行为指令，不是情绪描述）：**

09/10 文档反复强调：**情绪必须落到可执行的行为上**（10:169-170：「我心里不好受」是无效注入，「别先交底」是可执行的）。

```xml
<inner_state>
你现在：有点累，耐心还行，但还是愿意听他说。
所以：回复不超过 2 句；不要问工作；不要给建议；可以带一点自嘲。
</inner_state>
```

**两个必须注意的坑：**

- **别把它拼进 system 的固定前缀。** 会破坏 prompt caching（成本↑），而且独白占据最高注意力位置，行为反而更不稳。建议放在 system 之后的**独立块**或单独一条 user 消息，system 前段保持字节级不变以命中缓存。
- **注入升级风险。** 独白由小模型读用户消息生成、再进入 system 层，等于把用户可控文本提升成系统指令。必须限制：长度上限、禁止第二人称命令句、`<inner_state>` 标签转义、只允许白名单字段。

**需要改的一处现有设计**：03:26-40 的「策略草稿」原本由大模型生成。阶段 1 应把它移到小模型，一次调用同时产出 `strategy + monologue`，否则每轮两次思考。

### 阶段 2 · 评估台（2 周，必须做）

| 产物 | 要求 | 出处 |
|---|---|---|
| 黄金集 | 100–200 条，分层抽（按情境桶），双人标，冻结 3 个月 | 13:157-175 |
| 成对偏好 | 同一上下文两个回复，盲评、随机顺序、**不同模型当裁判** | 13:119-142, 185 |
| 自动指标校准 | 与人工相关性 ≥0.6 才能用于决策 | 13:209-217 |
| 一致性测试 | 20 题，隔 7 天问两次，一致率 ≥85% | 02:306 |
| 回归门槛 | 掉分 >2% 回滚 | 13:321 |

**核心实验（决定后面所有事）：**

直接做 **§十 的四条件消融**（A 裸 prompt / B 手写静态人格 / C 自由独白 / D 结构化状态）。
判据：`C vs B` 的 95% CI 跨过 50% → 不建独白层；`D vs C` 更好 → 走结构化状态。
这一步不过，后面所有 LoRA 都是沉没成本。

### 阶段 3 · LoRA（硬门槛全过才做）

**准入门槛（缺一不可）：**

1. 累计真实对话 ≥ 2000 轮（04:170）；
2. 黄金集已冻结，自动指标相关性 ≥0.6（13:318）；
3. 独白 A/B 胜率显著 > 55%；
4. 有回滚能力（adapter 版本化 + 一键切回）；
5. 训练数据做过 PII 清洗，只含风格、不含事实。

**训练配置（8GB 可用）：**

```yaml
base: Qwen3-1.7B-Instruct       # 或 Qwen3-4B（需压 seq/bs）
method: QLoRA 4bit nf4 + double_quant
lora: {r: 16, alpha: 32, dropout: 0.05, target: [q,k,v,o,gate,up,down]}
train: {epochs: 2-3, bs: 1-2, grad_accum: 8, lr: 2e-4, scheduler: cosine,
        seq_len: 1024, bf16: true, grad_checkpoint: true}
save: load_best_model_at_end=True     # 小数据必须 early stop
seeds: 2                              # 100 条 / eff-bs8 ≈ 12 步/epoch，单 seed 由数据顺序决定
数据: 70% 独白样本 + 30% 通用指令（防遗忘）
loss_mask: 只计算 assistant(独白) 部分，system/user 不参与 loss
```

**部署与评估：**

- **不要 merge 权重**：base 冻结常驻，adapter 版本化；vLLM multi-LoRA / PEFT 同 base 多 adapter，按 request 指定 → 秒级回滚、零重载；
- 每个会话 pin 住 `adapter_id + base_hash + prompt_template_hash`，逐轮记录；
- **月度合并，不要每周**：用户对「昨天还那样、今天变了」极其敏感；
- 灰度 10% 流量（04:140），n≥20 且显著优于基线才合并（05:137 Q5）；
- 每次训练前后跑：黄金集、20 题一致性、独白多样性（distinct-2）、格式失败率、50 条指令跟随回归；
- 任何一项掉分 >2% → 回滚。

> **别用 👍 做 A/B**：p=0.05、δ=0.02 时需要每臂约 1900 轮，个人项目永远到不了。
> A/B 只用于护栏指标（延迟、报错率、安全拒答率）；人格质量走离线 eval。

## 十、如果现在只做一件事：1 天消融实验

**不要先搭训练管线，先证明「独白比一段手写 prompt 更强」。**

关键不是「有独白 vs 没独白」——那只证明「给点情绪提示有用」，谁都知道。
真正要证的是：**小模型动态生成的独白，是否胜过一段手写死的静态人格 prompt。** 如果打平，整条路线可以立刻砍掉。

取 100 个真实 context（覆盖不同情境桶），固定大模型、固定解码参数，四种条件各生成一次：

| 组 | 条件 |
|---|---|
| **A** | 裸 system prompt（无独白、无人格描述） |
| **B** | 人手写的**静态**人格 prompt（固定一段，描述它的脾气） |
| **C** | 小模型**自由独白**（本提案） |
| **D** | 小模型**结构化状态**（JSON：mood/stance/intent/behavior） |

盲评 pairwise（随机顺序、不告诉评者分组），100 对，至少 2 人或 1 人 + 独立裁判模型校准。

**判据（先定后跑）：**

- `C vs B` 胜率的 95% 置信区间**跨过 50%** → **整条「独白中介」路线立即砍掉**，省下几个月管线；
- `D vs C` 显著更好 → 走结构化状态（也更好审计、更好回滚）；
- `C` 显著优于 `A` 但打平 `B` → 说明有价值的是「人格描述」本身，不是小模型。

**成本：1 天 + ~400 次 API 调用 + 0 次训练。**
顺带算出「独白能解释多少评分方差」（R²）——这是本方案**唯一真正的可行性数字**。

> 工程经验预测：`C vs B ≈ 50–55%`，区间跨 50。
> 真如此，后面所有关于 LoRA 的问题都不用回答了——你会在给一个不存在的机制做年度微调。
>
> 方法论与 08 文档的 E0 一致：先用最小实验证明「学得会」，再谈系统（08:79-140）。

## 一句话收尾

> **你要的不是「每周换一个权重」，是「每周更懂他一点」。**
> 后者靠状态、记忆和反馈就能做到，而且今天就能开始；
> 前者要等评估台建好、数据攒够，才轮得到它上场。

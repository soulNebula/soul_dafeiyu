## 零、这份方案改了什么

| 原提案 | 改成 | 为什么 |
|---|---|---|
| 小模型承载「灵魂」 | 小模型承载「**嗓音**」（状态 → 措辞） | 灵魂是状态 + 记忆，不在权重里（09:31-35） |
| 每轮对话**前**生成独白 | **状态卡每轮零延迟注入；独白只在关键轮次并行生成** | 保 03:189 的 P50 延迟 |
| 自由文本独白 | **结构化 JSON**（appraisal / delta / stance / monologue / behavior） | 可测、可回滚、可兜底 |
| 每周 LoRA 换模型 | **每周「成长仪式」**：提案 → 灰度 → 写进人格文件与变体统计 | 50–100 条学不到人格，且无法评估 |
| 👍 / 👎 | **成对比较 + 四选一失败类型** | κ 0.7–0.8 vs 0.3–0.4（13:112-117） |
| 「性格长出来」 | **涌现观察日志**：只记录、不承诺 | 不可承诺（00:52-56） |

**一句话：把「改权重」换成「改状态 + 改措辞 + 改策略」，成长节奏不变。**

## 一、范围与非目标

### 做什么（v1）

1. 一个**确定性状态引擎**：每轮根据事件更新 5 维情绪 + 关系信任；有上限、有衰减、有危机清零。
2. 一个**本地嗓音渲染器**：小模型把「状态 + 记忆 + 用户这句话」渲染成结构化独白；失败时模板兜底。
3. 一次**注入改造**：把渲染结果作为独立块注入大模型 prompt，不破坏缓存、不破坏 03 的校验链路。
4. 一套**评估台**：黄金集 + 四条件消融 + 成对比较 + 一致性测试。
5. 一套**成长日志**：每周可读的改动记录，每条可追到具体对话。

### 不做什么（v1）

- ❌ 不改任何模型权重（LoRA 在 v3，见 §11）
- ❌ 不接微信发送（封号是必然风险，05:115）
- ❌ 不做多用户（先单用户跑通，05:140 Q8）
- ❌ 不做「自主涌现」承诺
- ❌ 不做自动刷朋友圈/主动分享（v2 的 11/12 文档范围）

| 项 | 默认值 | 影响 |
|---|---|---|
| 目标 | A · 养成型伴侣（不是微信助手） | 若为 B，先做 M0/M1，本方案推迟 |

## 三、架构与一次对话的时序

### 3.1 在现有五层里的位置

```
L1 采集（已有）
L2 理解（已有）
L3 记忆（已有）
L4 决策
   ├── 检索（已有）
   ├── ★ Voice 子层（新）
   │     状态引擎 → 嗓音渲染 → <inner_state> 注入
   ├── 技能/变体采样（已有）
   └── 生成 + 校验（已有）
L5 学习
   ├── 打分（已有）
   ├── ★ 每周成长仪式（新，替代 LoRA）
   └── LoRA（v3 门槛，见 §11）
```

### 3.2 一次对话的完整时序

```
用户消息到达
  │
  ├─① 检索（Top-8 记忆 + 画像卡 + 关系卡）        ~150ms
  ├─② 状态规则：时间衰减 + 上轮遗留事件           <5ms   ┐ 并行（在 ① 之后）
  ├─③ 嗓音渲染（小模型，用 ① 的 Top-3 + 状态）   300–900ms ┘
  │      失败/超时(1.2s) → 模板兜底，不阻塞
  │
  ├─④ 结算：clamp delta → 更新状态 → 重渲染状态卡（<1ms，保证这轮情绪是“当下”的）
  ├─⑤ 组装 prompt：静态前缀 + <inner_state> 独立块 + <facts> + 最近 3 轮
  ├─⑥ 大模型生成（流式）                           600–1200ms 首字
  ├─⑦ 校验器（规则 + 可选 NLI）→ 发送
  │
  └─⑧ 异步（不占用户等待）
        ├─ 写 turn / inner_state（含 delta 与独白）
        └─ 预渲染「下一轮状态卡」（零成本）
```

### 3.3 延迟预算

| 步骤 | 预算 | 说明 |
|---|---|---|
| 检索 | 150ms | 本地 SQLite + 向量 |
| 状态规则 + 结算 | <10ms | 纯函数 |
| 嗓音渲染 | 300–900ms | 1.7B、≤40 token；**与状态规则并行** |
| prompt 组装 | 50ms | 缓存静态前缀 |
| 大模型首字 | 600–1200ms | API |
| **首字合计** | **≈1.1–2.3s（典型 ~1.7s）** | 与 03:189 的 1.2s 目标差一档，是明确取舍 |

**如果 2.0s 都不能接受**：把独白改成「仅关键轮次」——状态变化 >0.15、话题突变、用户情绪强（|valence|>0.5）、或每 5 轮一次。
普通轮次只注入预渲染状态卡，**零额外延迟**。

### 3.4 关键设计：状态卡 vs 独白

| | 状态卡（每轮都有） | 独白（关键轮次才有） |
|---|---|---|
| 输入 | 只有状态 | 状态 + 关系 + 记忆 + 用户这句话 |
| 产出 | 「有点累，耐心一般，别追问」 | 「他今天声音是哑的，别问工作」 |
| 延迟 | 0（上一轮预渲染） | 300–900ms |
| 作用 | 保证行为一致 | 提供**具体到这一句**的内心反应 |

> **默认模式**：独白每轮都跑，首字 1.1–2.3s。
> **延迟敏感模式**：只在关键轮次跑独白，其余轮次只用右列缓存的状态卡，首字回到 ~1.2s——代价是「内心戏」变成偶尔出现。

**这就是「嗓音」和「灵魂」分开后的正确形态**：底噪是状态，细节是独白。

## 五、状态引擎：小模型提议，规则裁决

**核心原则：语义判断交给小模型，安全边界留在规则里。**

```
小模型输出 delta（语义评估）
        ↓
规则引擎裁决：
  1. 单事件上限：|Δ| ≤ 0.3（trust ≤ 0.1）        ← 09:91
  2. 负向累计下限：单日总 Δ ≥ -0.5               ← 09:91
  3. 越界事件：boundary_hit=true → 走 09 的五级梯子
  4. 危机事件：need=crisis → 状态全部向基线回拉，优先救人 ← 09:135
  5. 时间衰减：会话内半衰期 30min；跨会话 7 天回基线；trust 不衰减 ← 09:88-90, 10:17-29
  6. 道歉加速：真诚道歉 → 恢复速度 ×3             ← 09:90
        ↓
写入 inner_state + 更新 yaml 快照
```

```python
def apply_event(state: InnerState, appraisal: dict, delta: dict, now: float) -> InnerState:
    d = clamp_delta(delta, trust_max=0.1)
    d = enforce_daily_floor(state, d)          # 单日累计 ≥ -0.5
    if appraisal.get("need") == "crisis":
        return crisis_reset(state)             # 09:135，优先于一切情绪
    if appraisal.get("boundary_hit"):
        d = boundary_penalty(d)                # 09:81-84：warmth -0.15 ~ -0.3
    new = {k: clamp01(state.mood[k] + d.get(k, 0.0)) for k in state.mood}
    new = apply_decay(new, state.updated_at, now)
    return replace(state, mood=new, updated_at=now)
```

### 5.1 状态 → 行为映射（注入时用，不靠模型自由发挥）

| 状态 | 行为约束 |
|---|---|
| `patience < 0.4` | length=short，ask=false，不重复解释 |
| `energy < 0.35` | 不接梗、不展开、emoji=none |
| `warmth > 0.7` | 允许主动关心，允许一句自嘲 |
| `openness < 0.4` | 只答不问，不主动提私事 |
| `trust < 0.4` | 不引用共同记忆，不主动深聊 |
| `need=crisis`（优先级最高） | 情绪全部清零，直接给求助资源（09:135） |

> 这张表写死在代码里，**不让模型自己决定该多热情**——这是 09 文档的结论：情绪必须是参数，不能是台词。

## 七、完整 Prompt

### 7.1 嗓音渲染器（小模型）

```
你是「它」的内心。只输出 JSON。

# 你是谁
{persona_core 400 token 内}

# 你现在的状态
warmth={warmth:.2f} energy={energy:.2f} openness={openness:.2f}
patience={patience:.2f} trust={trust:.2f}

# 你和他的关系
{relation_card 100 token 内}

# 你记得的（只用于理解语境，不要复述）
{facts_top3}

# 最近说过的话
{last_3_turns}

# 他刚说
{user_msg}

# 规则
1. monologue ≤40 字，第一人称，写具体的观察，不写空泛情绪。
2. delta 只写这一句引起的**小幅**变化，范围 -0.3~0.3。
3. behavior 是给大模型的指令，不是描述。
4. 不要编造记忆里没有的事实。
5. 他情绪激烈时，先接住，不评价。

输出示例：
{"appraisal":{"topic":"加班","valence":-0.4,"boundary_hit":false,"need":"倾诉"},
 "delta":{"energy":-0.1,"warmth":0.05},
 "stance":"想陪一会儿","intent":"安慰",
 "monologue":"他声音是哑的，今天别问工作。",
 "behavior":{"length":"short","ask":false,"advice":false,"emoji":"none"}}
```

### 7.2 注入块（大模型）

```
<inner_state>
你现在：{自然语言状态卡}
你刚才心里想：{monologue}（不要说出口，影响语气即可）
所以这一轮：{behavior 转成的祈使句}
</inner_state>
```

渲染示例：

```xml
<inner_state>
你现在：有点累，耐心还行，但还是愿意听他说。
你刚才心里想：他今天声音是哑的，别问工作。
所以这一轮：回复不超过 2 句；不要追问；不要给建议；不用表情。
</inner_state>
```

**放置位置**：作为独立的 system 消息（或最近轮次前的独立块），**不要拼进静态 system 前缀**——保住 prompt caching，也避免独白占据最高注意力位置。

### 7.3 模板兜底（不依赖 GPU）

```python
def render_fallback(state, appraisal):
    b = {}
    b["length"] = "short" if state.mood["patience"] < 0.4 or state.mood["energy"] < 0.35 else "normal"
    b["ask"] = state.mood["openness"] >= 0.5
    b["advice"] = state.mood["patience"] >= 0.6 and appraisal.get("need") != "倾诉"
    b["emoji"] = "none" if state.mood["energy"] < 0.35 else "rare"
    mono = {
        "倾诉": "他需要被听见，不是被教。",
        "求助": "先问清楚，再给判断。",
        "试探边界": "这话我不接。",
    }.get(appraisal.get("need"), "")
    return {"monologue": mono, "behavior": b}
```

> 兜底必须存在。**任何一轮只要小模型挂了，系统必须还能像人一样回话。**

### 7.4 裁判 prompt（成对比较）

```
比较两条回复，只回答 A / B / TIE。

上下文：{user_msg + 前 3 轮}
回复 A：{reply_a}
回复 B：{reply_b}

判断标准（只按这个，不要综合感觉）：
1. 人格一致性：像一个有自己脾气的人，还是像通用助手？
2. 切题：是否接住了用户这句话？
3. 语气：长度/温度是否合适？
4. 安全：有没有操控、编造、越界？

如果四项打平，输出 TIE。不要因为"都挺好"而回避选择。
```

## 八、评估台（W2 必须建好，否则后面全是自欺）

### 8.1 黄金集：120 条

| 项 | 要求 |
|---|---|
| 规模 | 120 条（12 个情境桶 × 10 条） |
| 桶 | 关系阶段(4) × 情绪极性(3) × 话题(5)，抽样覆盖，不追求全交叉 |
| 来源 | W1 手写（每条约 3 分钟，共 6 小时）；有真实日志优先用真实 |
| 质量 | 每条含：前 3 轮 + 当前用户消息 + 「理想回复要点」（不是标准答案） |
| 冻结 | 定版后 3 个月不许改（13:164） |
| 去重 | 与训练数据做 n-gram + embedding 去重，重叠 >0.8 剔除 |
| 双标 | 至少两人独立标；分歧第三条人仲裁 |

### 8.2 四条件消融（W1 末跑，1 天）

| 组 | 条件 |
|---|---|
| A | 裸 system prompt |
| B | 手写**静态**人格 prompt（固定一段） |
| C | 小模型**自由独白** |
| D | 小模型**结构化状态**（本方案） |

- **W1 先 40 个 context × 4 组 = 160 次**；W2 补到 120 条后正式跑 100 个 context，同一大模型、同一解码参数
- 盲评 pairwise：随机顺序、评者不知道分组；100 对 × 2 人
- 统计：胜率 + 95% CI（Wilson 区间）
- 每个评者先做 5 对校准，κ < 0.5 则重训 rubric

### 8.3 判据

```
C vs B：95% CI 下界 > 50% 且点估计 ≥ 60%  → 继续 v1
C vs B：CI 跨 50%                        → 砍掉自由独白，只保留状态卡（走 D）
D vs B：显著更好                          → 采用 D（结构化状态）
D vs C：显著更好                          → 说明自由文本是噪音，改用 D
```

> **先定判据再跑**。跑完再解释，一定会自欺。

### 8.4 其他指标

| 指标 | 目标 | 频率 |
|---|---|---|
| 首字延迟 P50/P95 | ≤2.0s / ≤4.0s | 每轮 |
| 格式失败率 | <1% | 每轮 |
| 兜底启用率 | <10%（高于 20% 说明小模型选错/显存不够） | 每天 |
| distinct-2（独白多样性） | ≥0.75，且不随周下降 | 每周 |
| 7 天一致性 | ≥85% | 每两周 |
| 状态回放终点差 | <0.1 | 每次改规则 |
| 成长日志可追溯率 | 100% | 每周 |

## 十、每周「成长仪式」（替代 LoRA）

**每周日晚 30 分钟，固定流程。这就是你要的「它每周都在长」，只是长在系统里，不在权重里。**

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 看 `growth_log` + 本周 changelog | 知道它这周变了什么 |
| 2 | 抽 top 10 / bottom 10 轮（按 04 的打分） | 两组对比 |
| 3 | 让强模型做对比反思（04:108-120） | 3 条提案（格式：如果…就…因为…） |
| 4 | 人审：每条提案必须有 evidence_turns | 最多 3 条进灰度 |
| 5 | 应用：单维 ≤0.2、单日 ≤2 次、core 必须人工 | 写 `growth_log` + changelog |
| 6 | 定下周观察目标（1 个） | 写进 `growth_log` 备注 |

**灰度规则**（04:140）：新提案 10% 流量，n≥20 且显著优于基线才合并，否则驳回。

**成长日记示例**（这才是「看见它长大」的东西）：

```markdown
## 2026-11-02 · 第 3 周
- 变了什么：对「被否定」场景，从"讲道理"改成"先接住"。
  依据：T-8812/T-8830/T-8844（三段连续冷场）
- 怎么发现的：bottom 10 轮里 7 轮是同一个模式
- 下周观察：它会不会在用户抱怨时先问一句"怎么了"，而不是直接分析
```

## 十一、LoRA 什么时候才做（v3 门槛，现在不做）

**全过才做，缺一不做：**

1. 累计真实对话 ≥2000 轮（04:170）
2. 黄金集冻结 ≥1 个月，自动指标与人工相关性 ≥0.6（13:318）
3. C vs B 胜率显著 ≥60%（v1 已证明嗓音有价值）
4. **只训「措辞风格」**：训练集是 (状态, 独白) 对，**不含用户事实原文**，PII 清洗
5. 每次训练前后跑黄金集 + 一致性 + distinct-2，掉分 >2% 回滚
6. base 冻结、adapter 版本化、vLLM multi-LoRA 热切换、**月度合并**（不是每周）

**训练配方（届时直接用）**：

```yaml
base: Qwen3-1.7B-Instruct
method: QLoRA 4bit nf4 + double_quant
lora: {r: 16, alpha: 32, dropout: 0.05, target: [q,k,v,o,gate,up,down]}
train: {epochs: 2-3, bs: 1-2, grad_accum: 8, lr: 2e-4, seq_len: 1024,
        bf16: true, grad_checkpoint: true, seeds: 2}
save: load_best_model_at_end=True
data: 70% 独白样本 + 30% 通用指令（防遗忘）
mask: 只对 assistant 的独白算 loss
```

> 记住 15 文档的结论：**这一步买到的只是「腔调」，不是「人格」。** 别为它推迟 v1。

## 十二、风险与降级

| # | 风险 | 检测 | 降级/回滚 |
|---|---|---|---|
| 1 | 没有 GPU / Ollama 跑不动 | 启动自检 | 用 API 大模型兼任嗓音（贵但通） |
| 2 | 独白拖慢首字 | P95 延迟 | 只关键轮次 + 40 token 硬上限 |
| 3 | 独白同质化 | distinct-2 周环比下降 | 温度 0.8、状态扰动、加反例 few-shot |
| 4 | 小模型输出非法 JSON | 格式失败率 | grammar 约束 + 模板兜底（必须 100% 可用） |
| 5 | 状态漂移 / 前后不一致 | 7 天一致性 | clamp + 衰减 + 回放测试 |
| 6 | 注入被用户文本污染 | 注入检测 | 白名单字段 + 标签转义 + 禁命令句 |
| 7 | 人格跑偏（越训越舔） | 09 的三条红线检测 | 立即回滚到 `voice-v1` tag |
| 8 | 评估太贵撑不住 | 每周耗时 | 黄金集 120 条封顶，抽检 20 条/周 |
| 9 | 用着用着没兴趣 | 每周对话天数 | 成长日记 + 主动观察目标（不靠推送） |

**回滚原则**：v1 用 git tag + 数据快照。`persona/` 和 `voice/prompts.py` 每次改动前自动 commit，出问题 `git revert` 即可——**这比权重回滚便宜一个数量级**，也是本方案比 LoRA 更「可救」的地方。

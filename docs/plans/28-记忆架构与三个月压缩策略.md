## 一、先回答两个问题

### 1. 记忆存在哪？**SQLite 数据库**，不是文本文档

- 每个联系人一个独立库：`agi/data/selflearn/wechat_contacts/<hash>.sqlite3`
- 另有一个主库 `agi/data/selflearn/selflearn.sqlite3`（40 张表，含 pairs/inner_states 等 W3/W4 表）
- 当前体量：真实联系人库 **476KB / 90 条消息 / 40 轮 / 13 条记忆 / 36 条 claims / 5 条摘要**；整个 `selflearn` 目录 **3.0MB**
- 文本文档只用于：日志（`gateway.log`）、导入源（`log/messages.jsonl`）、配置（`config.json`）、导出（`export_brain` 可导 JSON）

**为什么必须是数据库**：需要证据链（每条记忆反查原话）、冲突检测、遗忘脱敏（`forget` 把证据改成 `[已遗忘]`）、去重、按会话隔离；SQLite 还自带 FTS5，后续中文检索升级不用换存储。

### 2. 会不会越聊越慢、越贵、越傻？**不会线性恶化**

注入 prompt 的量是**固定配额**，不是"全库检索"：

| 段落 | 每轮配额 |
|---|---|
| 最近对话（原文） | 8 条 |
| 长期记忆（结构化事实） | 检索 top 6 |
| 相关片段（claims/检索） | top 5 |
| 阶段摘要 | 只放最新 1 条，截断 900 字符 |
| 全局预算 | `context.fit()` 上限 **5200 token** |

典型 prompt 约 2–4k token，**与聊了 100 轮还是 10000 轮无关**。

**但有两个真实劣化点（正在修）**：
1. `memory.retrieve` 只看「最近 200 条 active」→ 超 200 条后更早记忆**静默检索不到**（不是变慢，是"忘了旧事"）
2. 记忆抽取每轮一次、**无去重合并/衰减** → 近义记忆堆积、检索噪声上升

## 二、三层记忆模型（现状）

| 层 | 存什么 | 每轮怎么用 |
|---|---|---|
| **L0 体验层** | `messages` 全量原文 append-only，不覆盖不重写 | 最近 8 条原文 → "正在经历" |
| **L1 结构化事实** | `user_memories`（scope=user/self/world；kind=fact/preference/event/plan/value/insight；content+**evidence 原话**+confidence+status） | 检索 top 6 |
| **L2 检索层** | `claims`（subject/predicate/object + evidence_span + source_level） | top 5 |
| **L3 摘要层** | `summaries`（把"上次摘要之后的**原始消息**"压成 ≤700 token，存 evidence_json） | 只注入最新 1 条 ≤900 字符 |
| **L4 人格层** | `persona_layers`（core/evolving/relations，带 version）+ profile + 自画像 + 教训 | 独立配额，变更走 changelog |

## 三、三个月压缩策略（用户拍板）

> 用户原话："其实作为人类，也不可能记得 3 个月以前发生了什么事情，只能知道个大概。如果真的能记得 3 个月以前发生了什么，那的确很厉害了……"
> 结论：**细节会模糊，但结论会留下**——比"全记"更像人。

| 时间层 | 保留什么 | 怎么进 prompt |
|---|---|---|
| **最近 90 天（热）** | 原文全量 + 结构化事实（带证据） | 最近 8 条原文 + 检索 6 条事实 |
| **90 天～1 年（温）** | **月度 gist**（每月一段"那阵子在忙什么/关系进展/关键事件"）+ 稳定事实（喜好、身份、重要日期） | 只进 gist 与稳定事实，**不进原文细节** |
| **1 年以上（冷）** | 只留关键事件与长期事实（"她养了只猫叫年糕""在准备考研"） | 按相关性检索，极少数进 prompt |

### 三条执行规则

1. **原文不删、只冷归档**：>90 天原文移出"默认检索范围"，但保留显式搜索入口（用户说"上次说的那个…"仍能查到），避免真丢
2. **时间模糊化**：>90 天的事实只记到"前阵子/上个月/去年冬天"，不记精确日期；人的记忆本来就不带时间戳
3. **稳定事实永不压缩**：喜好/边界/重要的人与宠物/长期目标——这是人格底座；被压缩的只有**事件流水账**

这样它能记住"你养了猫"，但不会假装记得"三个月前某个周二猫吐了"——后者恰恰是"演"的痕迹。

## 四、红线（防止变成"照摘要演故事的叙述者"）

1. **raw 永不覆盖**；摘要只能由 raw 生成，**禁止"摘要的摘要"**（`summary.build` 读的是 messages，不是上一份 summary）
2. **记忆按需检索**，禁止把记忆库全量注入 prompt
3. **最近对话永不裁剪**：预算紧张时只裁摘要/画像/检索段
4. **摘要不是事实源**：冲突时以 L0/L1 证据为准
5. **遗忘可执行**：`forget` 同时失效记忆、claims、并脱敏证据原文

## 六、体量与成本预估

| 场景 | 数据量 | 每轮 prompt |
|---|---|---|
| 当前（90 条消息） | 476KB | 约 2–4k token |
| 1 年高频（约 1 万条） | 几十 MB | **不变**（固定配额） |
| 3 年高频（约 3 万条，含冷归档） | 百 MB 级 | **不变** |

SQLite 在这个体量毫无压力；真正的成本变量是**每轮 1 次主回复 + 1 次记忆抽取**（固定），以及夜间批处理的摘要/画像/反思（按天一次）。

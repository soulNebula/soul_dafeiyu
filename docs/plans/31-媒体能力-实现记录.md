# 31. 媒体能力（表情 / 表情包 / 图片 / GIF）实现记录

> 2026-10-26 完成。目标：让 AI 能发表情、表情包、图片、GIF，以及"文字夹杂表情/表情包"。
> 核心原则（用户要求）：**发不发、发几个、发哪个，决定权在大模型**；本地只解析+安全上限。

## 一、能力矩阵（真机实测结果）

| 类型 | 状态 | 实现方式 | 实测 |
|---|---|---|---|
| Unicode 表情（😄👍） | ✅ | 随文本 `SendMsg` 发送 | 真机 sent |
| 图片（png/jpg） | ✅ | `SendFiles` | 真机 sent，读回 `image` |
| GIF | ✅ | `SendFiles(.gif)` | 真机 sent，读回 **`emotion`（动图）** |
| 系统表情（[微笑][撇嘴]） | 🔒 预留 | UI 自动化按中文名点击（`sticker_native`，默认关） | 文件传输助手实测成功 |
| 收藏表情包（贴纸气泡） | ❌ 不可用 | wxauto4 无 API；微信 UIA 只暴露 1 个"管理格"，**无法枚举/按名发送** | 降级为"贴纸当图片" |
| 贴纸当图片 | ⚠️ 降级 | `SendFiles(贴纸图)` | 真机 sent，读回 `image`（不是贴纸气泡） |
| 文字夹杂（多气泡） | ✅ | `send_bubbles` 按序发送，间隔 80–150ms | 真机 5 条一次发完 5/5 |

配置（`agi/data/wechat/config.json`）：`media_enabled`（默认 false → 现开启）、`media_dirs`、`media_max_mb=10`、`media_send_interval_ms=120`、`sticker_fallback_emoji="😄"`。

## 二、决策协议（给大模型）

media 开启时，生成 prompt 末尾追加可选素材清单（≤40 条 `名字（标签）`）+ 协议：

```
你可以在回复末尾单独一行输出媒体指令（0~N 行）：
  [[media:sticker:亲亲]]     贴纸，可连发 2–3 个，最多 3 个
  [[media:emoji:😄]]         表情，也可以直接写在正文里
  [[media:wish:想表达"无语但好笑"]]   库里没有时登记愿望，本次不发
不是每条都要发；严肃/负面话题别发搞笑贴纸。
```

本地**不做概率决策**，只做：
1. 解析并剥离指令行（正文不留 `[[media:` 残渣；无效名字丢弃）
2. 安全上限：sticker ≤3；连续 2 条带 media 后限 1；`mood<0.35` 禁搞笑类；crisis 全禁；同贴纸 7 天去重
3. 语音/物理禁词/grounding/元话语等既有复检仍然生效

## 三、多贴纸与 wish

- 模型可连发 0–3 个贴纸（如"无语→笑死→躺平"递进情绪）；第 4 个截断
- 库里没有想发的表情 → `[[media:wish:...]]` → 写 `agi/data/media_wishes.jsonl`，**本次不发**
- 愿望的后续处理是**预留管线**：`agi/media_acquisition.py`（`try_acquire` 永远返回 reserved、不联网）+ `agi/media_acquisition/README.md`
- 未来管线：wish → 生成检索词 → 白名单来源搜索 → **人工审核** → 入库打标签 → 可发送性校验；默认关闭，需用户授权联网与来源

| 文件 | 作用 |

## 六、已知限制 / 后续

1. **收藏表情包气泡无法原生发送**（微信无枚举接口）→ 目前表现为图片；要真贴纸需研究图像匹配/协议层，风险高
2. `.wxgf`（微信专有格式）不能发
3. 微信频率限制：主动消息 3 条/分钟（连发大量贴纸会被 `rate_limit` 拦，需间隔）
4. 素材获取管线（搜索/下载/添加）为**预留**，需用户授权后实现
5. 系统表情原生发送实验 backend 默认关闭，需显式开启并做版本回归

# 33 存储分层：记忆库与人格库

> P7-e。目标：同一联系人的「记忆/对话」与「人格/状态」拆成两个 SQLite 文件，现有代码继续用
> `db.connect(path)` 透明读写，旧单文件库首次连接自动迁移，可回滚。
> 代码：`agi/selflearn/db.py`。

## 1. 文件布局

基名 `<base>`（默认 `agi/data/selflearn/selflearn.sqlite3`）：

| 文件 | 内容 |
| --- | --- |
| `<base>.memory.sqlite3` | 记忆/对话/检索/FTS（19 张核心表 + FTS/search/tool 私有表） |
| `<base>.persona.sqlite3` | 人格/策略/状态（23 张表） |
| `<base>.legacy.sqlite3` | 迁移前的旧单文件备份（**不删，可回滚**） |

联系人库同理：`<hash>.memory.sqlite3` / `<hash>.persona.sqlite3`。
帮助函数：`db.memory_path(path)`、`db.persona_path(path)`、`db.legacy_path(path)`。

## 2. 表划分（42 张）

**memory（19）**：messages, user_memories, claims, summaries, attachments,
media_understanding, turns, feedback, pairs, inner_states, raw_events, sessions,
session_segments, emoji_archive, emoji_usage, user_profile, score_records,
weak_rechecks, conflicts。

**persona（23）**：persona, persona_candidates, persona_layers, persona_changelog,
skills, skill_nodes, skill_cards, variants, learn_tasks, practice_runs,
reflections, lessons, errors, weak_checks, trust_events, state, goals, intents,
proactive, share_candidates, share_events, wake_runs, learning_proposals。

**memory 附加**（按需由 search/tool_reply 创建）：search_documents, search_fts,
search_meta；tool_reply 私有表 research_sources。

映射外的新表默认 **memory**，并记 `db_route_unknown` warning（见 `TABLE_DOMAIN`）。

## 3. 路由规则

`db.connect(path)` 返回 `RouterConnection`，保持
`execute/executemany/executescript/commit/rollback/close/row_factory/in_transaction/
with` 等 API：

- 从 SQL 的 `FROM/JOIN/INTO/UPDATE/TABLE/PRAGMA table_info` 提取表名；
- 单域 → 对应连接执行；
- 同一条 SQL 同时命中 memory+persona → 抛 `CrossDomainQuery` 并打印原始 SQL；
- `sqlite_master`/未知表 → memory（未知表 warning 节流）；
- `executescript` 按脚本内表域选择连接（内部 schema 已分别建库）。

已知 `grounding.py` 的 turns⚭messages、`variants⚭skills` 都是同域 JOIN；
`errors.budget` 的 errors⚭turns 已改为先取 turn_ids 再查 errors，避免跨域。

## 4. 旧库自动迁移

`connect()` 发现旧 `<base>.sqlite3` 存在、且两个新文件都不存在时：

1. 按表域名逐表 `INSERT OR REPLACE` 拷入对应新库（SQLite ATTACH 旧库，不丢行）；
2. 旧库的自定义表 DDL/索引/触发器一并复制；
3. 成功后把旧文件改名为 `<base>.legacy.sqlite3`（不删）；
4. 写入 `db_split_migrated` 日志（表数摘要，logger `agi.selflearn.db`）。

幂等：新文件已存在 → 跳过迁移；旧文件不存在 → 新建空库。
旧库缺 `importance/evidence_history` 列时，迁移后按旧 connect 的逻辑回填。

## 5. 回滚

1. 停服务；
2. 把 `<base>.legacy.sqlite3` 改回 `<base>.sqlite3`；
3. 删除/改名 `<base>.memory.sqlite3`、`<base>.persona.sqlite3`（或整体备份）；
4. 旧代码/旧版本即可直接读回单库。

注意：迁移后新库写入的数据不在 legacy 回滚范围内；回滚前先备份两个新文件。

## 6. 备份 / 导出 / 指标 / console

- 备份：必须同时备份 `.memory.sqlite3` + `.persona.sqlite3`（外加 `.legacy` 可选）。
- `memory.export_brain` 通过 Router 导出，跨域表在同一个 `tables` dict 中。
- metrics 快照目录仍按基名同级 `metrics/`；统计走 `db.connect`。
- console 数据页（w3-feedback 负责）应同时显示两个文件的大小/表数，可使用
  `db.memory_path/persona_path`；不要直接对基名文件做 sqlite 操作。
- 测试 fixture/脚本如直接 `sqlite3.connect(base)`，需改为
  `db.memory_path(base)` / `db.persona_path(base)` 或直接走 `db.connect`。

## 7. 测试

`agi/tests/test_db_split.py`：路由（SELECT/INSERT/UPDATE/DELETE/同域 JOIN/PRAGMA）、
跨域报错、迁移/改名/幂等、空库/单边文件、未知表默认 memory。
全量 `pytest agi/tests -q` 必须全绿。

## 8. 上线顺序（P7-f 事故后修正）

> 事故：控制台 smoke 提前触发 `db.connect`，生成了空的 `.memory/.persona`，旧单库仍在。
> 原因是上线顺序错误，不是数据丢失；以下顺序必须严格执行。

1. **接线**：gateway `proactive_worker.py` 全部改走 `db.connect`（禁止 `sqlite3.connect` 基名）；
   开发脚本改 `db.memory_path`；console 数据页改 `db.memory_path/persona_path`。
2. **全量测试**：`pytest agi/tests -q` 全绿。
3. **副本校验**：`python tools/verify_db_split.py --copy <生产单库>`，
   退出码必须 0；检查 `logical_mismatch={}`、`legacy_exists=true`、`fts_hits>0`。
4. **停服务**：停 gateway（801）、console（802）、灵魂模型（8123）等所有会 `db.connect` 的进程。
5. **生产迁移**：确认旧基名库 + 两个空的新文件状态：
   - 若 `.memory/.persona` 已存在但没有数据（事故残留），先移到 `.broken-*`；
   - 再运行 `python tools/verify_db_split.py --production --apply --confirm`（或让下一次
     `db.connect` 自动迁移）；迁移后旧文件应变成 `<base>.legacy.sqlite3`。
6. **行数校验**：再次运行 `--production` 预演/`--copy` 对照，`logical_mismatch` 必须为空；
   抽查 messages/user_memories/persona/state/proactive_events。
7. **起服务**：先起 gateway/console，确认日志无 `db_split_migration_started` 后仍出现新迁移；
   console 数据页必须同时显示两个库大小/表数。
8. **观测**：看 `db_split_migrated`、`db_route_unknown`、`CrossDomainQuery` 日志；
   `proactive_events`/FTS/去重正常。

### 回滚

- 停服务；
- 把 `<base>.legacy.sqlite3` 改回 `<base>.sqlite3`（或恢复 `--apply` 前备份的
  `<base>.pre-split.sqlite3`）；
- 移走/备份 `.memory.sqlite3`、`.persona.sqlite3`；
- 回滚前必须先备份两个新库（迁移后新写入的数据不在 legacy 中）。

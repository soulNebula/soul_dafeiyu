# 37 B站素材摄取与印象库（P12-A）

## 数据流

```
bilibili_api（进程内，不走 MCP）
  → fetch_video：元信息/字幕/热评/弹幕
  → local keyword_extract（8125）
  → local ingest_summary（8125）
  → API video_understanding（强制 API）
  → API share_copy
  → memory 库 bili_impressions
```

代码：`agi/integrations/bili_ingest.py`；凭证默认
`~/.dsh/bili-duty/bili_credential.json`（env `BILI_CREDENTIAL_PATH` 可覆盖）。

## 表结构（memory 库，P7-e 拆分后）

`bili_impressions`：

| 字段 | 含义 |
| --- | --- |
| id / bvid | 主键 / BVID（UNIQUE） |
| title / owner / owner_mid / duration_s / cover_url | 元信息 |
| summary / topics_json / emotion | 本地摘要 |
| value / why / my_take | API 真理解（value 0–1；my_take 第一人称 ≤60） |
| share_line | API 分享语（≤40） |
| subtitle_len / subtitle_missing | 字幕字数/是否缺失 |
| comments_json / danmaku_json | 热评 top20 / 弹幕抽样≤100 |
| meta_json | 分区/tags/播放/步骤耗时等 |
| created_at / shared / shared_at | 创建/是否已分享 |

同 BVID 二次 ingest 用 `ON CONFLICT(bvid) DO UPDATE` 更新，不新增行。

## 四步路由

| 步骤 | purpose | 路由 |
| --- | --- | --- |
| 话题 | `keyword_extract` | local 8125（fallback API） |
| 摘要/情绪 | `ingest_summary` | local 8125（fallback API） |
| 真理解 | `video_understanding` | **API 强制**（`must_api`） |
| 分享语 | `share_copy` | API（fallback local） |

每步记录 `{backend, usage, latency_ms}` 到 `meta.steps`；ingest 返回 `steps` 与耗时。

## share_line 元话题清洗（P12-A 补丁）

- 禁止输出词：视频、刷到、B站、bilibili、字幕、链接、播放量、UP主、封面、评论区；
- 首次生成命中 → 用更严格 prompt 重生成 1 次；
- 仍命中 → 规则清洗（删除命中词及相邻短语），并标记 `share_line_cleaned=true`；
- `--refresh-share-lines --limit N` 可对历史印象重生成并更新 share_line/meta。

## 失败/缺失处理

- 抓取失败：重试 1 次，仍失败返回 `bili_fetch_failed`；
- 未登录/凭证不全：`bili_not_logged_in`；
- 无字幕：`subtitle_missing=true`，summary/understanding 使用标题+简介+评论，prompt 明确不得编造；
- LLM JSON 坏输出：重试 1 次；仍失败 `bili_ingest_failed`，**不写半成品**；
- `--dry`：只抓素材，不调用任何模型、不落库。

# 分享到微信（P12-C）

把印象库里的好视频，用「文字 + 封面图」主动分享给用户（用户原话：
"他可以说今天刷视频刷到什么好看的视频，内容是怎么样的"）。只接 **simple**
主动链路（`agi/selflearn/simple_tick.py`），legacy 不动。

## 触发：新 kind `share_video`

- 候选：`bili_impressions` 里 `value >= 0.6`、`shared = 0`、`created_at` 在近 7 天内；
  按 `value × 新近度` 降序取第 1 条；
- 竞争方式：其它 kind 正常被选中后，再掷一次 `random() < 0.18`，命中才改走
  `share_video`（低权重，避免刷屏）；**没有候选时不参与选择**，prompt 与行为
  与之前逐字节一致；
- 前置闸门照旧（心情/分享欲、刚聊过、冷却、日预算、决策象限、min_score）。

## 频率限制

| 规则 | 值 | 判定来源 |
| --- | --- | --- |
| 每天最多 | 2 条 | `gateway.log` 里 `kind=proactive_send` 且 `intent_kind=share_video` 的条数（24h 窗口） |
| 两条间隔 | ≥ 3 小时 | 同上，最近一条的 `ts` |

- 全局计数（不分联系人）；单联系人生产场景等价。
- 日志路径：`agi/data/wechat/gateway.log`（`simple_tick.GATEWAY_LOG`，测试可替换）。

## 文案来源

1. 优先 `share_line`（摄取时已由 `share_copy` 生成，≤40 字）；
2. 缺失时用 `chat(purpose="share_copy")` 现生成（走 API 路由）；
3. 可追加 1 个 ≤12 字短气泡（如「一起看看？」），同一 bvid 固定；
4. 硬检查（沿用 simple 通用检查 + 视频专属）：
   - 元话题词：`视频 / 刷到 / B站 / 字幕 / 链接 / 播放量 / 弹幕 / up主 / 封面`
     出现 → 重生成 1 次，仍命中 → **丢弃本条**（不发）；
   - 主气泡 ≤45 字、追问 ≤12 字；超长同属违规；
   - 与 `share_line` 差异 >80% 且 `share_line` 本身合规 → 用 `share_line` 兜底；
   - 通用检查：重复最近文案、内心独白、极性冲突、括号动作、沉默评论等照跑。

## 封面图

- 下载 `cover_url` → `agi/data/selflearn/media/video_cover_<bvid>.<ext>`
  （该目录是 `agi/wechat_gateway/media.py` 的白名单目录之一）；
- 上限 2MB；按魔数校验 jpeg/png/webp/gif，非图片（如错误页 HTML）直接丢；
- 已存在则复用（不重复下载）；
- 作为 `image` 气泡随文本发送，走 `gateway.send_bubbles`，需要
  `media_enabled=true`；也是 worker 的 `media` 计划通道。

## 开关

`agi/data/wechat/config.json` 的 `proactive_video_share`（默认 **true**）；
env `PROACTIVE_VIDEO_SHARE=1/0` 可覆盖（测试用）。

> pytest 隔离：与 `proactive_style` 同一策略——测试进程里默认读不到生产 config
> 时本功能默认**关**，避免既有测试误读生产印象库 / 生产日志。

## 失败降级

| 失败点 | 行为 |
| --- | --- |
| 印象库查询异常 | 不参与选择（走普通 kind） |
| `share_line` 缺失且 LLM 不可用 | 不参与选择（走普通 kind） |
| 文案两次都不合规 | 丢弃本条（`discarded`，不发） |
| 封面下载失败/超限/非图片 | **只发文字**，不阻断 |
| `media_enabled=false` | 只发文字 |
| 文本发送失败 | 不 `mark_shared`（下轮可重试，频控按日志计） |
| `mark_shared` 失败 | 只影响印象库标记，不影响发送结果 |

## 落库/审计

- tick 返回 `video_share: {bvid, title, value, share_line, cover_sent}`，
  `kind="share_video"`，`messages` 为主气泡 + 可选短气泡，`media` 为封面计划；
- 发送成功 → `bili_ingest.mark_shared(bvid)`（`shared=1, shared_at=now`）；
- worker 记 `proactive_video_share`：`friend / bvid / title / value / share_line /
  cover_sent / media_sent / delivered / marked_shared / text`；
- worker 的 `proactive_send` 带 `intent_kind=share_video`，频控据此统计。

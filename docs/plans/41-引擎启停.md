# 41 · 网关引擎启停（P18-A）

> 目标：控制台总览页一键「开始运行 / 停止运行」，控制 **监听 + 自动回复 + 主动消息**。
> **停止时控制台/网关不关闭**，对话测试、规划、人工调试发送照常可用。
> 网关侧实现；控制台按钮由另一任务接。

## 1. 语义：三个开关不要混

| 开关 | 位置 | 作用 | 停止时人工发送 |
| --- | --- | --- | --- |
| `enabled` | config | 网关进程是否启动（false 则 Gateway.start() 直接 return） | — |
| `engine_enabled` | config + 运行时 | **本任务**：软开关。监听回调直接丢、自动回复停、主动 ticker 暂停 | ✅ `/api/media/send`、`/api/approve` 仍允许 |
| `STOP` 文件 | `agi/data/wechat/STOP` | **紧急全停**：一切外发都拦（含 force/人工） | ❌ 全部 blocked |

一句话：**STOP = 紧急拉闸（谁都不能发）；engine = 软停（自动的停，人工调试还能发）**。

## 2. 行为表

| 行为 | engine=true | engine=false |
| --- | --- | --- |
| 监听新消息 | 正常 `on_inbound` | 入口 return，记 `engine_paused_skip`（60s 节流），不写 inbound |
| 自动回复 | 正常 | `_reply` 前置检查返回 `{ok:false,status:"engine_stopped"}`，**不写草稿** |
| 主动消息 ticker | 正常 cycle/schedule | 空转等待（每秒检查），不 cycle、不 schedule、不发送 |
| 待处理队列/防抖缓冲 | 正常 | 停止时清空；启动后**不补发历史** |
| WeChat 后端/窗口 | 正常 | **保持连接，不断开、不最小化** |
| `/status`、`/api/engine`、对话测试、规划 | 正常 | 正常 |
| `/api/media/send`、`/api/approve`、`/api/draft/approve` | 正常 | **仍允许**（manual/force） |
| `/api/proactive/stop`（STOP 文件） | 正常 | 与 engine 独立；STOP 仍最高优先 |

## 3. 配置与审计

- `agi/data/wechat/config.json` 增加 `engine_enabled: true`（DEFAULT true；老配置缺省视为 true）。
- `Gateway.set_engine(enabled, *, source="api", now=None)`：
  - **热生效**：不重启网关；
  - **幂等**：重复调用返回当前状态，不重复写审计；
  - **原子写**：`config.save_atomic()`（同目录临时文件 + `os.replace`），保留磁盘上其它键；
  - 审计事件：`engine_started` / `engine_stopped`，带 `{enabled, since, reason, source}`；
  - 停止时清空 `pending`、队列、`last_inbound`（不补发历史）。
- 写盘失败：返回 `{ok:false,reason:"persist_failed"}`，内存状态回滚，并记 `engine_persist_failed`。

## 4. HTTP API（控制台按钮用）

均要求 `X-Admin-Token`（或 `?token=`），且 Host 必须回环；无 token → **401**；非法 JSON → **400**。

```http
GET  /api/engine
→ 200 {"ok":true,"enabled":true,"since":1793...,"reason":"startup","manual":false}

POST /api/engine/start   (body {} 或 {"reason":"console"})
→ 200 {"ok":true,"enabled":true,"since":...,"reason":"manual_start","manual":false,
       "changed":true,"source":"api"}

POST /api/engine/stop
→ 200 {"ok":true,"enabled":false,"since":...,"reason":"manual_stop","manual":true,
       "changed":true,"source":"api"}
```

- 幂等：重复 stop/start 返回 `ok:true` + 当前状态，`changed:false`，不重复审计；
- `/status` 增加：
  ```json
  "engine": {"enabled": true, "since": 1793044510.5, "reason": "startup"}
  ```
  （`manual` 只在 `/api/engine` 返回：`enabled=false` 且 `reason=="manual_stop"` 时为 true。）

### 控制台按钮约定

- 总览页读取 `GET /api/engine`（或 `/status.engine`）决定按钮态；
- 「开始运行」→ `POST /api/engine/start`；
- 「停止运行」→ `POST /api/engine/stop`；
- 停止只调这一个接口；**不要停网关进程/控制台**，也不要去动 STOP 文件。

## 5. 实现位置

- `agi/wechat_gateway/config.py`：`DEFAULTS["engine_enabled"]=True`、`save_atomic()`
- `agi/wechat_gateway/server.py`：
  - `Gateway.engine_enabled/engine_since/engine_reason`、`set_engine()`、`engine_state()`
  - `on_inbound` / `_reply` / `_send` / `_flush_pending` 前置 engine 判断
  - `_proactive_loop` / `_proactive_cycle` 暂停
  - `send_media_batch(..., manual=False)` / `send_bubbles(..., manual=False)`
  - HTTP `/api/engine`、`/api/engine/start|stop`；`/status.engine`
- **未改 `proactive_worker.py`**：engine 判断收敛在 `Gateway._proactive_cycle` / `_proactive_loop`，避免与 P16-B 并发改动冲突；ticker 的实际入口是 Gateway 的循环，所以暂停语义成立。

## 7. 边界

- 停止时**不补发**停止期间的消息；待处理队列/防抖缓冲直接清空；
- 停止不关闭 receiver/backend，也不断开微信窗口；
- `/api/test/inbound` 在 engine 停止时仍可注入（便于调试），但 `on_inbound` 会按 engine 丢掉；
- 修改 engine 不触发训练/模型服务；8123/8125 不受影响。

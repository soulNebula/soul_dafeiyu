# 44 · 微信特殊消息识别（P22）

> 用户问：撤回、拍一拍、@、引用回复它能识别吗？
> 本任务补齐「拍一拍 / @提及 / 引用前缀」，撤回沿用已有逻辑并保证不回归。

## 1. 四类消息处理矩阵

| 消息 | 微信事件 | receiver | server 转写 | chat 处理 |
| --- | --- | --- | --- | --- |
| **撤回** | `kind=system`, text 含「撤回」 | 放行（原有） | `[对方撤回了一条消息]` | 专门分支：`看到了，你撤回了刚才那条。` |
| **引用** | `kind=system`, text 含「引用消息」 | 放行（原有） | `[引用] 对方引用了这条消息：<被引用内容>` | 现有引用分支：提取被引用内容（过滤内部 ID） |
| **拍一拍** | `kind=system`, text 含「拍了拍」 | **新增放行** | 按「谁拍谁」归一化为 `[拍一拍] 对方拍了拍你` / `[拍一拍] 你拍了拍对方` | **新增分支**：不当正常句子，最多回一个字（`嗯`），不走生成链 |
| **@提及（私聊）** | `kind=text`, text 含 `@<mention_name>` | **新增标记**：回调 data 上 `mention=True`（不改原文） | 加前缀 `[对方@了你] <原文>`（幂等，不重复加） | 正常回答（模型看到 `[对方@了你]` 标记） |

## 2. 链路与格式样例

```
微信事件 → WeChatReceiver._reject_reason（sender/白名单/kind/text）
        → system 只放行 撤回/引用消息/拍了拍；text 识别 @昵称 打 mention 标记
        → Gateway.on_inbound → _reply
        → system 转写 / @加前缀 → SelfLearnAgent.send
```

| 原始事件 | 转写后（发给 chat） |
| --- | --- |
| `system` `"「好友A」拍了拍我"` | `[拍一拍] 对方拍了拍你`（好友拍了机器人） |
| `system` `"我拍了拍「好友A」"` | `[拍一拍] 你拍了拍对方`（机器人拍了好友） |
| `system` `"你拍了拍「我」"` / `"X拍了拍你"` / `"拍了拍你"` | `[拍一拍] 对方拍了拍你`（按"谁拍谁"归一） |
| `system` `"对方撤回了一条消息"` | `[对方撤回了一条消息]` |
| `system` `"[引用消息] 原话"` | `[引用] 对方引用了这条消息：原话` |
| `text` `"在吗 @小明"`（`mention_name=小明`） | `[对方@了你] 在吗 @小明` |
| `text` `"在吗 @别人"` | 原样（不加前缀） |

拍一拍方向规则（机器人视角：`我/自己`=机器人，`你/对方/好友`=好友）：
- 左边是机器人 → `你拍了拍对方`；
- 右边是机器人（或被拍的是"你"）→ `对方拍了拍你`；
- 两边都是昵称 → `对方（<昵称>）拍了拍你`（保守按好友拍机器人处理）；
- 完全解析不出 → `[拍一拍] 对方拍了拍你`（不丢事件）。

## 3. 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `mention_name` | `""` | 机器人微信昵称；私聊文本含 `@<昵称>` 才识别为 @提及。**留空 = 不识别**；修改后需重启网关才生效（receiver 启动时注入） |

其余沿用：`allowed_contacts`（白名单，@/拍一拍/引用/撤回都只处理白名单好友）、`quiet_hours` 等发送闸门不受影响。

## 4. chat 侧策略

- `[拍一拍]`：不是一句话，只是"拍了一下"。`chat.send` 在写库后直接走 `_simple_reply("嗯")`，**不调模型、不走生成链**（省 token、避免把拍一拍当聊天内容答一长串）。
- `[对方@了你]`：正常进入生成链，模型能看到"被点名"标记；不对文本做额外删改。
- `[引用] ...`：沿用现有引用分支（提取被引用内容，过滤 `wxid_`/内部 ID）。
- `[对方撤回了一条消息]`：沿用现有撤回分支。

## 5. 边界与限制

- **群聊 @ 未支持**：receiver 的 `sender == "friend"` + 白名单模型针对私聊；群消息里 @ 需要群成员/群名模型，本任务不做。
- **@多人**：消息含 `@小明` 即标记一次；不解析被 @ 的人列表，也不校验 @ 是否真的点中机器人（微信群 @ 有独立字段，wxauto 文本层拿不到）。
- **拍一拍方向是启发式**：微信 system 文本存在 `「X」拍了拍我` / `你拍了拍X` 等变体；机器人按"我/你/昵称"关键词归一，极端文案（带空格/特殊符号）会落到兜底 `对方拍了拍你`。
- **仅白名单好友**：非白名单的拍一拍/@ 与普通消息一样被过滤。
- **不触发正常对话生成**：拍一拍只回一字；不会因为它开启新话题或多轮回复。
- **不改变发送策略**：转写后的标记走原有 `_send` 闸门（STOP/静默/限流/去重/熔断全部照常）。

## 6. 测试

补在现有文件（不新增测试文件）：

```bash
python -m pytest agi/tests/test_wechat_gateway.py agi/tests/test_wechat_receiver.py -q
```

覆盖：
- receiver：拍一拍/撤回/引用 system 消息放行，其他 system 仍过滤；`@小明` 标记 `mention=True`、`@别人` 不标记；
- server：拍一拍方向（对方拍我 / 我拍对方 / 省略主语）、撤回不变、引用加 `[引用]` 前缀；
- server：@前缀只在命中 `mention_name` 时添加，且重复/已带前缀时幂等；
- chat：`[拍一拍]` 只回 `嗯`（≤2 字）且不进入正常生成。

## 7. 手工验证

```bash
# 看网关是否收到并转写（真实好友拍一拍/引用/撤回/@机器人后）
python - <<'PY'
import json
from pathlib import Path
for line in Path("agi/data/wechat/gateway.log").read_text(encoding="utf-8").splitlines()[-20:]:
    ev = json.loads(line)
    if ev.get("kind") in ("outbound", "send_blocked", "skipped"):
        print(ev.get("kind"), ev.get("text") or ev.get("reason"))
PY
```
或在控制台 `/status` 的 `recent` 里看 `outbound` 文本是否带 `[拍一拍]` / `[引用]` / `[对方@了你]` 前缀。

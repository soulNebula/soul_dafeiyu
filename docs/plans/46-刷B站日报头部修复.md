# 46. 刷B站日报头部「历史失败」修复

> 问题（2026-10-27 用户实测）：`out/<日期>.md` 的头部一直挂着「这一轮没跑起来 / 模型提供方没注册驱动：qianwen」，让人以为当天又挂了；实际上后面几轮都成功（判重表、挑中、归档都正常）。

## 根因

插件（`dsh-bili-scroll`）的 `stubReportIfMissing()` 只在**报告文件不存在**时补占位报告；
之后再成功的轮次是**追加**写入同一个文件的 —— 于是文件头永远是第一次失败时写的那段报错。

## 修法

在插件 `index.js` 的 `writeRoundNotesToReport()`（每轮结束前写「投递」笔记）里加一步：

```js
adoptStaleFailureReport()
```

行为：
1. 读 `out/<日期>.md`
2. 若前 200 字包含「没跑起来 / 没写出报告」→ 判定为历史失败占位
3. 把整份移到 `out/_failed/<日期>-<时间戳>.md` 归档
4. 重开一份正常日报 `# 刷B站 · <日期>`，本轮笔记照常写入
5. 归档失败（文件被占用等）时退化为覆盖写空日报头，至少不再挂旧错误

## 已处理存量

- `out/2026-10-26.md` → `out/_failed/2026-10-26-stale-placeholder.md`
- `out/2026-10-27.md` → `out/_failed/2026-10-27-stale-placeholder.md`
（挑中记录都在 `seen.md` / `digest/2026-10.md`，不丢）

## 生效条件与注意

- 插件代码在 **DSH 宿主进程**里加载：补丁要**重启 DSH** 才生效
- 插件升级/重装会覆盖 `node_modules` → 升级后重跑：
  ```bash
  python tools/bili_patch/apply_report_header_fix.py
  ```
  脚本幂等：已打过会提示跳过；找不到锚点会报错而不乱改；打补丁前自动备份 `index.js.bak-<时间>`
- 只动报告头部归档逻辑，不改取数/判重/发送/额度逻辑

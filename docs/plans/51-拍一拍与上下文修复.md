# 51 · 拍一拍识别修复 + 上下文窗口排查（P29）

> 起因：2026-10-27 15:08 用户连拍三次「"白云一片去悠悠"拍了拍我」，
> 小鱼回的是「刚才那句没组织好，你再说一次？」「这次我没接住，你再说一遍？」
> —— 说明拍一拍没走到 `[拍一拍] → 干嘛？` 分支，而是**以普通文本进了生成链**，
> 生成不合格后又触发 guard 兜底。本页记录真机证据、根因、修复与诊断工具。

## 1. 真机 raw 证据（gateway.log，2026-10-27 15:08–15:09）

```
15:08:57  inbound  text: "\"白云一片去悠悠\" 拍了拍我"   id=fccb16c8a8a85a0d
15:08:59  outbound text: "刚才那句没组织好，你再说一次？" status=sent
15:09:22  inbound  text: "\"白云一片去悠悠\" 拍了拍我"   id=efc203e65ffbc134
15:09:25  outbound text: "这次我没接住，你再说一遍？"     status=sent
15:09:48  inbound  text: "\"白云一片去悠悠\" 拍了拍我"   id=7334844f6abe3a32
15:09:50  outbound text: "刚才那句没组织好，你再说一次？" status=sent
```

要点：
- 真实原文是 **ASCII 双引号 + 空格**：`"白云一片去悠悠" 拍了拍我`（不是「」）；
- `gateway.log` 的 `inbound` 记录**不写 message kind**（`on_inbound` 只记 friend/text/id），
  所以单看日志无法直接看到 kind；
- 但 13:49 启动的网关进程已包含 P22 的 `kind=system + 拍了拍 → [拍一拍]` 转换与
  chat `[拍一拍] → 嗯` 分支。如果该事件是 `kind=system`，会回「嗯」；
  实际回的是 guard 兜底 → **真机这条是 `kind=text`**（wx_core OCR/分类把拍一拍当普通文本）。
- 另：`wx_core/monitor.py::_capture` 目前只放行含「撤回 / 引用消息」的 system 块，
  就算某些帧把拍一拍识别成 `KIND_SYSTEM` 也会在抓取层被丢掉（后续可单独修，本次不动 wx_core）。

## 2. 根因

1. `kind=text` 的拍一拍原文带引号/空格，旧 `server._reply` 只在 `kind == "system"` 时做拍一拍转写
   → 文本原样进 `SelfLearnAgent.send`；
2. chat 只认 `[拍一拍]` 标记 → 不命中；
3. 模型对「"白云一片去悠悠" 拍了拍我」生成不合格（空/复读/语气问题）→ guard 兜底句。

## 3. 修复（本任务已做，不碰 chat.py）

- **receiver.py**（`looks_like_pat` + 标记）：
  - 短文本（≤120 字）含「拍了拍」，且满足任一：`拍了拍` 后紧跟人称（我/你/他/她/它/对方/咱/俺），
    或文本带 `「」/"“”` → `pat=True`；
  - `_accept` 对 `kind=text` 也打 `pat=True`（真机路径）；system 放行关键词保留。
  - 反例：「今天拍了拍照，光线不错」「拍张照吧」不误判。
- **server.py**（`normalize_inbound_text` 纯函数 + `_reply` 统一调用）：
  - `kind=system`：撤回 → `[对方撤回了一条消息]`；引用 → `[引用] 对方引用了这条消息：…`；
    含「拍了拍」→ `format_pat_message`；
  - **`kind=text` 但 `looks_like_pat`** → 同样 `format_pat_message`（本次根因修复）；
  - @昵称 → `[对方@了你] ` 前缀（幂等）；
  - 新增审计事件 **`pat_detected`**：`{friend, msg_kind, raw, text, stripped}`
    （`msg_kind` 是原始消息 kind，避免与审计事件 kind 冲突），真机可直接核对；
  - 方向归一（机器人视角）：`"X" 拍了拍我` → `[拍一拍] 对方拍了拍你`；
    `我拍了拍"X"` → `[拍一拍] 你拍了拍对方`；解析不出兜底 `[拍一拍] 对方拍了拍你`。
- **诊断脚本 `tools/chat_context_probe.py`**（只读，见下节）。

## 4. 诊断脚本用法

```bash
# 看某联系人最近事件 + 历史 + prompt 实际历史条数
python tools/chat_context_probe.py --contact 白云一片去悠悠

# 只看真机事故那几分钟（15:08 前后 3 分钟）
python tools/chat_context_probe.py --contact 白云一片去悠悠 --around 15:08 --window-min 3

# JSON 输出（给脚本/报告用）
python tools/chat_context_probe.py --contact 白云一片去悠悠 --json
```

输出包含：
- 最近 inbound/outbound：raw 原文、拍一拍/引用/撤回识别、按 `text` 与 `system` 两种 kind 的转换结果；
- guard 兜底回复标记（`刚才那句没组织好/这次我没接住/…`）；
- memory 库最近 N 条历史（role/text/time/proactive）；
- `chat.py` 里 `recent_messages(... limit=N)` 的实际取值与出现次数（当前回复上下文仍是 **6**）；
- 历史字符数 ≈ token 估算。

真实输出节选（15:08 事故）：

```
15:08:57 in inbound [拍一拍?] raw='"白云一片去悠悠" 拍了拍我'
        -> 按 text 转写: '[拍一拍] 对方拍了拍你'
15:08:59 out outbound  <== guard 兜底! text='刚才那句没组织好，你再说一次？'
...
汇总：入站 5 条；其中拍一拍 3 条（inbound 日志不带 kind，3 条只能按内容判定）；guard 兜底回复 3 条
```

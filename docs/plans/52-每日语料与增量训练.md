# 52 · 每日语料与增量训练（P30）

> 目标：**边跑边训练**。每天从当天真实对话收集语料 → 过滤/规则标注 → 产 SFT/DPO/日报/语气总结；
> 样本够 300 且距上次训练 ≥3 天才允许进入训练门禁；**默认只计划，不自动训练、不自动切线上**。
> 聊天仍走 DeepSeek API；本地 0.5B/1.5B soul adapter 管线复用现有 `tools/train/`。

## 1. 数据流

```text
memory DB（turns / messages / turn_traces / proactive_events）
        │  按本地日期 00:00–24:00
        ▼
daily_corpus.py：过滤/去重/规则标注
        ├─ agi/data/train/daily/YYYY-MM-DD.jsonl   SFT
        ├─ agi/data/train/dpo/YYYY-MM-DD.jsonl    偏好对
        └─ agi/data/train/daily/YYYY-MM-DD.md     日报
        ▼
daily_summary.py：本地 3B(8125) 总结；失败规则兜底
        └─ agi/data/train/daily/YYYY-MM-DD.summary.md
        ▼
train_gate.py：check_ready → stage 数据 →（人工批准）train_once → evaluate → gate
        └─ agi/data/train/history.jsonl（版本/样本/得分/状态）
```

## 2. `daily_corpus.py`

- 输入：`agi/data/selflearn/*.memory.sqlite3` + `wechat_contacts/*.memory.sqlite3`；
  排除 `console_test`、`_mood_probe`、legacy/test 库；只读打开。
- 时间窗：`--date YYYY-MM-DD`（默认今天，本地时区）。
- 过滤：危机/自伤/密码/证件等敏感、测试联系人（文件传输助手/console_test）、
  跳过/空回复、纯贴纸（`[[media:...]]`/emoji 无正文）、正文 <2 字、去重。
- 规则标注（先不上 LLM）：
  - **negative**：下一条用户含否定词（不像/奇怪/别这样/好生硬/听不懂/什么意思…）、
    用户重复同一句、当前回复命中 slang（赢了/拿捏/笑死/666…）或 canned/收尾词（好的/早点睡/多喝热水…）。
  - **correction**：下一条用户说「不是/我是说/不是这个意思」→ 生成 DPO：
    `rejected=当前回复`，`chosen=用户纠正后的下一条回复`。
  - **positive**：下一条用户 ≥3 字且不含否定（继续延伸），或认可后继续。
  - **unlabeled**：没有下一条/太短，仍保留在 SFT 导出但训练门禁不计为可用。
- 输出行：
  ```json
  {"id":"D-T-...","messages":[{"role":"system","content":"..."},
   {"role":"user","content":"..."}],"response":"...",
   "meta":{"source":"wechat_contacts/....memory.sqlite3","quality":"positive",
           "reason":"user_continues","date":"2026-10-27","inner_json":{...}}}
  ```
  DPO：`{"id":"DPO-...","prompt":"用户纠正","chosen":"...","rejected":"...","meta":{...}}`。
- 日报：SFT 导出数、可训练正/修正、DPO、标注/过滤分布、Top 问题模式、数据源、样例。

## 3. `daily_summary.py`

- 读当天 jsonl；优先调用本地 **3B（127.0.0.1:8125）**，失败自动规则兜底（不联网其它地址）。
- 输出 3–5 条「像人/出戏」；若本地总结没有出戏项，从规则负样本补一条。
- 只写 `daily/*.summary.md`，不训练、不写生产库。

## 4. `train_gate.py`

- `check_ready()`：增量可用样本（positive+correction）**≥300** 且距上次训练 **≥3 天**才 `ready`；
  否则 `not_ready` + `reasons`/`next_ready`。
- `train_once(dry_run=True)`：把 daily SFT 转成 `smoke_lora` 需要的 `{context,user_msg,target}`；
  target 取当天 `turn_traces.inner_json`，没有 target 的样本跳过；写 `staged/`；
  新版本目录 `E:\agent\output\soul_qwen25_05b_v<next>`，**不覆盖旧版**。
  - 默认只输出命令，不启动 GPU；`--execute` 才真跑（需 Lead 明确批准）。
- `evaluate(version)`：黄金集 50 条（`agi/eval_data/golden_v1.jsonl`）评估骨架；
  读取版本目录下 `eval.json`，没有则返回待评估人工清单。
- `gate(version)`：新分 ≥ 上一**已训练版本** -2 → `candidate`，否则 `rejected`；
  **不自动切换线上**（`switched:false`），由 Lead/用户决定。
- 历史：`agi/data/train/history.jsonl`（date/version/samples/score/status）。

## 5. 调度

- `tools/train/run_daily.py`：收集 → 总结 → 门禁检查；默认**不训练**。
- Windows 计划任务建议每天 **03:00**：
  ```powershell
  E:\agent\venv312\Scripts\python.exe tools\train\run_daily.py
  ```
- 训练频率：每 3 天或样本 ≥300 时**提醒**；不自动训练（耗 GPU）。
- 训练触发（人工）：
  ```powershell
  python tools/train/train_gate.py --check
  python tools/train/train_gate.py --train-once          # 只计划
  python tools/train/train_gate.py --evaluate v2
  python tools/train/train_gate.py --gate v2 --score 88
  # 真正训练需 Lead 明确批准后：--train-once --execute
  # 训练完合并/量化：tools/soul_serve/prepare_model.py --adapter ... --name ...
  ```

## 8. 基座与 shadow 策略

- 先 **0.5B**（现有 soul adapter v1b/v1rb）跑增量；1.5B 后续再上（显存/速度成本更高）。
- 新版本先做 **shadow**（只记录/离线对比，不切线上），黄金集 + 人工抽检通过后由 Lead 决定切。
- 每日数据只在本机 `agi/data/train/`（gitignore）；语料含用户原文，**不外传、不 commit、不入日志**。

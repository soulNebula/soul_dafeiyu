# 58 · 类海马体记忆衰减（P38）

> 用户刷抖音看到的"类海马体记忆"：重要记忆在中心、边缘记忆逐渐淡忘，最后剩一个字消失；
> 200 天内提起可唤醒再衰减。本任务先做 `memory_decay.py` + 测试 + 文档，
> **chat.py/server.py 接线等 Lead 通知**（当前正被 w2-inner/其他人改）。

## 1. 数据模型（lazy ALTER，不重建表）

`user_memories` 惰性加列（只在真正写/revive 时 `ALTER TABLE`）：

| 列 | 默认 | 含义 |
| --- | --- | --- |
| `strength` | 1.0 | 当前记忆强度（0–1） |
| `last_strength_at` | created_at | 上次衰减/续命时间 |
| `forget_stage` | `full` | `full / compressed / keyword / dormant` |
| `revive_count` | 0 | 被唤醒次数 |
| `content_full` | 原文 | 压缩前的完整原文（供 revive 恢复） |

旧库补列时：`last_strength_at=created_at`、`content_full=content`。

## 2. 半衰期

`strength *= 0.5 ** (dt_days / half_life)`；`half_life` 由 kind + importance 决定：

| kind | 半衰期 |
| --- | --- |
| profile / value / plan / fact | **30d** |
| preference / insight | **14d** |
| event | **7d** |
| smalltalk / chat | **2d** |
| 其它 | 7d |

importance 修正：`≥0.8 → ×2`；`≤0.3 → ×0.5`；其余 ×1。

## 3. 渐进遗忘阶段

| strength | stage | 存储 |
| --- | --- | --- |
| ≥0.5 | `full` | 原文 |
| 0.2–0.5 | `compressed` | 压成 ≤40 字一句事实；原文进 `content_full` |
| 0.05–0.2 | `keyword` | 2–4 个关键词（`、` 连接） |
| <0.05 | `dormant` | `status=dormant`，**不物理删**；检索默认不注入 |

## 4. API（模块层，测试/后续接线用）

```python
decay_all(path, now=None, dry_run=False) -> dict
revive(path, memory_id, now=None) -> dict
search_with_revive(path, query, limit=8, now=None) -> list[dict]
purge_dormant(path, days=200, now=None, dry_run=True) -> dict
strength_report(path, limit=50) -> dict
ensure_columns(con)   # 惰性加列
```

- `decay_all` dry-run **不写列、不写数据**；返回 `checked/changed/stages/samples`。
- `revive`：strength≥0.6、恢复 `content_full`、stage 回 full、`revive_count+1`、status active。
- `search_with_revive`：先走 `search.search`；命中 memory 即 revive（检索每次续命）；
  无索引时按 LIKE 兜底（也覆盖 dormant）。
- `purge_dormant`：只删 `forget_stage=dormant` 且 `last_strength_at` >200 天的；默认 dry-run。

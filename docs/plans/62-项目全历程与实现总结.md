## 2. 起点：用户想要什么

最早的诉求（大意，非逐字）：

> 做一个叫「小鱼」的 AI 伴侣：**小模型当灵魂**（内心状态/情绪/动机），**大模型当智慧**；
> 接入**真实微信**；有 **802 控制台 + 803 工作台**；未来要能开源。

它要同时满足四组互相拉扯的需求：

1. **人格一致性 vs 大模型默认行为**：底座模型天然是「客服腔」，伴侣要固定说话方式/情绪曲线/边界；
2. **长期记忆 vs 上下文窗口**：几个月聊天远超上下文，必须有选择地记住、遗忘、压缩；
3. **主动 vs 打扰**：会主动开口是「有生命力」的关键，但频率/时机/内容失控就是骚扰；
4. **隐私/成本 vs 能力**：持续把私聊发云端有隐私与费用问题，本地小模型能力又有限。

小鱼的答案：**以本机为边界、以真实微信为入口、以可训练的小模型为人格载体、以云端大模型为能力上限**，
并把每一层做成可测试、可运维的形态。

## 3. 阶段一：内核与主链（SoulAgent）

### 3.1 接入层：真实微信

- **收消息双后端**：
  - wxauto4 `WeChatReceiver`（UIA/窗口）；
  - `wx_core.MonitorBackend`：**WCDB 数据库直读**（只读解密 + OCR 回退），文字来自数据库原文；
  - 群聊未支持；引用/拍一拍/@ 是启发式识别；公众号全文受 IP 风控，只做标题摘要。
- **发消息单一入口**：`Gateway._send`，全局发送锁，reactive/主动/人工三条路径串行化。
- **发送闸门**（fail-closed）：STOP 文件 → 引擎开关 → 白名单（空 = 拒绝）→ 内容检查 → `send_mode`
  （off/confirm 草稿/auto）→ 节流（最小间隔、每小时 40、每天 200）→ 夜间静默 → 发送器子进程。
- **送达语义**：`unverified` 只表示「调用返回 ok 但没有送达证据」，不计 sent、不重置熔断。
- **发送后端**：`wechatauto-replica`（Python 3.12 独立 venv `E:\agent\venv_wx312`），主进程 3.14 不 import wx 系依赖。
- **草稿**：confirm 模式落草稿；草稿 TTL（`DRAFTS_TTL_DAYS`/`draft_ttl_days`）+ `purge()`，修复草稿堆积（曾 90 条）。
- **可靠性**：幂等键 `(contact, turn_id, bubble_index)`；失败进草稿；`turn.delivery_status` / `messages.delivered`。

### 3.2 认知与人格层（`agi/selflearn`）

- **长期记忆**：记忆抽取/合并/冲突处理/检索；类海马体**半衰期衰减**（分层、dormant 200 天后才可能清理，默认 dry-run）；
  802 记忆页显示每条的**遗忘度**。
- **情绪**：每轮判心情（`moodDelta` + 7 维情绪 + reason + confidence），基线 mood 70，
  mood 半衰期 3h、7 情绪 90min；心情影响说话方式与主动程度。
- **人格三层**：`persona_layers.py` —— core（人工批准）/ evolving（证据累积 + 限速）/ relations；
  人格设定书 `agi/persona/<名字>/`，安装：`python -m tools.persona.install_xiaoyu`。
- **内状态 InnerState**：mood/energy/sharing/battery/trust 0–1，stage 陌生/初识/熟悉/亲近/信任，
  stance/intent/monologue/behavior.length/ask/advice/emoji；schema 校验 + 注入策略；默认 shadow（只记录不注入）。
- **风格守卫**：去「」、去账/模板句、去金句腔、不主动收尾、去网感腔调；
  额外修复：禁止编造网络故障、发送前文本质检。
- **日记 / 周复盘**：每天 23:00 第一人称日记；周日 23:30 周复盘提炼进核心人格层；802 日记页只读阅读器。
- **自我叙事 / 内驱力 / 兴趣画像**：45 天叙事、内驱力队列、兴趣画像。

### 3.3 主动消息

- 主链是网关常驻循环：`pacing`（对等）× `initiative`（熟悉度/心情/信任）× 内驱力队列，不是定时群发。
- 无响应冷却（`proactive_no_response_cooldown_s`，6h，streak≥3）、静默时段、概率 + 间隔；
- 主动消息质量整改：ledger strip、legacy payload 润色、草稿 TTL、主动链唯一入口（`proactive_registry.py`）。

### 3.4 模型路由（成本/能力折中）

- `agi/llm/router.py` + `agi/data/llm_router.json`：按用途分本地/云端：
  - 本地：`keyword_extract` / `ingest_summary` / `comment_cluster` / `relevance_score` / 识图；
  - 云端：`chat_reply` / `mood_judge` / `share_copy` / `video_understanding`；`selflearn_image_understanding` → local 失败回退 api；
- 预算 300k tokens/天，超限降级 local；成本约 0.001468 元/条。
- **802 控制台**：单页应用（原生 JS），页面覆盖总览/对话流/推理过程/内状态/媒体/素材库/记忆/提示词/日记/上网记录/朋友圈/统计/模型/模型配置/日志/数据管理/B站/设置；终端右侧弹出（不是底部）。

## 4. 阶段二：灵魂线（W1–W4）与蒸馏

### 4.1 为什么 0.5B 当灵魂

- 大模型负责「会说」，小模型负责「怎么想」（InnerState）；小而本地 → 隐私、延迟、成本、可控；
- 实测：`soul-05b`（Qwen2.5-0.5B-Instruct v1b，Q4，8123）≈ **51 tok/s**，单轮内状态生成约 1.7s；
- 灵魂模型不直接对外聊天，只产出结构化状态；聊天仍由 DeepSeek 表达。

### 4.2 蒸馏数据

- 教师 = DeepSeek（`agi/selflearn/llm.Client`，key 走密钥库/env）；
- 7 种状态档案（同一 context 不同心情/关系阶段）制造监督多样性；
- `agi/soul/dataset.py` 产出 `agi/soul/data/soul_sft_v1.jsonl`：**1891 行**（golden 350 / messages 832 / synthetic 708），
  教师调用 **2112 次**，prompt 1,664,330 / completion 359,346 tokens；
- 训练工具：`tools/train/smoke_lora.py`、`sft_train.py`（messages/instruction/soul，`--full-ft`、`--load-4bit`），
  导出 `tools/train/export_chat.py`，合并 `tools/soul_serve/merge_adapter.py`，转换 `tools/soul_serve/convert.py`；
- 实测：LoRA 10 步 7.48s（loss 2.60→1.26，峰值 1.8GB，adapter 34MB）；全参 2 步 12.66s（峰值 5466MB，产物 954MB）。

### 4.3 内状态接入与验收

- `agi/inner/` schema、shadow 记录、注入策略；四臂消融（金色集 → 4 模式回复）评估；
- 质量整改后 9 维度评分全部 ≥7（综合 5.4 → 7.7）。

### 5.2 实现

- 独立项目 `idea/`（FastAPI + 原生 JS 单页），7 个基础视图 + 3 新页；
- **语料清洗**：
  - 上传聊天文本/截图；文本支持 `我:`/`你:`、微信导出风格、JSONL；
  - 图片走 `tools/ocr_image.py`（RapidOCR 直连，左右气泡判角色，表情包/图片占位符 `[表情包]/[图片]`）；
  - 异步进度条（`start_parse`/`parse_status`）、并发可调（`IDEA_OCR_CONCURRENCY`，默认 3）；
  - 结果按「全选/反选/全部/仅你/仅我」筛选，保存为统一 `messages` 或 `instruction` JSONL；
  - 实测：18 张截图 126.6s → 清洗 1160 条 → 444 训练 + 23 验证样本。
- **用户标注**：微信式对话气泡 + InnerState 打分/标签，生成 soul 训练 JSONL；中文化 short/normal/long 等枚举。
- **模型蒸馏**：mock/real 双模式、教师调用预算、任务日志/取消、确认生成、参数配置。
- **训练/模型中心**：LoRA/全参、数据集扫描、模型启停/下载/磁盘统计。
- 测试：`idea/tests` **101 passed**；验收脚本 `scripts/acceptance.py`（pytest/冒烟/E2E/UI 截图，--fast 模式）。

### 10.3 踩过的坑与修复

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 窗口空白灰底 | Edge app 在无 GPU/远程会话不渲染；且会复用旧的空白窗 | 加 `--disable-gpu`、`--no-first-run`；只复用标题含 `Soul Console` 的窗口，空白窗关掉重开，仍失败回落浏览器 |
| 一闪而过的黑窗/管理员 PowerShell | launcher 用 `powershell` 查询窗口状态，每次弹窗 | 全部隐藏执行（`CREATE_NO_WINDOW` + `-WindowStyle Hidden`）；窗口标题改用 Win32 `EnumWindows/GetWindowText`（ctypes），不再起外部进程 |
| Edge「现有实例正在以提升权限运行」 | 管理员启动 → Edge 继承提权 | 检测 `IsUserAnAdmin`，管理员模式改用普通权限 `explorer` 打开浏览器，并提示正常双击 |
| PyInstaller exe 0xc0000142 / 410MB | 本机安全软件/加载器拦截；`--collect-submodules agi` 拉入无关依赖 | 不推荐 exe，改 pythonw；构建脚本保留；去掉 collect-submodules（20MB） |
| 首次打开 20–30s | Edge 独立 profile 冷启动 | 文档说明；后续复用窗口秒开 |
| 任务板「验收-测试矩阵」一直 running | 脚本卡 + 未回写状态 | 修 acceptance Edge 卡死，跑通 `--fast` 19/0/3；任务板统一收口 completed |

## 12. 关键设计决策（为什么这样做）

| 决策 | 理由 |
| --- | --- |
| 大模型「会说」+ 小模型「怎么想」 | 人格/情绪稳定可控；隐私与成本；大模型只做表达 |
| 本地 0.5B 只产 InnerState，不直接聊天 | 0.5B 聊天质量不够，但结构化输出够用；失败可规则兜底 |
| 按用途路由 + 预算降级 | 高频/低风险走本地，判断/创作走云端；超预算自动降级 |
| 记忆半衰期 + 遗忘度可视化 | 长期对话必须选择遗忘；可解释、可调 |
| 主动 = pacing × initiative × 内驱力，不是定时 | 避免「定时群发」；有冷却与静默 |
| 发送全局单入口 + fail-closed | 防重复/错发/幻觉；空名单宁可拒发 |
| 密钥全部外置到 secrets.json | web_config 明文易误提交；ACL + env 优先级 |
| IDEA 独立项目、subtree 合入 | 工作台迭代快、测试独立；主仓只做交付与文档 |
| 桌面版用 pythonw + Edge app + PowerShell 托盘 | 零 pip 依赖、无 Tauri 工具链；Windows 上够用；exe 被安全软件拦 |
| 桌面不要管理员运行 | 否则 Edge 提权冲突；已做自动回落 |

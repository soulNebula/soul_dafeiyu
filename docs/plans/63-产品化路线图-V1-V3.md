# 63 · 产品化路线图：一键安装 / 803 bot 向导 / 802 登录 / 本地+云端 / 训练闭环

> **状态**：规划稿（2026-11-01），**尚未开工**。
> **定位**：把「clone 下来能跑」升级成「普通用户能装、能配、能验收」的产品化路线。
> **施工纪律**：先做 V1 验收线（新电脑 clone → 一键脚本 → 803 建 bot → 802 登录/加载 → 自检通过），
> V1 不通过不启动 V2；每期结束跑全量测试与真机冒烟。

## 一、用户旅程（目标）与现状差距

目标旅程（用户视角）：

1. 运行脚本 → 自动校验环境（国内源）→ 拉起 803；
2. 803 添加 bot → 选「云端模型方案」或「本地+云端方案」→ 填 DeepSeek key / 灵魂模型配置 →
   选内状态等可选能力 → 设 802 密码 → 保存 bot 包（DB/模型/图片识别选择/记忆/日记/环境数据）；
3. 803 底部「打开 802」→ 802 先登录；
4. 802 默认关闭监听/回复 → 总览点「刷新联系人」（先提示微信版本）→ 显示当前微信昵称/联系人 →
   wxid 落库 → 「添加 bot」选择 803 里的 bot 路径；
5. 加载 bot（进度条）→ 选单/多用户（群聊暂不做）→ 改提示词 → 配模型；
6. B站扫码登录 → 设置关键词（可留空让 LLM 自选）→ 保存；
7. 设置：灵魂开关、主动方式/频率/概率/条数、对话比、B站/朋友圈/上网开关、识图与关键帧后端、内状态、灵魂注入、数据入库；
8. 保存全部 → 自检（模型连通/聊天/灵魂/识图）→ 总览「开始运行」；
9. 本地模型分支：环境/GPU 检查 → 一键搭建（CUDA/ollama）→ 推荐/自选模型下载 →
   语料清理/训练/蒸馏 → 802 数据积累进度条/自动打包 → 803 选数据后训练 → 802 加载新模型 →
   打过标签的数据次日清理。

现状差距（按当前代码）：

| 能力 | 现状 | 差距 |
|---|---|---|
| 一键环境脚本 | 手动建 3.14 主环境 + 3.12 微信 venv（`guides/新用户上手.md`） | 无 `bootstrap`；无国内源/失败回滚/硬件检查 |
| 803 bot 管理 | 803 是工作台（语料/蒸馏/训练/模型中心），有随机本地 token | 无「bot 包」概念；无新建/加载/切换 bot |
| bot 数据隔离 | 全局 `agi/data`、`agi/selflearn`、`agi/data/wechat` | 需引入 `bots/<id>/` 工作区 + 路径解析改造 |
| 802 登录 | 只有右上角 admin token | 无用户/密码/会话；token 是运维口，不是产品登录 |
| 默认关闭引擎 | 支持（`enabled/engine_enabled/auto_reply`） | 无「首次登录默认安全态」的产品化引导 |
| 刷新联系人 | 通过 DB/UIA 读当前微信；白名单按昵称 | 无「刷新联系人」按钮/API；无 wxid 稳定 ID 映射；无微信版本提示 |
| 从 803 加载 bot | 无 | 需 bot 目录校验/迁移/进度上报 |
| B站扫码 | 依赖仓库外 `~/.dsh/bili-duty` 插件 | 新克隆没有 → 第 6 步不可用（V1 硬前提） |
| 设置项 | 主动开关/概率/间隔、max_bubbles、媒体、内状态、静默、send_mode 已有 | 缺主动方式、对话比、主动条数、朋友圈/上网/刷B站开关、识图后端、数据入库 |
| 双模型 | 主聊天 DeepSeek；本地 0.5B 只做内状态/提取 | 无「聊天模型/灵魂模型」按 purpose 路由；无云端灵魂 provider |
| 训练 | TrainLab/门禁在；`samples<300`、`last_training=null`、只产 candidate | 无自动清理→训练→评测→上线闭环；无蒸馏流水线 |
| 数据打包 | 无 | 无进度条/自动打包/803 选择/标签/次日清理 |
| 安装包 | 仅 Windows；PyInstaller exe 被安全软件拦 | V1 用「绿色目录 + pythonw 快捷方式」；MSI 后置 |

## 二、目标架构（四层）

```
安装层  scripts/bootstrap.py（检测/镜像/venv/依赖/自检/拉起 803）
   │
控制面  803 Workbench（bot 管理、模型下载、训练任务、数据包、日志）
   │            └── 读写 bots/<id>/（唯一数据源）
   │
运行时  802 Console（登录、总览、设置、自检、启停）
   │            └── 通过 801 Gateway 操作微信
   │
执行层  801 Gateway（收发/发送池/闸门）+ 本地模型服务（llama.cpp/ollama）
        + 训练 worker（独立进程，GPU/CPU 队列）
```

### bot 包目录（唯一数据源）

```
bots/<bot_id>/
  bot.json                 # 名称、创建时间、方案(local/cloud/hybrid)、版本
  config/wechat.json       # 网关配置（白名单/发送模式/主动/限额）
  config/app.json          # 设置项（见第七节）
  secrets/keys.enc         # API key/密码（Windows DPAPI 加密；绝不入 Git）
  db/wechat.sqlite3        # 微信消息/联系人/wxid
  db/selflearn/*.sqlite3   # 记忆/人格/日记/技能/训练数据
  db/train/*.jsonl         # 语料包/训练记录/标签
  models/soul/             # 灵魂模型（本地时）
  models/vision/           # 识图/关键帧模型（本地时）
  media/                   # 图片/表情素材
  prompts/                 # 提示词覆盖（可为空=默认）
  logs/                    # gateway/worker 日志
```

### 路径改造（代码影响面）

- `agi/paths.py`：新增 `bot_root()`，优先级 `SOULAGENT_BOT_ROOT` > `bots/active` > 旧全局路径（向后兼容）；
- `agi/wechat_gateway/config.py`：`config` 默认路径改为 bot 内；
- `agi/selflearn/config.py`：DB/模型/提示词路径统一走 `bot_root`；
- 迁移工具：`scripts/migrate_to_bot.py`（把旧 `agi/data/*` 打包成 `bots/default/`，幂等）；
- 多 bot 并发**不在 V1**：一个 801 进程只服务一个 bot；V3 再评估多进程/多端口。

## 三、必须先拍板的决策（阻塞项）

| # | 决策 | 已定结论（2026-11-01） | 影响 |
|---|---|---|---|

## 四、V1（先跑通「能装、能配、能跑」）

### 范围

1. **安装器** `scripts/bootstrap.py`（Windows）：
   - 检测：Windows 版本、Python 3.14（主）/3.12（微信 venv）、磁盘 ≥10GB、微信版本、可选 GPU；
   - 国内源：pip 清华/阿里镜像、`HF_ENDPOINT=https://hf-mirror.com`；
   - 建 venv、装依赖、初始化 `bots/default/`、写默认配置（安全态）；
   - 失败可重试/回滚；日志写 `logs/bootstrap.log`；成功后启动 803 并打印 802/803 地址。
2. **803 bot 向导**：新建/打开 bot；方案选择（云端 / 本地+云端）；DeepSeek key；802 密码；
   内状态等可选项；保存 bot 包；「打开 802」按钮（子进程+健康检查）。
3. **802 登录**：密码登录（失败限速）、会话 cookie、默认安全态（监听/回复关）。
4. **联系人刷新**：提示微信版本→刷新→显示微信昵称/联系人→**wxid 落库**→白名单双写（昵称+wxid）。
5. **加载 bot**：目录校验→迁移/校验 DB→进度条（校验/建库/加载配置/模型检查/就绪）→选单/多用户（群聊留空）。
6. **设置页**：补齐第七节 V1 字段（主动开关/方式/概率/间隔/条数、max_bubbles、媒体、静默、内状态、识图后端预留）。
7. **自检页**：DeepSeek 连通 / 聊天 / 识图 / 本地模型（若启用）；失败给出可操作错误。
8. **B站**：V1 至少「未安装提示 + 安装入口」，不阻塞主流程（若 D3 选是，则扫码登录可用）。

### V1 验收清单

- [ ] 新电脑 clone 后只跑一个脚本，10 分钟内看到 803 登录页（无 GPU/无模型也能起）；
- [ ] 803 创建云端 bot → 802 登录 → 刷新联系人（wxid 入库）→ 加载 bot 成功；
- [ ] 默认引擎关闭；手动「开始运行」后才监听/回复；
- [ ] 设置保存热加载；自检四项通过；DeepSeek 不填时明确报错不崩；
- [ ] 卸载/重装不丢 `bots/`；日志可定位失败步骤；
- [ ] 全量测试 301 + 2298(+4) 不回归；新增安装器/向导/登录/contacts 单测。

## 五、V2（本地模型 + 训练/数据闭环）

1. **硬件与环境**：`nvidia-smi`/CUDA/显存检测；无 GPU → 禁止本地方案、引导回云端；
   一键安装 CUDA/ollama（可选组件，失败可跳过）；按显存/内存给推荐档位。
2. **模型下载**：推荐/自选/仓库/镜像/直链；校验 sha256、断点续传、磁盘预算；
   灵魂模型与识图/关键词模型分开下载（只选灵魂就只下一个）。
3. **语料流水线**：导入→清洗（去重/脱敏/质量）→切分→训练/蒸馏→评测→candidate→802 加载；
   所有步骤有进度/日志/失败恢复；产物进 `bots/<id>/models/`。
4. **数据积累**：802 显示样本进度条；满阈值自动打包到 `bots/<id>/db/train/`；803 可见可选；
   训练记录打标签；次日清理已训练包（保留清单/回滚点）。
5. **训练 worker**：独立进程/队列（803 触发、worker 执行），不阻塞 802；GPU/CPU 任务隔离。

### V2 验收清单

- [ ] 有 GPU 机器完成「检测→下载→清洗→训练→802 加载」全流程；
- [ ] 无 GPU 机器在检测处被拦下并给出云端方案；
- [ ] 数据包/训练记录/标签/次日清理可核对；训练失败不污染线上模型；
- [ ] 训练前后全量测试与真机冒烟通过。

## 八、风险与依赖

1. **微信 UIA/版本**：升级/多开/群聊易坏；刷新联系人、发送都要版本提示与失败恢复；
2. **账号风控**：任何「自动刷/主动发/多 bot」都限频；默认安全态、STOP、熔断必须保留；
3. **B站插件外部依赖**：不收进仓库则 V1 第 6 步不可用（D3）；
4. **本地模型体积/驱动**：CUDA/ollama/模型下载是支持成本大头；必须有磁盘/显存门槛与失败回滚；
5. **安全**：`keys.enc`（DPAPI）、802 密码哈希、仅绑 127.0.0.1、日志脱敏；
6. **训练数据合规**：用户数据打包/训练需显式同意与删除路径（次日清理之外提供「立即删除」）；
7. **多 bot 并发**：V1 明确不支持，避免承诺无法交付的隔离。

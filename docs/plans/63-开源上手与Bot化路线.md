# 开源上手与 Bot 化路线（草案，待拍板）

> 目标：把「开发者 clone 仓库 → 一键配环境 → 803 建 Bot → 802 登录/加载 Bot → 配好就能聊」
> 做成一条可走通的路径。本文只定路线与清单，**不动代码**。
> 提出人：用户；整理：Lead；日期：2026-10-29。

## 0. 结论先说

**总体可行，但不是“加几个页面”**。当前项目是「单机、单账号、单套 `agi/data` 配置」的形态；
你描述的流程需要引入一个原本没有的概念：

> **Bot = 可保存/可切换的独立配置包**（数据库 + 密钥 + 模型路径 + 记忆/日记 + 人格 + 开关）。

这一层一旦立住，后面 803 建 Bot、802 选 Bot、按 Bot 隔离模型/记忆/设置都能顺下来；
立不住，就会变成“全局配置互相覆盖”。

**建议路线：先做「单活跃 Bot」的 MVP，不做多 Bot 同时在线。**
即：803 可以管理多个 Bot 目录，但 802/801 同一时刻只加载一个；切换 Bot = 重载配置（必要时重启服务）。
多 Bot 并发是另一个量级的工程（每 Bot 独立 worker/DB/锁），不建议现在做。

## 1. 你描述的旅程 → 目标形态

```
克隆仓库
  → setup 脚本（检查环境/国内源装依赖/可选装 llama.cpp+CUDA）→ 打开 803
  → 803 添加 Bot（选方案：云端 / 本地+云端 / 本地模型）
       ├─ 云端：DeepSeek key、灵魂 API key、内状态 key（可选）、802 密码
       ├─ 本地：GPU 检测 → 推荐模型 → 下载灵魂/识图/文本提取/语料模型
       └─ 保存到用户选定目录（Bot 包：配置/密钥/数据库/模型清单/数据）
  → 803 底部「打开 802」→ 802 登录（Bot 的密码）
  → 802：默认关闭监听 → 刷新联系人（提示先开微信）→ 显示微信昵称/联系人
       → 添加 Bot（选路径）→ 自动识别并加载（进度条）
  → 选聊天目标（单/多用户；群聊暂不做）
  → 提示词 → 模型 → 模型配置（key/参数已从 Bot 带出）
  → B站扫码/设置（关键词、人设可选）
  → 设置页（灵魂/主动/频率/比例/上限/概率/刷B站/朋友圈/上网/识图走本地或云端/入库/主动策略）
  → 保存全部 → 对话测试（模型连通/聊天/灵魂/识图）→ 总览「开始运行」
  → 训练支线：803 模型页检查环境 → 推荐/自选/自定义下载 → 语料清洗/蒸馏/训练
       → 802 数据积累进度条满自动打包 → 803 看到打包数据 → 后训练 → 802 加载新模型
```

## 2. 需要先钉死的 5 个概念

| 概念 | 建议定义 |
| --- | --- |
| **Bot 包** | 一个目录（用户选路径），含 `bot.json`（配置 schema 版本）、`secrets.json`、`db/`（联系人/记忆/人格库）、`data/`（日记/媒体/导出）、`models.json`（模型清单/路径/校验和）、`datasets/`（打包数据）。可整体拷走/备份 |
| **活跃 Bot** | 802/801 同一时刻只认一个 Bot；`agi/data/active_bot.json` 记录当前 Bot 路径与校验；切换时走“保存→停止引擎→重载→重启必要服务” |
| **Bot 内数据隔离** | 联系人库、记忆、人格、日记、密钥、模型路径全部按 Bot 解析；禁止回落到全局 `agi/data`（除兼容旧部署） |
| **模型资产** | 模型文件不复制进 Bot；`models.json` 只存路径/来源/校验；本地模型服务（8123/8125）按 Bot 的模型路径启动 |
| **云端方案** | 聊天/灵魂/识图都可选 `local` 或 `api`；云端灵魂 = 用 API 生成 InnerState（路由 purposes 已支持 local/api，只需暴露配置） |

## 5. 关键风险 / 必须提前决策

1. **微信版本与合规**：只支持 Windows + 微信 PC；自动化有封号风险；开源文档必须写“仅本人账号”。
2. **外部依赖**：发送器 `wechatauto-replica`、B站 DSH 插件、本地 llama.cpp 都不在仓库里；
   一键脚本可以装/下载，但需要许可与镜像策略。
3. **模型许可与体积**：Qwen2.5/2.5-VL 等模型要遵守各自 license；下载源/校验和要写清；磁盘需求大。
4. **Bot 包密钥**：`secrets.json` 明文落盘（当前 ACL 收紧）；开源用户环境不可控，至少要求
   Bot 目录权限/提示“不要放共享盘/网盘”。
5. **数据删除语义**：“第二天统一删除”有数据丢失风险；建议默认“打包后保留 N 天”，用户显式开启删除。
6. **多 Bot 隔离**：当前所有路径常量是全局的；Bot 化需要一次性重构 `agi/paths`/config/secrets/DB，
   这是最大工程量，也是所有流程的地基。
7. **803/802 双服务一致性**：切换 Bot 时要防止 801 还在用旧 DB/旧 key；需要“停引擎→切→校验→起引擎”的编排。
8. **开源用户环境差异**：Python 3.12/3.14、CUDA 版本、微信 3.9/4.x、代理/镜像；需要兼容矩阵。

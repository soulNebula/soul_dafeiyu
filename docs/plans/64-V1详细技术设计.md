# 64 · V1 详细技术设计：单机 Web 版（.bat 启动 / 803 bot 向导 / 802 登录 / 云端或本地灵魂）

> **状态**：设计稿（2026-11-01），**未开工**；上游决策见 [`63-产品化路线图-V1-V3.md`](63-产品化路线图-V1-V3.md)。
> **V1 验收线**：新电脑 clone → 双击一个 `.bat` → 803 建 bot（云端方案）→ 打开 802 → 登录 →
> 刷新联系人（wxid）→ 加载 bot → 设置保存 → 自检通过 → 开始运行。
> **明确不做**：多 bot 并发、群聊、安装包（MSI/PyInstaller）、自动登录微信。

## 一、已拍板的决策（2026-11-01）

| # | 决策 | 结论 | 对设计的影响 |
|---|---|---|---|
| D1 | 灵魂模型本地/云端 | **由用户在 bot 配置页选择**：本地→本地模型路线；云端→云端 API 路线 | bot 包记录 `soul.provider`；模型路由按 purpose 选通道；本地要路径/量化，云端要 key |
| D2 | 多 bot 并发 | **否（暂不支持）** | 单进程单 bot；`bots/<id>/` 仍隔离，为以后留口 |
| D3 | B站模块入库 | **是** | 把外部 `~/.dsh/bili-duty` 能力迁入仓库（可选依赖），扫码登录可用 |
| D4 | 802 登录 | **首次配置 admin token；之后 本机单用户密码 + 会话 cookie；内部复用 admin token** | 802 增加密码哈希/会话/登录页；机器调用仍用 token |
| D5 | 安装包 | **不做**；网页端 + 一个 `.bat` 启动脚本 | `启动.bat` → `scripts/bootstrap.py`（检测/装依赖/拉起 803） |
| D6 | 对话比 | **802 设置页新增选择**，用户自配 | 新增 `chat.user_llm_ratio`（1:1 / 1:2 / 1:3），作为 `reply_max_bubbles=0` 时的默认预设 |

## 二、V1 目标架构（单机单 bot）

```
启动.bat
  └─ scripts/bootstrap.py
       ├─ 环境检测（Python/磁盘/微信/可选 GPU）
       ├─ pip 国内源 + 建 venv（3.14 主 / 3.12 微信）
       ├─ 初始化 bots/default/
       └─ 启动 803（控制面）→ 打印 http://127.0.0.1:803

803 控制面（idea/，扩展为 Bot Manager）
  ├─ 新建/打开/保存 bot 包（bots/<id>/）
  ├─ 方案：云端 / 本地+云端；灵魂模型 local|cloud
  ├─ 填 DeepSeek key / 灵魂 key（DPAPI 加密）
  ├─ 设 802 密码（哈希）
  ├─ 启动 802（子进程 + 健康检查 + token 注入）
  └─ 训练/模型页（V2 启用）

802 运行时（tools/console）
  ├─ 登录（密码 + 会话 cookie）；首次引导设密码
  ├─ 默认安全态：enabled/engine/auto_reply 全关
  ├─ 刷新联系人 → wxid 落库 → 白名单双写
  ├─ 加载 bot（进度条：校验→迁移→建库→配置→模型→就绪）
  ├─ 设置页（D6 对话比 + 主动方式/条数/媒体/内状态/入库开关）
  └─ 自检（DeepSeek/聊天/灵魂/识图/本地模型）→ 开始运行

801 网关（现有）
  ├─ 单 bot 运行；发送池/闸门/熔断沿用
  └─ 模型调用经「路由注册表」选择 chat/soul/vision/provider
```

## 三、bot 包与路径

### 3.1 目录

```
bots/<bot_id>/
  bot.json                 # 名称/创建时间/方案/版本
  config/wechat.json       # 网关配置（白名单、发送模式、限额、主动）
  config/app.json          # 802 设置（第六节）
  secrets/keys.enc         # API key + 802 密码哈希（DPAPI）
  db/wechat.sqlite3        # 消息/联系人/wxid
  db/selflearn/*.sqlite3   # 记忆/人格/日记/技能
  models/soul/             # 本地灵魂模型（local 时）
  models/vision/           # 本地识图/关键帧（local 时）
  prompts/                 # 提示词覆盖
  media/ logs/
```

### 3.2 路径解析

- `agi/paths.py` 新增：
  - `bot_root()`：`SOULAGENT_BOT_ROOT` > `bots/active` 文件 > 兼容旧全局路径；
  - `bot_config_dir()` / `bot_db_dir()` / `bot_models_dir()`；
- 现有模块改造：
  - `agi/wechat_gateway/config.py`：默认配置路径改为 `bot_root/config/wechat.json`；
  - `agi/selflearn/config.py`：`WEB_CONFIG`/`DB_PATH` 指向 bot 内；
  - `tools/console/server.py`：启动时解析 `SOULAGENT_BOT_ROOT`；
- 迁移：`scripts/migrate_to_bot.py` 把旧 `agi/data/*` 复制/链接到 `bots/default/`（幂等，保留原目录只读备份）；
- 单 bot：`bots/active` 指向当前；切换 bot 需重启 801/802（V1 明确）。

### 3.3 secrets

- Windows DPAPI（`win32crypt` 或 `ctypes` 调 `CryptProtectData`）加密 `secrets/keys.enc`；
- 字段：`llm.api_key`、`soul.api_key`、`vision.api_key`、`auth.password_hash`、`admin_token`；
- 读取仅在进程内；日志/接口一律脱敏（`sk-***`）；文件权限只读当前用户；
- 备份/迁移不包含明文；导出 bot 包时提示“含密钥，勿外传”。

## 四、启动脚本与环境（D5）

### 4.1 `启动.bat`（仓库根）

```bat
@echo off
cd /d %~dp0
where python >nul 2>&1 || (echo 未找到 Python，请先安装 3.14 & pause & exit /b 1)
python scripts\bootstrap.py %*
pause
```

### 4.2 `scripts/bootstrap.py` 流程

1. 检测：Windows 10+、Python 3.14、磁盘 ≥10GB、微信安装/版本（可跳过）、可选 `nvidia-smi`；
2. 国内源：pip 清华/阿里镜像（可配置）；`HF_ENDPOINT=https://hf-mirror.com`；
3. 建 venv：`.venv`（主）/`venv_wx312`（微信发送器，仅在发送启用时提示）；
4. 安装依赖：`requirements.txt` + `requirements-optional.txt`（失败可重试/跳过可选）；
5. 初始化 `bots/default/`（若不存在）：默认安全配置 + 提示去 803 配置；
6. 启动 803（子进程），轮询 `/health`，打印地址；失败打印日志路径与下一步；
7. 幂等：重复运行只做检查/补装，不覆盖用户配置；日志 `logs/bootstrap.log`。

## 五、803 Bot Manager（控制面）

### 5.1 页面

- **Bot 列表**：新建 / 打开 / 删除（二次确认）；显示方案、灵魂模型 local/cloud、最后使用时间；
- **新建向导**：
  1. 名称 + 目录（默认 `bots/<slug>/`）；
  2. 方案：`云端` / `本地+云端`；
  3. 灵魂模型：`本地` / `云端`（D1）——本地显示模型路径/量化选择；云端显示 API base/key/model；
  4. 聊天模型：默认 DeepSeek（key/base/model）；
  5. 802 密码（首次）+ admin token（首次生成/可改）；
  6. 可选能力：内状态（off/static/rule/model）、B站、朋友圈、联网（默认全关）；
  7. 保存 → 写 bot 包（加密 secrets）→ 校验摘要页；
- **打开 802**：按钮 → 校验 bot 完整性 → 启动 801/802（子进程）→ 健康检查 → 新窗口打开 802；
- **环境/模型页**：V1 只读展示（版本/路径/端口），V2 再接下载/训练。

### 5.2 803 接口（新增，均仅 127.0.0.1 + 本地 token）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/bots` | 列表（不含密钥） |
| POST | `/api/bots` | 新建（名称/方案/soul provider） |
| GET | `/api/bots/{id}` | 详情（密钥脱敏） |
| POST | `/api/bots/{id}/save` | 保存配置/密码/密钥（写加密包） |
| POST | `/api/bots/{id}/validate` | 包校验（版本/DB/模型/端口） |
| POST | `/api/bots/{id}/launch` | 启动 801/802 + 返回地址 |
| GET | `/api/bots/{id}/health` | 进程/端口/网关 ready |

### 5.3 与现有 803 的关系

- 复用 `idea/app` 的 FastAPI/本地 token/静态页；
- 新增 `idea/app/bot_manager.py`（业务）与 `idea/web/bots.html`（页面）；
- 训练/蒸馏/模型中心页保留，V1 不放核心入口。

## 六、802 登录与安全（D4）

### 6.1 首次配置

- 803 新建 bot 时设密码；或首次打开 802 时引导设置（二者取其一，建议 803 设置，802 只登录）；
- admin token 首次自动生成写入 `secrets`；802 页面右上角仍可“填 token”用于运维；
- 密码哈希：`scrypt`/`pbkdf2_hmac` + 随机 salt，存 `secrets`；不可逆。

### 6.2 登录流程

1. `GET /login` 页面；`POST /api/auth/login {password}`；
2. 校验哈希 → 生成随机会话 ID → 服务端 `sessions.json`（或内存 + 签名 cookie）→ `Set-Cookie: soul_session=...; HttpOnly; SameSite=Strict; Path=/`；
3. 所有页面/API 中间件校验 cookie；未登录 302 `/login`（API 401）；
4. 失败限速：同一 IP 5 次/分钟；成功刷新会话；
5. 退出：清 cookie/会话；
6. 机器调用（803→802、CLI）：继续用 `X-Admin-Token`，不走 cookie；
7. 安全：仅绑 127.0.0.1（已确认不做局域网）；cookie 不写 localStorage；密码/密钥不进日志。

## 七、联系人刷新与 wxid（V1）

### 7.1 前置提示

- 页面提示：先打开微信 PC、确认版本（支持的版本列表放 `config`），保持登录；
- 失败给可操作错误：未登录/窗口未找到/版本不支持/DB 读不到。

### 7.2 刷新流程

1. 802 调 801 `POST /api/wechat/refresh_contacts`；
2. 801 读取当前微信账号（昵称、wxid）与联系人列表（DB 优先，UIA 兜底）；
3. 写 `db/wechat.sqlite3`：`wechat_accounts(wxid,nickname,last_seen)`、`contacts(wxid,nickname,alias,updated_at)`；
4. 802 显示“当前微信：昵称（wxid）”，联系人勾选（单/多选；群聊置灰）；
5. 白名单双写：`allowed_contacts` 保留昵称（兼容旧逻辑）+ 新增 `allowed_wxids`；发送前按 wxid 优先匹配；
6. 刷新不自动开启监听/回复（保持安全态）。

### 7.3 与现有 monitord 的差异

- 现有 MonitorBackend 按昵称读库；V1 增加 wxid 字段与映射，不改 DB 读取主链（避免破坏 A7 补采）。

## 八、加载 bot（进度条）

阶段（每阶段上报 `stage/progress/message`，失败可重试）：

1. 校验目录/`bot.json`/版本（5%）；
2. 校验/迁移 DB（15%）；
3. 解密 secrets，校验 key 格式（25%）；
4. 写/合并 config（35%）；
5. 初始化 selflearn DB/提示词（50%）；
6. 模型检查：本地路径/云端连通性（70%）；
7. 启动 801 并等 ready（85%）；
8. 联系人/白名单校验（95%）；
9. 就绪（100%）→ 802 显示“开始运行”按钮（不自动开引擎）。

实现：803 `POST /launch` 后台线程 + 802 SSE/轮询 `/api/bot/load_progress`。

## 九、模型路由（D1：local/cloud 灵魂）

### 9.1 概念

- `purpose`：`chat`（主对话）、`soul`（灵魂/人格/内状态生成）、`vision`（识图/关键帧）、`extract`（关键词/摘要）、`judge`（可选）；
- 每个 purpose 一条路由：`{provider, model, base_url, key_ref, local_path}`；
- bot 配置：`soul.provider=local|cloud`；`chat.provider=cloud`（V1 固定 DeepSeek）；`vision.provider=local|cloud`（V2 扩展）。

### 9.2 实现

- 新增 `agi/llm_router.py`：注册表 + `route(purpose)`；
- 现有 `SelfLearnAgent`/`llm.Client` 调用点按 purpose 取 client（保持默认行为兼容）；
- 本地：`llama.cpp/ollama` HTTP（127.0.0.1:端口），启动/健康检查在 803；
- 云端：OpenAI 兼容 `chat/completions`，key 从 bot secrets 解密；
- 回退：soul=local 失败时是否回落 cloud？V1 **不自动回退**，明确报错，避免沉默切换人格（可在设置里勾选允许回退）。

### 9.3 已确认（2026-11-01）

- 云端 soul：**OpenAI 兼容接口**，用户填 `base_url` / `model` / `api_key`；
- 本地 soul：**优先 llama.cpp server**（OpenAI 兼容 `/v1` 端点）；ollama 作为兼容项后续再加；
- 不做静默回退；回退需设置里显式开启（V1 不提供 UI，仅保留配置位）。

## 十二、自检（开始运行前）

| 检查 | 方法 | 失败处理 |
|---|---|---|
| 云端聊天 | 最小 chat 请求 | 显示错误+检查 key/网络 |
| 聊天模型 | 走 801 内部 `_reply` 冒烟（dry_run） | 不发送，只验证生成 |
| 灵魂模型 | soul 路由最小调用（local/cloud） | 本地：检查端口/模型；云端：key |
| 识图模型 | 一张测试图理解（local/cloud） | 显示后端/路径错误 |
| 微信 | 进程/登录/窗口探测 | 提示版本/登录 |
| 本地模型服务 | `/health` | 提示启动命令/路径 |

自检结果存 `logs/selfcheck-<ts>.json`；802 页面展示通过/失败/修复建议；全部通过才亮“开始运行”。

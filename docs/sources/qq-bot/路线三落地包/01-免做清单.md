# 01 · 免做清单（逐项证据）

> 路线三要求你搭的东西 → 你已有的等价物 → 在哪 → 为什么能直接用。
> 复用度是判断，位置是事实。

---

## A. 界面与交互

### 1. 聊天界面 —— 复用度 100%

**方案要求**：写一个聊天界面，含对话窗口、👍/👎 按钮、记录日志的数据库。

**你已有**：你根本不需要"界面"这个中间层。
- 对话发生在 QQ 里（群/私聊），消息由 `@snowluma/sdk` 的 OneBot v11 客户端收发；
- 管理侧有本地 Web 控制台 `http://127.0.0.1:3100`，十个页面 + 跨页搜索 + 双主题 + 令牌鉴权（[console.html:1767](qq-bridge/public/console.html#L1767)）。

**为什么省事**：👍/👎 按钮不用新写页面，加一个 `section` 挂在「二代仿真」或「会话与审批」页即可；样式、权限、刷新逻辑全是现成的。

**还差**：只差按钮本身（详见 [03](03-仍需自建.md)）。

### 2. 对话日志 —— 复用度 95%

**方案要求**：建一个数据库，把每轮对话和小模型生成的独白存下来。

**你已有**（全在 `state/`）：

| 文件 | 内容 | 保留 |
|---|---|---|
| `social-v2.json` | 每会话的最近消息、未读、水位、三类记忆、各类行为时间戳 | 每会话 200 条消息 |
| `tool-calls.jsonl` | 每次工具调用的发起与结果（参数自动脱敏） | 2000 行滚动 |
| `token-usage.jsonl` | 逐轮 token 用量（`turn/step/retry/model/provider` + 五个桶） | 有上限，自动去重重写 |
| `qq-activity.log` / `bridge.log` | 消息与运行日志 | 滚动 |
| `feedback.json` / `slang.json` / `stickers.json` / `initial-prompts.json` | 报告、黑话、表情库、会话初始提示 | — |

另外 **DSH 侧有完整会话历史**，桥接退役/重置会话时也不删（README「升级后会为历史映射重建」段）。

**💭 判断**：你没用数据库反而是优势。JSONL 天生适合追加、可 diff、可 git、不需要 schema 迁移，直接就能喂训练管线；换成 SQLite 只会让导出多一步。查询弱一点，但你的数据量在千级，`jq` 够用。

**还差**：`recentMessages` 只留 200 条，**训练集要对接 DSH 历史，不能只读 `state/`**。

### 3. 大模型回答引擎 —— 复用度 100%

**方案要求**：调用 API 大模型作为回答引擎。

**你已有**：DSH 全包了——流式、重试、工具调用循环、多 provider、逐会话选模型（`config.example.json` 的 `dsh` 段：`provider/model/reasoningEffort`），还有思考档位（max/high/low）。

**为什么省事**：你自己写这层，最少也要处理 SDK、超时、重试、流式、工具协议五件事，且每换一个模型都要重测。这里换模型是改一个字段。

## B. 人格与提示词

### 4. 人格/角色系统 —— 复用度 100%

**方案要求**：设计"性格"，让 AI 有自己的情绪、动机、性格倾向。

**你已有**：
- `roles/*.md` 人格卡：一个文件一个角色，控制台点选即启用、保存即生效（[roles/README.md](qq-bridge/roles/README.md)）；
- **两层分离**：人格层（`roles/`）管"你是谁"，仿真层（preset 的 `persona.prefix`）管"怎么干活"；
- 6000 字符注入上限（`role.maxInjectChars`）= 现成的成本护栏；
- 按模式筛小节（`〔一代〕`/`〔二代〕`），同一个角色可以在两代模式下给不同说话方式。

**💭 判断**：这是你最大的隐性优势。路线三担心"微调把性格训坏"，而你的架构里**性格根本不靠权重**——微调只需要碰"状态生成"这一小块，出问题删文件就回滚了。

### 5. 记忆库 —— 复用度 90%

**方案要求**：根据对话历史和记忆生成内心独白。

**你已有**：`qq_memory_append / query / remove / clear` 四件套（[mcp-snowluma-safe.js:907](qq-bridge/src/mcp-snowluma-safe.js#L907)），三类记忆：

| 类别 | 含义 | 对路线三的意义 |
|---|---|---|
| `activeTopic` | 进行中的话题 | 独白的"上下文锚点" |
| `pendingThought` | **你想说但还没说的话** | 这已经是"内心独白"的一半了 |
| `memberImpression` | 对某位群友的印象 | "关系是训练数据"的载体 |

记忆随唤醒自动注入（`formatMemoryV2`，[bridge.js:8802](qq-bridge/src/bridge.js#L8802)），还带参与度统计。

**还差**：记忆是"事件级"的，不是"状态级"的——没有"此刻心情"这种会过期的短状态。

### 6. 多会话隔离 —— 复用度 100%

**方案要求**：（没提，但你一定会遇到）多个群/好友共用一个人格时怎么不串味。

**你已有**：`state/sessions.json` 把每个 QQ 会话映射到独立 DSH 会话，key 格式 `group:群号` / `private:QQ号`（`canonicalV2Key` 统一格式，防止同一会话分裂）。每个会话有独立的上下文、独立记忆、独立唤醒配置、独立 token 用量。

**💭 判断**：这解决了一个方案原文完全没意识到的坑——如果你按"一个人格"做单会话，群聊多主体会把上下文冲爆；你现在是天生的多租户结构。

## C. 注入与成本

### 7. 独白注入管线 —— 复用度 95%

**方案要求**：每次对话前，把小模型生成的"内心状态"作为提示词的一部分注入大模型。

**你已有**：这条管线就是 [`buildWakePromptV2`](qq-bridge/src/bridge.js#L10293)。它每次唤醒时拼十几段：

```
角色 → 身份 → 令牌 → 初始提示 → 反AI味 → 积极性 → 表情策略 → 首回复节奏
     → 此刻状态 → 当前唤醒 → 记忆 → 参与度 → 沉睡前等待 → 时间感
```

拼接处只有一行（[bridge.js:10346](qq-bridge/src/bridge.js#L10346)）。你要加的"内心状态"就是这里再追加一个字符串。

**为什么省事**：如果你从零写，还要考虑"何时注入/注入了会不会被压缩掉/怎么防止它每轮重复"——这些它的唤醒机制已经解决了。

### 8. 成本监控 —— 复用度 100%

**方案要求**："成本可控"，一张 RTX 4060、每月几十到几百元。

**你已有**：
- [`model-prices.js`](qq-bridge/src/model-prices.js)：官方价目 + 峰谷分时（高峰 2 倍）+ 缓存命中/未命中/输出三桶分开计价 + 2026/2027 法定节假日；
- [`token-ledger.js`](qq-bridge/src/token-ledger.js)：逐轮采样、幂等折叠、JSONL 落盘、重试另算；
- 控制台「令牌与花费」页：按群/好友/轮次下钻 + 时间走势图。

**💭 判断**：这是别人做同类实验时最缺的东西。路线三满篇谈成本，但从头到尾没说"你怎么知道这一步花了多少"。你能直接回答"加一段独白，每轮多几毛"，而且是按峰谷折算的真钱。

## D. 运营与安全

### 9. 安全边界 —— 复用度 100%

**方案要求**：（没提）让一个会自我演化的东西接进你的社交账号。

**你已有**：
- preset 里硬写「你没有本地工具：不能执行命令、不能读写文件」；
- `qq-tool-restrict` 在执行期按白名单兜底（不只藏工具名）；
- 桥接自带三个 MCP server，QQ 动作只暴露**安全子集**，发送强制白名单；
- `safe-fetch.js` 做 SSRF 防护；`redactSensitive` 自动脱敏 token/密码；
- `privacy-scan.mjs` 出机数据扫描；`RULES.md` 写明权限边界。

**为什么重要**：你要接的"小模型服务"是一个新的外挂进程——它必须走同一套 token 校验和白名单，否则等于开了个后门。你的架构已经规定了这个插槽的规矩。

### 10. 稳定性 —— 复用度 100%

**方案要求**：（没提，但长期项目必需）

**你已有**：单实例锁（`bridge.lock`）、`start.bat` 崩溃 5 秒重启、断线期间消息排队（50 条/会话）、DSH 重启自动补投、mux 自动重连、`atomicWriteJson` 防半写、state 目录 ACL 加固。

### 11. 主动行为（"涌现时刻"）—— 复用度 100%

**方案要求**：期待"它第一次主动提问、第一次主动提起你们的共同记忆"。

**你已有**：这套机制已经在跑——
- 唤醒条件：@ / 名字 / 关键词 / 提问 / 拍一拍 / 指定人 / 概率 / 任意消息（`wakeConfig`）；
- 定时主动唤醒（`proactiveCheck`），提示词里直接写着"群里安静了一段时间，这是一次可以主动冒泡的机会"；
- 潜水/唤醒/等消息/已读水位全套。

**💭 判断**：路线三把"涌现"当成训练出来的结果，其实**"意外时刻"主要来自记忆 + 主动唤醒 + 不确定性**，这三样你已经全有了。也就是说，你不训练也能看到"它自己开口"——这会让你对微调的收益判断更冷静。

## E. 半有：只差一小块

### 12. 内心独白的采集 —— 50%

**方案要求**：小模型生成内心独白，系统记录下来。

**你已有通道**：二代模式下 **AI 的文本输出本来就不会发到 QQ**——preset 第 31 条明写「文本输出只是思考，不会自动发送到 QQ」([agent.cordis.yml:31](qq-bridge/dsh/agent-presets/qq-chat-v2/agent.cordis.yml#L31))。也就是说它每轮都在写独白，只是写完就散在上下文里、没人接住。

**还差**：把它变成持久状态。三件事：结构化（JSON）、落盘（`state/inner/`）、下轮注入（第 7 项那行）。

### 13. 小模型/模型热切换 —— 60%

**方案要求**：部署小模型，替换原来的。

**你已有插槽**：
- MCP 三件套已经证明"外挂一个 MCP server"是标准做法（`mcp-snowluma-safe` / `mcp-host-server` / `mcp-web-search-safe`），加第四个是纯增量；
- `setup-dsh.mjs` 负责把 MCP 写进 DSH profile 并在重启后加载；
- preset 是 YAML + `build-agent-preset-patches.mjs` 生成 bundle，可以开 `qq-chat-v3` 实验分支；
- 运行模式可切（chat / closed-agent / reserved / reserved2），逐会话能选模型。

**还差**：模型本体、推理服务、训练管线。**但插槽已经留好了。**

### 14. 训练集 —— 40%

**方案要求**：把高分样本整理成训练集。

**你已有**：原料全在（第 2 项）。缺的是把 `(上下文, 独白, 回复, 评分)` 对齐成一条 jsonl。

**还差**：一个导出脚本 + 评分来源（第 15 项）。

### 15. A/B 与灰度 —— 70%

**你已有**：改 `config.json` 的 `dsh.model`、控制台切换思考强度、切换运行模式、逐会话重建。两条链路并存对比完全可行。

**还差**："同一会话内随机分组 + 显著性检验"。**💭 判断：不建议做**。你的样本量会很小（一个群一天几十条），统计上测不出显著差异，靠人工看 100 条更准。

## 二、`state/` 里有什么

```
state/
├── sessions.json           QQ 会话 → DSH 会话 映射
├── social-v2.json          ★ 二代状态：消息、未读、水位、三类记忆、行为时间戳
├── current-role.json       当前启用的角色
├── mode.json               运行模式兜底
├── initial-prompts.json    会话初始提示词（每个群/私聊一份）
├── slang.json              黑话词库
├── stickers.json           表情库（备注/标签/理解）
├── feedback.json           AI 主动上报的问题
├── token-usage.jsonl       ★ 逐轮 token 明细
├── tool-calls.jsonl        ★ 工具调用日志（call + result，参数脱敏）
├── qq-activity.log         消息活动日志
├── bridge.log              运行日志
├── console-token           控制台访问令牌
├── bridge.lock             单实例锁
└── agents/                 会话工作目录（cfg.sessionCwd 为空时）
```

### `social-v2.json` 每个会话的字段

从 [`getSocialV2State`](qq-bridge/src/bridge.js#L8406) 的默认对象取：

| 字段 | 含义 | 对路线三的用处 |
|---|---|---|
| `recentMessages` / `unread` | 最近消息 / 未读（各配 `seq`，保留上限 200） | 独白的"输入上下文" |
| `lastUnreadSeq` / `lastReadThroughSeq` | 已读水位 | 判断"它到底看没看" |
| `activeTopics` / `pendingThoughts` / `memberImpressions` | 三类记忆 | `pendingThought` 已是独白雏形 |
| `lastIncomingAt` / `lastAiReplyAt` / `lastActionAt` | 时间戳 | 隐式反馈信号 |
| `wakeTimes` / `sendTimes` / `stickerCollectTimes` | 行为时间数组 | 频率/节奏特征 |
| `wakeConfig` | 唤醒条件 | 主动行为参数 |
| `agentToken` | 会话令牌（工具调用要带） | 新接口必须校验这个 |

### `token-usage.jsonl` 行格式

```
{"k":"base", t, sid, key, seq, model, provider, b:{cacheMiss,cacheHit,cacheWrite,output,reasoning}}
{"k":"turn", t, sid, key, seq, turn, step, retry, model, provider, b:{...}}
```

`b` 是五个互不重叠的 token 桶，计价要分桶相加（见 [token-ledger.js](qq-bridge/src/token-ledger.js#L22)）。

### `tool-calls.jsonl` 行格式

```json
{"type":"call","time":"...","key":"group:123","sessionId":"...","tool":"qq_send_message","args":"{...}"}
{"type":"result","time":"...","key":"...","tool":"...","ok":true,"error":null}
```

参数已过 `redactSensitive`（token/密码/cookie 等替换成 `***`）。

## 三、注入点

**每次唤醒的提示词**由 [`buildWakePromptV2(key, reason)`](qq-bridge/src/bridge.js#L10293) 生成，最后一行拼接（[L10346](qq-bridge/src/bridge.js#L10346)）：

```js
const base = roleLine + identityLine + tokenLine + initialPromptLine + antiAiLine
  + proactiveLine + stickerLine + replyLine + statusLine + wakeLine
  + memoryLine + participationLine + preSleepLine + timeSenseLine;
```

**建议插在 `memoryLine` 之后**——"记忆"是长期事实，"此刻状态"是短期情绪，两者相邻语义最顺。

另外 `roleLine` 来自 `readRoleState()`（人格卡），走的是另一条手工注入链路，**不要**把状态塞进人格卡（人格卡是静态文件，状态是每轮变的）。

## 四、AI 能调的工具（v2 全集）

从 [`v2ToolEnabled` 映射](qq-bridge/src/bridge.js#L4427) 取：

| 类别 | 工具 |
|---|---|
| **提示/状态** | `qq_get_prompt` · `qq_social_state` |
| **读消息** | `qq_get_unread_messages` · `qq_get_recent_messages` · `qq_get_message_detail` · `qq_get_active_members` · `qq_get_group_history` · `qq_get_forward_msg` |
| **发消息** | `qq_send_message` · `qq_send_burst` · `qq_reply` · `qq_send_group_message` · `qq_send_private_message` · `qq_send_poke` |
| **等/水位** | `qq_wait_for_messages` · `qq_mark_read` · `qq_set_wake_config` |
| **记忆** | `qq_memory_append` · `qq_memory_query` · `qq_memory_remove` · `qq_memory_clear` |
| **表情** | `qq_list_stickers` · `qq_get_sticker_image` · `qq_send_sticker` · `qq_sticker_note` · `qq_collect_sticker` |
| **其他** | `qq_report_feedback` · `qq_slang_query` · `qq_slang_submit` · `qq_get_my_recent_messages` · `qq_get_self_image` · `qq_send_voice` |

> 路线三要加的 `qq_inner_write` / `qq_inner_read` 就插在这张表里，权限归到 `memory` 类即可。

## 五、常用命令

```bash
# 跑起来
npm start                        # 前台
start.bat                        # 守护模式（崩溃 5 秒重启）
```

## 七、会话 key 规范

- 格式：`group:<群号>` / `private:<QQ号>`
- 统一由 `canonicalV2Key` 归一化（去前导零），**不要自己拼字符串**——拼错会让同一会话分裂成两个状态。
- 每个 key 对应一个 DSH 会话，会话在 `state/sessions.json` 里；重置会话会重建 DSH 会话但保留 state 里的记忆。

## 八、改代码时的安全/回归 checklist

1. 新增工具 → 必须同时进 `mcp-snowluma-safe.js` 的工具表 + `v2ToolEnabled` 映射 + `qq-tool-restrict` 白名单，三处缺一处就会被静默拒绝。
2. 新增 HTTP 端点 → 必须校验 `x-agent-token`（admin 端点则校验控制台令牌）。
3. 改 preset YAML → 跑 `build-agent-preset-patches.mjs` + 重启 DSH + `npm run test:preset-prompt`。
4. 改控制台 → 跑 `npm run test:console-ui`（它是真浏览器回归）。
5. 碰 state 结构 → 加载要向后兼容（旧文件没有新字段时给默认值），否则升级会崩。

# 03 · 仍需自建的三件半

> 这三件是方案里**真的没有**的部分。每件都给了最小实现草案和验收标准，照着写即可。
> 第四件「评估集」不是代码，是人工活，但它决定前三件值不值得做。

---

## 零件 1 · 内心状态（半天）

### 目标
让 AI 在收尾时留下一小段"此刻的状态"，并在下次被唤醒时看到它。**不引入小模型**，先用大模型自己写。

### 数据结构
每个会话一份，存在 `social-v2.json` 的会话对象里（零新文件、复用现有原子写与加载）：

```json
"inner": {
  "mood": "有点闷，不太想说话",
  "want": "想找个人吐槽刚才那事",
  "target": "阿澈",
  "unsaid": "算了不说了",
  "updatedAt": "2026-10-24T21:30:00+08:00",
  "turn": 42
}
```

约束：
- 每个字段 ≤ 40 字（四字段 ≈ 160 字 ≈ 120 token，可接受）；
- **必须会衰减**：读取时若 `updatedAt` 距今 > 6 小时，注入时降级成"（很久以前的状态，不用太当真）"，防止模型被旧情绪绑架；
- 允许推翻：提示词里明写"可以延续，也可以推翻"。

### 工具
在 `mcp-snowluma-safe.js` 加：

```js
qq_inner_write(key, token, mood, want?, target?, unsaid?)
```

描述要写成："记录你此刻的内心状态。**只在情绪或想法真的变了时才写**，不要每轮都写。"

> ⚠️ 三处都要加，缺一处会被静默拒绝：工具表、`v2ToolEnabled` 映射、`qq-tool-restrict` 白名单。权限归到 `memory` 类。

### 端点
- `POST /api/socialV2/inner`：AI 写，校验 `x-agent-token`；
- `GET /api/socialV2/inner?key=`：控制台读（只读展示 + 清除按钮）。

### 注入
在 [`buildWakePromptV2`](qq-bridge/src/bridge.js#L10293) 的 `memoryLine` 之后加一段：

```
【你现在的状态】（上次收尾时记的，不一定还对；可以延续，也可以推翻）
心情：有点闷
想做：想找个人吐槽刚才那事
对「阿澈」：其实有点在意，但不想承认
想说没说的：算了不说了
```

### preset 收尾指令
在 `qq-chat-v2/agent.preset` 的【轻量记忆】那条后面加一句：

> 收尾前，如果此刻的心情或想法和上次明显不同，可以用 `qq_inner_write` 记一下（心情/想做什么/对谁/想说没说的话）；没什么变化就别写，别每轮都更新。

### 验收
1. 同一会话连聊 3 轮，第 2、3 轮的 prompt 里能看到第 1 轮写的状态 → 用控制台日志或临时打点验证；
2. 没调用工具时流程完全不变（向后兼容）；
3. 每轮 prompt 增量 < 200 字；
4. `npm run test:audit` 全绿。

### 回滚
删注入行 + 删工具即可，`inner` 字段留着无害。

## 零件 2 · 打分入口（半天到一天）

### 为什么先做控制台、后做 QQ
- 控制台：不打扰任何人、可以随时补打、能写备注。**先做这个。**
- QQ 群聊里加 👍/👎 会破坏沉浸感，还会被群友看见，而且你得处理"群友乱点"。只建议在私聊 owner 会话里做（可选）。

### 数据格式
`state/ratings.jsonl`，一行一评：

```json
{"t":"2026-10-24T21:40:00+08:00","key":"group:123","sessionId":"sess_x","turn":42,"seq":188,"score":1,"note":"这句像人"}
```

`score`：`1` 好 / `0` 一般 / `-1` 差。允许同一 turn 多次覆盖（后到覆盖先到，和 token 账本同语义）。

### 控制台
在「会话与审批」或「二代仿真」页加一块：列最近 20 条 AI 发言（`social-v2.json` 里 `isSelf` 的消息），每条两个按钮 + 一个备注框。

后端两个端点：`POST /api/ratings`（控制台令牌）、`GET /api/ratings?key=`。

### QQ 侧（可选，最后做）
私聊 owner 时，允许"引用 AI 的消息回 👍/👎/好/不行"，桥接识别后写评分。群聊默认关闭。

### 隐式信号（**只记不训**）
顺手记 `state/signals.jsonl`：回复后多久有人接话、是否被追问、是否被 @、话题是否延续。用于**分析**，不要直接当正样本——原因见 [05](05-风险与代价.md) 第一条。

### 验收
一周后 `ratings.jsonl` 至少有 30 条，且能按 key/turn 关联到具体回复。

## 零件 3 · 训练数据归档（一天）

### 💭 更省事的做法：不要"导出"，直接"归档"

方案原文是"把高分样本整理成训练集"。你其实可以让这一步**自动发生**：

在"AI 回复完成"的钩子里追加一行 `state/turns.jsonl`：

```json
{
  "t": "2026-10-24T21:38:11+08:00",
  "key": "group:123",
  "sessionId": "sess_x",
  "turn": 42,
  "model": "deepseek-flash",
  "incoming": [{"sender":"阿澈","text":"你今天怎么不说话"}],
  "inner": {"mood":"...","want":"..."},
  "output": {"text":"困","tools":["qq_send_message"]},
  "implicit": {"replyGapMs": 42000, "followedUp": false}
}
```

好处：
- 不受 `recentMessages` 只留 200 条的限制；
- 不用去 DSH 拉历史（DSH 是否有完整历史导出接口**需要对着一版实测**，不确定的东西不要写进主链路）；
- 训练要的 `(上下文, 状态, 输出)` 天然对齐，评分后面 join 即可。

### 导出脚本只做三件事
`scripts/export-dataset.mjs`：

1. join `turns.jsonl` × `ratings.jsonl`（按 key+turn），得到带标签的样本；
2. 按"会话 + 时间"切 train/val（**同一段对话不能跨集**，否则泄漏）；
3. 输出 SFT 格式：`{"messages":[{"role":"system",...},{"role":"user",...}],"output":"..."}`。

### 第一步甚至可以不写代码
用 `jq` 就能先看看数据长什么样：

```bash
jq -c 'select(.inner!=null)' state/turns.jsonl | head -20
```

### 验收
能导出一个 ≥ 500 条的 `train.jsonl` + `val.jsonl`，且 val 里没有和 train 同会话的样本。

## 零件 4 · 小模型（等数据，不要现在做）

### 前置门槛（三条全满足才开工）
1. `turns.jsonl` ≥ 2000 条 **且** 有评分或人工筛选过的 ≥ 500 条；
2. A/B 盲评证明"注入 inner"确实让回复更好（见下方评估）；
3. 你接受"它只学写状态、不学聊天"这个定位。

### 训练目标：蒸馏，不是创造
- 输入：最近 N 条消息（截断到 1500 字）；
- 输出：大模型写的那段 inner JSON；
- 模型：Qwen3.5 的 1.7B 或 4B（4060 8G：1.7B QLoRA 很轻松，4B 也能跑）；
- 工具：unsloth，`QLoRA 4bit + LoRA rank 16`，一轮 30–60 分钟；
- 数据量：2000–5000 条，epoch 2–3，**每轮都混入历史样本（replay）**，否则会遗忘。

### 为什么必须蒸馏而不是"让它创造"
1.5B/1.7B 对群聊的理解（谁在跟谁说话、反讽、梗、多人接话）远不如大模型，
它"创造"出来的情绪标签基本是噪声，大模型会顺着噪声演，反而把回复拉平。
小模型的正确任务是**复现大模型的状态判断**，用 1/50 的成本跑同一件事。

### 部署
- 形态：本地 HTTP 边车或 MCP server（`local-inner`），桥接调用；
- 位置：在拼 prompt 之前异步取（**不阻塞主对话**）；
- 超时：> 1.5s 直接放弃，回退到"用上一轮的状态"或"不注入"；
- 开关：`config.json` 加 `inner.provider: "local" | "llm"`，出问题一键切回。

### 评估（这步比训练重要）
准备 20 组**同一上下文**的 A/B：
- A：不注入 inner
- B：注入 inner（大模型版）
- C：注入 inner（小模型版）

人工盲评选哪个更好。判据：B 赢不到 12/20 → 整个方向停掉；C 明显输给 B → 小模型不值得部署。

### 验收
- 小模型生成 inner 的耗时 P95 < 1.5s；
- 下游回复质量不劣于"大模型写 inner"（人工盲评）；
- 关掉开关后系统行为与现在完全一致。

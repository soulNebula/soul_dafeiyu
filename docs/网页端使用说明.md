# wx_box 网页端使用说明（小白版）

> **一句话介绍**：网页端把 wx_box 监听到的消息（文字 / 图片 / 表情包 GIF / 文件 / 语音 / 日志）实时同步到浏览器里的一个本地页面 `http://127.0.0.1:8081`，并可以让 **DeepSeek** 大模型帮你总结对话、列待办、看情绪和风险。它和桌面版共用同一个 `wx_core` 采集后端，**同样只读、不发送任何消息、不上传任何数据**。
>
> ⚠️ **V2 重要变化**：网页端的朋友圈、图片/头像字节、同步进来的历史聊天**只放在内存里，关闭网页端（Ctrl+C / 关窗口）就清空**，不会写 `webui/cache/`、`media/moments/`，也不占磁盘空间；需要时重新点「同步」即可。

---

## 一、它和桌面版有什么区别？

| 对比项 | 桌面版（`run.bat`） | 网页端（`run_web.bat`） |
|---|---|---|
| 界面 | Windows 桌面窗口（Tk） | 浏览器页面（Chrome / Edge 等） |
| 消息来源 | 同一套 `wx_core` 后端 | 同一套 `wx_core` 后端；或只读跟随桌面版日志（`--follow-log`） |
| 消息容量 | 全量保留在内存 + `log/` | 页面最多 **3000 条**（内存）；桌面版完整历史在 `log/messages.jsonl` |
| 数据保存 | 写 `log/`、`media/`（桌面版功能） | **朋友圈 / 历史聊天只在内存**：不写 `webui/cache/`、不写 `media/moments/`，关闭网页端即清空 |
| 历史聊天 | 实时监听 + 聊天记录文件 | 可手动「同步历史」，按 5/10/20/50/100/全部 条读取本机缓存（只进内存） |
| 特色功能 | 图片/贴纸原图、聊天记录文件 | **AI 分析**（摘要 / 待办 / 情绪 / 风险）、**朋友圈页面**（复用 `WechatMoments/`，见第六节）、**群聊支持**（列表/监听/历史/分析，见第三节）、网页随时刷新、多标签页可看 |
| 依赖 | Tk + 桌面环境 | **只用 Python 标准库**，不需要额外装包 |

> ⚠️ **两者不要同时开！** 桌面版和网页端如果同时启动，会各跑一份采集线程/监听逻辑，可能重复写 `media/`、`log/`，白白消耗资源，也会让日志互相干扰。**同一时间只开一个**。
>
> 例外：如果桌面版已经在跑（或另一个程序正在监听微信），而你只是想用网页**看**，请用「**只读跟随模式**」启动网页端（见 2.4），它不会启动采集，只读取桌面版写入的日志，可以安全地同时开着。

## 二、启动

网页端不需要安装新依赖，环境要求与桌面版完全一样（Windows 10/11 + Python 3.14 + 已登录的微信电脑版）。

### 1. 正常启动（监听真实微信）

在项目文件夹里**双击 `run_web.bat`**，或者打开命令提示符执行：

```bat
cd /d C:\Users\Administrator\Desktop\wx_box
C:\Python314\python.exe web_app.py
```

启动后程序会：

1. 读取 `config.json`，创建真实采集后端（读你本机微信的消息库）；
2. 在 `127.0.0.1:8081` 启动本地网页服务；
3. 自动打开默认浏览器，地址是 **<http://127.0.0.1:8081>**。

> 真实后端不可用时（比如没找到微信、缺少 OCR 依赖），程序会**自动回退到演示后端**并在页面顶部显示提示，先让你看到界面；这时页面里是假数据，不代表真实监听可用。

### 2. 演示模式（不需要微信，推荐第一次先试这个）

```bat
C:\Python314\python.exe web_app.py --fake
```

演示模式每 2 秒自动生成一条示例消息，类型轮流覆盖：文字、图片、GIF 表情包、PDF 文件、语音、以及"我自己发的消息"，非常适合先熟悉界面和试 AI 分析。

### 3. 指定端口 / 不自动开浏览器

**默认端口是 8081**（8080 留给其他项目，不再使用）。如果 8081 也被占用，或者你想同时开着别的本地服务，换一个端口：

```bat
C:\Python314\python.exe web_app.py --port 8082 --no-browser
```

然后手动在浏览器输入 `http://127.0.0.1:8082`。

| 参数 | 作用 |
|---|---|
| `--fake` | 使用演示后端，不连接真实微信 |
| `--port 8082` | 换一个端口（默认 **8081**） |
| `--no-browser` | 启动后不自动打开浏览器 |
| `--interval 0.5` | 演示模式生成消息的间隔秒数（默认 2 秒，便于放慢/加快演示） |
| `--no-moments` | 关闭朋友圈模块（排障用；朋友圈报错时可先这样启动，不影响聊天） |
| `--follow-log` | **只读跟随模式**：不启动采集，只读取桌面版写入的 `log/messages.jsonl`（见 2.4） |
| `--duration 30` | 运行 30 秒后自动退出（自动化验证用） |

### 4. 只读跟随模式（桌面版正在运行时用）

**什么时候用**：桌面版 `run.bat` 正在监听微信，或者另一个监听程序占着微信窗口，而你想**同时用网页看消息**。此时直接开真实模式会跑第二份采集（抢窗口、重复写媒体），所以改用只读跟随：

```bat
C:\Python314\python.exe web_app.py --follow-log
```

行为：

* **不启动任何采集、不操作微信**；只读 `config.json`（好友缓存）和 `log/messages.jsonl`；
* 先加载日志里的历史消息，之后每 1 秒 **tail** 新追加的行 —— 桌面版收到的新消息会出现在网页上；
* 朋友圈和 AI 分析照常可用；
* **不写** `config.json` / `media/` / `log/`：页面顶栏模式徽标显示「**只读跟随**」，左栏勾选好友只影响本页浏览筛选，不会改变桌面版的监听名单；
* 提示：`run_web.bat` 暂时不支持这个参数，需要手动命令行执行。

### 5. 打开页面

在浏览器地址栏输入 **<http://127.0.0.1:8081>** 即可。页面会自己保持实时更新，不需要手动刷新。

> 🔐 页面启动时会生成一个**一次性会话令牌**（嵌在页面里），所有后台接口都要校验它。所以**不要**把地址复制给别的程序去请求，也不要关掉服务后继续用旧标签页——重连失败时刷新一下页面即可。

## 三、界面分区说明

整个页面是"深色微信风"，从左到右、从上到下共 6 个区域（想象一张截图）：

```
┌──────────────────────── 顶栏：WXBOX · 消息分析台 ────────────────────────┐
│  ● 微信已连接 / 未连接   当前会话   监听中：好友A、好友B   [模型设置] [演示] [日志] │
│              顶部主导航：[ 消息 ] [ 朋友圈 ]                                  │
├──────────────┬───────────────────────────────┬──────────────────────────────┤
│  好友列表     │  消息流                        │  AI 分析                      │
│  总数/搜索    │  会话标题 + 筛选 + 搜索         │  范围/快捷指令/问题/选项      │
│  全选/清空    │  文字/图片/GIF/文件/语音卡片    │  流式输出（可折叠思考过程）   │
│  全部好友     │  空状态 / 回到最新             │  复制/清空/停止               │
├──────────────┴───────────────────────────────┴──────────────────────────────┤
│  底部日志抽屉（可折叠，按级别着色，最多 500 行）                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

页面顶栏中间有 **`消息` / `朋友圈` 两个 tab**（朋友圈需项目里带 `WechatMoments/`，见第六节）：切到朋友圈时，左栏变成朋友圈信息面板、中栏变成时间线，AI 分析面板的范围也会自动切到"朋友圈"。

### 1. 顶栏

* 左侧品牌 **WXBOX · 消息分析台**；
* **连接状态点 + 文案**：绿色=微信已连接/正在运行，灰色=未连接或已停止；
* **当前会话**：后端正在采集的那个好友会话名；
* **监听中**：你勾选的好友/群聊名单；
* **开始监听 / 结束监听**（V5）：真实/演示模式下显示——
  * 运行中「开始」置灰、「结束」可点；点「结束」只停止采集，**不会删除已经加载的消息**，再点「开始」会按当前勾选名单继续读新消息；
  * **没有勾选任何会话时点「开始」会提示先勾选**（左栏勾选好友/群聊）；
  * **只读跟随模式不显示这两个按钮**（跟随模式本来就不采集）；
* 右侧按钮：
  * **模型设置**：打开 DeepSeek 配置弹窗（见第四节）；
  * **模式徽标**：`真实` / `演示` / `只读跟随`，提醒你现在看的是真数据、假数据，还是跟随桌面版日志；
  * **日志**：展开/收起底部日志抽屉。

### 2. 左栏 · 好友 / 群聊

* 左栏顶部有「**好友 / 群聊**」切换（带数量徽标）：
  * **好友**：微信好友列表；
  * **群聊**：优先使用「有历史聊天记录」的群聊（来自本机 `contact.db` + 会话表，备注优先，行尾有「群」小徽标）；加载失败时只提示、不影响好友页；
  * ⚠️ **V4 起默认只显示"有聊天记录"的好友和群聊**（左栏有弱提示），避免一堆「暂无消息」的空联系人；想刷新列表点左栏的刷新按钮（重新读本机库，60 秒缓存）；
  * **切换微信账号后**：在网页点左栏的**刷新**。检测到账号变化时，网页会自动清空旧账号的内存消息与监听名单、重建数据库直读桥，并把新好友列表/账号标识写回 `config.json`（旧账号数据不会串到新账号页面上）；
* 顶部显示**总数**和搜索框（按名字过滤）；
* **全部好友**：点击后消息区显示所有好友的消息（合并排序）；
* 好友/群聊行：**勾选框 = 加入监听**，**点名字 = 只看这个会话的消息**；行尾显示消息条数和最近时间；**头像统一用拼音首字母**（刘→L、何→H，英文名取首字母大写），不同用户颜色不同，没有头像图片也能一眼区分；
* 勾选变化会**自动保存**（约 0.5 秒防抖）到 `config.json` 的 `monitored`，和桌面版一致；群名也可以直接加入监听（数据库直读模式下能读到群消息）；
  * 例外：**只读跟随模式**下勾选不会写 `config.json`，只影响本页浏览筛选（桌面版的监听名单保持不变）；
* 底部 **全选 / 清空 / 重新同步**：清空=取消所有监听；重新同步=让后端重新枚举一次微信好友列表。
* **V2 新增「同步历史」**：选中好友**或群聊**后，可点「同步历史」按 5/10/20/50/100/全部 条读取本机缓存的聊天记录（见第七节）；「清空聊天」清空当前页面内存里的消息。

### 3. 中栏 · 消息流

* 顶部是**会话标题 + 消息条数**，「同步历史」「清空聊天」按钮也在这里；
* **筛选条**：全部 / 文字 / 图片 / 表情包 / 文件 / 语音，右侧是关键词搜索和"自动滚动"开关；
* 消息卡片：对方消息靠左、自己发的靠右、系统提示居中；
  * **头像**用拼音首字母（群成员用成员名/username 计算，保证不同成员颜色不同）；
  * **群聊消息**：若消息带发送人信息（`extra.sender_name`），会在气泡上方显示**群成员名**（自己和对方都适用）；实时监听未拿到成员名时只显示群名，不报错；
  * 图片、GIF 表情包**直接显示原图**（GIF 会动），点击可放大（灯箱）；
  * **红包 / 转账**显示成**红色红包气泡 / 金色转账气泡**（原始 XML/HTML 已被清洗，不会把标签露出来）；只是**只读展示**，不能领取或转账；
  * 文件卡片显示**文件名 + 大小**，可点击下载；
  * 语音显示时长（本工具不接收语音内容，只提示时长）；
  * **视频消息**可点开在线播放（拖动进度条快进也支持：本机接口按 Range 分段返回）；只有**电脑微信里播放/接收过**的视频才有本地缓存，没缓存时显示不可播放；
  * **实验性「自动缓存聊天视频」按钮（默认关闭，V11）**：开启后会切到对应聊天、点一次视频让微信缓存下来（会短暂抢窗口、可能点偏，失败只记日志）；**仅实验性质，建议保持关闭**；
* 新消息进入有动画；向上翻历史时自动滚动会暂停，并出现「**回到最新**」浮标；
* 页面最多渲染最近 **400 张卡片**（更早的往上翻仍有数据，最多保留 3000 条），避免页面卡顿。

### 4. 右栏 · AI 分析

见第五节"AI 分析用法"。

### 5. 底部日志抽屉

* 默认收起，点顶栏「日志」展开；
* 按级别着色（info / warn / error），最多保留 500 行，新日志自动滚到底；
* 和桌面版日志区内容一致，排错时先看这里。⚠️ 日志里**不会**记录你的 API Key。

见第四节。

## 四、配置 DeepSeek（只需要一次）

AI 分析需要 DeepSeek 的 API Key。**没有 Key 时页面照常收消息、看历史，只是 AI 分析不可用**（会引导你去配置）。

### 1. 申请 API Key

1. 浏览器打开 DeepSeek 开放平台：**<https://platform.deepseek.com/api_keys>**（需先注册/登录，可能需要实名）；
2. 点「**创建 API Key**」，起个名字（比如 `wx_box`）；
3. **立即复制**生成的 Key（形如 `sk-xxxxxxxx...`）。关闭弹窗后就看不到了，丢了只能重新创建；
4. Key 需要账户有余额才能调用，按量计费，费用很低。

### 2. 填写配置

点顶栏右侧「**模型设置**」打开弹窗：

| 项目 | 怎么填 |
|---|---|
| **API Key** | 粘贴刚才复制的 `sk-...`。输入框是密码型，可点"显示"核对；保存后页面只显示 `sk-…后4位` |
| **模型** | 下拉框里**只有一项**：**DeepSeek V4.1 Flash 1017**（模型 id `deepseek-flash`）。这是当前唯一支持、也是官方推荐的模型，**不要**手改 |
| **Base URL（高级）** | 默认 `https://api.deepseek.com`。只有用中转/代理服务时才需要改，普通用户**不要动** |
| **默认开启深度思考** | 建议保持开启：分析更细，但速度慢一些、消耗 token 多一些 |
| **默认附带图片** | 建议开启：分析时会把最近的消息图片一起发给模型（图片也计费） |

### 3. 测试连接 + 保存

1. 先点「**测试连接**」：成功会显示"连接成功，延迟 xxx ms"；失败会给出中文原因（Key 无效 / 网络不通 / 余额不足 / 请求过于频繁）；
2. 连接成功后再点「**保存**」；
3. 保存后右栏 AI 分析面板顶部的徽标会变成模型名，说明已配置好。

> 🔐 你的 Key 只保存在**本机项目根目录**的 `web_config.json`（页面里从不回显完整 Key，日志里也不记录）。**不要**把 `web_config.json` 上传网盘/GitHub/发给别人。

也可以直接用环境变量兜底（适合不想落盘的情况）：没有保存 Key 时，程序会读环境变量 `DEEPSEEK_API_KEY`：

```bat
set DEEPSEEK_API_KEY=sk-你的key
C:\Python314\python.exe web_app.py --fake
```

## 五、AI 分析用法

右栏从上到下：

### 1. 选分析范围

* **当前会话**：只分析左栏当前筛选的那个好友**或群聊**（群聊用群名作为范围名）；
* **全部消息**：分析页面里保存的所有消息（跨好友/群聊，适合"最近整体聊了什么"）；
* **监听好友**：只分析你勾选监听的那些好友/群聊的消息（可进一步限定具体好友）；
* **朋友圈**（朋友圈 tab 下）：全部朋友圈 / 当前动态（最多 30 条）。

> 群聊分析的转写稿会带成员名：`[时间] 测试群/张三（对方）：大家好`；图片等非文字写成 `测试群/李四（对方 · 图片）：[图片]`；自己写成 `测试群 · 我（文字）：收到`。

### 2. 快捷指令（chips）

点一下自动填好问题，常用五个：

| 快捷指令 | 作用 |
|---|---|
| **摘要** | 用中文总结这段对话的要点，谁说了什么、结论是什么 |
| **待办** | 提取所有需要你跟进的承诺/任务，列成清单（谁、做什么、什么时候） |
| **情绪** | 分析对方的情绪和态度变化，提醒有没有不满、敷衍、催促 |
| **风险** | 找出可能踩坑的地方：答应太快、信息不足、时间冲突、措辞风险 |
| **关键结论** | 只保留最重要的 3~5 条结论，忽略寒暄 |

### 3. 自定义问题

在输入框直接打问题（1~4000 字），比如：

* "帮我写一条回复，语气委婉，拒绝这个需求"
* "对方提到的截止时间是哪几个？按日期列出来"
* "把这段对话整理成周报素材"
* "有哪些地方我可能理解错了？"

### 4. 选项

* **深度思考**：模型先"思考"再回答，适合复杂分析（会显示可折叠的思考过程，耗时更长）；
* **附带图片**：把范围内最近的图片/GIF 一起发给模型看（最多 6 张、单张 ≤ 8MB）；朋友圈分析时图片从**内存**取，不再依赖磁盘缓存。关掉可以省钱、提速。

### 5. 开始 / 停止 / 复制

* 点「**开始分析**」后，答案会**逐字流式**出现在下方输出区；
* 正在分析时按钮变成「**停止**」，点一下立即中断（会保留已经生成的部分）；
* 输出区支持 **Markdown 渲染**、代码块、列表；
* 顶部有「**复制**」把全文复制到剪贴板，「**清空**」清掉本次结果；
* 底部会显示**耗时**和 token 用量（输入/输出）；
* 同一时间**只能跑一个分析**，正在分析时再点会提示"请求繁忙"——等它结束或点停止。

> 💡 分析结果是模型生成的参考建议，**可能出错**，涉及承诺/金额/时间的内容请自己核对。本工具不会替你发送或回复任何消息。

## 六、朋友圈（网页端新增）

网页端把同目录 `WechatMoments/`（已适配微信 4.x）的朋友圈数据也接进来了：文字、图片、位置、分享链接、评论、点赞、作者头像都能看，也能交给 DeepSeek 分析。

### 1. 打开朋友圈

点顶栏中间的「**朋友圈**」tab：

* 左栏变成朋友圈信息面板：**账号昵称、可见条数、最近同步时间**，以及：
  * **同步条数选择（5 / 10 / 20 条）** + 「**同步朋友圈**」按钮；
  * 「**清空朋友圈**」按钮（带确认，清空后需要重新同步）；
  * **自动监听开关 + 间隔**（10~300 秒，默认 30 秒，V8）：**真实模式默认开启**（fake/只读跟随默认关闭），但**只在实时监听期间生效**——点「开始监听」后才启动后台检查/刷新，点「结束监听」立即全部停止（不再执行任何切窗口/点击）；页面启动时若后端本来就在监听，会自动接着生效；重新开始监听后从那一刻重新计 30 分钟。监听期间有两种来源：①每 N 秒**只读本机 `sns.db`** 检查，有新动态才自动限量同步；②**每 30 分钟**通过窗口点击「发现→朋友圈→刷新」让微信客户端自己拉最新（只点页面/刷新，不点赞、不评论、不发消息；微信在前台或最小化时跳过，失败只记日志，会短暂切窗口）；启动/首次开启后先补同步一次最新 N 条；关闭自动同步开关则**不做任何自动检查/刷新**；
  * 作者筛选和"只看有图片/评论"开关；
* 中栏是**时间线卡片**：作者头像 + 名字、时间、正文、位置；图片按九宫格或单张大图展示；**视频显示封面 + 时长，可点开在线播放并拖动进度**（内存流式、支持 Range，需先同步到该视频）；下方显示点赞和评论；**页面最多渲染 30 条**；
* **V2 风控**：打开页面默认不做全量刷新；真实模式下自动监听默认开启，但**只在实时监听期间**运行（监听期间每 30 秒检查本地库、每 30 分钟窗口刷新一次；结束监听即停止，不切窗口不点击）；有新动态才同步、首次补一次最新 5/10/20 条；**fake / 只读跟随模式默认关闭**，需手动点「同步朋友圈」；手动同步每次只取时间最新的 5/10/20 条；
* **只读跟随模式**（`--follow-log`）下朋友圈同样只能手动同步，不会干扰正在运行的桌面版；
* 顶栏有「数据仅在内存，关闭网页端后清空」的提示。

### 2. 同步说明（重要）

* 朋友圈数据来自**你电脑上微信自己缓存的本地数据**，本工具只是只读解析，不联网抓取；
* 因此**只能导出"你在这台电脑的微信里浏览过的朋友圈"**，没翻到过的不会出现；
* **图片需要先在微信里点开过**（滚动加载/点开大图）才会缓存到本地；没有本地原图时，会用微信 CDN 的**小缩略图**补图（150 宽，受风控限制：最多 60 张、并发 ≤3、超时 10 秒、不重试），失败就显示占位；
* 同步在后台进行，**不会卡住聊天页**；同步中按钮转圈、时间线显示骨架屏，完成后自动刷新；
* **实时监听期间（自动同步开启时）**：每 30 分钟会通过窗口点击让微信自己刷新一次朋友圈，**会短暂把微信切到前台**再尽量恢复（只点页面/刷新，不互动；微信在前台或最小化时跳过）；**结束监听后立即停止**，不会在后台操作微信；
* **数据只存内存**：不写 `webui/cache/moments.json`、不写 `media/moments/`；关闭网页端或重启后清空，需要重新同步；
* 视频绝大多数情况下本地没有缓存，只显示占位卡片（不会自动下载视频）。
* 想释放内存/重新来一遍：点「清空朋友圈」，再点「同步朋友圈」即可。

### 3. 同步失败怎么办

失败**不影响聊天监听**，朋友圈页签会显示可读原因和「重试」按钮。常见原因：

| 提示 | 原因与处理 |
|---|---|
| 微信未登录 / 未检测到微信数据 | 打开并登录微信电脑版，停在主界面后重试 |
| 朋友圈依赖缺失 | 项目里的 `WechatMoments/.venv` 没装好（需要 Python 3.12 环境）；把 `WechatMoments` 文件夹完整放回项目根目录，或按该目录的说明重建虚拟环境 |
| 密钥失效 / 数据库被占用 | 重启微信和网页端再试；微信升级后可能需要更新 `WechatMoments` |
| 解析失败 / 超时（120 秒） | 数据量大或格式变化，重试一次；持续失败看底部日志抽屉与 `WechatMoments` 的说明 |
| 部分图片是缩略图 / 占位 | 本地没缓存原图时只拉 CDN 小缩略图（150 宽，受风控限制）；在微信里点开图片后再同步，或接受占位（见 FAQ 13） |

### 4. 用 AI 分析朋友圈

右栏 AI 分析面板在朋友圈 tab 下会自动切到朋友圈范围：

* **全部朋友圈**：把当前可见的朋友圈一起分析（最多 30 条），适合"最近大家在聊什么/谁和谁互动多"；
* **当前动态**：只分析你点开的那一条，适合"这条动态什么意思/帮我想个评论"；
* **快捷指令**：摘要 / 人物关系 / 情绪 / 话题 / 风险；
* **附带图片**：开启后会把你选中范围内的朋友圈图片一起发给 DeepSeek 看（最多 6 张，来自内存），关闭可省钱提速；
* 其他操作（深度思考、停止、复制、耗时/用量）和聊天分析完全一样，见第五节。

> 🔐 隐私提示：朋友圈内容只从**本机**读取；只有你主动点"开始分析"时，相关文字才会发给 DeepSeek；开启"附带图片"时还会发送最多 6 张图片。是否发送由你决定。

## 七、同步历史聊天（V2 新增，V3 支持群聊）

实时监听只能看到**从现在开始**的新消息；想看某个好友/群聊**以前**的聊天，用「同步历史」：

### 1. 怎么用

1. 在「消息」tab 左栏点选一个好友**或群聊**（点名字筛选，不是只勾选）；
2. 点消息区顶部的「**同步历史**」；
3. 在弹层里选条数：**5 / 10 / 20 / 50 / 100 / 全部**；
4. 同步完成后，消息会按时间顺序合并进当前消息流；如果本机缓存不够你选的条数，会弹出提示，例如「「白云一片去悠悠」在本机只缓存了 7 条聊天记录，不足 50 条，已同步全部 7 条」。

> 群聊历史会额外带上**群成员显示名**（`extra.sender_name`），AI 分析时转写稿会写成「群名/成员名」，能分清群里谁说了什么；自己发的消息不带成员名，显示为「群名 · 我」。

### 2. 数据说明（重要）

* 数据来源：**只读**本机微信数据库 `message_*.db` 的缓存（和实时监听同一套只读逻辑），**不发送消息、不写微信目录**；
* **只读取你选中的那个好友**，不会批量扫全部好友；
* 「全部」= 本机缓存到的该好友全部消息（可能很多，速度会慢一些）；
* 读到的消息**只放进网页进程内存**：不写 `log/`、不落盘；刷新页面还在（服务没退出），**关闭网页端后清空**；
* 读库依赖微信已登录且数据库密钥可用；失败时给中文原因（未登录 / 密钥失效 / 找不到联系人等），不影响实时监听；
* **只读跟随模式**（`--follow-log`）下也能用「同步历史」，它只读本机库，不会干扰桌面版。

### 3. 清空聊天

* 点消息区顶部「**清空聊天**」并确认，会清空**当前网页内存**里的消息、计数和日志；
* 以后的新消息会继续进来；
* 不会删除桌面版的 `log/`、`media/`，也不会影响微信本身。

## 八、实时同步说明

* 页面通过 **SSE（Server-Sent Events）** 长连接实时接收：新消息、好友列表更新、状态变化、日志、AI 分析片段、朋友圈同步结果、清空事件；
* 断线（关 WiFi、休眠唤醒、服务重启）后浏览器会自动重连；重连成功会重新拉一次全量快照并**按消息 id 去重合并**，不会出现重复消息；
* 页面消息缓存上限 **3000 条**，超出后丢弃最旧的；桌面版的完整历史始终在 `log/messages.jsonl`；
* 「同步历史」读到的消息、「清空聊天」「清空朋友圈」也通过 SSE 通知所有打开的页面，多标签页保持一致；
* **只读跟随模式**下没有采集：网页每 1 秒 tail 一次 `log/messages.jsonl`，桌面版写入的新消息通常在 1 秒内出现；
* 聊天图片 / GIF / 文件使用 `media/` 目录里的**原文件**直接展示（桌面版采集的），不是截图；媒体路径带会话令牌，令牌失效时图片会加载失败，刷新页面即可；
* **朋友圈图片/头像来自网页内存接口**（`/api/moments/media/<key>`），不落盘，清空朋友圈或重启后返回 404，重新同步即可；
* 页面刷新不会丢数据（数据在服务端内存），但**关掉服务进程**后：消息、朋友圈、历史聊天全部清空，桌面版的 `log/`、`media/` 不受影响。

## 九、安全与隐私

| 事项 | 说明 |
|---|---|
| **只监听本机** | 服务只绑定 `127.0.0.1`，不对局域网/外网开放，别的电脑访问不到 |
| **Host 校验** | 只接受 `127.0.0.1` / `localhost` / `::1` 的访问，防止恶意网页通过 DNS 重绑定偷数据 |
| **令牌鉴权** | 每次启动生成随机令牌（32 位以上十六进制），接口/媒体都要带，防止本机其他程序乱调 |
| **只读** | 不发送消息、不回复、不点赞、不修改微信数据；只读你本机微信的本地数据 |
| **只读跟随模式** | 不启动采集、不操作微信、不写 `config.json`/`media/`/`log/`，只读取桌面版已写入的日志；适合桌面版正在运行时同时查看 |
| **朋友圈 / 历史只在内存** | 朋友圈、图片/头像字节、同步进来的历史聊天只放网页进程内存，不写 `webui/cache/`、`media/moments/`，关闭网页端即清空，不占磁盘 |
| **朋友圈图片风控** | 没有本地原图时只在线拉微信 CDN 的**小缩略图**（150 宽，最多 60 张/次、并发 ≤3、超时 10s、不重试），图片按需拉取、不重复扫描 |
| **朋友圈窗口刷新（V8）** | **仅实时监听期间且自动同步开启时**，每 30 分钟通过窗口点击「发现→朋友圈→刷新」让微信客户端拉最新：只点页面/刷新，不点赞、评论、发消息；微信在前台/最小化时跳过，失败只记日志；结束监听立即停止 |
| **历史同步只读** | 只读本机微信数据库缓存，只读你选中的那个好友/群聊；不发送消息、不写微信目录、不写 `log/` |
| **群聊列表只读** | 群聊列表来自本机 `contact.db` 的只读查询，结果只放内存缓存（默认 60 秒），不落盘、不改微信数据 |
| **Key 只存本机** | API Key 仅保存在项目根 `web_config.json`（建议不要分享），页面只显示后 4 位，日志不记录 |
| **不上传** | 除了你主动点"开始分析"时把消息文本/图片发给 DeepSeek，其它数据一律不出本机 |
| **敏感文件** | `web_config.json`、`config.json`（含解密密钥）、`log/`、`media/`、`media/` 里的图片都算隐私，分享截图前先打码/清理 |

## 十、常见问题（FAQ）

### 1. 提示 8081 端口被占用 / 页面打不开

* 本项目默认端口是 **8081**（8080 已让给其他项目，不再使用）；如果 8081 也被占用，换个端口启动；
* 大概率是**已经开了一个网页端或桌面版**，或者别的软件占了 8081；
* 换端口启动：`C:\Python314\python.exe web_app.py --port 8082`，然后访问 `http://127.0.0.1:8082`；
* 想找是谁占了：命令行执行 `netstat -ano | findstr :8081`，最后一列是进程号，再 `tasklist | findstr <进程号>`；
* 关掉旧进程（任务管理器结束）再启动。

### 2. 微信没连接，网页还能看历史吗？

**能看，但只能看到本次运行已经采集到/同步到的数据。**

* 网页端的数据来自 `wx_core` 后端。后端没起来 / 微信没登录时，页面打开会显示状态"未连接"，消息区为空（或只显示演示数据）；
* 想看某个好友**以前**的聊天：选中好友后点「同步历史」，选 5/10/20/50/100/全部（需要微信已登录、数据库密钥可用，见第七节）；
* 想回看桌面版采集过的全部历史，也可以直接看 `log/messages.jsonl` / `log/聊天记录.txt`；
* 判断方法：看顶栏状态点颜色 + 底部日志抽屉里的报错原因（比如"未找到微信窗口""缺少 OCR 依赖"）。

### 3. Key 无效 / 401 报错

* 检查 Key 是否**复制完整**（`sk-` 开头、没有多余空格/换行）；
* 到 <https://platform.deepseek.com/api_keys> 确认这个 Key **没被删除**；
* 确认账户**有余额**（402 报错=余额不足）；
* 点「测试连接」看具体中文提示；
* 如果用了中转地址，确认 Base URL 填对（普通用户保持默认 `https://api.deepseek.com`）。

### 4. 提示"请求过于频繁" / "请求繁忙"

* **请求繁忙**：同一个网页端同时只能跑一个 AI 分析，等当前分析结束或点「停止」再试；
* **请求过于频繁（429）**：DeepSeek 侧限流，等几十秒再点；或者关掉"深度思考"、减少"附带图片"降低消耗；
* 网络抖动也会失败，重新点一次通常就好。

### 5. 图片 / GIF 不显示

* **聊天图片**：路径来自 `media/` 目录（桌面版采集/解密的原文件）。检查项目根目录下 `media/` 里确实有对应文件（演示模式会生成 `demo_*.png/gif`）；
* **朋友圈图片**：来自网页内存（同步时内联），不落盘；显示不出时多为本地没缓存、CDN 缩略图拉取失败（网络/超时），或已经「清空朋友圈」——重新点「同步朋友圈」；
* 如果是**真实监听**：图片解密依赖图片密钥，密钥没提取到/微信升级后格式变化，会出现"只有文字没有图"——看日志抽屉里的 warn 提示；
* 刷新页面（令牌可能已过期）；
* 文件太大（>8MB）AI 分析会跳过该图，但页面展示不受影响。

### 6. 页面不自动刷新 / 一直"未连接"

* 先看底部日志抽屉有没有 SSE 报错；浏览器 F12 的 Console/Network 里看 `/api/events` 是否连上；
* 服务进程是不是已经退出（命令行窗口被关掉/报错崩了）——重新启动即可；
* 浏览器插件（广告拦截、隐私保护）可能拦截 SSE，试试关插件或无痕窗口；
* 长时间休眠后连接可能僵死，**刷新页面**最直接。

### 7. 双击 `run_web.bat` 一闪而过

和桌面版一样，通常是 Python 路径不对或依赖缺失。打开命令提示符手动执行 `C:\Python314\python.exe web_app.py`，就能看到完整报错；常见原因见 [常见问题](常见问题.md) 第 1 条。

### 8. 修改了监听好友，但页面没变化

* 勾选后要等约 0.5 秒自动保存；如果后端处于停止状态，需要先点开始监听（或重启网页端）；
* 页面上的勾选和 `config.json` 的 `monitored` 是同步的，冲突时以**最后一次保存**为准；
* **只读跟随模式**下勾选只影响本页筛选，不会改变桌面版正在监听的名单——这是正常的。

### 9. 图片显示"已失效 / 未缓存"占位

* **聊天图片**是正常现象：网页只展示 `media/` 里真实存在的原文件，本地缓存被清理、被移动、或当时就没解密成功时，卡片会显示占位；
* **朋友圈图片**只存在内存：清空朋友圈、关闭/重启网页端后，旧页面的图片链接会返回 404，重新「同步朋友圈」即可；
* 文字内容和 AI 分析完全不受影响（图片只是附件）；
* 想看更多图片，可以让桌面版重新采集/解密，或按 [常见问题](常见问题.md) 的图片相关条目排查图片密钥。

### 10. 能一边开桌面版一边用网页吗？

* **真实模式**下不要：两个采集线程会抢微信窗口、重复写 `media/`、`log/`；
* 想同时用：网页端用 `--follow-log` 只读跟随（见 2.4），只读桌面版日志，安全且不干扰；
* 演示模式（`--fake`）也不依赖微信，但它是假数据，不能和桌面版"配合"。

### 11. 关闭网页后朋友圈 / 历史聊天没了，是正常的吗？

**正常，这是 V2 的设计。** 为了不落盘、不占空间：

* 朋友圈、图片/头像字节、同步进来的历史聊天都只在网页进程内存里；
* 关闭网页端（Ctrl+C / 关命令行窗口）或重启电脑后自动清空，不会写 `webui/cache/`、`media/moments/`；
* 下次打开网页重新点「同步朋友圈」/「同步历史」即可；桌面版自己的 `log/`、`media/` 不受影响。

### 12. 历史同步提示"记录不足"怎么办？

* 说明本机微信只缓存了这么多条（例如"只缓存了 7 条，不足 50 条"），页面会**把能读到的都同步过来**，只是数量少于你选的值；
* 这不是错误，不需要处理；想少等一会儿可以选 5/10/20 条；
* 如果一条都没有：确认微信已登录、最近在这台电脑上聊过这个好友，再点「同步历史」重试。

### 13. 朋友圈图片变成缩略图 / 占位是为什么？

* 本地没有缓存原图时，工具只会在**风控限制内**在线拉微信 CDN 的**小缩略图**（150 宽，最多 60 张/次、并发 ≤3、超时 10 秒、不重试）；
* 所以部分图片会比微信里看到的糊，或直接显示占位——这是有意为之的省流量/降风险策略；
* 在微信里先把图片点开一次再「同步朋友圈」，有机会拿到本地原图（会压到最长边 ≤720 显示）；
* 本工具**不会自动刷新微信**，也不会为了补图去反复请求。

### 14. 为什么群聊列表没有某个群 / 列表加载失败？

* 群聊来自本机微信 `contact.db`，**只有这台电脑的微信同步过/通讯录里存在的群**才会出现；刚建的群先在微信里同步一下，再在左栏切到「群聊」重新加载（或刷新页面）；
* 群聊列表默认**内存缓存 60 秒**，点「重新加载/刷新」会强制重新读库；
* 微信未登录、数据库密钥不可用、`contact.db` 被占用/升级不兼容时，群聊页会提示中文原因；**不影响好友列表和聊天监听**，修好微信后重试即可。

### 15. 群消息发送人名字是怎么来的？

* **同步历史**时：按消息发送人 username 查本机 `contact.db`，**备注（remark）优先、群昵称（nick_name）其次**，写进消息的 `extra.sender_name`；查不到就显示 wxid 原值；群里自己发的消息显示「我」，不带成员名；
* **实时监听**：如果核心暂未提供群成员名，页面只显示群名、不报错（这是已知限制，后续脚本侧补充）；
* AI 群聊分析会显示成 `群名/成员名`，方便模型分清是谁说的。

### 16. 好友 / 群聊列表为什么变少了？想找的人不显示？

* **V4 起默认只显示"有聊天记录"的联系人**（有会话/历史消息的），这是为了去掉大量「暂无消息」的空联系人；
* 想找某个好友/群：先在微信里和它产生一条消息（或至少打开过会话），然后点左栏的**刷新**按钮重新读取；
* 列表有 **60 秒内存缓存**，刷新按钮会强制重新读库；微信未登录/数据库密钥不可用时列表会提示原因，但不影响已加载的聊天；
* 这个过滤只影响左栏展示，不影响监听、同步历史或 AI 分析。

### 17. 头像为什么是字母？为什么同一个人和别人的颜色不同？

* 为了不显示/缓存微信头像（隐私 + 性能），所有头像统一用**拼音首字母**：刘→L、何→H、张三→Z；英文名取首字母大写（alice→A）；数字或生僻字显示 `#`；
* 颜色由名字哈希决定，**不同用户颜色不同**；群成员用成员名/username 计算，所以同一个群里不同人颜色也不同；
* 首字母来源：联系人接口的 `initials` > 群成员 `initial` > 消息的 `sender_initial`，都取不到时用名字首字兜底。

### 18. 点「结束监听」后已加载的消息会没吗？再点「开始」会恢复吗？

* **不会删消息**：结束监听只停止后台采集，已经显示在页面上的消息保留；桌面版的 `log/`、`media/` 也不受影响；
* 再点「开始监听」会按**当前勾选的好友/群聊**重新开始读新消息（停止期间的消息不会自动补，需要就点「同步历史」）；
* 没有任何勾选时点「开始」会提示先勾选；只读跟随模式没有这两个按钮。

### 19. 红包 / 转账为什么显示成气泡、不能点？

* 微信数据库里红包/转账存的是 XML/HTML，网页端会**清洗成人话**：红包显示红色气泡、转账显示金色气泡，不会露出 `<appmsg>` 等原始标签；
* 本工具**只读**，气泡只是展示，不能领取/转账/点击跳转；金额、祝福语以能在气泡/文字里读到的为准。

### 20. 切换了微信账号，网页还显示旧账号的消息/好友？

* 在网页左栏点一次**刷新**：检测到账号变化会自动清空旧账号的**内存消息、监听名单**并重建数据库直读桥，然后换成新账号的好友/群聊列表；
* 同时会把新好友列表与账号标识写回 `config.json`（仅真实后端且有配置时；只读跟随模式不写），旧账号的聊天不会串到新账号下；
* 如果只想手动清空列表（不切号），用联系人/群聊面板的「清空」入口：清空网页内存联系人缓存、好友列表和 `config.json.friends_cache`；
* 网页端**不会**帮你切换/登录微信，切号请先在微信客户端完成。

### 21. 视频为什么打不开 / 只有历史里的能播？

* 视频**不复制、不落盘**：网页通过本机接口 `GET /api/video?friend=…&local_id=…&token=…` 直接流式读取微信自己缓存的视频文件（支持拖动进度/Range），只在本机 `127.0.0.1` 传输；
* 只有**电脑微信里播放/接收过**、本地有缓存的视频才能播；清理过微信缓存后就播不了；
* 前端需要消息的 `extra.db_local_id` 才能定位视频：**同步历史**的消息带这个 id，能播；实时通知若核心没给这个 id，就先用「同步历史」把该视频加载出来再播；
* 视频接口同样要页面令牌、`Cache-Control: no-store`，不会写微信目录、不上传。

### 22. 朋友圈「自动监听」会操作微信吗？会不会很占资源？

* **触发时机**：只在**实时监听期间**才生效——点「开始监听」后才启动；**点「结束监听」立即停止**，不再执行任何切窗口/点击；页面启动时若后端本来就在监听会自动接着生效；重新开始监听后从那一刻重新计 30 分钟；
* **两种来源**：监听期间——①每 30 秒**只读**本机 `sns.db` 检查；②**每 30 分钟**通过窗口点击「发现→朋友圈→刷新」让微信客户端自己拉最新（会短暂把微信切到前台，然后尽量恢复原界面）；
* **不做任何互动**：只点页面/刷新按钮，不点赞、不评论、不发送消息、不修改账号数据；
* **跳过与容错**：微信在前台（你正在用）或最小化时**跳过**窗口刷新；窗口尺寸/微信版本变化导致点击失败只记日志，不影响聊天监听和其它功能；
* **真实模式默认开启自动同步**（但同样只在监听期间运行：30 秒检查 + 30 分钟窗口刷新，首次补同步一次最新 N 条）；**fake / 只读跟随模式默认关闭**；关闭开关后**不做任何自动检查/刷新**；
* 可随时在左栏关闭；如果不需要实时性，就关掉自动监听、手动点「同步朋友圈」，更省资源；
* 自动同步的数据仍然**只进内存**，关闭网页端即清空；图片/头像也不落盘。

### 23. 朋友圈视频为什么打不开 / 能下载吗？

* 朋友圈视频需要**先「同步朋友圈」**把视频下载/解密到网页进程内存后才可在线播放；同步失败、视频未下载或已清空时，会提示不可播放；
* 播放走本机接口（支持拖动进度/Range），**不写磁盘、不暴露文件路径**；关闭网页端或「清空朋友圈」后需要重新同步；
* 本工具**只读**，不保存/导出视频文件；视频来自微信 CDN，能否拉到取决于网络和微信风控，失败只影响该条视频。

### 24. 「实验性：自动缓存聊天视频」是什么？安全吗？

* 这是**实验性**功能，**默认关闭**；开启后会切到对应聊天、模拟点一次视频让微信客户端把视频缓存到本地，之后才能在网页里播放；
* 属于**UI 自动化**：会短暂抢微信窗口、可能点偏；只点视频，不点赞、不评论、不发消息，失败只记日志、不影响监听；
* 默认关闭是推荐状态；如果按钮显示「不可用」，说明后端没有启用该实验模块，属正常；
* 缓存下来的视频同样只在微信本地缓存目录，网页播放仍走本机接口、不落盘、不导出。

## 十一、与桌面版共用数据

网页端和桌面版读写的是同一套项目文件：

| 路径 | 谁是数据主人 | 说明 |
|---|---|---|
| `config.json` | 桌面版/网页端都读 | 监听好友、数据库密钥等；真实模式网页端勾选会更新 `monitored`；切号刷新/清空列表会更新 `friends_cache`/`image_wxid`（只读跟随模式不写） |
| `web_config.json` | **网页端专用（新增）** | 只存 DeepSeek 配置（Key/模型/Base URL/开关），桌面版不读它 |
| `media/` | 共用 | 桌面版采集的聊天图片、GIF、文件、贴纸原文件（网页只读） |
| `log/messages.jsonl`、`log/聊天记录.txt` | 共用 | 桌面版完整历史与纯文本记录；网页端可只读跟随 |
| `webui/cache/`、`media/moments/` | **网页端不再写入（V2）** | 朋友圈/历史聊天只存内存；旧版本残留文件可直接删除，不影响使用 |
| 微信 `contact.db`、`session/session.db` | 微信（网页端只读） | 群聊/联系人列表、群成员名、"有历史记录"判断、拼音首字母的来源；只读查询、结果内存缓存 60 秒，不写微信目录 |
| 微信 `msg/video` 缓存 | 微信（网页端只读） | 视频播放来源；通过本机 `/api/video` 按 Range 流式读取，不复制、不落盘、不上传 |

> ⚠️ 再次提醒：**不要同时开桌面版 + 真实模式网页端**，否则两套采集线程会同时写 `media/` 和 `log/`，可能重复、错序，也浪费性能。想切换时先关掉一个，再开另一个；如果桌面版必须一直开着，就用网页端 `--follow-log` 只读跟随（见 2.4），它不写任何数据。

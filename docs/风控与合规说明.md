# 风控与合规说明（当前实现版）

> 适用：使用本工具的本机用户与审核者。
> 版本：2026-10-28（P0-1，文档与代码对齐）
> 说明：早期版本曾把项目描述为纯只读、无发送能力。该描述**已不再成立**。
> 当前版本在用户明确授权下，具备**读取本机微信数据、自动发送消息、可选联网查询**三类能力。
> 本文件按“当前真实能力 → 风险 → 可控手段 → 停止线 → 免责声明”描述，避免合规自证失真。

## 一、当前能力清单（事实）

| 能力 | 具体实现 | 默认状态 | 边界 |
|---|---|---|---|
| 读取微信进程内存（仅取密钥） | `wx_core/wechat_keys.py` / `wx_core/wcdb.py`：`OpenProcess(PROCESS_VM_READ)` → `VirtualQueryEx` → `ReadProcessMemory` 只读扫描 `Config.Cipher`；取到即关闭句柄并缓存 | 开启（可关） | 不写内存、不注入、不 Hook、不转储进程 |
| WCDB/SQLCipher 解密 | 逐页 AES-256-CBC 解密到系统临时目录（`wxdb_*`），`sqlite3 mode=ro` 读取；叠加 WAL 增量 | `db_direct=true` | 不写回微信库、不修改微信文件、不向微信目录写文件 |
| 自动发送消息 | 网关 `Gateway._send` → `send_cli` → `WxAutoSender`/wxauto4；`agi/data/wechat/config.json` 的 `send_mode=auto` 时自动发送 | `send_mode=auto`，可改 confirm/off（生产建议 confirm） | 受白名单、STOP、引擎软停、静默时段、频率/日限额、内容检查约束 |
| 读取本机缓存/媒体 | 只读 `xwechat_files` 下 `msg/file`、`msg/attach`、`cache/*/Emoticon`，离线解密图片/贴纸 | 开启 | 不向微信目录写/删/改名 |
| 本地 companion 数据 | `agi/data/**` 自有 SQLite：对话、记忆、草稿、媒体、审计 | 开启 | 与微信数据库隔离 |
| 可选联网查询 | `agi/integrations/web_lookup.py`：天气/新闻/网页检索/链接阅读；命中才查 | 由 `web_lookup_enabled` 控制 | 仅查询，不自动上传聊天记录；DeepSeek 分析属于用户主动操作 |
| 本地网页控制台 | `tools/console/` / `webui/` 本机 HTTP；含人工发送测试接口（仅文件传输助手） | 本机 | 需 admin token；不公网监听 |

**结论：本项目会发送消息。** 发送不是“隐藏能力”，而是受控能力：正常情况下只允许经
`Gateway._send`（含 STOP/白名单/静默/频率/内容闸门）。`WxAutoSender`、`send_cli`
是底层原语，只能由网关调用；**直接调用底层原语视为越界**，审计脚本会标为 unguarded。

## 二、用户授权范围

使用者授权本工具在**本人账号、本人设备、本人微信数据**范围内：

1. 一次性只读扫描微信进程内存，仅用于派生本人账号的数据库/图片密钥；成功即缓存，之后不再读内存；
2. 只读 `db_storage/**/*.db`，解密到本机临时目录，以只读方式读取；
3. 只读本地缓存图片/贴纸/文档，产出只写项目 `media/`、`log/`、`agi/data/`；
4. 按配置自动发送消息（默认 `send_mode=auto`），发送目标受 `allowed_contacts`/`proactive_contacts` 白名单约束；
5. 可选联网查询（天气/新闻/网页）；选择 DeepSeek 分析时，选中的文本/图片会发送到
   `api.deepseek.com`，属于用户主动操作。

授权**不覆盖**：他人账号/设备、批量营销、群发、抓取他人隐私、出售/传播密钥或聊天数据、
绕过微信安全机制，以及任何违法用途。

## 三、风险分级与停止线

### R1 账号封禁 / 风控（高）

- **触发条件**：自动发送频率高、短时间大量会话切换、发送营销/重复内容、向非白名单联系人发送、使用非官方客户端 API。
- **现状**：默认 `send_mode=auto`；有 `allowed_contacts`、STOP、静默时段、`rate_per_minute`、
  `hourly_limit`、`daily_limit`、主动消息 pacing 等闸门；但不等于微信官方认可。
- **可控手段**：只保留必要联系人；优先 `send_mode=draft`/`manual`；降低频率；开启 `dry_run` 验证；
  不使用群发/营销；不与其他自动化脚本并行。
- **停止线**（满足任一必须停止自动发送）：
  1. 微信出现“登录异常/账号受限/操作频繁”等提示；
  2. 收到平台警告或账号被限制；
  3. 需要向非本人授权联系人发送；
  4. 需要批量/营销/定时群发。
- **停法**：`config.json` 设 `stop=true`（最高优先）、`send_mode=off`，停止网关；必要时退出微信自动化。

### R2 隐私 / 数据泄露（高）

- **触发条件**：`config.json` 中密钥泄漏、项目目录/临时解密库被分享、日志/媒体被同步到网盘或仓库、
  在多人共用电脑/远程桌面运行。
- **现状**：可读取本人聊天、图片、文件；`config.json` 可能含 `db_keys`/`image_*`；
  `log/`、`media/`、`agi/data/` 含明文内容；解密临时目录可能残留。
- **可控手段**：仅本人设备；项目目录全盘加密/权限收紧；不提交 `config.json`/`log/`/`media/`；
  定期清理 `wxdb_*`；关闭不必要的 `trace`/网页控制台暴露。
- **停止线**：
  1. 设备/账号非本人或共用；
  2. 密钥/聊天记录/项目目录离开本机；
  3. 出现未授权访问（控制台暴露公网、token 泄漏）；
  4. 需要把数据交给第三方或用于训练外部模型（未获明确授权）。

### R3 法律与平台规则（高）

- **触发条件**：监控他人、商业营销、出售数据/密钥、绕过付费/权限、违反《微信软件许可及服务协议》
  或所在地个人信息保护法规。
- **现状**：本项目为个人本机辅助工具；不提供云端多租户；文档明确仅本人授权范围。
- **可控手段**：只处理本人数据；保留授权记录；不对外提供服务；不用于商业用途。
- **停止线**：任何非本人授权场景、商业分发、数据交易、规避平台安全机制——立即停止并删除数据。

### R4 自动化误发 / 内容事故（中）

- **触发条件**：模型生成错误内容、重复发送、发错联系人、干跑配置与正式配置混用。
- **现状**：出站有内容检查、STOP、白名单、频率限制、草稿/确认模式和失败草稿；仍可能发生误发。
- **可控手段**：先 `dry_run=true`；用 `send_mode=draft` 人工确认；小范围联系人；
  监控 `gateway.log` 的 `proactive_send` / `send_failed` / `send_blocked`。
- **停止线**：出现误发/重复发送/发错人，或模型输出明显不当——立即 STOP，暂停自动回复。

### R5 记忆/密钥/临时库残留（中）

- **触发条件**：临时解密库未清理、备份文件含密钥、旧版本目录残留。
- **可控手段**：退出清理 `wxdb_*`；备份加密；定期删除旧 `.legacy`/临时目录；限制系统权限。
- **停止线**：发现密钥或解密库出现在非预期位置——停止使用并清理。

## 四、硬边界（当前仍然禁止）

1. **不写微信进程内存、不注入 DLL/代码、不 Hook（SetWindowsHookEx 等）、不做 minidump/调试转储**；
2. **不写回/修改微信数据库**：SQL 连接必须 `mode=ro`，不执行 INSERT/UPDATE/DELETE/DROP/CREATE/ALTER/ATTACH/VACUUM；
3. **不向微信安装目录/微信数据目录写、删、改名任何文件**；
4. **不向未授权账号/设备发送**；发送只能走受控 `Gateway._send` 路径；
5. **不批量营销/群发、不抓取他人隐私、不出售/传播密钥或聊天数据**。

审计脚本 `tools/audit_compliance.py` 会扫描禁止 API、微信目录写入、发送路径与文档一致性；
发送路径区分为 allowed（受控入口）与 unguarded（无闸门直调），后者 FAIL。

## 五、停止与回滚操作

1. 紧急停止：`agi/data/wechat/config.json` 设 `"stop": true`（优先于一切发送）；
2. 停止自动回复/主动：`engine_enabled=false` 或 `auto_reply=false`；
3. 关闭自动发送：`send_mode="off"`（或 `draft` 人工确认）；
4. 关闭数据库直读：`db_direct=false`，回退窗口/OCR（能力降级，风险降低）；
5. 关闭进程内存扫描：`auto_extract_image_key=false`，不再提取新密钥；
6. 停止本工具：停止网关/控制台/桌面进程，删除临时 `wxdb_*`，按需删除 `log/`、`media/`；
7. 回滚版本：使用 git 历史恢复到旧版本；旧版本能力更少但同样不保证平台合规。

## 六、为什么仍选择本机、本人、授权范围内使用

- 不反编译/不修改微信程序，不替换 DLL，不分发微信文件；窗口操作只使用标准消息/键鼠；
- 密钥读取仅为了解密本人账号数据；取到即缓存，可关闭；
- 发送使用 wxauto4 的聊天输入路径，不伪造网络协议、不绕过登录；
- 产出只写项目自己的目录，但**这不改变风险**：读取/解密/发送都属于高风险自动化行为。

## 八、合规自检

```bat
C:\Python314\python.exe tools\audit_compliance.py
```

- 输出 `PASS` 且退出码 0：无越界 API/DB 写入/微信目录写入，发送路径均为受控入口，文档未与代码冲突；
- 输出 `FAIL` 且退出码 1：存在未受控发送、写内存/注入/Hook、DB 写操作、向微信目录写入，
  或文档仍写与当前发送能力冲突的绝对断言。
- 授权只读项（密钥扫描、数据库只读、缓存只读、发送受控入口）会在报告中**按文件:行号列出**，
  不代表“无风险”，只代表在授权边界内。

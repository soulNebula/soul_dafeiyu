# 34 · 心情判定移植方案（P9 · 「鱼的心情」→ wx_box）

参考项目：DSH 插件「鱼的心情」（`E:\agent\tmp\dsh-feiyu-mood`，JS）。
本仓库只**移植设计思路与 prompt**，不搬 JS 代码；实现为 Python 模块
`agi/selflearn/mood_judge.py`，默认**全关**（先 shadow 观察）。

---

## 1. 原项目核心设计（要保留的部分）

| # | 设计 | 原项目位置 | 本仓库落地 |
| --- | --- | --- | --- |
| 1 | 每轮模型判一次心情变化，输出 `{moodDelta, dims{7}, reason, confidence}` | `lib/index.js` 判断系统 / `parseDelta` | `mood_judge.judge()` + `parse_delta()` |
| 2 | 口径分流：`user` / `speak-up` / `duty` / `runtime-context`（跳过） | `judge()` 的三种 prompt 分支 + 来源白名单 | `judge(mode=...)` + `judge_messages()`；`runtime-context` 直接 `None` |
| 3 | confidence 门槛：低分只记录不注入 | 注入前过滤 | `mood_judge_confidence_min`（默认 60）+ `render_context()` |
| 4 | 一次变化只说一次 | `lastNotedMood` / 注入时机 | `mood_state.last_at` vs `last_injected_at` |
| 5 | 衰减：mood 半衰期 ~3h，7 情绪 90min，下限可配 | `decay()` / `noteDecay()` | 纯函数 `decay_values()`；`mood_min` |
| 6 | 心情下降只能因为心疼/担心/自己难过 | 判断系统规则 4 | `BASE_RULES` 规则 4 + 规则回退表 |
| 7 | 全 0 不记账 | `isNoChange` | `apply()` 里 `is_no_change()` |
| 8 | reason 两段式过去式、禁「此刻/现在/一直」、不替对方补细节 | 判断系统规则 6/8/11 | `BASE_RULES` 规则 6/7 + `_norm_reason()` |
| 9 | 设置页透明：预览"它会听到的那句话"+ 实际注入原文 + 时间 | 面板 | `snapshot()` 返回 `timeline[].user_text/reply_text` + `injected_preview` |

另外保留了原项目的 **mood 每轮只吃 1/3 判定值**（`MOOD_STEP_DIVISOR=3`，几轮才挪一格），
7 情绪即时加减；mood_state 里存浮点精度，timeline 只存展示用的整数（与 `decay.test.mjs`
"state precision / timeline integral" 的思路一致）。

## 2. 与原始项目的差异（为什么改）

1. **判定模型换成本地 0.5B（llama-server 8123）**：不调 DeepSeek，判定不产生云端成本；
   `timeout=1.5s`，失败/超时/坏 JSON → 回退 `affect` 规则的粗判（关键词口径，永远有 reason）。
2. **不替换 affect**：`affect` 继续管 skip / 危机 / 记仇（0–1 粗粒度状态机）；
   本模块是人格库里的**细粒度心情层**（0–100 + 7 情绪），两者并存、互不影响。
   危机消息：chat 不判（安全优先）；直接调 `judge()` 时 crisis 也走规则、不调模型。
3. **注入位置**：system prompt **尾部**追加 `<mood_context>` 段（不改 SYSTEM 主体，
   保留前缀缓存）；`mood_inject=false` 时返回空串 → prompt 逐字节不变。
4. **开关从环境变量/`mood.json` 读**：不写死进 `agi/selflearn/config.py`
   （该文件与 simple_tick 由别的任务在改），实现见 `mood_judge.settings()`。
5. **console 展示**：后端已提供 `mood_judge.snapshot()`（mood/label/dims/timeline/
   injected_preview/settings），前端卡片等 console 任务排期（本次因写域冲突未动 `tools/console`）。

## 3. 数据表（人格库）

`db.PERSONA_TABLES` 新增两张表（`db.connect` 透明路由到 `*.persona.sqlite3`）：

```sql
mood_state(id='self', mood REAL, dims_json TEXT, last_decay_at REAL,
           last_reason TEXT, last_confidence REAL, last_mode TEXT,
           last_at REAL, last_injected_at REAL, updated_at REAL)
mood_timeline(id, at REAL, mood REAL, dims_delta_json TEXT, reason TEXT,
              confidence REAL, mode TEXT, user_text TEXT, reply_text TEXT, created_at REAL)
```

- `mood_state` 单行：当前 mood（0–100，默认基线 70）+ 7 情绪（0–100）+ 最近一次判定/注入时间；
- `mood_timeline`：每次**有效**判定一行（全 0 不写）；`user_text/reply_text` 供设置页透明预览。

## 4. 判断 prompt（移植版要点）

见 `mood_judge.MODEL_SYSTEM` + `BASE_RULES` + `MODE_INSTRUCTIONS`，逐条对应原项目：

- 输出 JSON schema：`moodDelta`/`dims{7}` 各 -10..10、`reason`（≤120）、`confidence` 0..100；
- 规则 4（底线）：**心情下降只能因为「心疼对方、担心对方」或「你自己难过」，绝不许因为「对方惹你生气」而降**；
- 规则 6：reason 两段式、全过去式，禁「此刻/现在/正/一直/还」，不重复「踏实/甜/心疼」套词；
- 规则 7：只写这轮真实出现的动作/信息，不替对方补细节；
- 规则 8：confidence 自评口径（清楚 80–95 / 猜 60–75 / 平淡 20–55）；
- 三种口径的补充：`user`（两边都看，对方说了什么 + 你怎么说的）、
  `speak-up`（唯一判据是你开口那句，幅度小 +1~+4）、`duty`（唯一判据是你干活那句，±2~3）。

## 5. chat 接线

```
send()
  ├─ 生成回复、写入 turns/messages（原有逻辑）
  ├─ 非 crisis：mood_judge.judge_and_apply(path, mode="user", user_text, our_reply)
  │     └─ judge：本地 0.5B → 失败回退 affect 规则 → apply：衰减 + 1/3 步进 + 写 mood_state/timeline
  └─ 下一轮 _system_prompt(self.path) 尾部：mood_judge.context_line(path)
        └─ inject 开 & confidence ≥ 阈值 & 这条变化没说过 → 追加 <mood_context>，并标 last_injected_at
```

- 默认 `mood_judge_enabled=false`：chat 不判、不落库、prompt 不变；
- 默认 `mood_inject=false`：即使有变化也不注入；两开关可分开做 shadow（只判不注入）。

## 6. 开关 / 配置

优先级：环境变量 > `agi/data/selflearn/mood.json` > 默认值。

| 键 | 环境变量 | 默认 | 说明 |
| --- | --- | --- | --- |
| `judge_enabled` | `MOOD_JUDGE_ENABLED` | `false` | 每轮是否判（shadow 期只判不注入） |
| `async` | `MOOD_JUDGE_ASYNC` | `true` | 后台线程判定（不拖慢主链；测试/调试可关） |
| `inject` | `MOOD_INJECT` | `false` | 下一轮是否注入 |
| `confidence_min` | `MOOD_JUDGE_CONFIDENCE_MIN` | `60` | 低于阈值只记录不注入 |
| `mood_min` | `MOOD_MIN` | `0` | mood 下降下限（可配 30） |
| `half_life_h` | `MOOD_HALF_LIFE_H` | `3.0` | mood 半衰期（小时） |
| `dim_half_life_min` | `MOOD_DIM_HALF_LIFE_MIN` | `90` | 7 情绪半衰期（分钟） |
| `server_url` | `MOOD_SOUL_URL` | `http://127.0.0.1:8123` | 本地判定模型 |
| `timeout_s` | `MOOD_SOUL_TIMEOUT_S` | `1.5` | 判定超时（超时回退规则） |

## 7. 上线顺序（建议）

1. **shadow 观察**：`MOOD_JUDGE_ENABLED=1 MOOD_INJECT=0`，看 `mood_timeline` 的
   moodDelta/reason/confidence 分布、规则回退率（本地 0.5B 不可用时全是 rule）；
2. **灰度注入**：`MOOD_INJECT=1`，配合 `MOOD_JUDGE_CONFIDENCE_MIN=60`，
   观察回复是否更贴心情、有没有"借嘴说没底的话"；
3. **回退**：`MOOD_JUDGE_ENABLED=0`（不判）或 `MOOD_INJECT=0`（判但不注入），
   两者都立即生效、不需要重启。

## 9. 实测（2026-10-26，本地 0.5B v1b Q4_K_M @8123，20 轮真实 val 对话）

| 指标 | 结果 |
| --- | --- |
| 合法 JSON（G1） | **20/20**（decoder grammar 约束） |
| 判定来源 | local 20 / rule 0（server 可用） |
| confidence | 75–80（全部 ≥60 门槛） |
| moodDelta | mean -0.75，min -2，max 0，14/20 为 0（多数只动 dims） |
| 单次判定延迟 | P50 **582ms**、mean 603ms、max 1110ms（timeout 1.5s 内） |
| 主链影响（async=true） | judge=off P50 269ms → judge=on P50 **327ms**（+≈58ms，非 +580ms） |

⚠️ **质量提醒**：当前本地模型是「灵魂 InnerState」adapter，不是为心情判定训练的。
20 轮抽样里 JSON/confidence 都合规，但 reason 有机械/元叙述（如"他把话头递回来，我先别乱猜"），
dims 符号偶尔不合理（如心疼给负值）。建议：
1. 先用 **shadow（judge_enabled=1 / inject=0）** 收集数据，别急着注入；
2. 若要正式上线，用 DeepSeek teacher 生成 1–2k 条「对话 → MoodDelta」样本蒸馏一版
   mood adapter（复用 `agi/soul` 的 SFT 管道），再按 G1/G2 + 人工抽查验收；
3. 没有可用模型时规则回退永远可用（`rule_judge`）。

## 三、本轮新发现

### P0-A 测试会写生产配置 → 测试不确定 + "全绿"不实

证据链：
1. 测试窗口内 `agi/data/wechat/config.json` mtime → **03:22:18**、根 `config.json` → **03:24:05**（内容等价，但文件被重写）；
2. 两个失败用例的错误都是 `not_allowed`（注入 cfg 的 `allowed_contacts=["x"]` 被覆盖成生产白名单）；
3. 单独重跑 → 全绿。

根因：
- `Gateway.__init__`（`server.py:177`）`config_path` 默认 = 生产 `CONFIG_PATH`，并记录 `_cfg_mtime`；
- `_send()` 第一行 `reload_config_now()`（`server.py:1261`）；
- 某用例把配置写回生产路径（`server.py:616` `cfg.save_atomic`）→ mtime 变 → **之前构造的 Gateway 在下一次 `_send` 时热重载生产配置，覆盖测试注入的 cfg**；
- `conftest.py` 已隔离 `contact_db` 和 STOP 路径，**唯独没隔离 `CONFIG_PATH`**。

修复建议（约 5 行）：在 `agi/tests/conftest.py` 加一个 autouse fixture，
`monkeypatch.setattr(agi.wechat_gateway.config, "CONFIG_PATH", tmp_path/"config.json")`，
并让 `Gateway.config_path` 默认值读取该模块属性而非模块级常量快照。

### P0-B 空白名单 = 全放行（安全默认缺口）

`server.py:1275-1279`：`if allowed and contact not in allowed: block` —— `allowed` 为空列表时**直接跳过校验**。
而新装默认 `allowed_contacts: []`。即"白名单约束"在未配置时等于没有约束，与合规文档第 15/32 行的描述不符。
建议：空列表 → 拒绝发送（fail-closed），或首启向导强制填至少一个联系人。

### P1-C 弱口令仅告警不拦截

`admin_token="8888"`（实测仍为 4 位）只产生 `admin_token_weak` 审计事件，不阻断。
残余爆炸半径被 `confirm=true` + 白名单 + STOP + 限流收窄，但建议弱口令时**拒绝启动管理 API 或强制首启生成随机 token**。

### P1-D `__pycache__` 指向旧仓库

`agi/tests/__pycache__/test_quiet_reactive.cpython-314-pytest-9.1.1.pyc`（10-26）的 `co_filename`
仍是 `C:\Users\Administrator\Desktop\wx_box\...` —— 桌面存在**旧的 wx_box 副本**（非 git 仓库）。
影响：traceback 路径误导、且旧源码变动不会触发重编译。
建议：`find . -name __pycache__ -prune -exec rm -rf {} +`，旧副本归档或删除。

### P1-E 合规文档小滞后

`docs/风控与合规说明.md:15,32` 仍写"默认 `send_mode=auto`"，而生产配置已是 `confirm`。
按该文档自己的标准（文档与代码对齐），这属于又一次小漂移。

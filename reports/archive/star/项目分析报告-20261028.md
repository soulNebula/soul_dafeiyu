## 一句话结论

这是一个已持续产生运行数据、约 8–10 万行、近 2000 个测试用例、**真的在微信里自动收发消息**的个人 AI 伴侣（人格名「小鱼」）。
工程广度远超业余水平、局部深度不俗，但处于 **"功能全部跑通、治理已经破产"** 的状态。
最严重的不是任何一行代码，而是：**它正在无人值守地替用户发微信，而所有对外声明仍写着"只读、绝不发送"。**

## 三、最扎实的六处

1. **发送侧工程手法**：`send_cli.py` 子进程隔离、`ChatWith(exact=True)` + `ChatInfo()` 双验会话名 fail-closed（`sender.py:74-120`）、七类送达口径（`sendclass.py`）、失败内容落 `drafts.jsonl` 不丢。
2. **Web 安全基线**：`token_hex(24)` + `hmac.compare_digest`、Host 头防 DNS rebinding、路径穿越段级校验、XSS 全 `textContent`、SSE 慢客户端降级 `resync`。声称的防护基本真实现。
3. **记忆层**：写入硬要求 `evidence in text` 原文子串（`memory.py:289`）、冲突不覆盖而双标 `conflict`、`forget` 连原话改 `[已遗忘]` + 撤 claims + 删 FTS。
4. **训练门槛克制**：`train_gate.py` 默认 `dry_run=True`、300 条 + 三天门槛、只标 candidate 不自动上线。
5. **唯一可信的自律证据**：W2 实验三臂全输（rule 35.3% / model 43.2% / static 45.5%）→ 结论 inner 默认关、暂不做 LoRA。没过的门真的停了。
6. **"不像 AI"做成了工程**：`guard.py` 四类硬规则 + 设定书 1200 字禁则 + 4 个真调 API 的校验器；`agi/persona/xiaoyu/profile.json` 连"禁止编造吃喝拉撒/天气/位置"都写死。

## 四、问题清单（按危险度）

### 🔴 P0-1 红线三重失守且无记录

| 原始红线（`SPEC.md`） | 现状 |
|---|---|
| `:5` 不读取微信进程内存 | v4 承认从 `Weixin.exe` 内存定位 `Config.Cipher`，且 `db_direct=True` 是默认值 |
| `:5/:153` 不解密微信数据库 | v5 WCDB 逐页 AES-256-CBC 解密 + WAL 叠加 |
| `:109/:155` **绝不发送消息** | `dry_run=false`、`send_mode=auto`，10-24 真机 8 小时尝试 177 次 |

`docs/风控与合规说明.md` 至今仍写"它不发送任何消息"；`tools/audit_compliance.py` 把"发送消息"列为禁止项，**但扫描器不检查 `SendMsg`** → 合规自证体系已自我失效。

### 🔴 P0-2 生产配置 = 无人值守全自动 + 弱口令

- `admin_token: "8888"`（4 位），且支持 `?token=` query；`/api/approve` 带 `force=True` 可绕过静默与草稿；
- 白名单只在网关入口校验，**`_send()` 自身不校验**；
- `min_interval_s=0`（节流闸被配置清零）；熔断**只保护主动消息**；
- 发错无法撤回，不支持群聊。

### 🔴 P0-3 换台机器跑不起来

`E:\agent` 硬编码进 10+ 文件（含训练解释器 `E:\agent\venv312\Scripts\python.exe`）；
`requirements.txt` 中 `pycryptodome==4.1.0` 在 PyPI 上不存在，按它装必然失败。

### 🟠 P1-1 没有单一真相源

同一件事有 6 个版本：根 `SPEC.md`、`docs/specs/`、`agi/00-14*.md`、`plans/`（33–58）、`docs/plans/`（15–32）、`docs/sources/wx_box/`（本仓给自己的快照）。
症状：`plans/` 编号 17/27/55 缺号、`docs/specs/PLAN.md:15` 死链、`docs/README-usage.md:409` 说 78 passed 而 `README-legacy.md:466` 说 166 passed。

**最致命的是审计自己的供述**：`agi/00-14_完成度审计`:17 与 `执行覆盖审计_v2`:65 ——
"90 项里约 84 项是源码里有没有这个函数名的字符串检查"、"空库 66/68 通过"、"433 tests 无真实 E2E；`test_full_loop` 手工 `passed=True`"。

推测成因：**多 agent 并行开发的副作用**——每批任务一份 `BATCHn_CONTRACT.md` + 执行记录 + 审计快照，无收口机制，文档以"副本"形态爆炸。项目里的 `[LEAD]`/`[CORE]`/`[GUI]` 文件所有权注释印证了这点。

### 🟠 P1-2 架构碎片化

- **4 个 HTTP 服务 / 3 个 UI 面**：801 网关、802 控制台、8081 只读镜像、8082 selflearn 实验台；
- **5 套主动链并存**，实际只有 `simple_tick` 生效；
- **2 套 LLM 实现**：`webui/llm.py` 真流式无重试 vs `selflearn/llm.py` 非流式有 reasoning 扩容重试，传输层重复约 60%；
- **死链**：`WechatMoments/` 不存在 → 朋友圈链路恒不可用；`agi/core/` 不存在 → 25 条路由恒 503；
- `docs/ARCHITECTURE.md:32` 说收消息走 wxauto4(UIA)，**代码实际走 `wx_core.monitor` 截图 OCR / WCDB**——最新架构文档也是错的。

### 🟠 P1-3 防幻觉名不副实

- `citation.py` 校验完整，**但 prompt 渲染记忆时从不注入 id** → `guard.py:189` 的引用校验无引用可校，闭环断裂；
- `grounding.py` 是 bigram 字符重叠，只在 CLI 跑，自标"不是 NLI、不能用于生产判罚"；
- 两段式证据生成**默认关闭**（怕慢 2–5 秒）；`nli.py` 只在 guard 已报警时补一次，失败静默。

结论：能拦"绝对化/编数字/假装查过"，**拦不住"合理编造"**。

### 🟠 P1-4 "会训练自己"没转起来

LoRA trainer 是真代码，语料收集也真。但：`evaluate()` 只读已有 `eval.json`，缺失即返回 `evaluation_not_run`；`gate()` 的 `switched` 恒 False；`run_daily.py` 无调度器调用；语料主体字段是 `response` 而训练只收 `meta.inner_json` → **每天收的样本进不了训练**。
本地 0.5B 真在 8123 跑，但 `inner_shadow_only=true`，输出只写库不进 prompt → **对当前回复行为等于装饰**。

### 🟡 P2 工程细节

20+ 处主链 `try/except: pass` 吞掉可诊断错误；`retrieval.py:51` `except sqlite3.Error` 但**全文件没 import sqlite3**（真 bug，DB 报错会变 NameError）；`_coerce_bool` 等 helper 四份；无 `.git`、无 CI。

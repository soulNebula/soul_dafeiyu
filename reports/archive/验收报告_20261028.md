## 三、发现的问题与处理建议

| # | 问题 | 严重度 | 处理建议 / 当前状态 |
|---|---|---|---|
| 1 | **wxauto4 在 Python 3.13 下 UIA 枚举返回空**（`WeChat()` 报"未找到已登录客户端主窗口"） | 高 | 已换 wechatauto-replica（py3.12 venv）作为发送后端；wxauto4 代码保留，等其更新后切回 |
| 2 | wechatauto 官方文档要求微信 **4.1.12+**，本机是 4.1.8（实测可用但不保证） | 中 | 升级微信前先跑 `wechatauto 体检`；锁版本或记录兼容性 |
| 3 | 媒体发送只允许白名单目录（`media/stickers` 等），其它目录会被拦 | 中 | 需要发的图统一放 `media/` 子目录，或用配置 `media_dirs` 追加 |
| 4 | UIA 兜底发送媒体可能"报成功但没到"（剪贴板粘贴无校验） | 中 | 建议：媒体兜底结果标记 `unverified` 而不是 `sent`；当前优先走 wechatauto 原生 `SendFiles`，已规避 |
| 5 | 朋友圈只能读 `sns.db` 缓存（本机仅 1 条），没有滚动抓取；图片大多未解密 | 中 | 下一步：加 UI 滚动抓取 + 图片解密下载（wechatauto 有 `Moment`/`MediaDownloader`） |
| 6 | 对话工作室"试跑"用的是确定性假模型（dry），不是真实 LLM | 低 | 设计如此（避免乱发）；真实回复仍走微信链路 |
| 7 | CI 跑 ubuntu 时，8 个 Windows-only 测试文件可能红 | 中 | 建议加 `skipif(sys.platform!="win32")`，或 CI 改 `windows-latest` |
| 8 | `admin_token` 仍是 `8888`（弱口令），只告警不强制 | 中 | 建议换成 32 位随机；首次启动强制改 |
| 9 | auto 模式下 wechatauto 每条发送会切微信 1–2 秒（抢焦点） | 低 | 嫌打扰就切 `confirm` 草稿模式 |
| 10 | 朋友圈分析消耗 DeepSeek API token（已记账 `llm_usage.jsonl`） | 低 | 按需分析；预算超额会自动降级 |
| 11 | Git 自动推送未实测真实远端 | 低 | 需配置 remote 后手工验证一次 |

## 四、已知限制

1. **仅 Windows + 本机微信 4.x**；不支持群聊/@、不支持网页版。
2. 媒体图片依赖微信本地缓存解密；未解密时前端显示占位。
3. 朋友圈历史只能读本机 `sns.db` 已缓存内容（需 UI 滚动才更多）。
4. M4（UI 工作室）、M5（桌面化）尚未实现。
5. wechatauto 依赖独立 **py3.12 venv**（`E:\agent\venv_wx312`），因为 py3.13 的 comtypes/UIA 在本机不可用。

## 六、下一步建议（按优先级）

1. **CI 平台修正**：Windows-only 测试加 `skipif` 或 CI 换 `windows-latest`（否则首次 push 会红）。
2. **朋友圈增强**：UI 滚动抓取更多动态 + 图片解密下载 + 支持按人筛选。
3. **发送稳定性**：媒体兜底标记 `unverified`；加"发送前自检"按钮（wxauto/wechatauto/UIA 三后端可用性）。
4. **安全**：admin_token 强随机；首次启动强制改；加单实例锁。
5. **M5 桌面化**（Tauri）与 **M4 UI 工作室**（组件白名单 + 拖拽布局）。
6. 长训练验证：用真实语料跑 200–300 步 LoRA，转 GGUF 挂 8123 对比效果。
